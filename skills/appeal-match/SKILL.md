# appeal-match — 案件刺さるアピール生成

`/appeal-match <案件概要テキスト or ファイルパス>` [`トーン=<丁寧|カジュアル|フラット>`] [`長さ=<10秒|30秒|詳細>`]

## 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| 案件概要 | **必須** | 求人票・募集要項・スカウト文・案件相談DMなど。テキスト貼り付けでも、`@<path>` でファイル参照でも可 |
| トーン | 任意 | `丁寧` / `カジュアル` / `フラット`（デフォルト: フラット＝箇条書き型）|
| 長さ | 任意 | `10秒` / `30秒` / `詳細`（デフォルト: 10秒＝3点前後・各1〜2行）|

## 参照する素材（読み込み必須）

**毎回必ず最新を読み込む。記憶ベースで書かない。**

- 田村太一_職務経歴書＆自己PR: `/Users/apple/.cursor/work/個人/田村_職務経歴書＆自己PR.md`
  - 基本プロフィール / 職務経歴 / 強み・提供価値（01〜03）
  - 成果をあげるための仕組み（7種の自動通知）
  - 支援実績（BtoB/人材 4件・不動産 4件・EC/店舗/買取 5件 ＝計13ケース）
  - サービスメニュー / スキル・ツール

## 実行フロー

```
- [ ] Step 1: 案件要件の抽出（必須スキル・業務内容・媒体・予算規模・稼働形態・期間）
- [ ] Step 2: 職務経歴書を読み込み、要件にマッチする強み・実績・仕組み・ツールを特定
- [ ] Step 3: マッチ要素を「案件文脈の言葉」に微加工して3点前後の箇条書きに圧縮
- [ ] Step 4: 指定トーン・長さで整形して出力
```

### Step 1: 案件要件の抽出
案件文から以下を構造化して抜き出す（出力には載せない・内部処理）:

- **必須スキル**: 媒体名・領域（例: GDA/YDA、Meta、リスティング、LPO、CRM…）
- **業界・商材**: BtoB / EC / 不動産 / 店舗 / 買取 / 人材 など、職務経歴のどのケース群に近いか
- **予算規模**: 月間運用額（30万〜2億円の範囲のどこか）
- **業務内容のキーワード**: 「初回設計」「毎朝ルーティン」「レポート」「戦略立案」「クリエイティブ」など
- **稼働条件**: 時間/期間/リモート可否
- **隠れた論点**: 少額案件 → 効率設計 / 多業界 → 業界横断ノウハウ / ルーティン → 自動化 など、案件側の本音ニーズを読む

### Step 2: マッチング
職務経歴書の各セクションに対して、Step1の要件に**直接的に応える**要素を洗い出す:

- **強み 01〜03**: 「事業視点の戦略立案」「高度な広告運用力」「AI活用×マーケ」のどれが本案件で効くか
- **実績・数値**: 95%（19/20社）、月30万〜2億円、業務削減25%、各ケースの%指標
- **業界カバー**: 13ケースのうち本案件に近い業界を特定（複数業界なら「業界横断」として束ねる）
- **仕組み（7通知）**: ルーティン業務系・運用効率系の案件に強くマッチする独自要素
- **媒体カバー**: 検索/ディスプレイ/SNS/ダイナミック/認知/LPO/CRM のうち案件要件と重なるもの

### Step 3: 微加工して箇条書き化
- 各箇条書きは「**短い見出し（強み名）** ／ 数値や事実 ＋ 案件への寄せ」の形に
- 案件側の言葉（媒体名・業界・稼働条件）を必ず1つ以上織り込む（=「カスタマイズ感」を出す）
- 抽象的な強みより**具体数値（%・社数・金額・年数）**を優先
- 案件と無関係な実績は外す（全部盛らない）

### Step 4: 出力フォーマット
デフォルト（10秒・フラット）の標準形:

```
**＜本案件に活かせる強み＞**

- **<強み見出し>** ／ <数値・事実> ＋ <案件文脈に寄せた一言>
- **<強み見出し>** ／ <数値・事実> ＋ <案件文脈に寄せた一言>
- **<強み見出し>** ／ <数値・事実> ＋ <案件文脈に寄せた一言>
```

長さオプション:
- `10秒`: 3点 × 各1〜2行（デフォルト）
- `30秒`: 3〜4点 × 各2〜3行（背景の補足を1行ずつ追加）
- `詳細`: 3〜5点 × 各3〜5行（実績例・該当ケース・補強根拠を含める）

トーンオプション:
- `フラット`: 上記標準形（デフォルト）
- `丁寧`: 「〜が可能です」「〜の経験がございます」などです・ます調
- `カジュアル`: 「〜できます」「〜やってます」など軽め

## 実行原則

1. **必ず職務経歴書を毎回 Read してから書く**。記憶や過去会話で代用しない（内容は随時更新される）。
2. **盛らない・足さない**。職務経歴書にない実績や数値を創作しない。微加工は「言い換え」「寄せ」までで、新規事実は加えない。
3. **案件と無関係な強みは外す**。例: GDA/YDA案件なのに「SNS運用が得意」を入れない。
4. **数値・事実 > 抽象表現**。「豊富な実績」より「13業界以上」「月30万〜2億円」を優先。
5. **箇条書きは最大4点まで**。読む気を削がない。デフォルト3点。
6. **「なぜこの案件にこの強みか」が一瞬で繋がる構造**にする（並列ではなく、案件要件との対応関係が見える）。
7. 出力末尾で「トーン・長さ・項目の調整可」と1行だけ案内する。冗長な前置き・まとめは入れない。

## 入力パターンの解釈

- **テキスト貼り付け**: そのまま案件文として処理
- **`@<path>`**: ファイルを読み込む
- **トーン/長さの指定が混ざる**: 文末の `トーン=…` `長さ=…` を抽出して残りを案件文として処理
- **「もっと短く」「もっと詳しく」などのフォローアップ**: 直前出力を再整形（再マッチング不要）
