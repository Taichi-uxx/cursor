# English-review — 英単語・フレーズ復習クイズ

`/English-review [ファイルパス]`

## 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| ファイルパス | 任意 | 出題対象の英語学習mdファイル。省略時は `~/.cursor/English/vocabulary.md` |

## 対象ファイル形式

想定する主なファイル:
- `~/.cursor/English/vocabulary.md` （単語ストック・NARUTO世界観）
- `~/.cursor/English/reviewing_cambly_重要度順.md` （Cambly実践レビュー・重要度順）
- 上記と同構造の他ファイル

**基本構造（両ファイル共通）:**
```
### <英単語 or フレーズ>   ← 「/」区切りで複数表現の場合あり（例: `I get it / I get that`）
新規：✓                    ← 任意。English-addlistで追加直後に付与される「未検証」マーカー
ミス：×（または ××、×××、... ）  ← 任意。過去に間違えた回数を×の数で表す
重要度：★★★★★
Meaning：<意味・訳>
Example：<例文>
```

**出題対象:** 「ミス：」欄が存在する（×が1つ以上）エントリ **または** 「新規：✓」フラグがあるエントリ。両方無いエントリは対象外。
行の順序は `### <word>` → `新規：✓`（あれば）→ `ミス：×...`（あれば）→ `重要度：` を前提とする。

**Meaning書式のバリエーション（両対応必須）:**

パターンA（`vocabulary.md`）: 英語+カッコ内日本語
```
Meaning：Real or authentic.（本物の／マジの）
```

パターンB（`reviewing_cambly_重要度順.md`）: 日本語直書き
```
Meaning：なるほど／納得できる
```

**複数意味エントリ:**
```
### <word>
ミス：××
重要度：★★★★
Meaning：
　1. <意味1>
　2. <意味2>
Example：
　1. <例文1>
　2. <例文2>
```

## 実行フロー

```
- [ ] Step 1: ファイル読み込み・エントリのパース
- [ ] Step 2: 出題対象を抽出（ミス欄あり or 新規フラグあり）＋優先度でソート
- [ ] Step 3: 30問ずつバッチ出題（問題は英語のみ）
- [ ] Step 4: ユーザーが「答え」と言ったら答え合わせ（単語訳＋例文＋例文訳）
- [ ] Step 5: 間違えた問題番号を聞く
- [ ] Step 6: 実ファイル更新（間違い→ミス欄に×追加／正解＋新規→新規フラグ削除）
- [ ] Step 7: 未出題の対象エントリが残っていれば Step 3 に戻る
```

### Step 1: パース

- ファイルを `### ` で分割し、各エントリを構造化
- 各エントリから以下を取得:
  - `word`: `### ` の直後の見出し（`/` 区切りの複数表現もそのまま保持）
  - `is_new`: `新規：✓` 行の有無（あれば true）
  - `mistake_count`: `ミス：` 行の × の数（`ミス：` 行が無ければ 0）
  - `meaning_jp`: `Meaning：` から日本語訳を抽出（下記ルール参照）
  - `example`: `Example：` 内の例文（複数あれば全て）

**`meaning_jp` 抽出ルール（両書式対応）:**

1. `（...）` が含まれる場合 → カッコ内を日本語訳として採用（vocabulary.md想定）
2. `（...）` が無い場合 → `Meaning：` の後ろ全体を日本語訳として採用（reviewing_cambly想定）
3. 複数意味エントリ（`　1. ...　2. ...`）は各行ごとに上記ルールを適用
4. どちらのパターンでも「日本語部分だけ」を取り出す（英語の意味説明があってもそれは訳ではない）

### Step 2: フィルタ＋ソート

**対象:** `mistake_count >= 1` **または** `is_new == true` のエントリ

**優先度（降順）:**
1. `mistake_count` が多い順（3個 > 2個 > 1個）
2. 同じミス数の中では「新規フラグ有」を先に
3. `mistake_count == 0 && is_new == true`（=新規のみ）は最後のグループ
4. 同グループ内は元ファイル出現順を維持

**両方持つエントリ**（新規＋ミス×N）は `mistake_count` に応じてソートしつつ「新規フラグ有」として扱う。

### Step 3: 出題（30問／バッチ）

**問題文には日本語を一切含めない。** 英単語（フレーズ）と例文のみ。

出力形式:
```
**Q1. <word>**
"<example sentence>"

**Q2. <word>**
"<example sentence>"

...

**Q30. <word>**
"<example sentence>"

---

答え合わせしたくなったら「答え」って言ってください。
```

複数例文があるエントリは、例文1つを代表として選ぶ（原則1番目）。

### Step 4: 答え合わせ

ユーザーが「答え」「answer」等の合図を出したら、以下の形式で回答:

```
**Q1. <word>** — <日本語訳>
例文：<英語の例文>
訳：<例文の日本語訳>

**Q2. <word>** — <日本語訳>
例文：<英語の例文>
訳：<例文の日本語訳>

...
```

**例文の日本語訳は必ず付ける**（単語単体ではなく例文とセットで覚えるため）。
例文の日本語訳が元ファイルに無い場合は、その場で自然な日本語に訳して提示する。

複数意味あるエントリは全て番号付きで列挙:
```
**Q3. crack** — ①ひび／割れ目 ②パキッという音 ③難問を解く・見破る
例文：Shikamaru managed to crack the enemy's formation strategy.
訳：シカマルは敵の陣形戦略を見破ることに成功した。
```

末尾で:
```
---
間違えた問題番号を教えてください（例：「1, 5, 8」「Q3とQ7」など）。
```

### Step 5: 間違えた番号を受け取る

- 「1, 5, 8」「Q3とQ7」「全部」「なし」等の自由入力を解釈
- 番号を特定 → 対応する `word` を確定
- **今バッチの正解番号 = バッチ全問 − 間違い番号**（差分で確定）

### Step 6: 実ファイル更新

**バッチ内の全問について、以下4パターンに応じてEdit実行:**

| ケース | 元の状態 | 操作 |
|---|---|---|
| ①間違い＋新規あり | `新規：✓` あり、ミス欄なし | 新規行を削除 ＋ `ミス：×` 行を新設 |
| ②間違い＋既ミス | `ミス：×...` あり | `ミス：×...` に×を1つ追加 |
| ③間違い＋新規＋既ミス | `新規：✓` と `ミス：×...` 両方あり | 新規行を削除 ＋ `ミス：×...` に×を1つ追加 |
| ④正解＋新規あり | `新規：✓` あり | 新規行を削除（ミス欄はいじらない） |
| ⑤正解＋既ミスのみ | `ミス：×...` のみ | 変更なし |
| ⑥正解＋新規＋既ミス | 両方あり | 新規行を削除（ミス欄はいじらない） |

**Editツールの具体操作:**

- **`ミス：×` 追加/新設** — 対象エントリの直前 `### <word>` を含めて一意化:
  ```
  ### <word>
  ミス：×（旧値、無ければ「重要度：」行の直前に新設扱い）
  ```
  → 
  ```
  ### <word>
  ミス：××（×1個追加）
  ```
  ミス欄が元々ない場合は `### <word>` の直後（新規行があれば新規行の位置）に `ミス：×\n` を挿入する形。

- **`新規：✓` 削除** — `### <word>` を含めて一意化:
  ```
  ### <word>
  新規：✓
  ```
  → 
  ```
  ### <word>
  ```
  つまり `新規：✓` 行を1行まるごと削除する（前の `### <word>` を残したまま次の行を消す）。

- 複数エントリの更新は、それぞれ個別に Edit する（1回ずつ）

**更新完了後のサマリ:**
```
更新完了：
- ミス追加：<word1>, <word2>（間違い×N件）
- 新規解除：<word3>, <word4>（正解×M件）
- 新規解除＋ミス追加：<word5>（間違い＋新規×L件）
```

### Step 7: 次バッチへ

- 未出題の対象エントリ（ミス付き or 新規付き）が31問目以降に残っていれば「次の30問行きますか？」と確認
- 「はい」等の合図で次バッチを Step 3 から実行
- 「もういい」「終わり」等で終了

全て出題しきったら:
```
全ての対象エントリの出題が完了しました。おつかれさま。
```

## 実行原則

1. **問題文に日本語を絶対に混ぜない**。単語/フレーズと例文のみ。
2. **答え合わせの前に答えを見せない**。ユーザーが「答え」と明示するまで待つ。
3. **答えは「単語の意味＋例文＋例文の日本語訳」の3点セット必須**。例文の訳が元ファイルに無ければその場で自然な日本語に訳す。単語の訳だけで済ませない。
4. **ファイル更新は実ファイルへの反映を必ず行う**（Editツール）。会話上だけで済ませない。ミス追加も新規フラグ削除も両方必ずファイルに書き込む。
5. **ソート順を守る**：ミス×数の降順 →（同数内）新規あり優先 → 新規のみ最後。忘れやすいものから先に出題。
6. **1バッチ30問固定**。それ以下の場合は残り全部を1バッチで出す（例: 対象が12個なら1バッチ12問）。
7. **重複出題しない**。同一セッション内で同じエントリを2回出さない。
8. **ミス欄も新規フラグも両方無いエントリは対象外**。
9. **正解時も新規フラグは削除する**。新規は「未検証」フラグなので、出題した時点で検証済みになる。ただしミス欄は正解時にはいじらない（既存の学習履歴を残す）。
