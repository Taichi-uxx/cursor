# copy-build — コピー生成ワークフロー

`/copy-build <LP URL（必須）> 媒体=<媒体（必須）> [案件=<案件/商品情報 任意>] [ターゲット=<ターゲット情報 任意>]`

## 入力（4項目）

| 項目 | 必須 | 内容 |
|---|---|---|
| LP URL | **必須** | 着地ページのURL。Playwrightで取得（§Step1） |
| 媒体 | **必須** | 配信媒体。例: Google検索 / P-MAX / Demand Gen / Yahoo検索 / YDA / Meta(FB) / Meta(IG) / LINE / TikTok / X / YouTube。**未指定なら実行を止めてユーザーに確認**（媒体でファネル位置・刺す属性・良いコピー基準が変わるため推測で進めない） |
| 案件/商品情報 | 任意 | 商品MDパス/商品名/USP等。あれば精度向上 |
| ターゲット情報 | 任意 | 既知のペルソナ/ターゲット。無ければ入力から自動生成（§Step2） |

AI-Studio組織体（①CMO → ⑤CD → ⑥Copywriter → ㉑㉒㉓Persona → ⑤CD → ①CMO）でコピーを量産・選抜するオーケストレーター。ロールの詳細定義は下記を**実行時に必ず読む**（本ファイルに再掲しない）：

- 役割: `@/Users/apple/.cursor/work/AI-Studio PJT/agent-drafts/01_cmo.md` `05_creative-director.md` `06_copywriter.md` `03_customer-analyzer.md` `persona-template.md`
- 原則: `@/Users/apple/.cursor/work/principle/クリエイティブ/コピー/`（コピー.md / エモーションリレー_LP逆算.md / 媒体別コピー指針.md / コピー生成_価値種別.md / _動機・心理種別.md / _勝ちCRの要素.md / _良いコピーの型.md / _行動経済学.md）
- **媒体補正（必須）**: `@/Users/apple/.cursor/work/principle/クリエイティブ/コピー/媒体別コピー指針.md` — 指定媒体の該当§と§9（媒体適合チェック）を生成・評価で必ず適用
- 規制トーン: `@/Users/apple/.cursor/work/principle/業界知見/<業界>/`
- 田村基準: `@/Users/apple/.cursor/work/principle/マーケ戦略/田村の判断軸.md`

## 実行フロー

```
- [ ] Step 1: 入力解釈・LP取得
- [ ] Step 2: ペルソナ解決（案件に無ければ入力から自動生成）
- [ ] Step 3: ①CMO キックオフブリーフ
- [ ] Step 4: ⑥Copywriter 18案生成（6アプローチ×3案・並列）
- [ ] Step 5: 3ペルソナ採点
- [ ] Step 6: ⑤CD 採点・採否（80点閾値・最大3回ループ）
- [ ] Step 7: ①CMO 最終QC
- [ ] Step 8: 出力バンドル
```

### Step 1: 入力解釈・LP取得・媒体ロード
1. **入力バリデーション**: LP URL と 媒体 が揃っているか確認。**媒体が無ければ即停止してユーザーに媒体を確認**（推測で進めない）。
2. **LP取得（Playwright主軸）**:
   - `browser_navigate` でLP URLを開く → 描画待ち（`browser_wait_for`）→ `browser_snapshot` でDOM/テキスト構造を取得、必要なら `browser_take_screenshot` でファーストビュー視覚も確認。JSレンダリング/フォーム遷移LPもこれで本文が取れる。
   - 取得本文を **FV / 共感 / ベネフィット / 証拠 / オファー / CTA** の6ブロックに構造化（ライターA用）。
   - Playwrightが使えない/失敗時のみ WebFetch → それも不可なら商品情報で代替し「ライターAは想定LP仮説に縮退」を後続に明記。
3. **媒体ロード**: `媒体別コピー指針.md` から指定媒体の該当§（ファネル位置・刺す属性・コピー鉄則・推奨フォーマット）と §9（媒体適合チェック）を読み込み、後続の生成・評価へ渡すコンテキストにする。
4. 業界を推定し `principle/業界知見/<業界>/` を特定（規制・NG表現の事前把握）。
5. `案件=` 指定 or 文脈から案件名が分かれば `work/client/<案件名>/` の有無を確認。

### Step 2: ペルソナ解決 ★重要
1. **案件にペルソナ/ターゲット情報があるか確認**：`work/client/<案件名>/strategy.md` や同フォルダ内のペルソナ/ターゲット記述。
2. **ある場合** → それを `persona-template.md` の「私について」形式に整形して **3ペルソナA/B/C** を確定。
3. **無い場合（＝多くのケース）** → `03_customer-analyzer.md` のロールに従い、**Step1の入力情報（LP本文＋商品情報＋業界）だけ**から意味ある多様性を持つ3ペルソナを**その場で生成**。`principle/マーケ戦略/ペルソナ設計要点.md` を参照。属性に留めず価値観/購買行動/情報接触/不安・欲望・葛藤/口癖・語彙まで描く。
4. 採用/生成した3ペルソナ定義を**成果物として明示出力**。クライアントフォルダがあれば `work/client/<案件名>/personas_generated.md` への保存を提案（次回流用のため）。
5. このStep2の3ペルソナで以降の採点ループが回る（生成でも実データでも同じループ）。

### Step 3: ①CMO キックオフブリーフ
`01_cmo.md` に従い、目的/対象/ゴールKPI/制約/評価基準を1〜3行で確定。

### Step 4: ⑥Copywriter 18案生成
`06_copywriter.md` の振る舞いに**完全準拠**。スピードと文脈分離のため、**6アプローチを Agent ツールで並列サブエージェント化**（general-purpose）：

| サブエージェント | 渡す情報 | 返す物 |
|---|---|---|
| A LP逆算 | エモーションリレー_LP逆算.md + LP6ブロック + ブリーフ + 3ペルソナ | 起点インサイト+感情リレー表+最有力3案 |
| B 価値種別 | コピー生成_価値種別.md + ブリーフ + 3ペルソナ | 切り口の異なる最有力3案 |
| C 動機・心理 | コピー生成_動機・心理種別.md + 〃 | 〃 |
| D 勝ちCR要素 | コピー生成_勝ちCRの要素.md + 〃 | 〃 |
| E 良いコピーの型 | コピー生成_良いコピーの型.md + 〃 | 〃 |
| F 行動経済学 | コピー生成_行動経済学.md + 〃 | 〃 |

全サブエージェントに共通制約を渡す：メイン15字以内/サブ30字以内、業界NG表現、同一アプローチ内3案は切り口を変える。**加えて Step1 でロードした「指定媒体の媒体別コピー指針」を全サブエージェントに必ず渡し、各アプローチに媒体補正をかけさせる**（ファネル位置・刺す属性・推奨フォーマット・トーンを媒体に合わせる）。18案に統合。

### Step 5: 3ペルソナ採点
`persona-template.md` の評価フォーマットで、Step2の3ペルソナが**18案を採点**（`<thinking>`思考過程 → 感情リアクション → 購買意向10点 → 刺さる/刺さらない点）。各ペルソナは**指定媒体の閲覧文脈で見ている前提**で反応する（例: TikTokなら発見モード、Google検索なら能動検索モード）。3ペルソナを並列サブエージェント化してよい。

### Step 6: ⑤CD 採点・採否
`05_creative-director.md` に従い 5軸×5点=25点 → ×4で100点換算。
- **採点前ゲート**: `媒体別コピー指針.md` §9 の媒体適合5観点（ファネル整合/文脈馴染み/フォーマット適合/トーン適合/役割分担）を各案にチェック。媒体不適合は減点し、差戻し理由に媒体観点を明記。
- 最高点案が **80点以上** → ✅採用候補へ
- 全案80点未満 → 🔄該当アプローチに**具体的改善指示**（媒体適合の指摘を含む）を出して差戻し（そのアプローチの3案のみ再生成）→ **最大3回ループ**
- 3回後も未達 → 最高点案を「⚠️条件付き採用」でCMOへ

### Step 7: ①CMO 最終QC
`01_cmo.md` の判断ロジック：①期待値プラス ②戦略マッチ80%超。両クリアで採用、片方不足は差戻し理由＋次アクション提示。

### Step 8: 出力バンドル
```markdown
## /copy-build 結果

### 採用コピー
- メイン / サブ / 採用アプローチ / 採用理由（5軸＋ペルソナ評価）

### 差替候補（2案）
- 候補1 / 候補2（アプローチ・スコア・想定使いどころ）

### ペルソナ別 感情リアクション
- ペルソナA/B/C それぞれの一言反応とスコア

### 制作経緯ログ
- 6アプローチ各代表案とスコア / 差戻し回数と改善内容 / CMO最終QC

### 使用ペルソナ定義
- A/B/C（生成か実データかを明記。生成なら保存提案）

### 前提
- 対象媒体 / LP取得方法（Playwright or 代替）/ 推定業界
```
`work/client/<案件名>/outputs/` があれば `copy_YYYY-MM-DD_<商品>.md` で保存、無ければ本文提示＋保存先提案。
