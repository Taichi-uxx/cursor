# copy-build — コピー生成ワークフロー

## 入力（4項目）

| 項目 | 必須 | 内容 |
|---|---|---|
| LP URL | **必須** | 着地ページのURL。Playwrightで取得（§Step1） |
| 媒体 | **必須** | 配信媒体。例: Google検索 / P-MAX / Demand Gen / Yahoo検索 / YDA / Meta(FB) / Meta(IG) / LINE / TikTok / X / YouTube。**未指定なら実行を止めてユーザーに確認**（媒体でファネル位置・刺す属性・良いコピー基準が変わるため推測で進めない） |
| 案件/商品情報 | 任意 | 商品MDパス/商品名/USP等。あれば精度向上 |
| ターゲット情報 | 任意 | 既知のペルソナ/ターゲット。無ければ入力から自動生成（§Step2） |

## 実行原則（厳守・例外なし）

1. **オーケストレーター（このスキルを動かすメインエージェント）は、生成・ペルソナ生成・採点・代筆を一切行わない。** 役割は「入力取得」「サブエージェントへの委譲」「結果の集約」だけ。Step2〜7はすべて**独立サブエージェント**に委譲する。インラインでの自己採点・自己生成・一人多役は**禁止**（過去にこれをやって品質が崩壊した）。
2. **LP情報は「定義スキーマで構造化抽出」して渡す（全文ベタ渡しもアドホック要約も禁止）。** LP全文をそのまま渡すとコンテキスト肥大で生成精度が落ちる。一方オーケストレーターの場当たり5行要約は素材を喪失する（初回失敗の原因）。よって Step1 で**規定の商材ブリーフ・スキーマ**（後述）に沿って抽出する。規定フィールドの省略は禁止。抽出は独立サブエージェントが行い、オーケストレーターは判断を加えない。ペルソナは③が作る「名刺＋フル定義」の二層で運用し、勝手な1行圧縮や要約は禁止（実行原則#5で詳細）。
3. **品質優先。時間・手数を惜しまない。** 速いことより、各サブエージェントが十分な情報で深く考えることを優先する。
4. 各Stepのサブエージェントは会話文脈を見られない前提で、必要情報を自己完結で渡す。

5. **ブリーフ＆ペルソナは「実行用＋記録用」の二層化。情報過多は精度劣化を招く。** 下流SA起動時は**実行用を本文に埋め込み**、記録用は**参照パスのみ**伝える（全文埋め込み禁止）。
   - **商材ブリーフ**: Step1抽出SAが (a) 実行用（800字以内・訴求要点／お客様の声原文／数字・オファー／規制ガード／状況シグナル）と (b) フル版（規定スキーマ全項目・原文保持）の**両方**を別ファイルで出力する
   - **CMOブリーフ**: Step3 SAが (a) 実行用（1ページ・4ブロック＝目的／感情温度／絶対NG／評価軸）と (b) 詳細根拠（市場仮説・LTV・競合観察等）の**両方**を別ファイルで出力する
   - **ペルソナ**: Step2 ③SAが各ペルソナファイル冒頭に「## 名刺」セクション（300字以内・属性／刺さるツボ／離脱ボタン／口語1行）を必須で置く（フル定義の前段）。下流SAには名刺セクションを参照させる。**ただしStep5のペルソナ採点SAだけは「ペルソナ本人として人格を借りる」ため当該ペルソナのフル定義を渡す**（例外）
   - **principleファイル**（コピー/CLAUDE.md／媒体別コピー指針.md／コピー手法5原則／業界知見／田村判断軸）は**全文Read指示にしない**。SA起動時に「§◯◯だけ読め」と該当節を必ず指定する

### Step 1: 入力解釈・LP取得・媒体ロード
1. **入力バリデーション**: LP URL と 媒体 が揃っているか確認。**媒体が無ければ即停止してユーザーに媒体を確認**（推測で進めない）。
2. **LP取得（Playwright主軸・オーケストレーターはツール実行のみ）**:
   - `browser_navigate` → `browser_wait_for` → `browser_snapshot` で全文取得、`browser_take_screenshot`（fullPage推奨）でビジュアル取得。JS/遷移系LPもこれで取れる。
   - Playwright不可時のみ WebFetch → それも不可なら入力の商品情報で代替し「ライターAは想定LP仮説に縮退」を後続に明記。
3. **商材ブリーフ抽出（独立サブエージェント・必須）**: 取得したsnapshot全文＋スクショを**抽出専任サブエージェント**に渡し、**下記2つのスキーマで両方生成**（保存: フル版 `01_商材ブリーフ.md`／実行用 `01_商材ブリーフ_実行用.md`）。オーケストレーターが要約してはならない。

4. **媒体ロード**: `媒体別コピー指針.md` の指定媒体該当§＋§9を読み込み、後続へ渡すコンテキストに。

### Step 5: 3ペルソナ採点（独立サブエージェント・必須）
**ペルソナ採点はオーケストレーターがやらない。ペルソナA/B/Cそれぞれを別々の独立サブエージェント（計3体）として起動し並列実行する。**「並列化してよい」ではなく**必須**。各SAに渡すもの:
- **入力**: `persona-template.md` 評価フォーマット＋**当該ペルソナのフル定義**（例外：人格を借りるためフル定義を渡す）＋18案（**各案にアプローチ識別タグ A〜F 付き**）＋商材ブリーフ実行用＋指定媒体の閲覧文脈
- 採点軸: 指定媒体の閲覧モード（例: Metaなら受動スクロール、Google検索なら能動検索）で `<thinking>`思考過程→感情リアクション→購買意向10点→刺さる/刺さらない点 を出す。一人三役は禁止。

### Step 6: ⑤CD 採点・採否（独立サブエージェント・必須）
**⑤CD採点はオーケストレーターがやらない。独立 ⑤CDサブエージェント**を起動。渡すもの:
- **実行用（本文埋め込み）**: 18案（**各案にアプローチ識別タグ A〜F 付き**）＋3ペルソナ採点結果＋商材ブリーフ実行用＋①CMOブリーフ実行用
- **必読指示**: `05_creative-director.md`／`コピー/CLAUDE.md` §核となる節／`媒体別コピー指針.md` §9 媒体適合5観点

**6軸合計25点**（自分ごと化5/便益・リスク明示5/LP-FVとの一貫性5/わかりやすさ3/独自性4/CTA強度3）→ ×4で100点換算（閾値80点）。**自己採点・点数の忖度を禁止。甘く付けない（過去に甘採点で品質崩壊）。全落選案を簡潔理由つきで必ず残す（アプローチ識別タグ付きで記録）。**
- **アプローチ別の枠を強制しない**：⑤CD は純粋に得点上位を選び、採用案が特定アプローチに偏ってもOK（収束したらそれが王道判断・lp-build / banner-ad-build と同等原則）。アプローチ識別タグは出力バンドルまで引き継ぐ。
- **採点前ゲート**: `媒体別コピー指針.md` §9 の媒体適合5観点（ファネル整合/文脈馴染み/フォーマット適合/トーン適合/役割分担）を各案にチェック。媒体不適合は減点し、差戻し理由に媒体観点を明記。
- 最高点案が **80点以上** → ✅採用候補へ
- 全案80点未満 → 🔄**該当アプローチSA（06a〜06f のうち1つ）に具体的改善指示**（媒体適合の指摘を含む）を出して差戻し（そのアプローチの3案のみ再生成）→ **最大3回ループ**
- 3回後も未達 → 最高点案を「⚠️条件付き採用」でCMOへ

### Step 7: ①CMO 最終QC（独立サブエージェント・必須）
**独立①CMOサブエージェント**を起動。渡すもの:
- **実行用（本文埋め込み）**: 採用候補＋スコア＋ペルソナ評価＋①CMOブリーフ実行用（Step3の期待値・評価軸原文）

判断ロジック：①期待値プラス ②戦略マッチ80%超。両クリアで採用、片方不足は差戻し理由＋次アクション提示。オーケストレーターはこの判断を代行しない。
