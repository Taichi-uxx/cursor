# copy-build — コピー生成ワークフロー

`/copy-build <LP URL（必須）> 媒体=<媒体（必須）> [案件=<案件/商品情報 任意>] [ターゲット=<ターゲット情報 任意>]`

## 入力（4項目）

| 項目 | 必須 | 内容 |
|---|---|---|
| LP URL | **必須** | 着地ページのURL。Playwrightで取得（§Step1） |
| 媒体 | **必須** | 配信媒体。例: Google検索 / P-MAX / Demand Gen / Yahoo検索 / YDA / Meta(FB) / Meta(IG) / LINE / TikTok / X / YouTube。**未指定なら実行を止めてユーザーに確認**（媒体でファネル位置・刺す属性・良いコピー基準が変わるため推測で進めない） |
| 案件/商品情報 | 任意 | 商品MDパス/商品名/USP等。あれば精度向上 |
| ターゲット情報 | 任意 | 既知のペルソナ/ターゲット。無ければ入力から自動生成（§Step2） |

## 実行原則（厳守・例外なし）

1. **オーケストレーター（このスキルを動かすメインエージェント）は、生成・ペルソナ生成・採点・代筆を一切行わない。** 役割は「入力取得」「サブエージェントへの委譲」「結果の集約」だけ。Step2〜7はすべて**独立サブエージェント**に委譲する。インラインでの自己採点・自己生成・一人多役は**禁止**（過去にこれをやって品質が崩壊した）。
2. **LP情報は「定義スキーマで構造化抽出」して渡す（全文ベタ渡しもアドホック要約も禁止）。** LP全文をそのまま渡すとコンテキスト肥大で生成精度が落ちる。一方オーケストレーターの場当たり5行要約は素材を喪失する（初回失敗の原因）。よって Step1 で**規定の商材ブリーフ・スキーマ**（後述）に沿って抽出する。規定フィールドの省略は禁止。抽出は独立サブエージェントが行い、オーケストレーターは判断を加えない。ペルソナ定義は③が作ったフル定義をそのまま渡す（1行圧縮禁止）。
3. **品質優先。時間・手数を惜しまない。** 速いことより、各サブエージェントが十分な情報で深く考えることを優先する。
4. 各Stepのサブエージェントは会話文脈を見られない前提で、必要情報を自己完結で渡す。

### Step 1: 入力解釈・LP取得・媒体ロード
1. **入力バリデーション**: LP URL と 媒体 が揃っているか確認。**媒体が無ければ即停止してユーザーに媒体を確認**（推測で進めない）。
2. **LP取得（Playwright主軸・オーケストレーターはツール実行のみ）**:
   - `browser_navigate` → `browser_wait_for` → `browser_snapshot` で全文取得、`browser_take_screenshot`（fullPage推奨）でビジュアル取得。JS/遷移系LPもこれで取れる。
   - Playwright不可時のみ WebFetch → それも不可なら入力の商品情報で代替し「ライターAは想定LP仮説に縮退」を後続に明記。
3. **商材ブリーフ抽出（独立サブエージェント・必須）**: 取得したsnapshot全文＋スクショを**抽出専任サブエージェント**に渡し、下記スキーマで `商材ブリーフ` を生成させる。オーケストレーターが要約してはならない。

   ```
   ## 商材ブリーフ
   - サービス名:
   - サービスカテゴリ:（ジャンル・領域。例「商用車買取」「オンライン英会話」）
   - サービスの強み・特徴（3〜5個・LP原文の表現を保持して）:
   - LPのFVの訴求・メインコピー:（FVの見出し原文ママ）
   ── 以下コピー素材として必須（初回失敗で喪失した要素。省略禁止）──
   - 実績・具体数値・受賞/規模（数字は原文ママ）:
   - お客様の声（実物の引用を2〜3本、原文ママ）:
   - オファー・特典・CTA（無料/即日/保証/価格 等）:
   - 想定ターゲットの状況シグナル（LPフォーム選択肢・対象記載などから読める顧客像）:
   - 業界・規制上の注意（景表法/薬機法等のNG表現）:
   ```
   ※「強み3〜5個」「FV訴求」「実績・お客様の声・オファー」は **LP原文の言い回しを保持**して抜く（言い換え要約しない＝コピーの種を殺さない）。
4. **媒体ロード**: `媒体別コピー指針.md` の指定媒体該当§＋§9を読み込み、後続へ渡すコンテキストに。
5. 業界を確定し `principle/業界知見/<業界>/` を特定（規制・NG表現）。
6. `案件=` 指定 or 文脈で案件名が分かれば `work/client/<案件名>/` の有無を確認。

### Step 2: ペルソナ解決 ★重要（独立サブエージェントで実行）
**オーケストレーターはペルソナを書かない。独立した ③Customer Analyzer サブエージェントに委譲する。**

1. **案件にペルソナ/ターゲット情報があるか確認**：`work/client/<案件名>/strategy.md` や同フォルダ内のペルソナ/ターゲット記述。
2. **③Customer Analyzer サブエージェントを起動**し、以下を渡す：
   - 役割定義 `@/Users/apple/.cursor/work/AI-Studio PJT/agent-drafts/03_customer-analyzer.md`
   - `@/Users/apple/.cursor/work/principle/マーケ戦略/ペルソナ設計要点.md` と `ヒアリング項目.md` を必読指示
   - **Step1の商材ブリーフ（規定スキーマ全項目）＋FVスクショ**／案件情報があればそれも（LP全文ベタ渡しはしない）
   - 指示：意味ある多様性を持つ**3ペルソナA/B/C**を `persona-template.md` の「私について」**全項目**（基本情報/価値観・性格/購買行動/情報接触/不安・欲望・葛藤/口癖・語彙）を**埋めて**出力＋各ペルソナのカスタマージャーニー
3. 案件にペルソナがあればそれを③に渡して整形、無ければLPから生成（どちらも③が担当）。
4. ③の出力した3ペルソナ定義を**そのまま成果物として明示**。クライアントフォルダがあれば `work/client/<案件名>/personas_generated.md` 保存を提案。
5. この3ペルソナ（フル定義）が以降の生成・採点に渡る。1行要約に圧縮して下流に渡してはならない。

**各ライターサブエージェントに渡す情報**:

### Step 5: 3ペルソナ採点（独立サブエージェント・必須）
**ペルソナ採点はオーケストレーターがやらない。ペルソナA/B/Cそれぞれを別々の独立サブエージェント（計3体）として起動し並列実行する。**「並列化してよい」ではなく**必須**。各サブエージェントに渡す：`persona-template.md` 評価フォーマット＋Step2の当該ペルソナのフル定義＋18案＋Step1商材ブリーフ＋指定媒体の閲覧文脈。各ペルソナは指定媒体の閲覧モード（例: Metaなら受動スクロール、Google検索なら能動検索）で `<thinking>`思考過程→感情リアクション→購買意向10点→刺さる/刺さらない点 を出す。一人三役は禁止。

### Step 6: ⑤CD 採点・採否（独立サブエージェント・必須）
**⑤CD採点はオーケストレーターがやらない。独立 ⑤Creative Director サブエージェント**を起動し `05_creative-director.md` ＋フォルダ共通 `CLAUDE.md` ＋18案＋3ペルソナ採点結果＋Step1商材ブリーフ＋媒体指針を渡す。**6軸合計25点**（自分ごと化5/便益・リスク明示5/LP-FVとの一貫性5/わかりやすさ3/独自性4/CTA強度3）→ ×4で100点換算（閾値80点）。**自己採点・点数の忖度を禁止。甘く付けない（過去に甘採点で品質崩壊）。全落選案を簡潔理由つきで必ず残す。**
- **採点前ゲート**: `媒体別コピー指針.md` §9 の媒体適合5観点（ファネル整合/文脈馴染み/フォーマット適合/トーン適合/役割分担）を各案にチェック。媒体不適合は減点し、差戻し理由に媒体観点を明記。
- 最高点案が **80点以上** → ✅採用候補へ
- 全案80点未満 → 🔄該当アプローチに**具体的改善指示**（媒体適合の指摘を含む）を出して差戻し（そのアプローチの3案のみ再生成）→ **最大3回ループ**
- 3回後も未達 → 最高点案を「⚠️条件付き採用」でCMOへ

### Step 7: ①CMO 最終QC（独立サブエージェント・必須）
**独立 ①CMO サブエージェント**を起動し `01_cmo.md` ＋採用候補＋スコア＋ペルソナ評価＋LP原文を渡す。判断ロジック：①期待値プラス ②戦略マッチ80%超。両クリアで採用、片方不足は差戻し理由＋次アクション提示。オーケストレーターはこの判断を代行しない。
