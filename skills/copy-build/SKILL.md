# copy-build — コピー生成ワークフロー

`/copy-build <LP URL（必須）> 媒体=<媒体（必須）> [案件=<案件/商品情報 任意>] [ターゲット=<ターゲット情報 任意>]`

## 入力（4項目）

| 項目 | 必須 | 内容 |
|---|---|---|
| LP URL | **必須** | 着地ページのURL。Playwrightで取得（§Step1） |
| 媒体 | **必須** | 配信媒体。例: Google検索 / P-MAX / Demand Gen / Yahoo検索 / YDA / Meta(FB) / Meta(IG) / LINE / TikTok / X / YouTube。**未指定なら実行を止めてユーザーに確認**（媒体でファネル位置・刺す属性・良いコピー基準が変わるため推測で進めない） |
| 案件/商品情報 | 任意 | 商品MDパス/商品名/USP等。あれば精度向上 |
| ターゲット情報 | 任意 | 既知のペルソナ/ターゲット。無ければ入力から自動生成（§Step2） |

AI-Studio組織体（①CMO → ⑤CD → ⑥Copywriter → ㉑㉒㉓Persona → ⑤CD → ①CMO）でコピーを量産・選抜するオーケストレーター。ロールの詳細定義は下記を**実行時に必ず読む**（本ファイルに再掲しない）：

- **媒体補正（必須）**: `@/Users/apple/.cursor/work/principle/クリエイティブ/コピー/媒体別コピー指針.md` — 指定媒体の該当§と§9（媒体適合チェック）を生成・評価で必ず適用
- 規制トーン: `@/Users/apple/.cursor/work/principle/業界知見/<業界>/`

## 実行フロー

```
- [ ] Step 1: 入力解釈・LP取得
- [ ] Step 2: ペルソナ解決（案件に無ければ入力から自動生成）
- [ ] Step 3: ①CMO キックオフブリーフ
- [ ] Step 4: ⑥Copywriter 18案生成（6アプローチ×3案・並列）
- [ ] Step 5: 3ペルソナ採点
- [ ] Step 6: ⑤CD 採点・採否（80点閾値・最大3回ループ）
- [ ] Step 7: ①CMO 最終QC
```

## 実行原則（厳守・例外なし）

1. **オーケストレーター（このスキルを動かすメインエージェント）は、生成・ペルソナ生成・採点・代筆を一切行わない。** 役割は「入力取得」「サブエージェントへの委譲」「結果の集約」だけ。Step2〜7はすべて**独立サブエージェント**に委譲する。インラインでの自己採点・自己生成・一人多役は**禁止**（過去にこれをやって品質が崩壊した）。
2. **情報は要約せず原文で渡す。** LP本文・お客様の声・具体金額・ペルソナ定義などをオーケストレーターが圧縮して渡してはいけない。サブエージェントには一次情報をそのまま渡す。
3. **品質優先。時間・手数を惜しまない。** 速いことより、各サブエージェントが十分な情報で深く考えることを優先する。
4. 各Stepのサブエージェントは会話文脈を見られない前提で、必要情報を自己完結で渡す。

### Step 1: 入力解釈・LP取得・媒体ロード
1. **入力バリデーション**: LP URL と 媒体 が揃っているか確認。**媒体が無ければ即停止してユーザーに媒体を確認**（推測で進めない）。
2. **LP取得（Playwright主軸）**:
   - `browser_navigate` でLP URLを開く → 描画待ち（`browser_wait_for`）→ `browser_snapshot` でDOM/テキスト構造を**全文**取得、`browser_take_screenshot`（fullPage推奨）でビジュアルも取得。JSレンダリング/フォーム遷移LPもこれで本文が取れる。
   - **取得した snapshot 全文テキスト＋スクショは原文のまま保持し、以降の全サブエージェントへそのまま渡す**（お客様の声・買取例の具体金額・各セクション原文＝コピーの素材を絶対に削らない）。
   - 6ブロック（FV/共感/ベネフィット/証拠/オファー/CTA）への整理は**構造把握の補助マップとして追加で作る**だけ。原文の代替・要約版にしない。
   - Playwrightが使えない/失敗時のみ WebFetch → それも不可なら商品情報で代替し「ライターAは想定LP仮説に縮退」を後続に明記。
3. **媒体ロード**: `媒体別コピー指針.md` から指定媒体の該当§（ファネル位置・刺す属性・コピー鉄則・推奨フォーマット）と §9（媒体適合チェック）を読み込み、後続の生成・評価へ渡すコンテキストにする。
4. 業界を推定し `principle/業界知見/<業界>/` を特定（規制・NG表現の事前把握）。
5. `案件=` 指定 or 文脈から案件名が分かれば `work/client/<案件名>/` の有無を確認。

### Step 2: ペルソナ解決 ★重要（独立サブエージェントで実行）
**オーケストレーターはペルソナを書かない。独立した ③Customer Analyzer サブエージェントに委譲する。**

1. **案件にペルソナ/ターゲット情報があるか確認**：`work/client/<案件名>/strategy.md` や同フォルダ内のペルソナ/ターゲット記述。
2. **③Customer Analyzer サブエージェントを起動**し、以下を渡す：
   - 役割定義 `@/Users/apple/.cursor/work/AI-Studio PJT/agent-drafts/03_customer-analyzer.md`
   - `@/Users/apple/.cursor/work/principle/マーケ戦略/ペルソナ設計要点.md` と `ヒアリング項目.md` を必読指示
   - **Step1のLP原文フルテキスト＋スクショ**（要約版でなく原文）／案件情報があればそれも
   - 指示：意味ある多様性を持つ**3ペルソナA/B/C**を `persona-template.md` の「私について」**全項目**（基本情報/価値観・性格/購買行動/情報接触/不安・欲望・葛藤/口癖・語彙）を**埋めて**出力＋各ペルソナのカスタマージャーニー
3. 案件にペルソナがあればそれを③に渡して整形、無ければLPから生成（どちらも③が担当）。
4. ③の出力した3ペルソナ定義を**そのまま成果物として明示**。クライアントフォルダがあれば `work/client/<案件名>/personas_generated.md` 保存を提案。
5. この3ペルソナ（フル定義）が以降の生成・採点に渡る。1行要約に圧縮して下流に渡してはならない。

### Step 3: ①CMO キックオフブリーフ
`01_cmo.md` に従い、目的/対象/ゴールKPI/制約/評価基準を1〜3行で確定。

### Step 4: ⑥Copywriter 18案生成
`06_copywriter.md` の振る舞いに**完全準拠**。スピードと文脈分離のため、**6アプローチを Agent ツールで並列サブエージェント化**（general-purpose）：

| サブエージェント | 渡す情報 | 返す物 |
|---|---|---|
| A LP逆算 | エモーションリレー_LP逆算.md + LP6ブロック + ブリーフ + 3ペルソナ | 起点インサイト+感情リレー表+最有力3案 |
| B 価値種別 | コピー生成_価値種別.md + ブリーフ + 3ペルソナ | 切り口の異なる最有力3案 |
| C 動機・心理 | コピー生成_動機・心理種別.md + 〃 | 〃 |
| D 勝ちCR要素 | コピー生成_勝ちCRの要素.md + 〃 | 〃 |
| E 良いコピーの型 | コピー生成_良いコピーの型.md + 〃 | 〃 |
| F 行動経済学 | コピー生成_行動経済学.md + 〃 | 〃 |

**各ライターサブエージェントに渡す情報（要約・圧縮禁止。原文をそのまま渡す）**:
- **LP原文フルテキスト**（Step1のPlaywright snapshotテキスト全文）＋**FVスクリーンショット画像**。オーケストレーターが5行に要約して渡すのは厳禁。お客様の声・買取例の具体金額・各セクション原文など"コピーの素材"を削らない
- LPを6ブロックに**整理した補助マップ**（原文は別途フル添付のうえ、構造把握用に追加。要約での代替ではない）
- **3ペルソナのフル定義**（Step2で③が生成したpersona-template全項目。1行要約に圧縮しない）
- ①CMOキックオフブリーフ全文 / 指定媒体の媒体別コピー指針の該当§＋§9原文 / 業界知見の規制原文 / 担当アプローチのprincipleファイルパス
- 共通制約：**メイン20字以内**/サブ30字以内、字数超過案は自動失格で再圧縮必須、業界NG表現、同一アプローチ内3案は訴求の切り口を変える、媒体補正必須

6体は**独立サブエージェントで並列実行**（インライン代筆禁止）。18案に統合。

### Step 5: 3ペルソナ採点（独立サブエージェント・必須）
**ペルソナ採点はオーケストレーターがやらない。ペルソナA/B/Cそれぞれを別々の独立サブエージェント（計3体）として起動し並列実行する。**「並列化してよい」ではなく**必須**。各サブエージェントに渡す：`persona-template.md` 評価フォーマット＋Step2の当該ペルソナのフル定義＋18案＋LP原文＋指定媒体の閲覧文脈。各ペルソナは指定媒体の閲覧モード（例: Metaなら受動スクロール、Google検索なら能動検索）で `<thinking>`思考過程→感情リアクション→購買意向10点→刺さる/刺さらない点 を出す。一人三役は禁止。

### Step 6: ⑤CD 採点・採否（独立サブエージェント・必須）
**⑤CD採点はオーケストレーターがやらない。独立 ⑤Creative Director サブエージェント**を起動し `05_creative-director.md` ＋18案＋3ペルソナ採点結果＋LP原文＋媒体指針を渡す。5軸×5点=25点 → ×4で100点換算。**自己採点・点数の忖度を禁止。甘く付けない（過去に甘採点で品質崩壊）。**
- **採点前ゲート**: `媒体別コピー指針.md` §9 の媒体適合5観点（ファネル整合/文脈馴染み/フォーマット適合/トーン適合/役割分担）を各案にチェック。媒体不適合は減点し、差戻し理由に媒体観点を明記。
- 最高点案が **80点以上** → ✅採用候補へ
- 全案80点未満 → 🔄該当アプローチに**具体的改善指示**（媒体適合の指摘を含む）を出して差戻し（そのアプローチの3案のみ再生成）→ **最大3回ループ**
- 3回後も未達 → 最高点案を「⚠️条件付き採用」でCMOへ

### Step 7: ①CMO 最終QC（独立サブエージェント・必須）
**独立 ①CMO サブエージェント**を起動し `01_cmo.md` ＋採用候補＋スコア＋ペルソナ評価＋LP原文を渡す。判断ロジック：①期待値プラス ②戦略マッチ80%超。両クリアで採用、片方不足は差戻し理由＋次アクション提示。オーケストレーターはこの判断を代行しない。
