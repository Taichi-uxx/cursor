# English-addlist — 英語学習ノート追記

`/English-addlist [メモ]`

## 目的
Cambly・海外ドラマ・SNS・日常会話中に出会った英単語・フレーズ・言い回し・学びメモを、
既存の英語学習ファイル群の**既存フォーマットに沿って**追記する。手書きでフォーマットを
揃える手間をなくし、重複追加や重要度順ファイルの反映漏れを防ぐ。

## 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| メモ本文 | 任意 | 追加したい英単語・フレーズ・学び。呼び出し時に渡してもよいし、対話で受け取ってもよい |

呼び出し時にメモが空なら「追記したいメモを送ってください」と促す。

## 対象ファイル

- `~/.cursor/English/vocabulary.md`（単語ストック・NARUTO世界観／重要度★順ソート）
- `~/.cursor/English/reviewing_cambly_日付順.md`（Cambly実践レビュー・日付順の時系列ログ）
- `~/.cursor/English/reviewing_cambly_重要度順.md`（日付順を重要度順に再編集したもの／日付順が更新されたら必ず同期）

親フォルダの `~/.cursor/English/CLAUDE.md` の学習方針・重要度付与ルール・フォーマット規約を
必ず読み込み・遵守する。

## 実行フロー

```
- [ ] Step 1: 追加先ファイルの選択（vocabulary / reviewing_cambly_日付順 の2択）
- [ ] Step 2: メモを構造化（見出し / 意味 / 例文 / 重要度 / ニュアンス）
- [ ] Step 3: 重複チェック（既存エントリと突き合わせ、重複はスキップ）
- [ ] Step 4: 追加先ファイルへ既存フォーマットで書き込み
- [ ] Step 5: reviewing_cambly_日付順 を更新した場合は 重要度順 にも反映
- [ ] Step 6: 追記結果サマリ出力（追加件数・スキップ件数・「新規：✓」を付けた件数）
```

### Step 1: 追加先を選ぶ

ユーザーが指定していなければ、以下の2択で確認する:

1. `vocabulary.md`（単語ストック・重要度順）
2. `reviewing_cambly_日付順.md`（Cambly等の実践レビュー・日付順）

**重要度順ファイル (`reviewing_cambly_重要度順.md`) はユーザーが直接指定する対象ではない。**
これは日付順ファイルの派生・自動同期される側なので、ユーザーが日付順を選んだ場合に
自動的に同期先として扱う。

### Step 2: メモを構造化

ユーザーから渡されたメモは自然文・箇条書き・単なる単語羅列など様々な形で来る。以下の要素に
分解する:

- **見出し**：英単語 or フレーズ本体（複数表現なら `/` 区切りで並記可）
- **重要度**：★5〜★1（日常会話頻度で評価。CLAUDE.md の評価軸に従う）
- **Meaning**：意味・訳語。複数意味・用法があれば番号分け（`　1. ...　2. ...`）
- **Example**：具体的な場面が浮かぶ例文。無味乾燥な例文は禁止
  - `vocabulary.md` 追記時は NARUTO 世界観に合わせる
  - `reviewing_cambly_日付順.md` 追記時は元セッションの文脈に合わせる（自由）
- **Nuance／Usage**：必要に応じて。カジュアル度、使い分け、類似表現との差分など
- **注意**：発音の落とし穴、攻撃的トーン、避けるべき場面など（必要時のみ）

**ユーザーが例文・重要度・ニュアンスを書いていない場合は、こちらで補完する。**
- 例文：CLAUDE.md 記載の世界観・具体場面ルールに従い自然に作る
- 重要度：日常会話頻度で自分の判断で★を振る（自信がなければ「★3で暫定」等と明記）
- ニュアンス：CLAUDE.md 記載通り「なぜ不自然か／ネイティブならどう言うか／類似との差」を意識

複数のメモが同時に来た場合は、それぞれ個別のエントリとして分割・構造化する。

### Step 3: 重複チェック

追加先ファイル（および `reviewing_cambly_重要度順.md` の同期対象なら重要度順ファイルも）を
先に読み込み、以下の条件で重複を判定する:

- **見出し完全一致**（大文字小文字・記号無視・trim後）
- 見出しに `/` 区切りで複数表現がある場合、いずれか1つでも既存見出しと重なれば重複扱い
  （例: 新規 `I get it` が既存 `I get it / I get that` と重複）

重複と判定したエントリは**スキップ**し、ユーザーに「〜は既存のためスキップ」と明示する。
勝手にマージ・上書きはしない（更新が必要なら事前相談する運用）。

### Step 4: 追加先ファイルへ書き込み

#### 4-A. `vocabulary.md` に追加する場合

**既存フォーマット:**
```
### <word or phrase>
新規：✓
重要度：★★★★★
Meaning：...
Example：...
```

- `新規：✓` を `### <word>` の直後、`重要度：` の前に必ず入れる（新規追加識別用）
- 挿入位置は「同じ重要度セクションの末尾」に追加（既存の★順位を崩さない）
  - 明確な★セクションが存在しない場合は、同じ★を持つ既存エントリのブロック末尾に付ける
- Meaning・Example の書式は既存のパターン（英語+カッコ内日本語 / 番号付き複数意味）に合わせる

#### 4-B. `reviewing_cambly_日付順.md` に追加する場合

- ファイル末尾（もしくは該当日付セクション）に、その日の日付セクション `## M/D` を作って追記
- 日付は**今日の日付**（会話コンテキストで参照可能な `currentDate` を使う）を `M/D` 形式で
- 既に今日の日付セクションが存在すれば、そのセクション末尾に追記
- **`新規：✓` フラグは付けない**（日付順ファイルは時系列ログなので、追記時点が新規であることが自明）

**書式は統一しない。** 日付順ファイルは学習履歴のログであり、統一書式に押し込めることで
ユーザーが書いた原メモの重要な学び（表の比較、類義語対比、対義語、コアイメージ、
複数の関連表現、`❌ / ✅` の対照、`【Correction Log】` `【Phrases to Master】` などの
自由なセクション見出し等）が漏れることを防ぐ。以下の原則で書く:

- ユーザーが送ったメモの構造・粒度・情報量を**そのまま活かす**。省略・圧縮しない
- 見出し階層（`###` や `####`）、箇条書きスタイル、表、コード風の `❌ / ✅` 表現などは
  既存の日付順ファイルで使われている慣習を参考にしつつ、メモの内容に一番合う書き方を選ぶ
- テンプレ的な `重要度 / Meaning / Example` の枠に無理に嵌めない
- 迷ったら「後で見返して原メモの学びが全部復元できるか」を判断基準にする

なお、Step 5 の重要度順への同期時には**そこで初めて統一書式に整形する**（重要度順ファイル側は
書式が厳格なので）。日付順は原メモの豊かさを保存し、重要度順は整った復習用に整形、という
役割分担にする。

### Step 5: 重要度順ファイルへの同期（日付順を更新した場合のみ）

`~/.cursor/English/CLAUDE.md` のルール:
> `reviewing_cambly（日付）.md` を更新したら必ず `reviewing_cambly_重要度順.md` も更新する

**必ず同期する。省略しない。**

- 日付順に書いた自由フォーマットのメモから、復習単位となる「単語・フレーズ」を抽出し、
  重要度順の統一書式（`### / 新規 / 重要度 / Meaning / Example / Nuance`）に整形して転記
- **原メモの学びが重要度順側で漏れないよう注意。** 表・類義語対比・コアイメージなどの
  重要ポイントは Nuance 行に集約するか、複数用法として番号分けで残す
- 追記した各エントリの重要度（★5〜★1）に対応するセクション末尾に追加
- **`新規：✓` フラグを `### <word>` の直後に付ける**（重要度順ファイルは復習用なので新規追加分を識別できるようにする）
- 既存エントリと重複する表現があれば、複数意味は番号分けで追記マージ（重複しない意味だけ足す）
- Meaning・Example・Nuance の書式は重要度順ファイルの既存パターンに合わせる

**書式例（重要度順ファイル追記時）:**
```
### <word or phrase>
新規：✓
重要度：★★★★★
Meaning：...
Example：...
Nuance：...
```

### Step 6: サマリ出力

作業完了後、以下の1ブロックでまとめる:

```
追記完了：
- vocabulary.md: 追加 N件（新規フラグ付き）、スキップ M件
- reviewing_cambly_日付順.md: 追加 N件（今日: M/D セクション）
- reviewing_cambly_重要度順.md: 追加 N件（新規フラグ付き）、スキップ M件

追加した見出し:
- <word1>（★5）
- <word2>（★4）
...
```

スキップしたものがあれば理由付きで別行に出す。

## 「新規：✓」フラグの扱い

**目的**：`vocabulary.md` と `reviewing_cambly_重要度順.md` は復習用途で長期蓄積される
ファイル。定期的に「今回追加した分」だけ抜き出して集中復習したいので、追記直後に識別可能な
フラグを残す。

**書式**：`### <word>` の直後、`重要度：` の前に `新規：✓` の1行を挿入。

**注意点**：
- `ミス：` 行（`English-review` スキルが使う）と共存可能（両方あっても順不同でOK、ただし
  順序を揃えたいなら `新規：✓` → `ミス：×...` → `重要度：` の順を推奨）
- フラグ除去はユーザーが復習後に手動で消すか、別スキルで一括除去する運用（このスキルは
  付与のみ担当）
- 日付順ファイルには**絶対に付けない**（時系列ログの性質上、追記時点が新規であることが
  自明のため。重複情報を残さない）

## 実行原則

1. **フォーマット方針はファイル別に厳守**：
   - `vocabulary.md` / `reviewing_cambly_重要度順.md`：統一書式（`### / 新規 / 重要度 / Meaning / Example / Nuance`）を厳守
   - `reviewing_cambly_日付順.md`：**統一書式に押し込めない**。ユーザーが送った原メモの構造・粒度・情報量をそのまま保存する（学習履歴の豊かさを優先）
2. **重複追加をしない**。見出し一致でスキップし、勝手にマージしない。
3. **日付順を更新したら必ず重要度順も更新する**（`English/CLAUDE.md` 明記ルール）。省略禁止。
4. **CLAUDE.md の学習方針を守る**：単なる訳語で終わらせず、例文・ニュアンス・カジュアル度も
   セットで書く。無味乾燥な例文（`I like apples.` 等）は禁止。
5. **重要度は日常会話頻度で評価**。ビジネス頻度・書き言葉頻度で評価しない。
6. **「新規：✓」は vocabulary.md と reviewing_cambly_重要度順.md のみ**。日付順には付けない。
7. **不可逆な操作（削除・上書き）は事前確認**。追記のみで作業完結する。
8. **世界観の統一**：`vocabulary.md` への追記例文は NARUTO 世界観に揃える（既存慣習）。
