# English-review-jp2en — 英単語・フレーズ復習クイズ（日→英）

`/English-review-jp2en [ファイルパス]`

英→日（意味を答える）ではなく **日→英（英作文する）** 形式。
「意味は分かるけど自分で口から出せない」フェーズを潰すための実践練習モード。

## 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| ファイルパス | 任意 | 出題対象の英語学習mdファイル。省略時は `~/.cursor/English/vocabulary.md` |

## 対象ファイル形式

想定する主なファイル:
- `~/.cursor/English/vocabulary.md` （単語ストック・NARUTO世界観）
- `~/.cursor/English/reviewing_cambly_重要度順.md` （Cambly実践レビュー・重要度順）
- 上記と同構造の他ファイル

**基本構造:**
```
### <英単語 or フレーズ>   ← 「/」区切りで複数表現の場合あり
新規：✓                    ← 任意
ミス：×（または ××、×××、...）  ← 任意
重要度：★★★★★
Meaning：<意味・訳>
Example：<例文>
```

出題対象・優先度は `English-review` と同じ。詳細は下記フロー参照。

## 実行フロー

```
- [ ] Step 1: ファイル読み込み・エントリのパース
- [ ] Step 2: 出題対象を抽出（ミス欄あり or 新規フラグあり）＋優先度でソート
- [ ] Step 3: 各対象エントリの例文について「日本語訳」を事前準備
- [ ] Step 4: 10問ずつバッチ出題（問題は例文の日本語訳のみ）
- [ ] Step 5: ユーザーが「答え」と言ったら答え合わせ（英単語＋英例文＋日本語意味）
- [ ] Step 6: 間違えた問題番号を聞く
- [ ] Step 7: 実ファイル更新（間違い→ミス欄に×追加／正解＋新規→新規フラグ削除）
- [ ] Step 8: 未出題の対象エントリが残っていれば Step 4 に戻る
```

### Step 1: パース

`English-review` と同一。各エントリから `word` / `is_new` / `mistake_count` / `meaning_jp` / `example` を取得。

### Step 2: フィルタ＋ソート

**対象:** `mistake_count >= 1` **または** `is_new == true` のエントリ

**優先度（降順）:**
1. `mistake_count` が多い順
2. 同じミス数の中では「新規フラグ有」を先に
3. `mistake_count == 0 && is_new == true`（=新規のみ）は最後のグループ
4. 同グループ内は元ファイル出現順を維持

### Step 3: 例文の日本語訳を事前準備

**この形式では、問題文＝例文の日本語訳。よって出題前に必ず訳文を確定させる。**

各エントリの `example` について:
1. 元ファイルに `例文訳：` などの日本語訳が併記されていれば、それを採用
2. 併記が無い場合（大半のケース）、その場で自然な日本語に訳す
3. **複数例文があるエントリ（多義語・複数用法）は全例文を採用する**。`bother` のように用法ごとにニュアンスが違う語は、1例だけだと他の意味の練習にならないため。各例文をそれぞれ日本語化する
4. 訳は「自然な日本語会話体」で。直訳ではなく意訳寄り、ただし元英文の情報を落とさない

**訳出のコツ:**
- 例：`I'll figure it out somehow.` → `なんとかするよ／なんとかなるって。`
- 例：`— It's expensive but the quality is great. — Fair enough.` → `— 高いけど品質は良いよ。— まあ確かに。`
- 対話形式の例文（`—` 区切り）は対話のまま日本語化する（英作文時に文脈が伝わるため）

### Step 4: 出題（10問／バッチ）

**問題文には英語を一切含めない。単語も例文もヒント無し。日本語だけ。**

**出題単位はエントリ（＝1 Q番号 = 1 エントリ）**。多義語で例文が複数あるエントリは、1つの Q# の下に全例文を並べる。

出力形式:
```
**Q1.**
「<例文の日本語訳>」

**Q2.**
「<例文1の日本語訳>」
「<例文2の日本語訳>」
「<例文3の日本語訳>」
「<例文4の日本語訳>」

**Q3.**
「<例文の日本語訳>」

...

**Q10.**
「<例文の日本語訳>」

---

英訳できたら（or 諦めたら）「答え」って言ってください。
```

**単語ヒント（`<word>` 表示）は出さない。** 何のフレーズ・単語を使うかも当てるのがこのモードの主眼。
出題は日本語文のみ（多義語は複数行）。英語学習者側で「これはあの表現かな」と想起する練習になる。

**多義語の複数例文出題**: `bother` のように意味・用法が複数あるエントリは、意味ごとに1例文を並べて全て提示する。同じ Q# 内でも「用法ごとに違う英語表現になる」ことが多いので、共通の単語を使うヒントは出さない（＝ユーザーは1つの単語だけで全例文を訳そうとしないよう注意する — というより、実は全例文で同じ単語を使う場合がほとんどなので、それに気づけるかも試練）。

### Step 5: 答え合わせ

ユーザーが「答え」「answer」等の合図を出したら、以下の形式で回答:

```
**Q1.** — <英単語 or フレーズ>
英例文：<英語の例文>
日本語訳：<Step 3 で提示した日本語訳（＝問題文）>
意味：<単語・フレーズの日本語意味>

**Q2.** — <英単語 or フレーズ>
英例文：<英語の例文>
日本語訳：<問題文の日本語訳>
意味：<単語・フレーズの日本語意味>

...
```

- 「意味」は元ファイルの `Meaning：` から抽出（`meaning_jp`）
- **多義語（複数例文）エントリは意味を先に列挙し、各例文＋訳を(1)(2)(3)...で全て出す**:
  ```
  **Q8.** — bother / can't be bothered
  意味：①邪魔する／困らせる ②わざわざ〜する ③気になる／悩ませる ④can't be bothered = やる気にならない／めんどくさい
  （1）
  　英例文：Don't bother me when I'm working.
  　日本語訳：仕事中は邪魔しないで。
  （2）
  　英例文：Don't bother calling — he won't pick up.
  　日本語訳：わざわざ電話しなくていいよ — どうせ出ないから。
  （3）
  　英例文：It really bothers me that he never replies.
  　日本語訳：彼が全然返信くれないの、めっちゃ気になるんだよね。
  （4）
  　英例文：I can't be bothered to cook tonight.
  　日本語訳：今夜は料理する気になれないな。
  ```

末尾で:
```
---
間違えた問題番号を教えてください（例：「1, 5, 8」「Q3とQ7」など）。
多義語Qは「1つでも訳せなかったら間違い」でカウントするのがおすすめ（1つでも詰まる用法が残っているなら次回もう1回出したいので）。
「全然違うけど意味は通じる」レベルも間違い扱い推奨。
```

### Step 6: 間違えた番号を受け取る

- 「1, 5, 8」「Q3とQ7」「全部」「なし」等の自由入力を解釈
- 番号を特定 → 対応する `word` を確定
- **今バッチの正解番号 = バッチ全問 − 間違い番号**（差分で確定）

### Step 7: 実ファイル更新

`English-review` と同一の6パターン処理:

| ケース | 元の状態 | 操作 |
|---|---|---|
| ①間違い＋新規あり | `新規：✓` あり、ミス欄なし | 新規行を削除 ＋ `ミス：×` 行を新設 |
| ②間違い＋既ミス | `ミス：×...` あり | `ミス：×...` に×を1つ追加 |
| ③間違い＋新規＋既ミス | 両方あり | 新規行を削除 ＋ `ミス：×...` に×を1つ追加 |
| ④正解＋新規あり | `新規：✓` あり | 新規行を削除（ミス欄はいじらない） |
| ⑤正解＋既ミスのみ | `ミス：×...` のみ | 変更なし |
| ⑥正解＋新規＋既ミス | 両方あり | 新規行を削除（ミス欄はいじらない） |

**Editツールの具体操作** は `English-review` の Step 6 と同じ:

- **`ミス：×` 追加/新設** — 対象エントリの直前 `### <word>` を含めて一意化して Edit
- **`新規：✓` 削除** — `### <word>\n新規：✓\n` を `### <word>\n` に置換して1行まるごと削除
- 複数エントリの更新はそれぞれ個別に Edit する

**更新完了後のサマリ:**
```
更新完了：
- ミス追加：<word1>, <word2>（間違い×N件）
- 新規解除：<word3>, <word4>（正解×M件）
- 新規解除＋ミス追加：<word5>（間違い＋新規×L件）
```

### Step 8: 次バッチへ

- 未出題の対象エントリが11問目以降に残っていれば「次の10問行きますか？」と確認
- 「はい」等の合図で次バッチを Step 4 から実行
- 「もういい」「終わり」等で終了

全て出題しきったら:
```
全ての対象エントリの出題が完了しました。おつかれさま。
```

## 実行原則

1. **問題文に英語を絶対に混ぜない**。単語ヒントも英例文も無し。日本語1文だけ。
2. **答え合わせの前に答えを見せない**。ユーザーが「答え」と明示するまで待つ。
3. **答えは「英単語＋英例文＋日本語訳（＝問題文）＋日本語意味」の4点セット必須**。
   - 「日本語訳」は問題文と重複するが、答え合わせ時に問題を遡らなくて良いよう毎回提示する。
4. **ファイル更新は実ファイルへの反映を必ず行う**（Editツール）。会話上だけで済ませない。
5. **ソート順を守る**：ミス×数の降順 →（同数内）新規あり優先 → 新規のみ最後。
6. **1バッチ10問固定**（jp2en は英作文負荷が高いため）。それ以下なら残り全部を1バッチで出す。
7. **重複出題しない**。同一セッション内で同じエントリを2回出さない。
8. **ミス欄も新規フラグも両方無いエントリは対象外**。
9. **正解時も新規フラグは削除する**（＝出題した時点で検証済み扱い）。

## 出題形式の判断ガイド（English-review との使い分け）

| モード | いつ使う？ | 難易度 |
|---|---|---|
| `/English-review` | 「意味を思い出す」フェーズ。単語を覚えたての初期復習 | 低〜中 |
| `/English-review-jp2en` | 「実際に口から出す」フェーズ。意味は分かるが英作文で詰まる段階 | 中〜高 |

同じエントリを両モードで復習することで「認知 → 産出」の両方向を鍛えられる。
ミス欄・新規フラグは両モードで共通の実ファイルを更新するため、進捗が二重管理にならない。
