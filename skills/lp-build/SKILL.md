# lp-build — LP生成ワークフロー（アイキャッチ先行・分離合体型・一枚絵生成）

`/lp-build <LP URL（必須）> 媒体=<媒体（必須）> FV面=<pc|sp（必須）> [案件=<案件/商品情報 任意>] [ターゲット=<ターゲット情報 任意>] [広告=<流入広告の主訴求 任意>]`

> 設計思想: LPを一発生成しない。FV（アイキャッチ）と本文構成は別ゲーム
> （`principle/クリエイティブ/LP/LP.md`〈本質① FV3秒勝負〉vs〈本質② 物語温度〉）。
> **アイキャッチを先に確定**し、その温度・約束・訴求軸を制約に本文を作って**合体**する。
> FV画像は **AIで文字込み一枚絵を直接生成**（2026-05-26 確定方式・banner-ad-build と同方式）。
> PC（横長 ~1536×1024）／SP（縦長 ~1024×1536）の**いずれか1面 oneshot 生成**。
> 案件特性で PC優先 / SP優先 をスキル起動時にユーザーが指定する。

## 入力（6項目）

| 項目 | 必須 | 内容 |
|---|---|---|
| LP URL | **必須** | 着地ページ/参考LPのURL。Playwrightで取得(§Step1) |
| 媒体 | **必須** | 流入媒体。例: Google検索 / P-MAX / Demand Gen / Yahoo検索 / YDA / Meta(FB) / Meta(IG) / LINE / TikTok / X / YouTube。**未指定なら実行を止めて確認**（媒体でファネル位置・刺す属性・FVトーンが変わる。推測で進めない） |
| **FV面** | **必須** | `pc` or `sp` の2択。**未指定なら実行を止めて確認**（pc=横長 1536×1024 ／ sp=縦長 1024×1536 のいずれか1面 oneshot 生成。両面生成は本スキルでは未対応）。PC流入メイン商材なら `pc`／SP流入メイン商材なら `sp` |
| 案件/商品情報 | 任意 | 商品MDパス/商品名/USP等。あれば精度向上 |
| ターゲット情報 | 任意 | 既知のペルソナ/ターゲット。無ければ入力から自動生成（§Step2） |
| 流入広告の主訴求 | 任意 | 広告→FVの連続性設計の基点。無ければStep1で商材ブリーフから推定し「広告仮説」と明記 |

## 実行原則（厳守・例外なし）

1. **オーケストレーター（このスキルを動かすメインエージェント）は、生成・ペルソナ生成・採点・承認・代筆を一切行わない。** 役割は「入力取得」「スクリプト/ツール実行」「サブエージェントへの委譲」「結果の集約」だけ。Step2〜12はすべて**独立サブエージェント**に委譲する。インラインでの自己採点・自己生成・自己承認・一人多役は**禁止**（/copy-build初回でこれをやり品質崩壊した）。
2. **⑰は自分のアイキャッチを自分で承認しない。** G1/G2/G3 の各ゲートは必ず**独立した⑤CDサブエージェント**が承認/差戻し/採択する。アイキャッチ確定**前**に⑨本文構成へ進まない（先行確定が崩れると本フローの意味が消える）。
3. **LP情報は「定義スキーマで構造化抽出」して渡す（全文ベタ渡しもアドホック要約も禁止）。** Step1で規定の商材ブリーフ・スキーマに沿って独立サブエージェントが抽出する。規定フィールドの省略禁止。ペルソナは③が作る「名刺＋フル定義」の二層で運用し、勝手な1行圧縮や要約は禁止（実行原則#6で詳細）。確定FV定義（メイン/サブ/CTA/約束/訴求軸/温度）は⑨へ原文で申し送る。
4. **画像はAIで文字込み一枚絵を直接生成（2026-05-26 確定方式・banner-ad-build と同方式・旧ハイブリッドは廃止）。** 日本語コピー・CTA・ロゴまで生成AIに描かせる。FV面 = pc（横長 1536×1024）／sp（縦長 1024×1536）のいずれか1面を oneshot 生成（両面生成は本スキルでは未対応）。日本語タイポ崩れリスクは**⑤CD G3 で機械的不採用**として担保（許容しない・崩れたら fail）。一枚絵プロンプトは**最小指示型**：全文日本語・必須5セクション（商材／ビジュアル方向（装飾密度明示）／画像内テキスト（ラベル方式）／フォント（`バナー/フォントパレット.md` から固有名で1つ選択）／色（ベース＋アクセント2色）／禁止（他社ロゴ・マスコット＋最大級表現の2項目のみ））＋任意2セクション（装飾要素／タイポグラフィ）。**位置指定・フォントpt指定・各テキストの色指定・競合コピー原文列挙・NG語10件網羅・日本語正確描画念押し・タイポ崩れ抑制セクションは禁止**（モデル誘導効果と誤描画リスクの元）。詳細は `agent-drafts/17_fv-eyecatch-designer.md` 出力フォーマット G2/G3 参照。
5. **品質優先。時間・手数を惜しまない。** 速さよりも各サブエージェントが十分な情報で深く考えることを優先する。各Stepのサブエージェントは会話文脈を見られない前提で、必要情報を自己完結で渡す。

6. **ブリーフ＆ペルソナは「実行用＋記録用」の二層化。情報過多は精度劣化を招く。** 下流SA起動時は**実行用を本文に埋め込み**、記録用は**参照パスのみ**伝える（全文埋め込み禁止）。
   - **商材ブリーフ**: Step1抽出SAが (a) 実行用（1500字以内・サービス／訴求要点／実績数値／状況シグナル／規制ガード／視覚DNA詳細／広告→FV温度の7ブロック）と (b) フル版（規定スキーマ全項目・原文保持＋視覚言語化）の**両方**を別ファイルで出力する
   - **CMOブリーフ**: Step3 SAが (a) 実行用（1ページ・4ブロック＝目的／感情温度／絶対NG／評価軸）と (b) 詳細根拠（市場仮説・LTV・競合観察等）の**両方**を別ファイルで出力する
   - **ペルソナ**: Step2 ③SAが各ペルソナファイル冒頭に「## 名刺」セクション（300字以内・属性／刺さるツボ／離脱ボタン／口語1行）を必須で置く（フル定義の前段）。下流SAには名刺セクションを参照させる。**ただしStep9のペルソナ評価SAだけは「ペルソナ本人として人格を借りる」ため当該ペルソナのフル定義を渡す**（例外）

   - **アプローチA（汎用方法論）**: `LP作成_CVを取るLP.md`（FV設計手順＋鉄板8パート構成＋評価4軸）／担当: 17a / 09a

   各専任SAには**担当アプローチのファイルだけ**を必読指示する（他2アプローチには触れない＝発想の混線を避ける）。⑤CDの採点ルーブリックは共通で適用（Lモデル相当案もCTAあり前提で採点・例外設けない）。アプローチ識別タグ（A/B/C）は G1/G2/G3 採択→⑨申し送り→Step10 本文構成→Step11 合体整合→出力バンドルまで一貫して引き継ぐ。
