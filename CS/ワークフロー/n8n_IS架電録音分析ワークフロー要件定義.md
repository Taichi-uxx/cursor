# n8n IS架電録音分析ワークフロー要件定義

## 1. 概要
IS（インサイドセールス）の架電録音データを自動分析し、アポ獲得結果に基づいた分析結果をスプレッドシートに記録するワークフロー

## 2. システム構成
- **トリガー:** Google Drive
- **音声認識:** Google Speech-to-Text API または Whisper API
- **分析エンジン:** OpenAI GPT API
- **出力先:** Google Spreadsheet
- **実行環境:** n8n

## 3. 詳細要件
### 3.1 トリガー要件
- **機能:** Google Driveファイル監視
- **監視対象フォルダ:** `/IS録音データ/`（具体的なパスを指定）
- **対象ファイル形式:** `.wav`, `.mp3`, `.m4a`, `.flac`
- **トリガー条件:** ファイル新規アップロード時
- **実行頻度:** リアルタイム監視（Webhook推奨）またはポーリング（5分間隔）

### 3.2 音声認識要件
- **機能:** 録音データのテキスト化
- **入力:** 音声ファイル（最大100MB）
- **出力:** テキスト形式の会話内容
- **言語:** 日本語
- **話者分離:** 可能であれば実装（IS担当者と顧客の区別）
- **品質要件:**
    - 認識精度: 80%以上
    - 処理時間: 音声1分あたり30秒以内

### 3.3 分析要件
- **機能:** 会話内容の分析とサマリー生成
#### 3.3.1 分析判定基準
- **アポ獲得成功の判定条件:**
    - 具体的な日時での面談約束
    - 「お時間をいただければ」等の前向きな回答
    - 次回コンタクトの約束（具体的日程付き）
- **アポ獲得失敗の判定条件:**
    - 明確な断り
    - 興味なしの表明
    - 連絡不要の要求
    - 途中での通話終了

#### 3.3.2 分析出力項目
- **アポ獲得成功時:**
    - 概要（100-200文字）
        - 顧客の業界・規模
        - 提案内容の要点
        - アポ設定日時
    - 成功要因（200-300文字）
        - 顧客の関心を引いたポイント
        - 効果的だった営業手法
        - タイミングの良さ
        - 具体的な会話の流れ
- **アポ獲得失敗時:**
    - 概要（100-200文字）
        - 顧客の反応
        - 断られた理由
        - 会話の流れ
    - 失敗理由と改善点（300-400文字）
        - 断られた主な理由
        - 改善すべき営業手法
        - 次回に活かすべきポイント
        - 具体的な改善提案

### 3.4 データ出力要件
- **出力先:** Google Spreadsheet
#### 3.4.1 スプレッドシート構造
| 列名 | データ型 | 説明 |
|:---|:---|:---|
| A. 日時 | DateTime | 録音日時（ファイル作成日時） |
| B. ファイル名 | Text | 録音ファイル名 |
| C. IS担当者 | Text | ファイル名から抽出またはマニュアル入力 |
| D. アポ結果 | Text | "獲得" or "未獲得" |
| E. 顧客概要 | Text | 業界、規模等 |
| F. 会話概要 | Text | 分析結果の概要 |
| G. 成功要因/改善点 | Text | アポ結果に応じた分析内容 |
| H. 録音時間 | Time | 録音の長さ |
| I. 処理完了日時 | DateTime | ワークフロー実行完了時刻 |

### 3.5 エラーハンドリング要件
- **想定エラーケース:**
    - 音声認識失敗（ノイズ、音質不良）
    - API制限超過
    - ファイル形式不対応
    - スプレッドシート書き込みエラー
- **エラー時の動作:**
    - エラーログをSlackまたはメールで通知
    - 失敗ファイルを別フォルダに移動
    - リトライ機能（最大3回）

### 3.6 セキュリティ要件
- **API認証:** OAuth 2.0使用
- **データ保護:** 録音データは分析後削除オプション
- **アクセス制御:** 必要最小限の権限設定
- **ログ管理:** 処理履歴の記録

### 3.7 パフォーマンス要件
- **並行処理:** 最大3ファイル同時処理
- **タイムアウト:** 1ファイルあたり最大10分
- **ファイルサイズ制限:** 最大100MB
- **月間処理量:** 最大1,000ファイル

## 4. 技術仕様
### 4.1 n8nノード構成
- Google Drive Trigger - ファイル監視
- HTTP Request - 音声認識API呼び出し
- Code Node - データ整形・分析ロジック
- OpenAI Node - GPT分析
- Google Sheets Node - データ出力
- Slack/Email Node - エラー通知

### 4.2 必要なAPI・サービス
- Google Drive API
- Google Speech-to-Text API または OpenAI Whisper API
- OpenAI GPT-4 API
- Google Sheets API
- Slack API（通知用）

### 4.3 設定パラメータ
- 監視フォルダパス
- 分析プロンプトテンプレート
- 出力スプレッドシートID
- API認証情報
- 通知設定

## 5. 運用要件
### 5.1 監視・メンテナンス
- 日次処理状況確認
- 月次API使用量確認
- エラー率監視（5%以下維持）

### 5.2 データ管理
- スプレッドシートの定期バックアップ
- 古い録音データの自動削除（3ヶ月後）
- 分析精度の定期検証

### 5.3 改善・拡張
- 分析精度向上のためのプロンプト調整
- 新しい分析項目の追加
- ダッシュボード機能の検討
