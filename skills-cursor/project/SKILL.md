# Project Progress Manager

プロジェクトごとに `進捗.md` を作成・更新するスキル。複数ターミナル・複数セッションをまたいで作業状況を引き継ぐためのハブファイル。

## いつ使うか

- `/project` が明示的に呼び出されたとき
- ユーザーが3ステップ以上のタスクを開始する宣言をしたとき（「〇〇案件のレポート作成開始」「××の分析やります」等）
- セッション終了・中断する旨を示唆したとき（「今日はここまで」「あとで続き」等）→ 既存進捗.mdの更新

## ファイル仕様

### ファイル名
- 固定で `進捗.md`
- 1プロジェクト1ファイル（同一フォルダ内に複数の進捗.mdを作らない）

### 格納先の判定

引数 `$ARGUMENTS` または会話文脈から判定：

| プロジェクト種別 | 格納先 |
|---|---|
| クライアント案件 | `~/.cursor/work/client/<クライアント名>/進捗.md` |
| 社内・自分のプロジェクト | `~/.cursor/work/<該当カテゴリ>/<プロジェクト名>/進捗.md` |
| 発信系プロジェクト | `~/.cursor/contents/<該当カテゴリ>/<プロジェクト名>/進捗.md` |
| 既存フォルダで進行中 | そのフォルダ直下 |

迷う場合のみユーザーに確認。明確に判定できれば確認不要。

## 実行フロー

```
- [ ] Step 1: 格納先フォルダを判定する
- [ ] Step 2: 既存の進捗.mdの有無を確認する
- [ ] Step 3: 新規作成 or 更新を分岐
- [ ] Step 4: 必要情報をユーザーに確認
- [ ] Step 5: ファイルを作成・更新して通知
```

### Step 1: 格納先フォルダを判定

会話文脈から：
- クライアント名が出ていれば `client/<クライアント名>/`
- プロジェクト名が明示されていればそのフォルダ
- 不明確な場合のみ確認:「このプロジェクトの格納先はどこにしますか？（例: `work/client/green/`）」

### Step 2: 既存ファイルの確認

```bash
ls <格納先>/進捗.md 2>/dev/null
```

### Step 3: 分岐

- **存在しない** → 新規作成モード（Step 4へ）
- **存在する** → 更新モード（既存内容を読み込み、何を更新するかユーザーに確認）

### Step 4: 必要情報を確認（新規作成時）

以下を会話文脈から拾い、不足分のみAskUserQuestionで確認：

1. **プロジェクト名**
2. **クライアント名 / 担当案件**（該当する場合）
3. **背景・目的**（なぜこのプロジェクトをやるのか）
4. **期限・マイルストーン**（任意）
5. **初期タスク一覧**（あれば。なくてもOK）

### Step 5: ファイル作成

以下のテンプレートで `進捗.md` を作成する：

```markdown
# 進捗｜<プロジェクト名>

## 基本情報

- **プロジェクト名**: <name>
- **クライアント / 案件**: <client>
- **担当**: 田村太一
- **ステータス**: 🟢 進行中 / 🟡 一時停止 / 🔵 完了 / 🔴 ブロック中
- **開始日**: YYYY-MM-DD
- **期限**: YYYY-MM-DD（未定なら「未定」）
- **最終更新**: YYYY-MM-DD HH:MM

## 背景・目的

<なぜこのプロジェクトをやるのか。事業上の意味、クライアントの課題、自分が達成したいゴール>

### ゴール
- <達成したい状態1>
- <達成したい状態2>

## タスク一覧

| # | タスク | ステータス | 担当 | 期限 | メモ |
|---|---|---|---|---|---|
| 1 | <タスク名> | ⏳未着手 / 🔄進行中 / ✅完了 / ⛔ブロック | 太一/AI | YYYY-MM-DD | <補足> |
| 2 | ... | | | | |

## 中断ポイント（再開時はここから）

> **最終作業日時**: YYYY-MM-DD HH:MM
>
> **今どこで止まっているか**:
> <セッション終了時点で何をしていて、次は何をすればいいかを具体的に>
>
> **次のアクション**:
> 1. <具体的に何をやるか>
> 2. ...

## 作業ログ

### YYYY-MM-DD
- <やったこと1>
- <やったこと2>
- **学び・気づき**: <あれば>

---

> このファイルは `/project` コマンドで作成・更新される。複数ターミナル・セッション間で参照可能。
```

#### 各セクションの埋め方ルール

- **ステータス絵文字**: 🟢進行中 / 🟡一時停止 / 🔵完了 / 🔴ブロック中
- **タスク絵文字**: ⏳未着手 / 🔄進行中 / ✅完了 / ⛔ブロック
- **日時**: `date "+%Y-%m-%d %H:%M"` で取得
- **背景・目的**: 抽象的な「効率化」ではなく、**事業上の意味**を書く（CLAUDE.md準拠）
- **中断ポイント**: 再開時にAIが読んで即作業継続できる粒度で書く

### Step 5（更新時）: 差分追記

既存ファイルがある場合は以下を更新：

1. `最終更新` を現在時刻に
2. `タスク一覧` のステータスを更新（完了したものは ✅、新タスク追加など）
3. `中断ポイント` を今の状況で上書き
4. `作業ログ` に今日の作業を**追記**（既存ログは消さない）
5. プロジェクト全体のステータスが変わったら `基本情報` の `ステータス` を更新

## 通知例

```
✅ 進捗.md を作成しました

📁 /Users/apple/.cursor/work/client/green/進捗.md
📌 プロジェクト: green社_2026春商戦キャンペーン
🟢 ステータス: 進行中
📋 初期タスク: 5件

次のアクション: 競合A・B・CのLP構成分析（タスク#1）
```

## 重要な注意点

- **不可逆操作はしない**: 既存進捗.mdの内容を消すような上書きは禁止。必ず追記・更新ベース
- **クライアント機密**: 進捗.mdにAPIキーやパスワードなど機密情報を書かない
- **重い分析タスク**: 進捗.mdに「サブエージェントへ委譲」と明記して、メインコンテキストを温存する
- **複数プロジェクト並走時**: 同一フォルダに複数の進捗.mdを作らない。プロジェクト単位でフォルダを分ける
