# セッション1: P-MAX最新事例（オーディエンスシグナル＋最適化対象CV）

## 概要
P-MAXを活用する上で重要な **"オーディエンスシグナル"と"最適化対象CV"** に関する最新事例を紹介。
重要度: ★アカウント状態に応じて。

## 事前周知（直近アップデート・機能仕様）

### SSC・ローカルキャンペーンのP-max統合（2022年7-9月予定）
- 2022年7-9月を目途に、ショッピングキャンペーン（SSC）と来店キャンペーンはP-MAXに機能統合される予定
- それまでは、上記2つのキャンペーンとP-MAXを並走させると、**P-MAXがオークション優先されてしまい、コスト・CVが目減りする**

### Equivalent設定
- **用途**: 同一クライアント・別アカウントであれば、P-MAXと既存キャンペーンのディスプレイ／YouTube／検索キャンペーン（完全一致）が競合しないように設定可能
- **設定方法**: 必要であれば業種担当に依頼

### 配信不可カテゴリ（業種）
- サプリ・薬、アルコール、ギャンブル、デート、中絶、アダルト、政治系カテゴリは配信不可
- 厳密には配信できてしまうが、**GDN・FIND等の面では上記カテゴリは配信できないため、その在庫に配信されない状態**になる
- → P-MAXを配信しているのに、検索面しか掲出しない、という事象が起こり得る

## 要点
- 機械学習は **より多くの参考データを与えることで働きを強化**
- シグナルとして **リマーケティングリスト・カスタムインテント・カスタマーマッチを紐づけることで、学習の早期終了が見込める**
- Google広告管理画面より、CVしているユーザーがどんなオーディエンスに分類されるか確認可能
- **関連性の高いユーザーセグメントを紐づけることが推奨**
- ただし「シグナルを絞る」と「自動入札の学習進行」が同時に起きるため、**改善要因の切り分けには注意**が必要

# セッション2: Googleファインドキャンペーンの最適化されたターゲティング導入事例

## 概要
ファインド広告における「最適化されたターゲティング（OT）」機能の検証事例。
順次ディスプレイ広告における全てのキャンペーンタイプで使用できるようになるデフォルト機能のため、効果検証を行い活用を図っていく。
重要度: ★★★★

## 事前周知（最適化されたターゲティングの基礎）

### 「最適化されたターゲティング」と「オーディエンス拡張（標準キャンペーン）」の違い
- **オーディエンス拡張（従来）**: 手動で指定されたオーディエンスに **似たユーザー** にまでリーチ範囲を広げてCV増加を図る
- **最適化されたターゲティング**: 予算や入札単価に関するキャンペーンパラメータの範囲内で、**高度な機械学習を駆使してCVを達成する見込みの高いユーザーが選定** される。広告主はシグナル（手動オーディエンス）を指定してアルゴリズムに伝えることで、このプロセスを調整可能

### 移行状況（2022年2月時点）
- 既存のVAC、ファインドキャンペーンは「最適化されたターゲティング」への移行が進行中
- 既存の標準ディスプレイキャンペーンでは引き続き「オーディエンス拡張」が利用可能。移行条件・完了時期は未開示
- **新規作成する標準ディスプレイ／ファインドキャンペーン及び広告グループの設定は「最適化されたターゲティング」設定が可能**
- 既存キャンペーンでも管理画面上で新規広告グループを作成すれば「最適化されたターゲティング」の設定が可能
- Google公称: 最適化されたターゲティングを使用したことで、広告のCVが **平均20%増加**

### 使い方
1. **最適化されたターゲティングのみ使用** — スマートディスプレイキャンペーンのようなイメージ
2. **手動で選んだオーディエンス（シグナル）と併用** — 手動シグナルを超えてGoogleの機械学習がターゲットを拡張可能。手動ターゲティングだけでは見逃す可能性がある顧客も獲得

### オーディエンスシグナルとは
- 広告主自身がCVに達するユーザーと考える、**手動で指定されたオーディエンスセグメント**（自社データリスト、カスタムオーディエンス、購買意向の強いオーディエンスなど）
- アルゴリズムはまずこれらのシグナルを使用し、その後それよりも高い成果を出しているターゲティング条件が見つかった場合にそれ以外のユーザーも獲得しようとする
- 省略可能だが、キャンペーンの準備期間の短縮に役立つ可能性あり

### 主なメリット
1. **キャンペーンの成果が向上** — 目標CPA、CV数最大化、目標広告費用対効果、CV値最大化に基づきパフォーマンス向上
2. **将来的にも優れたパフォーマンスを実現** — 機械学習と自社所有・自社運用のオーディエンスデータを併用
3. **複数のプロダクトの利便性が一つに** — ファインド、動画アクション、ディスプレイの各キャンペーンの自動化ターゲティングが統合

## 検証目的
- 仮説: 最適化されたターゲティング機能をオンにすることで、**今までターゲティングしていなかった新規ユーザーでのCV獲得ができ、前後でCVsの純増が見込まれる**
- 検証方法: 非リマケキャンペーン配下の広告グループのOT機能をオン
  - リマケキャンペーンは成果棄損リスクと非リマケユーザーを含むことへの懸念で除外
- 注目指標: CVs/CPA

## 事例: 住宅業界（前後比）

### トライアル概要
- 12/5に非リマケファインドキャンペーンの最適化されたターゲティング（OT）設定をオン
- 前期間: 2021/11/27〜12/4（OFF）／後期間: 2021/12/6〜12/13（ON）
- TEST: GDN ／ CTL: YDA

### 結果サマリ

- 11月→12月とダウントレンドで他CPNでは成果悪化傾向だが、**非リマケファインドではCPC大幅低下でCPAが57%に大幅改善**。CTRが1.70%→3.00%と明らかな指標変動
- 同タイミングでリマケファインドは成果悪化しており、OT設定オンでリマケ対象ユーザーが非リマケから配信された可能性も検討したが、**リマケファインドのIMP増加・非リマケファインドのIMP減少からその可能性は小さい**

### 考察（GRP別）
- カスタムインテントではOTが配信量の **9割** を占め、通常配信と比べ大幅に低いCPCで配信でき低CPAでCVを多く獲得 → GRP全体で成果改善
- **セグメントボリュームが大きい購買意向ではOT配信量が1割と少ない** → ボリュームが小さいターゲティングのほうがOTによる拡張と相性がいい可能性有
- ただし、もともと購買意向で配信していたユーザーにカスタムインテントのOTから配信されるようになっただけという可能性も否定不可
- 高CTRは通常オーディエンスでもみられることから **OTではなく配信面のシェア変動等によるもの** と考えられる一方、CPCは明らかにOTでのみ低水準 → OTによる配信先ユーザーの違いによって低CPCとなっていると考えられる

## 検証結果まとめ・推奨検証フロー
- リマケでのOT導入が難しい場合、**成果棄損リスクが小さい非リマケでの検証を推奨**
- 既存オーディエンスの中でも **成果が良くモチベーションの高いオーディエンスリストをシグナルとして設定** することにより成果改善につながる可能性が高い

### 推奨フローチャート
1. リマケ/非リマケで予算及びKPI区分が異なるか
   - YES → リマケOT設定による成果棄損リスクが懸念か → YES → **非リマケでの検証実施（推奨）**
   - YES → 成果棄損リスク懸念 NO → リマケまたは非リマケどちらか、または同時に検証
2. NO → リマケ/非リマケをそれぞれOT設定した時のユーザー重複が懸念か → YES → **1キャンペーン1広告グループに複数リスト紐づけて検証（推奨）**

# セッション3: ETA廃止に伴う、RSAの一本化移行に関する検証

## 概要
2022年6月30日よりETA（拡張テキスト広告）の作成・編集が不可となるため、実質的にRSAに一本化される。成果を毀損することなく移行可能かを検証。
重要度: ★★★★★（全案件マスト実装）

## RSAとは
**より豊富なテキストを使って、ユーザーに関連性の高いメッセージを表示する広告タイプ**

### 特徴
1. **設定しているアセットが組み合わされて表示される** — 最大でタイトルアセット15本、説明文アセット4本登録可能。検索毎に各アセットが組み合わされ表示
2. **ピン留め機能を使用可能** — タイトル1-3、説明文1-2それぞれで必ず掲載したいアセットを固定可能。複数アセット設定時は設定したいずれかが掲載
3. **2022年6月30日よりETAの作成・編集が不可に** — 実質的にRSAに一本化

### メリット
1. **ユーザーに適切なTDが表示される** — ユーザーの関心に合わせてアセットが組み合わされる
2. **インサーションできるクエリが増える** — ETAと比較し多くの本数を入れられるため、インサーションできるクエリの幅が広がる。クエリが拡張する **部分一致と相性が良い**

## 検証目的・方法
- 仮説: RSAに一本化することで、RSAの最適化がうまくいかず悪い組み合わせとなった際にETAがフォローできなくなり成果が悪化する可能性。ただしRSAにアセットが集中することで最適化の精度が上がる可能性もある
- 検証方法: ①RSAのみ設定 VS ②既存のRSA+ETA設定 でのグループ全体の成果差分を検証
- 前後比の場合はトレンド的なクエリ変化が想定されるため、**D&E（同一期間比較）を推奨**

### 注目ポイント
- 獲得クエリの傾向に差分はあるか
- 同一のクエリに対しての成果がどのように異なるか
- 一本化RSAと既存RSAで勝ちアセットに傾向差はあるか
- 配信初動とそれ以降でアセット別IMPは異なるか（学習により選出アセットが変わるか）

## 検証結果まとめ（RSA一本化）
**RSA一本化により成果維持・もしくは改善傾向がみられる**
- 品質が落ちている傾向は見られるが、**CVRの上昇がみられる**
- **ETAの比率が小さいアカウントは成果毀損の可能性は少ないか。RSAのシェアを伸ばしてからの一本化がベター**
- ETAで勝っていたTDがRSA内でIMP比率を伸ばしており、勝ちETAを止めてもRSAから表示されるか
- CVRについては再現性があるかはまだ検証余地あり。**BIGワードのシェアが大きい案件などは要注意**

**Q: DSAのIMPが出ない事象について**
A: 動的広告ターゲットのURL `https://www.aaa.co.jp/bb/1/index.html` とキャンペーンのドメイン設定 `http://www.aaa.co.jp` のドメインが不一致（「www.」か「/」かの違い）であり、URLの設定不備で表示回数が発生していない。動的ターゲットのステータスには「有効（制限付き）：一致するランディングページはありません」と表示。**キャンペーンの設定（キャンペーンのドメイン設定）とターゲット（動的広告ターゲットURL）を一致するように修正すれば解決**。

**Q: レスポンシブディスプレイ広告において広告掲載時に必ず表示されるアセットはあるか？**
A:
- 広告見出し: 長い広告見出しと短い広告見出しのいずれかが表示
- 短い広告見出しと説明文が設定されている場合は、その両方が常に表示
- 説明文 / ロゴ・会社名: いずれかが常に表示
- 最終URLのドメイン: ドメイン名/ロゴ・会社名 組み合わせによって該当項目が表示される数が異なる
- ネイティブ広告で常に表示されるアセット: 広告見出し（長／短いずれか）、会社名

## 太一の示唆

### P-MAX運用への示唆
- **「シグナルを絞る」の決定ロジックを設計せよ** — 確度の高いユーザーセグメント（フォーム遷移ユーザー等）をシグナル化すると、CTR343%/CVR203%という劇的改善。「全リマケユーザー」のような大括りシグナルは初動の学習ボリューム確保時のみ。学習進行後は **「シグナルの段階的絞り込み」を運用計画に組み込む**
- **媒体CPAとクライアント計測CPAの乖離率をP-MAXのKPIに加えよ** — GDN_P-MAX事例ではNB含めQuote乖離率37.9%が成果毀損の主因。「媒体CV/CVRが良い ≠ クライアント成果が良い」を肝に銘じ、**乖離率を入札最適化のレバー** にする
- **SSC・ローカルキャンペーンとP-MAXの並走は禁忌として運用ルール化** — 2022年7-9月の機能統合までは「P-MAXがオークション優先 → コスト・CVが目減り」する。クライアント説明時もこれを前提に
- **配信不可カテゴリの整理を案件初期にチェック** — サプリ・薬・アルコール・ギャンブル・デート・中絶・アダルト・政治系はP-MAX掲出面が検索面に偏る。これら業種は **P-MAX選択前に媒体メリット試算が必要**

### 最適化されたターゲティング（OT）への示唆
- **「リマケから攻める」ではなく「非リマケから攻める」が定石** — 成果棄損リスクが小さい非リマケで先行検証 → 効果が出た部分のシグナル特性をリマケに横展開する順序が安全
- **OTは「セグメントボリュームが小さいターゲティング」と相性が良い** — 住宅事例ではカスタムインテント（小ボリューム）でOT配信量9割、CPAは大幅低下。**「購買意向（大ボリューム）」へのOT付与は配信量1割止まり**で効果出にくい。OT適用先の優先順位設計を
- **OT検証時の指標切り分けに注意** — 高CTRはOTではなく「配信面シェア変動」の影響が大きい。一方 **低CPCはOTの直接効果**。「CPCの変動」を主指標に据えるのが効果検証として筋が良い

### RSA一本化への示唆
- **「勝ちETAの構成要素をRSAに組み込む」が移行成功の最低ライン** — 人材事例で勝ちETAの組み合わせがRSAでIMP比率3倍に伸長。**移行前に勝ちETAのタイトル・説明文を抽出 → RSAアセット化のオペレーション** を案件横断で標準化すべき
- **「ETA比率が高い／BIGワードシェアが大きいアカウント」は段階移行を計画** — 一気に切るのではなく、RSAシェアを高めてからの一本化がベター。**特に1本のETAにCost80%が集中している事例（人材）では、影響大きい**
- **DSAとRSAの組み合わせを意識した「条件付きクエリの受け皿」設計** — 不動産事例ではRSA一本化でDSAがCVR490%まで上昇（条件付きクエリの受け皿に）。**RSA移行と同時にDSAを準備しておくことで、品質低下分のクエリを拾える**
- **検証方法はD&E（同一期間比較）を必須に** — 前後比較ではトレンドのクエリ変化が混入する。新規施策のテスト設計でも **コントロール対象を必ず設けるカルチャー** を組織で徹底

### 案件横断の運用観点
- **「★5＝全案件マスト実装」のラベリングを社内ナレッジ管理に活用** — IREP指標の真似で、案件CSとして「全クライアントで実装済みか／検証中か／不要か」のステータス管理ができる
- **広告表示オプションの階層設計を即見直し** — 今後はアカウント階層設定がカスケード反映される。**「グループ専用オプション」と「アカウント横断オプション」を明確に分離** しないと意図しない掲出が発生
