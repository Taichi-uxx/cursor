# Yahoo!動的ディスプレイ広告（DAD）運用ナレッジ

## 出典

- 元ファイル: `/Users/apple/.cursor/知見・ナレッジ移管/DAD/DAD.docx`
- 作成時期: 2023年9月（社内勉強会資料）
- 媒体上の正式名: YDA（運用型）のキャンペーン目的「商品リスト訴求」=DAD（Dynamic Ad for Display）

## 用途（どんなときに参照するか）

- **Yahoo!軸でダイナミックを増やしたいとき**：Criteo以外でダイナミックの掛け先を広げる選択肢を整理する
- **Criteoと並走させる妥当性を整理したいとき**：在庫の重複が少ないこと、ユニーク面でのIMP積み上げが見込めることを根拠にできる
- **DAD導入のスケジュール・ToDoを確認したいとき**：「約1.5か月」を見込んだうえで顧客に逆算スケジュールを提示する
- **リタゲタグの追加パラメータ仕様を確認するとき**：静的リタゲ実装済みアカウントに追記すべきパラメータ／7種類のタグ階層を確認する
- **アカウント構造・運用設計を考えるとき**：プレイスメント切り出し（PCブラパネ）、商品セット、複数訴求クリエイティブの設計判断に使う

## 1. DADとは / メリット

YDA（運用型）のキャンペーン目的「商品リスト訴求」で配信できるダイナミック広告。Yahoo! JAPANの自社面（特にアプリ面）が独自在庫として効くのが最大の価値。

> Yahoo! JAPANアプリ面は、Criteoからは配信されないYDA独自の在庫
> 他ダイナミックと併用することで、獲得件数の積み上げが期待できる
> 通常のYDA同様、最低入札単価もなく日予算の調整も可能

**示唆**：Criteo単独運用の案件で「これ以上獲得が伸びない」状態のとき、DAD追加は獲得の純増施策として第一候補になる。最低入札のハードルもないため小さく試しやすい。

## 2. 配信面の優位性（Criteoとの棲み分け根拠）

### ユニーク掲載面（DADでしか出ない枠）

- PCブラパネ面（PCブランドパネル）
- Yahoo! JAPANアプリ
- PC/SP中面タイムライン

### ユニーク掲載面 IMP比率

> YDAのインプレッションのうち、DADが掲載され、他社ダイナミック商品が配信されない掲載枠の比率（※パートナー面を除く）
> **SP：約8割、App：約5割**

**示唆**：SPで約8割がCriteoと食い合わない独自在庫なので、「Criteoとカニバるのでは」という懸念は基本的に外していい。Criteoと並走させる提案の最強根拠。

## 3. 導入手順・スケジュール

> ToDo（スムーズに進んでも約1.5か月かかる）

顧客への初回説明時に「1.5か月かかる」を前置きしておくこと。短納期案件は要注意。

### 導入チェックリスト

#### A. リタゲタグ設置（最優先・早めに着手）

- [ ] リーチを早めに溜めるため、他作業と並行せず最優先で着手
- [ ] 既存の静的リタゲがある場合も、**ダイナミック用パラメータの追記が必要**（タグ差し替えではなく追記）
- [ ] Criteoにない取得項目があるため、Criteo用タグの流用ではカバーできない箇所を確認
- [ ] 7種類のタグ階層（後述）を、サイトのページ構造に合わせて割り当て
- [ ] サンクスページは**リタゲタグ（ページ種別：コンバージョン）とコンバージョンタグの両方**を設置（別物）

#### B. データフィード準備

- [ ] フォーマットはDAD独自（Googleの業種別フォーマットのようなものはない）
- [ ] 管理画面 > ツール > 商品リスト > 商品リスト更新 からテンプレートDL
- [ ] **ファイル形式はTSV**（他媒体と違うので注意）
- [ ] 必要日数は「ダイナミック初挑戦か」「Criteo等他ダイナミックの経験有無」「商品数」で大きく変動
- [ ] 配信に影響しない**テストアップロードモード**でエラーチェック
- [ ] 初回アップロード（全件更新）時は**deleteカラムを含めない**（差分更新専用のため、初回に入っているとエラー）
- [ ] 1〜30万件まで配信可。上限は申請で開放可
- [ ] 1日のアップロード上限は4回まで

#### C. クリエイティブ

- [ ] フィードアップロード＆審査完了後でないと広告入稿不可
- [ ] **ロゴ3サイズ必須**：`400×200` / `600×80` / `600×600`
- [ ] **キャンペーンバナーの制作を忘れがち**（要注意）
- [ ] フルサイズは全サイズ網羅が媒体推奨（ロゴエリアとフルサイズはどちらかのみでも可）
- [ ] ロゴ・キャンペーンバナーは管理画面から入稿
- [ ] フィードの審査承認数が**1以上**になって初めて「商品リスト訴求」キャンペーンが作成可能になる

## 4. ページ階層別タグ一覧（7種類）

> DADには7種類のタグがあり、Criteoにはないタグ種別もあるため注意

| ページ | タグ種別 | 必須/推奨 | Criteo |
|---|---|---|---|
| トップページ | home | 推奨 | あり |
| 商品一覧ページ | category | 推奨 | あり |
| 検索結果ページ | search | 推奨 | **無し** |
| 商品詳細ページ | detail | **必須** | あり |
| 商品カートページ | cart | **必須** | あり |
| CV直前（購入・申込ページ） | conversionintent | **必須** | **無し** |
| CVページ | conversion | **必須** | あり |

> 必須タグであっても、該当ページが存在しない場合は設置不要

**示唆**：`search` と `conversionintent` はCriteoにない取得項目。Criteo実装済みサイトでも、この2つは新規でタグ依頼が必要になる。エンジニア依頼時は「Criteoと同じ感覚で」ではなく、この2つを明示すること。

## 5. ページ種別ごとのパラメータ設定

> 「パラメータ」=各種動的に取得する項目（≠計測ツールのパラメータ）

### 取得すべきパラメータ

| パラメータ | 役割 | 備考 |
|---|---|---|
| サイトリタゲID | アカウント固有のID | リタゲタグ発行時点で既に入っている |
| Label | 任意のグループ振り分け | カスタムラベルでリタゲ対象をグルーピング可。ダイナミック特有ではない |
| **ページタイプ**（※ダイナミック用） | ページ階層 | 「どの階層まで到達したユーザーか」を学習させる |
| **商品ID**（※ダイナミック用） | 閲覧商品の特定 | **学習上最も大切な情報** |
| **カテゴリID**（※ダイナミック用） | 閲覧商品のカテゴリ | **Feed上の`categoryid`カラムと一致させることが最重要** |
| **価格・個数**（※ダイナミック用） | 商品単価等の学習 | EC等で価格・個数の概念がある案件は動的取得。単一商材は固定値「1」 |

### ダイナミックリタゲタグの構成

> 通常のサイトリタゲタグとダイナミック用タグは別物ではない
> **サイトリタゲタグ＋各種パラメータ＝ダイナミック用リタゲタグ**

**示唆**：既存YDA運用案件の場合、タグ差し替えではなく「パラメータ追記」の依頼で済む。エンジニアへの依頼時の伝え方を間違えないこと。

### サンクスページの注意

- リタゲタグ《ページ種別：コンバージョン》とコンバージョンタグは別物
- サンクスページには**両方**設置必要
- Criteoはタグ1種類でリタゲ・CV両機能を兼ねる → 媒体ごとにラインナップが違うので、種類と設置階層の把握は必須

## 6. データフィード仕様

### フォーマット

- DAD独自フォーマット（管理画面からテンプレートDL）
- **28項目**あり、必須/任意にかかわらず**カラム名は記載必須**
- 29番目「Delete」のみ完全任意（カラム名記載も不要）
- `product type`カラムは「＞」でつなぐと複数項目を含められる

### 補足

- Googleにあるような業種別フォーマットは存在しない
- ファイル形式は**TSV**
- 1〜30万件配信可（申請で上限開放）
- 1日のアップロード上限は4回
- **テストアップロードモード**でファイル形式チェック（本番反映なし）

### アップロード結果の確認

- 管理画面 > ツール > 商品リスト から更新履歴を確認
- エラーレポート確認項目：
  - **エラー**：ファイル形式、文字数、環境依存文字の有無など
  - **フィード審査**：TD表現方法、商品画像のサイズオーバーなど

### キャンペーンバナー

- 期間限定訴求等を追加し、ロゴ／商品画像と交代表示
- ロゴURL・商品URLとは別に**キャンペーン用URL**設定可
- ロゴエリアとフルサイズはどちらかのみでも入稿可（フルサイズ全網羅推奨）

## 7. アカウント構造（運用設計）

> 基本的にはYDAと同様の考え方
> CV母数を担保しつつ、CVR差の大きいページ階層・リーセンシーで分ける
> ページ階層・リーセンシーで分割するのもDADの特徴の一つ

**示唆**：Reeboke事例ではページ階層・リーセンシーで切り分けていた。Criteoと違って**プレイスメント精査も可能**（Y面切り出し等）なので、運用の自由度は高い。

### ユーザーリストの作り方

- 一般的なURLベース以外に**タグ階層ベース**でも作成可能
- **タグ階層ベースが推奨**：お客さん側でURL変更があっても正常に機能するため

**示唆**：サイトリニューアル・URL変更が見込まれる案件は最初からタグ階層ベースで組んでおく。後からの作り直しコストを削れる。

## 8. 商品セットを用いた設定

> フィードは1種類しかアップロード出来ないが、「商品セット」を使って特定商品群の除外や入札調整が可能

- Facebookの製品セットと同じ概念
- 任意の商品グループに分割し、広告グループに紐づけ可
- 通常配信時は「デフォルトの商品セット（全商品）」を紐づける
- **特定商品セットAの入札強化時、デフォルト商品セットとカニバが生じるので注意**

**示唆**：「主力商品だけ入札強化したい」「廃番／在庫切れ商品を除外したい」要望にはこの機能で対応。ただしカニバ管理を忘れずに。

## 9. パラメータ設定（計測パラメータ）

- デバイス/キャンペーン/広告グループ別などの粒度で設定可
- パラメータは**フィード内に付与**
- **キャンペーンバナーのパラメータは管理画面の「広告編集」欄から設定**
- `{ifmobile}` / `{ifnotmobile}` は**利用不可**（2021/10/20アップデート）

### 「広告」で設定できる項目

配信クリエイティブに反映される項目の一部は広告編集画面から設定可：

- CTAボタン
- 広告の枠線等に使われるベースカラー
- Price/Sale Priceの前後に表示する語句
  - 例：「1,000円（税込）」と表示したい場合、フィード`price`に「1,000」、価格のサフィックスに「円（税込）」を設定
  - 未設定時は自動で「￥」（全角）が前挿入される

## 10. 改善Tips・成功事例

### PCブラパネ面への配信事例

> PCブランドパネル面は、通常DADに比べCTRが約**4.56倍**と高い
> ブラウザを開いて1番最初に接触する広告だからこそ高CTRに繋がった
> ブランドパネル静止画よりもCPCを抑えて配信可能

**アクション**：依頼は必要だが改善インパクト大。**PCブラパネ面切り出しは原則やる**。ブランドパネル静止画と比較してもCPC優位なので、ブランドパネル予算の置換候補にもなる。

### 単一・少数商材を複数訴求に分けて配信

> 同一商品でも複数訴求・クリエイティブに分けることで伝えられるメッセージが多様化し、CTR向上が見込める
> 複数訴求ポイントがある商材なら、訴求ごとにクリエイティブを作ってABテストする方法ではなく、ダイナミックで複数訴求入れる方法も取れる

**事例**：少数商材を複数訴求に分けて配信した結果、通常リタゲ比で
- CTR：**2.83倍**
- CVR：**4.07倍**
- CPA：**約45%**に抑制

**示唆**：商材数が少ない案件でも「ダイナミックは商品数が必要」と諦めない。訴求の切り口でフィードを増やせば、ダイナミックのCTR/CVR優位を享受できる。単一商材EC・SaaSにも応用可能。

## 11. 運用判断のショートカット

| シーン | 判断 |
|---|---|
| Criteoが頭打ち、これ以上獲得を伸ばしたい | DAD並走を提案（SPユニーク面8割が根拠） |
| 短納期で「来月から配信したい」と言われた | 1.5か月かかる旨を即時返答。タグ・フィード・クリエイティブの3工程で逆算 |
| 既存YDA案件でDAD追加 | タグ差し替えではなく「パラメータ追記」依頼。`search`/`conversionintent`はCriteoにないので明示 |
| フィードが小さい/単一商材 | 複数訴求でフィード行を増やす設計を検討（事例：CPA45%） |
| PCの成果改善余地を探したい | PCブラパネ面切り出しを最初に検討（CTR4.56倍実績） |
| URL変更が見込まれるサイト | 最初からタグ階層ベースでユーザーリスト構築 |
| 主力商品の入札強化要望 | 商品セットで対応。デフォルトセットとのカニバに注意 |
