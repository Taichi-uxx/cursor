- **FB DPAとCriteo経由DPAの使い分け**を整理したいとき（面・人ベース・Instagram面のどれを取りに行くか判断するため）

## 1. Facebook DPAの優位性（媒体選定の論点）

DPA枠で他媒体（Criteo・GDN/DAD等）と並走させる際の、Facebookを選ぶ根拠。提案・選定時はこの4観点で比較する。

### 1-1. 人ベースのターゲティングによるレコメンド

> Facebookダイナミックが他媒体と比較して獲得効率が良い事例も多くあるため、複数並走してメディア選定することが推奨

CookieベースではなくFacebookアカウント（=人）にひもづくシグナルでレコメンドするため、クロスデバイス・iOS14.5以降の環境でも相対的に強い。**新規DPA設計時は「Criteoだけ」「FBだけ」ではなく、まず並走してから絞る**のが基本方針。

### 1-2. 面の網羅（Criteo経由FBとの違い）

| 観点 | Facebook DPA直接 | Criteo経由のFB配信 |
| --- | --- | --- |
| FB面の配信ボリューム | 多い | **少ない** |
| Instagram面 | **配信可能（購入導線として需要増）** | 不可／限定的 |
| 人ベース最適化 | 直接効く | 経由のため弱まる |

→ **「Criteoで足りているからFB不要」とは言えない**。特にIG面を取りに行くならFB DPA直接配信が必須。

### 1-3. 豊富なターゲティング機能

リタゲだけでなく**ブロード／プロスペクティング**も可能。

| 階層 | 通常のDPA他媒体 | Facebook DPA |
| --- | --- | --- |
| 顕在層（リタゲ） | ◎ | ◎ |
| 検討層 | ○ | ◎ |
| 潜在層 | × / △ | **◎（FB機械学習で非リタゲでも取れる）** |

> 通常のFacebook広告同様、機械学習の精度が高いので、非リタゲでも効率良く取れる

→ **WEB×EC案件の配信設計では「リタゲ＋プロスペ＋ブロード潜在」の三層構成**を組むのが定石。

### 1-4. 多彩なクリエイティブフォーマット

| フォーマット | 仕様 | 使いどころ |
| --- | --- | --- |
| **カルーセル** | 最大30点の商品を表示 | 視認性を保ったまま多数商品を訴求したいとき（標準系） |
| **スライドショー** | 1カルーセルカード内で複数画像／動画が切替 | 1商品あたりの情報量を増やしたい、動画素材があるとき |
| **コレクション** | カタログ連携でDPAでもコレクション広告化可能 | 工数をかけずリッチ訴求したいとき。トップ画像はカタログ／通常バナー／動画から選択可 |
| **商品タグ付き広告**（IG面のみ） | タグクリックでFB/IGショップの商品詳細へ | ショップ運営案件。後述の §7-2 参照 |

→ **クリエイティブはパターンを無限に作れる**ため、基盤を整備したらクリエイティブPDCAを回し倒すのが成果最大化ルート（§3-1）。

### 1-5. 業種別カタログによる最適化配信

EC／ホテル／フライト／目的地／不動産・住宅／自動車 など業種別カタログを作成可能。商材に応じて適切なカタログタイプを選ぶ。

## 2. 導入手順とスケジュール（新規立ち上げ時）

### 2-1. ピクセル

- サイト上にピクセルを設置（**アプリ案件であればSDKのイベントを埋める**）
- 新規配信の場合（通常のFB広告未実施）: **FacebookページやInstagramアカウントとの紐づけが必要**
- 既存配信に追加する場合: **ダイナミック広告で必要なパラメータを追記する必要あり**

### 2-2. 製品カタログ

> Facebookの場合、フィードを作ってアップロードしたら終わりではなく、「製品セット」の作成が必要

- 配信に影響しない**テストアップロードも可能**（本番投入前に検証可）
- 製品セットの作成後に広告入稿が可能になる

### 2-3. クリエイティブ

「製品セット」作成後 → 広告入稿可能。

## 3. 推奨実装設計（基盤づくりの原則）

### 3-1. 大方針

> 基盤をしっかり作って、後はメンテナンスだけの状態にする
> 基盤を作った後は、クリエイティブで成果を最大化していく

DPAは「基盤8割 / クリエイティブ運用2割」ではなく、**「基盤をガチガチに作り、クリエイティブPDCAに100%リソースを振る」**設計思想。基盤の手戻りは致命的なので初期に時間をかける。

### 3-2. ピクセルは全階層へ設置

> ピクセルは可能な限り全階層に実装し、ユーザーのモチベーション及び興味関心を細かく収集することでエンジン学習を最大化させる

基本イベントだけでなく、**詳細イベントも可能な限り実装**する。
- 参考: Reference - Meta Pixel - Documentation - Meta for Developers
- イベントを埋めることで「そのイベントに接触したユーザー」のリストも作成可能 → 柔軟な運用設計に直結

**事例（ふるさと納税）**:
> ふるさと納税では年末になって、お気に入りリストに入れていた商品の中から商品を選ぶユーザーが結構いる。そこで「AddToWishlist」オーディエンスに対して、年末強化するみたいな戦術もとれる

→ **季節性のある商材では、AddToWishlist/AddToCart等の中間イベントオーディエンスを年末等に強化配信する**戦術が有効。

### 3-3. カタログ情報は最大限反映

> カタログは可能な限りすべての情報を埋めることで商品データを正確に学習し、アップセルやクロスセルのレコメンドを最大限に活かすことが可能

- 必須項目: https://www.facebook.com/business/help/120325381656392?id=725943027795860
- 任意項目: Reference - Catalog - Documentation - Meta for Developers
- **Instagramショッピング（オーガニック）でもカタログを利用する**ため、任意項目まで埋めておくと「広告だけじゃなくオーガニックでも利用できる」とクライアント提案の武器になる

### 3-4. アカウント構造

> 基本、1CP/1ADS/1製品セット/複数広告本数で構成する。1CP内にADSを複数作っての運用は非推奨

| 構造 | 推奨 | 理由 |
| --- | --- | --- |
| 1CP / 1ADS / 1製品セット / 複数広告 | ◎ | 学習が溜まる。FB推奨設計 |
| 1CP / 複数ADS / 複数製品セット | × | **カタログがADSに紐づくため、CP内で複数カタログがあると競合する** |
| 複数の製品セットを使い分けたい | → **複数CPを立てる** | 競合回避 |

- 広告本数: **できるだけ全パターンをトライアル**し、どれが刺さるかを見極める
- リスト作成: **URLベースではなくPixelベースで作成**することが可能・おすすめ

### 3-5. カスタムラベルの活用

> カスタムラベルを活用した商品のカテゴライズにより、関連性の高い商品のみをADGに紐づけ可能。ターゲティング×製品セットを組み合わせることで、様々なトライアル・マッチング向上が可能

→ **「どんなターゲティング×製品セットの組み合わせが成果を最大化するか」**を企画段階で複数仮説立てておく。

### 3-6. パラメータ設定

- **アイレップ標準パラメータを利用**
- パラメータはフィード内 or 広告単位で設定可だが、**広告単位での設定がオススメ**（案件ごとの細かいカスタマイズがしやすい）
- 参考: https://www.facebook.com/business/help/1016122818401732

### 3-7. 競合クリエイティブの確認

- **広告ライブラリで競合の配信中クリエイティブを確認可能** → 企画前に必ずチェック

## 4. 製品カタログを用いたクリエイティブ反映

カタログの一部項目はクリエイティブにそのまま反映可能（どの項目を反映するかは選択可）。

**反映可能な項目**:
title / brand / description / price / sale price / custom_label_00-04 / 販売店ID / 簡単な説明 / URL

### 事例

> custom_labelに「現在価格+"⇒"+セール価格」を入れたことで成果改善

→ **カスタムラベルにマーケ訴求テキスト（値引き表現等）を仕込む**のが定石ハック。「カスタムラベル＝商品カテゴリ分け」だけと考えず、訴求要素の運搬手段としても使える。

## 5. 製品セットの仕組み

### 5-1. カタログマネージャー

フィード系の情報を見るときは**すべて「カタログマネージャー」内**で確認。

### 5-2. 製品セットとは

> 広告セット単位で紐づける「配信に使用する製品の集合体」

- フィード取り込み時点で「すべての製品」が出現
- そこから**一定ルールで絞り込み→配信対象だけの集合体（=製品セット）**を作成
- フィルタリングはフィード項目に基づく

> 逆に言うと、フィード上の項目を網羅していなければ任意の項目でフィルタリングできなくなる

→ **「あとから絞り込みたい」と思っても、フィードに項目が無ければ手詰まり**。§3-3のカタログ情報網羅は、製品セット設計の柔軟性確保の意味でも重要。

## 6. クリエイティブのリッチ化（バッジ・フレーム）

### 6-1. 2系統のリッチ化手法

| 種類 | データソース | できること |
| --- | --- | --- |
| **バッジ** | カタログ（フィード） | 「価格」「割引率」等を、形・色・フォント・配置を自由に設定して付与 |

- 広告単位の **「Edit Creative」** から付与

→ **割引訴求はバッジ、訴求コピー/CTAはフレームと使い分ける**のが基本。

## 7. ヘルスチェック・運用監視

### 7-1. 確認場所まとめ

| 確認対象 | 場所 | 補足 |
| --- | --- | --- |
| カタログのデータ更新が正常か | カタログマネージャー > 該当カタログ > データソース > 概要 | **取り込み失敗時は個人FBアカウントにメールが飛ぶ**ので要受信確認 |
| ピクセルのデータ更新が正常か | カタログマネージャー > 該当カタログ > イベント > ピクセル | — |
| カタログとピクセルの商品ID不一致率 | コマースマネージャー > イベント | 各階層の一致率／不一致商品IDが確認可能 |
| カタログ別のマッチレート | コマースマネージャー > カタログ > イベント | 1イベントソースが複数カタログにリンクされた際にカタログ別に確認可能 |

### 7-2. 商品ID不一致率の基準

> タグで取得する商品IDとフィード上の商品IDとの不一致率は成果にダイレクトに影響する。**最低でも80%以上を確保している必要がある**

→ **不調診断の第一歩は商品ID一致率の確認**。80%を切っていればクリエイティブをいくら変えても成果は出ない。

### 7-3. カタログ更新の運用ルール

- 基本: **1日1回・1つの製品カタログを連携**すれば問題なし
- **大型案件（商品点数が数百万点）のみ複数商品ファイルからの連携を推奨**
- **100万点以上になるとFacebookがエラーを起こしやすい** → 分割連携検討

### 7-4. 画像サイズ

> Instagram面への配信を考えると画像サイズは1対1がオススメ。フィードに入れる商品画像も1対1にすることを推奨

→ **新規案件のフィード設計時は商品画像を1:1で揃えるよう先方に依頼**。

## 8. アップデート機能（適用判断シート）

| # | 機能 | 用途／適用条件 | 効果 |
| --- | --- | --- | --- |
| ① | **AAA × ダイナミック広告** | アプリ案件 | 設定簡素化で機械学習促進。1CPで「インストール＋アプリ内アクション」両立最適化 |
| ② | **商品タグ付き広告**（IG面のみ） | FB/IGショップ運営案件 | ショップ遷移ステップが増え「ショップ遷移しやすいユーザー」シグナルを学習活用可能 |
| ③ | **ダイナミックフォーマットとクリエイティブ機能** | カタログ使用案件全般 | フォーマット・クリエイティブ・リンク先をユーザー別に自動最適化 |
| ④ | **自動類似オーディエンス（LAL）** | DPAリタゲADSがある全案件 | iOS14.5以降のリタゲ縮小をカバー。10%表記だが配信時は1〜10%で自動変動 |
| ⑤ | **ショップエンゲージメントオーディエンス** | ショップ保有案件 | ショップ内行動をエンゲージメントカスタムオーディエンスとして利用可能 |
| ⑥ | **カタログ別マッチレート確認** | 1イベントソースに複数カタログ紐づけ案件 | カタログ単位での品質可視化 |

### 8-1. AAA × ダイナミック広告（詳細）

- AAA = Automated App Ads（2020年9月ローンチ、アプリ新機能）
- **設定項目を少なくして機械学習促進**
- ターゲット設定・配信面は選択不可（**自動配置のみ**）
- 最低年齢指定・カスタムオーディエンス除外・地域設定は適用可能
- **1CPで2つの最適化が両立**:「アプリのインストール」と「アプリイベント（課金等）」の組み合わせ最適化
- ダイナミッククリエイティブ最適化（自動組み合わせテスト）も併用

### 8-2. 商品タグ付き広告（詳細）

- 広告に商品タグを付与 → クリックでFB/IGショップ（アプリ上）の商品詳細ページへ
- 購入意向が高まったら外部ウェブサイトへ遷移
- 作成方法: https://help.instagram.com/772817050237551
- DPAでの商品タグ付き広告作成方法: https://www.facebook.com/business/help/517601898571657?id=1913105122334058

> Instagram上での行動が1ステップ増える分、従来の「CTs・CVsしやすい」というシグナルの他に「ショップ遷移しやすいユーザー」というデータも最適化に活用できる

### 8-3. ダイナミックフォーマットとクリエイティブ機能（詳細）

- カタログ使用時に、広告フォーマット等をユーザー別に自動最適化
- **広告フォーマットはカルーセルかコレクション**
- どのフォーマット／コレクションスタイルで配信されるかは**指定不可**
- **フォーマットごとの成果は確認不可**（→ 配信比較したいときは別CPで切り分ける）

### 8-4. 自動類似オーディエンス（LAL）— 導入手順の落とし穴

リリースの背景: iOS14.5以降のリタゲ縮小をカバーするため。

**導入手順（重要：手順を間違えるとリタゲ＋LAL混合になる）**:

1. DPAリタゲADSで「自動類似オーディエンスをオン」にする → オーディエンスが自動生成される
2. ⚠️ **このまま公開するとリタゲ＋自動類似オーディエンス配信になる** → 一旦管理画面上の編集は**下書きを破棄**する
3. **新規で広告セットを作成**し、該当の自動類似オーディエンスを設定する
4. 下書きを破棄しても、オーディエンスには自動類似オーディエンスが作成されているので問題なし

→ **「オンにして保存」してしまうとリタゲが汚染される**。手順2の「下書き破棄」を絶対に忘れない。

### 8-5. ショップエンゲージメントオーディエンス（詳細）

- 導入推奨案件: ショップを保有している案件
- **注意点**: ショップへのアクセス数が少ない場合、ショップオーディエンスによる影響は限定的
- 推奨策:
  - 先に**商品タグ付き広告（§8-2）でショップへのアクセス数を増やす**
  - もしくは最もボリュームを確保できる**「ショップページ見た人」を選択**

## 9. 管理画面上の設定（リファレンス）

### 9-1. カタログ連携

- パス: コマースマネージャ > データソース > カタログ > 新しいフィードを追加
- データ取得元: **「スケジュール設定したフィードを利用」**を選択し、データフィードが格納されているサーバーを設定
- 参考:
  - カタログのデータフィードのフィールドと仕様: https://www.facebook.com/business/help/120325381656392
  - データフィードファイルを使ってアイテムをカタログにアップロード: https://www.facebook.com/business/help/125074381480892
  - 開発者ガイド: Guides - Catalog - Documentation - Meta for Developers

### 9-2. キャンペーン設定

- **目的: 「カタログ販売」を選択**し、対象のカタログを指定

### 9-3. 広告セット設定

- 商品セット: 「宣伝する製品」部分で配信対象とする商品セットを選択
- ターゲット:
  - **アップセル製品** → 指定した製品セットの商品を**閲覧**した人にリタゲ
  - **クロスセル製品** → 指定した製品セットの商品を**購入**した人にリタゲ
  - デモグラ／プロスペクティブ配信（未訪問ユーザーへの配信）も可能
  - リーセンシー指定可能

### 9-4. 広告設定

- FMT（フォーマット）を選択
- 見出しや説明文に**表示するカタログ項目を選択**
- 画像はカタログから自動抽出される
