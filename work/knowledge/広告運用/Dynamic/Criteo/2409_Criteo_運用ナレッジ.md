Criteoの「全体像 / 実装 / オーディエンス / クリエイティブ作成 / 運用」を1本に統合した参照用ナレッジ。社内勉強会、獲得向けオーディエンス資料、管理画面でのクリエイティブセルフ作成マニュアルを源泉に、現場で「次に何を判断・操作するか」が分かる粒度で再構成している。

## 用途

このナレッジは以下のシーンで参照する。

- Criteo導入可否を判断するとき（配信面のカバレッジ、フルファネル対応プロダクトを確認）
- 案件キックオフ時にタグ実装仕様を確認するとき（ローダー/Criteoタグ/データレイヤーの役割と設定先）
- フィードFMTを選定 / カテゴリ設計を行うとき（オリジナルFMT vs CPPF、第1〜第3階層の使い分け）
- 獲得向けに配信するオーディエンスを設計するとき（Similar / Lookalike / RDAC / Commerce / Persona / Location の選定）
- 管理画面でクリエイティブをセルフ作成するとき（ダイナミック / アダプティブ / 画像 / 動画 / クーポン）
- 入稿後のクリエイティブを編集 / 差し替えするとき（クリエイティブと広告クリエイティブの違い、編集影響範囲の把握）
- 配信エンジンの選定・移行を判断するとき（CO → ACO / ARO の切替判断）

## 1. Criteo 全体像

### 1.1 配信面

> Yahoo!JAPANをはじめ、Criteoの配信面は主要メディアをおさえているため、日本国内のインターネットユーザーを9割以上ターゲティング可能

→ 国内主要メディアを横断するため、リーチ確保目的だけでも候補に上がる媒体。

### 1.2 フルファネルのプロダクト

| ファネル | プロダクト | 役割 |
|---|---|---|
| 認知 | 動画広告（インストリーム / アウトストリーム） | リーチ最大化 |
| 比較・検討 | Contextual Similar / Commerce | ページ文脈から関連商品をレコメンド（Cookieレス） |
| 比較・検討 | InMarket（旧トラフィックジェネレーション） | サイト未来訪ユーザーにサイト来訪を促す |
| 比較・検討 | アプリ広告（AppInstall） | 未インストールユーザーへのインストール促進 |
| 獲得 | アプリ広告（AppRetargeting） | DL済ユーザーへのアプリ内購買促進 |
| 獲得 | アプリ広告（AppEngagement） | 休眠・未アクティブユーザーの再活性化 |
| 獲得 | オムニチャネル | オンライン×オフラインで店舗誘導 or Web購入促進 |
| 獲得 | オーディエンスマッチ | 長期離脱ユーザーのリエンゲージメント |
| 獲得 | Prospecting（旧CCA） | サイト未訪問の潜在顧客への類似配信 |
| 獲得 | ダイナミックリターゲティング | Criteoの代表格である動的リマケ |

### 1.3 Criteoエンジンの3層構造

> Criteoエンジンは3つのエンジンから構成されている
> ①入札予測エンジン:どのユーザー/どの広告枠に配信すべきか?
> ②レコメンドエンジン:どの商品をレコメンドするべきか?
> ③クリエイティブエンジン:どのようなバナーデザインにすべきか?

→ Criteoの「自動化」は単一エンジンではなく、入札 / レコメンド / クリエイティブの3層が連動する。改善の打ち手も「どの層に手を入れるか」で整理すると見通しが良い。

## 2. 実装 — タグとフィード

### 2.1 タグ全体像

| タグ種別 | 役割 | 設定先 | 備考 |
|---|---|---|---|
| ローダータグ | Criteoサーバーの呼び出し、タグ取得情報の送信、訪問タグ（動的ローダーの場合） | GTM もしくは直貼り | 静的 / 動的の2種類。**新規案件は動的ローダー必須** |
| データレイヤー | Webサイト上の変数をGTMで利用しやすく受け渡す | クライアントWebサイト | **クライアント側での実装が必要** |
| Criteoタグ | リターゲティングタグ / CVタグ / 訪問階層把握 / 学習に必要な情報取得（商品ID・価格・個数） | GTM もしくは直貼り | **mCV（マイクロCV）の設定は不可**。設定先により別タグガイド |

### 2.2 静的ローダー vs 動的ローダー

> 2021年3月に動的ローダーがリリース。従来版の静的ローダーでも Criteoタグは機能するが、新規案件は動的ローダーを実装する。

- 機能差分: **動的ローダー = 静的ローダー + 訪問タグ**
- 動的ローダーを実装すると訪問タグが自動的に機能する

### 2.3 訪問タグの意味

> CV動線からは外れる副次的なページ (会社概要、 FAQ、 お客様の声等) への訪問を捉えることで、直帰率改善やエンジン最適化促進が望める。

- 階層タグが何も発火していない状態で、**ページロード30秒経過 or ページを閉じた時**に自動発火
- 訪問タグのみの発火では**リタゲ対象にはならない**
- 外部計測ツールとの実績乖離対策に有用
- あくまで副次的なページ用。ユーザーモチベーションは最も低い

### 2.4 タグで取得すべきパラメータ

> 各階層タグで取得できるパラメーターは、学習最適化観点で必ず取得する。
> ROAS最適化エンジンで運用する場合は価格・個数も動的に取得すると最適化に寄与する。

- リストページでもカテゴリ判別のために**3つの商品IDの取得がマスト**
- 3つ取得が難しい場合はリストタグを設定する意味がないため、他タグで代替
- 非EC業種で価格や個数の概念が無い場合は固定値「1」の取得でOK。**何も取得しないはNG**

### 2.5 フィードFMTの選び方

| FMT | 概要 | 最適化キー | 適用 |
|---|---|---|---|
| Criteoオリジナル | 標準フォーマット | `categoryid1, categoryid2, categoryid3` | 小売以外 |
| CPPF | 小売り向け。EC業種の学習最適に有用なカラム複数 | `product_type` | **小売はCPPFを選択** |

- 1アカウントに設定可能なフィードファイルは1つのみ
- 参考URL（社内勉強会内に記載）
  - オリジナル: https://guides.criteotilt.com/other/simplefeed_retail_ja/
  - CPPF: https://help.criteo.com/kb/guide/ja/-x6IPthZ4ZW/Steps/886830,886860,886864

### 2.6 カテゴリ設計

> カテゴリの第1階層は入札粒度となり、第2・第3階層はレコメンドに影響する。

- 第1階層 = 入札粒度 / 第2・第3 = レコメンドへの影響
- チェックポイント
  - カテゴリが1〜3階層まですべて網羅されているか
  - カテゴリは入札 / レポーティングを加味した設計か
  - カテゴリ2,3はユーザーのモチベーションが加味された設計か

### 2.7 フィードファイルのアップロード

- フィードファイルは直接アップロード不可。**任意のサーバーに格納した上で管理画面でインポート設定**
- 定期アップロード設定は **4回/日まで**
- ファイル形式 / 文字コードが管理画面設定とファイルで違いがないか要確認
- Criteo社依頼で **CriteoFTPを無料で開設可能**

## 3. 配信設計とエンジン

### 3.1 配信設計のフレーム

> ①プロダクト × ②目標・目的 × ③オーディエンス × ④エンジン × ⑤クリエイティブ

→ 目標・目的は「認知 / 比較検討 / 獲得」だけでなく、**アクイジション（新規）/ リテンション（既存）** の軸も合わせて整理する。

### 3.2 エンジンの命名規則

| 接頭 | 入札ロジック |
|---|---|
| A〇〇 | 自動入札 |
| B〇〇 | 目標予算最適 |
| 〇〇（2文字） | 手動入札 |

| 中央 | 最適化対象 |
|---|---|
| O**V**O | 訪問（Visit）最適 |
| O**C**O | コンバージョン（Conversion）最適 |
| O**R**O | 売上（Revenue）最適 |

### 3.3 エンジン移行プロセス

> デフォルトのCOエンジンから開始し、他エンジンの基準を満たし次第、KPIに沿ったエンジンへ移行

- CPA最適 → **ACO**
- ROAS最適 → **ARO**

### 3.4 ブランドセーフティ

- ドメイン: 各10万件を上限にブラックリストアップロード可能
- コンテンツカテゴリ: 特定のセンシティブカテゴリの保護レベルを選択可能
  - 「厳密」を選択すると、必ずしもネガティブではない話題までシビアにブロックされる

## 4. オーディエンス設計

### 4.1 全体マップ

| 種別 | 概要 |
|---|---|
| プリセットオーディエンス | Criteoが標準提供する固定セット |
| リタゲオーディエンス | **Criteoの真骨頂** |
| コマースオーディエンス | Criteoが持つ膨大な行動データを基にした属性ターゲ（Google product カテゴリ / 興味関心 / 商品カテゴリ / ブランド / 性別 / 消費習慣＝購入力） |
| ロケーションオーディエンス | 住所情報を元に、自社店舗周辺のオフラインユーザーへリーチ。コマースオーディエンスとの掛け合わせ可 |
| 類似（シミラー）オーディエンス | サイト流入ユーザーをCriteo側で類似拡張。Lookalikeにアップデート版あり |
| カスタムオーディエンス | オーディエンスを組み合わせて好みのユーザーへ配信。ノンプリセット用 |
| 顧客オーディエンス | ハッシュ化Email / オフラインCRM / CDP / DSPなど1stパーティデータで構築 |
| イベントオーディエンス | 購入アクション・遷移から、購入頻度に基づきセグメント化（例: 1回限りの購入者） |

### 4.2 獲得向け6種オーディエンス（深掘り）

`Similar / Lookalike / RDAC / Commerce / Persona / Location` の6種が獲得向けの主力。**獲得最大化エンジン**と組み合わせて使う。

#### 4.2.1 比較表

| オーディエンス | 拡張のベース | 主な利用業種 | 主な目的 |
|---|---|---|---|
| Similar | サイト訪問ユーザーの**アカウント単位**の類似拡張 | 求人 / アパレル / 金融 / トラベル | 新規応募・新規購入・新規申込・新規予約 |
| Lookalike | Hashed Email / CVデータ等の**ユーザー単位**の類似拡張 | 金融 / アパレル / 単品通販 | 承認率改善 / ROAS改善 / LTV改善 |
| RDAC | 楽天会員データ（1億以上）× Criteoエンジン | アパレル / コスメ / 日用品 / フィットネス | 競合user獲得 / 新規購入 / 新規会員獲得 |
| Commerce | Criteo保有のShopper graph（Google Product Category × 価格帯 × ブランド × 性別 × 消費習慣） | アパレル / ECモール / コスメ | 新規会員登録 / 新規購入 |
| Persona | Criteo独自セグメント（過去の購買傾向・閲覧・購買力からペルソナ予測） | 求人 / コスメ / 単品通販 | 新規会員登録 / 新規購入 |
| Location | 位置情報ベースで周辺ユーザーへ配信。Store to web / Store visit / Store CV | 教育 / コスメ / アパレル | 周辺集客 / 店舗誘導 / 店舗購入 |

#### 4.2.2 Similar vs Lookalike の違い

- **Similar**: アカウントレベルで類似ユーザーへ拡張。サイト流入ユーザーを購入履歴・エンゲージメントでスコアリング → AIが類似ユーザーを特定 → エンゲージメントを予測して質の高いユーザーへ最適化配信
- **Lookalike**: クライアント提供のユーザーリスト（Hashed Email等）をもとに、**直近の閲覧商品や購買行動を用いて最も高い類似性を持つユーザーへ配信**。Hashed Email以外にも Device ID（GAID / AAID）、Gum ID、Cookie ID で類似拡張可能
  - データ提供が難しい場合は、Criteoタグで取得したCVデータをもとに配信可能

→ **Similar = サイト来訪データ起点 / Lookalike = 顧客データ起点**。LTV改善や承認率改善が目的なら、CRMリストを使えるLookalikeが基本線。

#### 4.2.3 RDAC（楽天データ連携）

> 1億以上の楽天会員情報や閲覧/購買行動情報を元に顕在顧客のみならず、潜在顧客まで狙ったユーザーへターゲティング配信。楽天DMP×Criteoエンジンを連携させた精度の高いターゲティング。

- 設計例
  - 類似商品閲覧ユーザー（アパレル × 新規購入）
  - 年齢性別デモグラ（20代〜30代女性）× コスメ閲覧ユーザー
  - 特定の日用品（洗剤等）を閲覧・購入しているユーザー
  - 年齢性別デモグラ × 該当地域のユーザー（フィットネス × 新規会員獲得）

#### 4.2.4 Commerce（Shopper graph 属性ターゲ）

- 設計軸: Google Product Category / 価格帯 / ブランド / 性別 / 消費習慣
- 設計例
  - brandで「NIKE / Puma / adidas / The North Face / ASICS / Mizuno / Under Armour / New Balance / Converse / FILA / Sketchers / lululemon」を選択
  - Google Product Category「ファッション・アクセサリー」「美容・健康」× 価格帯「中・高」× デモグラ「女性」× 消費習慣「中・高・非常に高い」

#### 4.2.5 Persona（Criteo独自セグメント）

- 過去の購買傾向・閲覧商品・カテゴリ・ブランド・購買力から、**今後接触・購入する可能性のある製品・サービスを予測したペルソナ**
- 設計例
  - 求人 × 新規会員登録: 【求職者】【学生】【若い成人】【旅行好き】
  - コスメ × 新規購入: 【ラグジュアリー商品に関心】【フィットネスに関心】【オフィス通勤の再開】
  - 単品通販 × 新規購入: 【若い成人】【ラグジュアリー商品に関心】【食に関心】

#### 4.2.6 Location（位置情報）

- 3モード
  - **Store to web**: 店舗周辺ユーザーへWeb誘導（例: 学習塾校舎の周辺10km以内 → ウェブ資料請求）
  - **Store visit**: 店舗近隣ユーザーを店舗へ誘導
  - **Store CV**: 店舗近隣ユーザーに対し店舗購入を促進
- コマースオーディエンス等のオンライン興味関心との掛け合わせ可

## 5. クリエイティブ全体設計

### 5.1 ダイナミックバナーの最適化要素

> 「サイズ×グリッド×ビュー×ナビゲーション×カラーセット×CTAサイズ×グリルコン×フレキシブルコンテナ×アシンメトリックグリッド」

→ 上記の組み合わせでレイアウトが自動生成される。**レイアウト指定で配信を絞ることも可能**。

- 1行フィードに限定 → 単一商材でも違和感のない「モノレイアウト」配信
- 数行フィードに限定 → 訴求ポイントごとに複数行のフィードを用意して様々なFMTで配信（例: ①Web申込はこちら ②入会キャンペーン ③最大5000P還元）

### 5.2 フィードで広告表示されるカラム

- 「赤字のカラム」を使用すると**バナーの所定位置に自動表示**
- 反映前にビジュアルチェックしたい場合 → 任意のカラム名を使用し、事前にデモバナーを作成

### 5.3 Extra系カラムの活用

> extra_atpとextra_txtカラムを追加することで任意のテキストをバナーに表示可能。

- `extra_atp` は本来 `price` が表示される場所に任意テキストを表示するカラム
- そのため `price` / `sale_price` との**併用は不可**

### 5.4 オプション機能

利用可能なクリエイティブ改善オプション:

- エクストラバッヂ
- スターレイティングバッヂ
- ディスカウントバッヂ
- ロゴサイズクーポン
- フルサイズクーポン
- カウントダウンクーポン

### 5.5 イメージオプティマイゼーション

> 画像解析AIを活用した、 商品画像最適化機能がリリース。複数の商品画像の中から成果が見込める画像を自動選定し配信される。

- 解析項目: アスペクト比 / 人物の有無 / 色 / 写真・イラスト / 画像サイズ
- 実施フロー: `additional_image_link` にカラム追加し、媒体社へ連絡

### 5.6 その他のCriteo クリエイティブFMT

| FMT | 特徴 |
|---|---|
| DataDrivenAds | 曜日・時間によるクリエイティブ最適化 |
| RichMedia広告 | 回転 / スライド切替 / カウントダウンなど |
| Adaptive広告 | データフィード不要。YGのレスポンシブと同等 |
| Showcase広告 | 売れ筋商品 / 新入荷商品をハイライトし、シングル画像または動画を表示 |
| ロケーションバナー | ユーザーの位置情報と商品の位置情報に基づくレコメンデーション |

## 6. 管理画面でのクリエイティブセルフ作成手順

クリエイティブセルフ作成マニュアル（2024年9月）を、迷わず再現できるチェックリスト形式に再構成。

### 6.1 重要概念: クリエイティブ vs 広告クリエイティブ

| 区分 | 配下 | 役割 | 編集可能項目 |
|---|---|---|---|
| **クリエイティブ** | クリエイティブライブラリ | デザインテンプレート。それ自体では配信できない | デザイン / 遷移先（パラメータ除く） |
| **広告クリエイティブ** | 広告セット配下 | クリエイティブを広告セットに紐づけたもの。配信可能 | 配信ステータス / 広告クリエイティブ名 / パラメータ / スケジュール |

注意点:

- **紐づく広告クリエイティブが「ON」でなければ、広告セットを「ON」にしても配信されない**
- クリエイティブのデザインを編集すると、**紐づけられた全ての広告クリエイティブに変更が即反映される**
- Criteo側で作成した「Criteoのクリエイティブ」は**管理画面で編集不可**

### 6.2 入口の選び方

| 経路 | 入口 | こんなときに使う |
|---|---|---|
| キャンペーンモジュールから | キャンペーン > 広告 右上「クリエイティブを新規作成」>「新しいクリエイティブをデザイン」 | クリエイティブ作成と同時に広告セットへ紐づけたい |
| クリエイティブモジュールから | クリエイティブのライブラリ 右上「＋新しいクリエイティブ」 | デザインだけ先に作成し、後で広告セットへ紐づけたい |
| 既存クリエイティブを使う | キャンペーン > 広告 右上「クリエイティブを新規作成」>「既存のクリエイティブを使う」 | ライブラリの作成済みクリエイティブを広告セットに紐づける |

### 6.3 ダイナミック広告の作成チェックリスト

- [ ] クリエイティブ名を入力（ライブラリでの表示名）
- [ ] フォーマット「ダイナミック広告」を選択 → 次へ
- [ ] ロゴをドロップしてアップロード
  - [ ] 必要に応じて「高度なロゴオプション」でロゴの比率 / サイズ / エリア位置 / 表示位置を設定
- [ ] バックグラウンド / メインテキスト / 価格の色を指定（オプションでロゴ背景も指定可）
- [ ] フォントは基本固定（オプションでスタイル設定可）
- [ ] ボタン文言を最大8つ指定（**推奨は文字数を抑えめに。表示は自動最適化**）
- [ ] 表示ルールを選択
  - **画像全体を表示**: 商品エリアにフィット、余白が発生することあり
  - **画像を拡大**: エリアに合わせて自動トリミング
  - 必要なら「一度に表示する商品数」を制限（トグルON → 数字入力）
- [ ] 価格のフォーマットを選択
- [ ] 保存
  - キャンペーンモジュール経由: 「クリエイティブを保存して続行」→ 広告セットへの紐づけへ
  - クリエイティブモジュール経由: 「保存して終了」（未入力時はドラフト保存）

### 6.4 アダプティブ広告の作成チェックリスト

- [ ] レイアウトを選択（「モンタージュ」「エディトリアル」「インバナー動画」は**同一テキストで同時作成可**）
- [ ] ロゴ画像をドロップ
- [ ] モンタージュの場合: 「新しいスライドを追加する」で画像をドロップ
  - 推奨3サイズ以外は自動トリミング（調整可）
  - スライドは複数追加可、順序は矢印で入替
  - モンタージュ使用時は「画像の見出し」を入力（未入力ならモンタージュのみになる）
- [ ] 画像の表示方法を「画像全体を表示 / 画像を拡大」から選択
- [ ] インバナー動画の場合: 動画を入稿
- [ ] 見出し・説明を入力
- [ ] ボタン文言を最大8つ指定
- [ ] ロゴエリア / タイトル / 背景 / テキスト / の色を指定
- [ ] ランディングページURLを設定
- [ ] 保存

### 6.5 画像広告の作成チェックリスト

- [ ] **できるだけ多くのサイズの画像**をドロップ
- [ ] プレビューで自動生成クリエイティブを確認
- [ ] リダイレクト先URLを入力し、URLテスト
- [ ] 保存

使用可能サイズ一覧（マニュアル記載）:

- ディスプレイ系: 300×250 / 728×90 / 160×600 / 468×60 / 300×600 / 336×280 / 200×200 / 320×50 / 970×250 / 970×90
- モバイル / その他: 320×480 / 480×320 / 320×568 / 360×640 / 640×360 / 320×100 / 768×1024 / 1024×768 / 360×592 / 375×667

### 6.6 動画広告の作成チェックリスト

- [ ] **25MB未満 / 30秒未満の mp4 ファイル**をアップロード
- [ ] リダイレクト先URLを入力し、URLテスト
- [ ] 保存

### 6.7 広告セットへの紐づけ手順

クリエイティブライブラリ経由 / キャンペーンモジュール経由のどちらでも、共通の入力項目を埋める。

- [ ] 広告クリエイティブ名を入力
- [ ] 紐づける広告セットを選択
- [ ] フィードを使うフォーマットなら、商品フィルターの詳細設定を活用（作成済み商品セットを使う場合は**広告クリエイティブ作成後に編集画面で紐づけ**）
- [ ] ダイナミック / アダプティブの場合、インベントリタイプを選択
  - **デフォルトでディスプレイ・ネイティブの両方が選択**されているため、ネイティブを使わないならチェックを外す
- [ ] 広告トラッキングを設定（任意）
- [ ] スケジュール設定が必要ならトグルON → タイムゾーン確認 → 開始 / 終了日時を入力
- [ ] **広告配信を開始** をクリック（複数インベントリ選択時は「複数の広告配信を開始」）
  - **広告には設定の一時保存がない**。広告セットがONならクリックと同時に即配信開始

### 6.8 入稿後の編集

- 広告クリエイティブの編集
  - キャンペーン > 広告 から対象の「︙」 → 「クリエイティブを編集する」
  - 編集可能項目: 広告クリエイティブ名 / 説明（任意）/ 商品フィルター詳細設定 / 広告トラッキング / スケジュール設定
- クリエイティブ（デザイン）の編集
  - クリエイティブのライブラリで対象の「︙」 → 「編集」
  - **紐づけられた全広告クリエイティブに即反映**される点に注意
  - Criteoが作成した「Criteoのクリエイティブ」は管理画面で編集不可

## 7. クーポンの作成手順

### 7.1 起動

- [ ] キャンペーン > 広告タブ > 「クーポン」 > 「クーポンを作成」

### 7.2 入力チェックリスト

- [ ] クーポン名を入力
- [ ] 紐付ける広告セットを選択
- [ ] ランディングページURL（+ 任意でトラッキングコード）を入力
  - クーポン独自のトラッキングコードを設定する場合はトラッキングコードを含めて入力
- [ ] フォーマット種類を選択（**ロゴエリア推奨**）→ 次へ
- [ ] 必要サイズの素材をドロップ（サイズは「リストを表示」で確認）
- [ ] 素材が正常にアップ → 緑色表示を確認 → 次へ
- [ ] 表示頻度を選択（デフォルト 3）
- [ ] 表示期間を選択（デフォルト 3）
- [ ] ローテーション数を選択（デフォルト 2）→ 次へ
- [ ] クーポン素材をセットしたバナーサイズを選択して更新
- [ ] 対象バナーへのクーポン設定とリンク先をクリックで確認 → 次へ
- [ ] スケジュール設定の有無を選択（不要なら最終ステップへ）
- [ ] 日本のタイムゾーンを選択し、開始日・終了日・時刻を設定
- [ ] **利用規約の同意にチェック**
- [ ] 「スケジュール」をクリックして確定

### 7.3 クーポン運用上の制約

- **1つの広告セットには1つのクーポン**しか紐づけられない
- 異なるスケジュール設定のクーポンを紐づけた場合、**新しい方が優先**して配信される（前のクーポンはアーカイブされる）
- クーポンが設定可能なクリエイティブタイプは「**ダイナミック広告**」と「（マニュアル該当箇所のFMT）」
- クーポンは広告セット単位の設定のため、**クリエイティブごとには設定できない**

## 8. よくある質問 / 運用上の注意

### 8.1 クリエイティブ表示まわり

- バナーに表示する商品数を制限したい → 表示ルールの高度なオプションで「一度に表示する商品数を制限」可
- ダイナミック広告のバナーサイズを制限したい → 細かい制限は不可。「クリエイティブの配置設定」で大まかな制限のみ
- シングルのみ配信したい → **一度に表示する商品数を1に設定**
- ボタンは最大文字数まで入れたいが見切れない？ → **掲載バナーサイズや閲覧環境によっては見切れる**
- バナーに画像が表示されない → アドレスのアクセス許可を確認

### 8.2 デザイン編集制限

- Criteoが過去に作成したクリエイティブを編集したい → **管理画面では編集不可**。クリエイティブサービスレベルで依頼するか、新規作成で対応
- ロゴを変更したい → **管理画面で作成したクリエイティブのみ編集可能**。それ以外は新規作成
- ロゴサイズを変更したい → 該当クリエイティブの編集 > 高度なロゴオプションから変更可
  - **ロゴエリアクーポンを使用している場合は、クーポンもリサイズして再入稿が必要**。再入稿しないと元サイズのまま配信されはみ出す
- ロゴ画像の推奨サイズ → 一定以上推奨（具体値はマニュアル該当箇所 / 営業担当へ確認）。対応拡張子・ファイルサイズ上限あり
- ダイナミック広告のロゴ遷移先URLを変更したい → 管理画面では編集不可。**【ロゴURL変更依頼】を担当者へ依頼**。アカウントレベルの設定のため、広告セット単位での遷移先分岐は不可
- ダイナミック広告で文字だけのフォーマットにしたい → 管理画面では不可。クリエイティブサービスレベルで依頼

### 8.3 インベントリタイプの理解

- **ディスプレイ**: Criteoがレンダリング（商品カタログ × クリエイティブFMTを組み合わせる処理）を行い生成。ロゴ・画像・説明文・バッジ等を任意で設定可
- **ネイティブ**: 配信先ページのデザイン / トーン&マナーに合わせて溶け込む形で掲載。パブリッシャー側が一部素材を使ってレンダリングするため、**ロゴは出ない / 設定した表示ルールは適用されない**

## 9. 運用のコツ（示唆メモ）

- **エンジン選定はKPI起点で**: デフォルトの`OCO`系から開始し、CPA目的なら`ACO`、ROAS目的なら`ARO`に切替。エンジン変更を遅らせず、運用初期に判断軸を決めておく
- **タグは「3商品ID」を死守**: リストページでの3商品ID取得ができない構造だとリストタグの意味が消える。実装フェーズで構造化データの仕様を必ず確認
- **獲得拡張は「データ起点」で選ぶ**: CRMリストがあるなら **Lookalike** を最優先で検討（承認率・ROAS・LTV改善）。なければ **Similar**。楽天系コマースなら **RDAC**、店舗誘導があるなら **Location** を組み合わせる
- **クリエイティブはレイアウト制御で「自社の顔」を保つ**: 単一商材なら「モノレイアウト」、複数訴求なら「数行フィード」設計でブランド見え方をコントロール
- **クーポンは「1広告セット1クーポン」の制約に注意**: スケジュール上書きで前のクーポンが自動アーカイブされる挙動を、出稿管理シートに反映しておく
- **管理画面編集の即時反映に注意**: ライブラリ側のクリエイティブを編集すると紐づく全広告に反映される。配信中案件はコピー新規作成のほうが安全
- **配信開始は即時**: 「広告配信を開始」クリックで一時保存なく即配信になるため、広告セットのON / OFFと最終チェック手順を必ず運用フローに組み込む
