## 用途（どんな時に活用できるか）

## 1. 広告カスタマイザとは

> 広告のタイトルや説明文に、あらかじめ登録しておいたデータを自動で挿入することができる機能。データフィードとカスタマイザ用パラメータ（`{○○.●●}` ってやつ）で構成されているTDを用いる。

### できること
- 広告グループを分割しなくても広告文を動的に変えられる
- キャンペーン終了日までのカウントダウン（セールをよく実施するEC系などで多い）
- フィード上で広告のオンオフをスケジュール設定 → 自動で広告の切り替え

### データフィードの原理
> 原理としてはXLOOKUPみたいな感じ。データがたくさんある表（＝データフィード）からXLOOKUP（＝カスタマイザ用パラメータ）を使って条件に合うものを引っ張ってくる。

### 注意
- フィード上の情報が参照できなかった場合に備えて、**汎用広告**を入稿する必要がある（XLOOKUPで言うとエラー時の値を設定しておく）
- ただし、**デフォルトバリュー**を設定しておけば汎用広告は不要

## 2. 広告カスタマイザ vs キーワード挿入機能（インサーション）

### キーワード挿入機能の入稿
- `{keyword：デフォルトのテキスト}〜〜〜`
- 「デフォルトのテキスト」部分は、KWの文字数オーバー等で挿入後の文字数を超える場合に表示される
- 例：「{keyword：タブレット}を格安購入」
  - クエリ「防水タブレット」→「防水タブレットを格安購入」
  - クエリ「機能的な防水タブレット」→「タブレットを格安購入」（オーバーでデフォルト）
- キーワード挿入は **クエリではなく反応した"キーワード"** が挿入される

### カスタマイザがインサーションより主流の理由

| 理由 | 詳細 |
|---|---|
| 薬機法・ブランドNG回避 | インサーションはKW登録自体はOKでも、TDに入ると薬機法NGになる場合がある（例：「サプリ 痩せる」のTD化）。ブランド名の安売り訴求化も同様 |
| 不自然なTD回避 | 例：「スニーカー 白い」がKWだと「スニーカー 白い ならReebok」のような不自然な文になりうる |
| カスタマイズの余地 | カッコ等で「【安い】スニーカーなら…」のような工夫が可能。インサーション以上にCTRを上げられる |

### インサーションを使う場面
- どのKWで挿入されても不自然でなく、手っ取り早くTDを改善したいとき（例：「Reebok / リーボック」など指名CP）
- 確実に品質スコアを上げたいとき

### メリット・デメリット整理

| 項目 | カスタマイザ | インサーション |
|---|---|---|
| メリット | KWごとに適したTDを当てられる／薬機法・ブランドNG回避設定が可／フィード更新だけで反映 | フィード作成不要で着手が早い／登録KWが強制的にTDに組み込まれ、確実に品質スコアが上がる（部分一致の品質スコアは"そのKW"で検索された際の品質） |
| デメリット | フィード作成が必要／成果（CTR・推定CTR上昇による品質スコア）はTDの質次第 | KWによっては不自然/薬機法NG/ブランドNGなTDが生成されうる／改善余地が無い |

**示唆**: 実装するなら**カスタマイザ推奨**。工数はかかるが、インサーションのリスク（薬機法・ブランド毀損）が大きい。デフォルトバリュー設定で汎用広告も不要にできる。

## 3. 使用例

### ① 商品ごとの広告出し分け
- Google推奨構造（できるだけグループまとめ→データ蓄積で学習最適化）と組み合わせる
- 入稿例：`{=【フィード名】.見出し1}ー○○公式サイト`

### ② カウントダウン機能
セールやキャンペーンなど期間限定プロモーションで、自動で残り時間を表示し、期間終了後は配信停止する機能。**汎用広告は不要**。

#### A. フィード作成なし（1回限りのセール向け）
```
{=countdown("yyyy/mm/dd hh:mm:ss","ja",開始日数)}
```

#### B. フィード利用（複数セール繰り返し向け）
- 終了日時を含めたフィードを作成
- `{=countdown(フィード名.終了日時,"表示言語",開始日)}`
- フィードの「終了日時」欄を更新するだけで繰り返し実施可能

### ③ スケジュール機能
- フィード上で開始日 or 終了日を指定 → 手動オンオフ不要で広告切替
- **汎用広告が必要**
- 拡張：クライアントの商品DBと連携できれば「在庫連動」も実現可能（テックチームに相談）

## 4. フィード入稿の手順とTips

### フィード作成
- Excel形式
- カラム名の指定：
  - ① トリガーとするターゲットを指定する項目（KWごとに出し分けたい場合など）
  - ② 必要に応じた追加項目（カウントダウンなら「終了日」）
  - ③ それ以外は任意のカラム名でOK

### フィードアップロード

#### Google
- 管理画面（Excel）：ツールと設定 → 設定 → ビジネスデータ → 青「＋」 → 「テキスト広告のカスタマイザデータ」
- テンプレのダウンロードも可能

#### Yahoo!
- エディタ（CSV）：キャンペーンエディタ → 共有ライブラリ → データ自動挿入リスト

### フィードの更新：置換 vs 更新（**更新が推奨**）

| 種類 | 用途 | 審査 |
|---|---|---|
| 置換 | フィードの中身すべて差し替え | 全行に審査が生じる |
| 更新（推奨） | 一部の行のみ更新 | 更新箇所のみ審査 |

- 更新時は**アクション列とID列**を含める必要がある
- アクション列：編集=`Set` / 追加=`Add` / 削除=`Removed`
- Yahoo!は**置換しか選べない**ので注意
- プレビューは1000件までしか表示されない

### 入稿順序の鉄則
> フィードを先に管理画面にアップロードしないと広告入稿できない（フィードアップロード → 広告入稿の順）。

### よくあるトラブルQA

| Q | A |
|---|---|
| 広告がアップできない | 先にフィードをアップロードしないといけない |
| 文字数オーバーで審査落ち | フィードで指定したテキストいずれかを入れて文字数オーバーすると審査落ち。どの組み合わせでも超えないようフィード上で設定 |
| 1広告に複数フィード参照させたい | 不可 |
| カスタマイザで変更できる場所 | タイトル・説明文・パス（広告表示OPは不可） |

### デフォルト値の補足
- データフィードにアイテムが無くても広告が常に表示される
- **カウントダウン使用時はデフォルト値使用不可**

## 5. 応用：地域／デバイス／リスト出し分け

### 地域ごとの出し分け
- ユーザーの現在地や関心地域に応じて出し分け可
- 例：`{=地域カスタマイザ.地域名}の結婚相談所なら○○`
- ターゲット地域の制限：「興味関心のある地域＋ユーザーの所在地」または「ユーザーの所在地のみ」を選択可。未設定でも基本は前者優先。

### IF Function（デバイス・ユーザーリスト）
- IF関数で条件を満たした場合に特定メッセージを挿入、それ以外はデフォルトを挿入
- **カスタマイザと異なりフィードを使用しない**
- Yahoo!とGoogleの違い：**Yahoo!はユーザーリストが設定できない**
- 用途例：カートを放棄したユーザーに購入完了を促す特典訴求

## 6. RSAでのカスタマイザ入稿（ETAと異なる）

### 概要
> RSAはタイトル・説明文みたいなカラムを管理画面上で作成しないといけない。

### 重要ポイント
- タイトルと説明文でカスタマイザを使う場合は、**タイトルのフィードと説明文のフィードの2つ**を作る（ETAのように1つに集約できない）
- フィードはExcelファイル
- フィードカラムの「Customizer：」以降を管理画面で設定したカラム名と揃える
- RSAはマッチタイプ入力せず**完全一致なら `{}` のような記号をKWに入れる必要がある**
- 計算が時間かかりそうなら**計算方法を手動にする**
- アップロード後、属性で作成したタイトル部分の「値の数」が更新されているか確認
- デフォルト文はETAのカスタマイザで指定したデフォルトテキストと同じものを使う
- RSAはとりあえず一本バルクで入れてみる（入れられなかったら手動）
  - 手動の場合はカスタマイザ部分を空欄で入稿し、管理画面で「{」と入力 → カスタマイザ選択

### 入稿手順

| ステップ | 内容 |
|---|---|
| ① 広告属性を定義 | 管理画面：ツールと設定 → 設定 → ビジネスデータ → データフィード → 広告カスタマイザ属性。「属性」は任意テキストOK。「データの種類」は「テキスト・数値・価格・割合」から選択 |
| ② 適切な粒度で値を設定 | ①の属性に、実際にカスタマイザを使用する広告で表示するテキスト（値）を入力。必要に応じて各コンポーネント（アカウント／CP／GRP／KW）画面の表示項目から「広告カスタマイザ属性」を選択し適用 |
| ③ 広告入稿 | カスタマイザ用パラメータを使用してRSAを入稿。属性・値を設定する前にカスタマイザ広告は入稿できない。アセットで `{` を入力するとプルダウンが出て「広告カスタマイザ」が選べる |

> RSAでは、ETAで使用するデータフィードを使わず、代わりに属性・値を設定することで配信が可能。

## 7. 注意事項チェック

### IMPが出ない場合
- 汎用広告があることを確認
- デフォルト値があることを確認

### 審査
- フィードにも審査が入る。しかも**不承認アラートのメールが来ない**
- 1行審査落ちしてもそれ以外のフィードは配信される

### 掲載確認
- Googleはプレビュー機能あり → 必ず確認
- Yahoo!はプレビュー機能なし → 配信後に確認する運用

### フィード上限
- Google：500万行 / Yahoo!：100万行

### D&Eとの併用
- **ターゲットキャンペーン／ターゲット広告グループを使った広告カスタマイザは併用不可**

### テスト時の注意
- DefaultValueを含まないフィードを使った広告カスタマイザ広告は、**通常広告と併用で同広告グループ配下に入稿しなければ配信されない**

## まとめ（次アクション視点）

- カスタマイザ実装は**インサーションよりリスク低**（薬機法・ブランド毀損を防げる）。デフォルトバリュー設定で汎用広告も省ける
- カウントダウン／スケジュール／在庫連動を組み合わせると、セール案件のオンオフ運用工数を大幅圧縮できる
- RSAでは「属性定義 → 値設定 → 入稿」の手順がETAと異なる。タイトルと説明文で**フィードが2つ必要**
- フィード更新は **「更新（Set/Add/Removed）」が推奨**。Yahoo!は置換しか選べないので、毎回全行審査になる点に注意
