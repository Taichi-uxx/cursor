# 部分一致の活用

## 出典
- ファイル: `知見・ナレッジ移管/リスティング/部分一致の活用.docx`
- 内容: REHATCH社内（または前社）勉強会資料。「自動入札時代の部分一致の使い分け方」を整理した運用ガイド
- 投稿日: 不明（推定: Search Quatro時代＝2020〜2022年頃）

## どんな時に活用できるか
- 検索広告のマッチタイプ設計（完全一致/フレーズ/部分一致の使い分け）を整理したいとき
- クライアントに「なぜ部分一致を入れるべきか」を説得材料込みで説明したいとき
- アカウント構造刷新（HagakureからGORIN/MUGENへ）の際に、クエリコンフリクト対策を設計したいとき
- 部分一致追加の検証設計（D&Eを使うか、前後比較で済ますか）を判断したいとき
- クエリ除外メンテのフレームワーク（傾向把握→構造対処→メンテ）を設計したいとき

## 結論サマリ
**自動入札の進化により、「部分一致は使わない理由がない」状態になった。**「完全一致でしか買ってはいけないもの」以外は部分一致で買ってよい。ただしクエリコンフリクト対策＝構造の整備とメンテが前提。

## 1. 部分一致活用の意義（なぜ今、部分一致なのか）

### 自動入札が世界を変えた
- 従来：登録KW単位で入札制御 → クエリ別の単価設定のためにKWを完全一致化していた
- 現在：自動入札により**クエリごと**の入札制御が可能に。成果の良いクエリに配信が寄り、悪いクエリは抑制
- 結果：クエリ単位の単価設定のためにKWを完全一致化する意義は消えた

### 部分一致の新しい役割
- **「思いもよらぬクエリの発掘」** = 想定できないクエリをどう拾うか、にシフト
- Google社データ：今年検索されて来年も検索されるクエリは全体の2割。クエリを想定してKWを購入するのは不可能

### 過去の「できなかったこと」と現在の解決策

| 過去の課題 | 現在の解決策 |
|---|---|
| クエリ別の入札ができない | 自動入札で制御可能 |
| クエリ別にTDを制御できない | グループ構造とクエリの制御で管理 |
| クエリ別にLPを制御できない | グループ構造とクエリの制御で管理 |
| クエリ別レポートの切り分け | これだけは変わらず（手間は残る） |

> 「自動入札を導入すること」と「グループ構造を整えること」で部分一致のデメリットは解消され、未知のクエリを発掘・成果最大化につなげることができる

### マッチタイプアップデートの影響
- **絞り込み部分一致廃止**により、片絞り（例: `+保険 損害`）のリーチが減少 → 未入稿のクエリを拾いにくくなった
- 実際にIMPが減少した案件もあり → **ますます部分一致追加の必要性が高まっている**

---

## 2. クエリコンフリクト（唯一の弊害と対処法）

### コンフリクトとは
- 1つのクエリは1つのグループからヒットする構造が基本
- 異なるグループから同じクエリに広告される状態 = クエリコンフリクト
- 結果：不適切なTD/LPが露出する可能性

### 重要原則
- 広告グループ = 「見せたいTD」と「連れていきたいLP」を制御するコンポーネント
- **同グループ内のKW重複は問題なし**（TD・LPが同じなので）
- 異なるグループ間のコンフリクトのみが問題

---

## 3. KWの買い方｜判断フレーム

### 完全一致で買うべきもの
- **絶対掲載したいKW、主要なKW**（拡張の予測ができないので確実に押さえる）
- 指名系、ブランド名、その言い換え（量も少なく手間も少ない）
- BIG系など、レポート分割の必要性が明らかなKW
- 参考：英語KWではスペース有無で拡張しない可能性あり（`recruitagent`→`recruit agent`に拡張しない可能性）。半角/全角は気にしなくてよい

### 完全一致でしか買うべきでないもの
- **拡張範囲の制御が難しいKW、語数の短い単ワード**
- 例：「ホテル」単ワード部分一致は、「東京 ホテル」「大阪 ホテル」「旅館」に拡張 → コンフリクト制御不能
- LP分割が必要なBIGワードが、BIGワード系グループからコンフリクトすると制御不能

### 部分一致で買うべきもの
- **完全一致でしか買ってはいけないもの以外、すべて**
- 部分一致で買ってはいけない理由がないなら、買ってしまえばいい
- 例：「キャッシュレス決済」（モチベの広がりが少ない）、「車査定」（単ワード依存業態でTD/LPを出し分ける必要が少ない）

### 絞り込むべきか（フレーズ一致にするか）の判断
- そのKWがターゲット特定に**必須**ならフレーズ一致（「このKWが含まれていないと絶対に嫌」な時だけ絞り込む）
- 多数の言い換えがあるKWはむやみに絞り込まない（機会損失につながる）
- 例：「土日休み 転職」を絞り込むと成果下がる（「土日祝」「完全週休二日制」「休みが多い職場」など事前想定難しいクエリが多いため）
- 例外：指名グループから指名KWを含まないクエリを出さないための制御は絞り込む

## 4. 完全一致追加の意味は薄れている

### なぜ過去は完全一致追加していたか（すべて「手動調整」のため）
- 入札単価を制御したい → 上限CPCを個別に設定
- 絶対掲載したい → 完全一致で担保
- レポートを切り分けたい → 完全一致でモニタリングしやすく
- 追加済フラグでフィルタしたい → 完全一致で使いやすく

### 自動入札後、すべて代替可能に
- 入札単価制御 → 自動入札にすれば不要
- 絶対掲載 → 部分一致でも同じ
- レポート切り分け → 部分一致追加も同時にすればOK
- フィルタ → クエリレポートはマッチタイプでフィルタ可能

### これからのクエリ追加方針
- **「部分一致追加」と「完全一致追加」を併用**。完全一致のみで追加する意義はない
- CVを多く獲得する重要なクエリが発掘されたら部分一致追加
- モニタリング重要度が高い場合のみ、同時に完全一致も追加
- 「IMP1, CV1」みたいな細かいKWはわざわざ追加不要
- 完全一致比率は、**クエリマッチタイプ比率**でモニタリング可（部分一致KWでも完全一致するクエリを拾えるため）

## 5. 完全一致のメリット整理（補足）

### 完全一致のメリット
- **コンフリクト対策**：クエリと同一の完全一致KWが最優先で選定される
- **カスタマイザが使用可能**：確実にTDを出し分けたいクエリに適切なTD掲出
- **モニタリングが行いやすい**：Tableauでの媒体横断モニタリング

### アカウント内類似KWの選定優先度
1. クエリと同一の完全一致KW
2. スペル違いのクエリと同一の完全一致KW
3. 広告ランクが最も高いKW

→ 完全一致KWであれば、ほかのグループからはほとんど出ない（例外：広告ランクが高くかつクリック単価が低い品質の高いKWに上書きされる可能性）

## 6. 部分一致追加の検証方法

### A. 厳密に検証したい場合 → D&E（下書きとテスト）
- 部分一致なしのオリジナルキャンペーンと、部分一致追加のテストキャンペーンを作成
- 同期間でテストできるため時期的要因を排除
- テストキャンペーンのCV増加分 = 部分一致の効果
- 注意：Cost差が大きいと比較困難、初動の学習期間は除外

### B. 簡単に振り返る場合 → 前後比較
- 部分一致は成果悪化事例が少ない → クライアント合意取れれば継続前提でOK
- ただし初動のクエリモニタリングは必須
- **合算CVで評価**（前後比で当該CPの広告種別問わず合算値）
- コントロールを別途用意（Yahoo!の同一KW、似たカテゴリの実施対象外など）
- 部分一致KWには既存クエリの成果も含まれるため、**単純なマッチタイプ比較はNG**

## 7. メンテナンス（クエリ除外の考え方）

### クエリ除外の本質
- 成果が悪いから ≠ 除外する理由
- **そのグループから掲載すべきではないから除外** = コンフリクト対策
- ユーザーの気持ちに向き合うこと

### 手順：「傾向をつかみ」→「構造対処して」→「メンテ」
1. クエリをIMP上位・Cost上位から全部見る（200行くらい見れば傾向見える）
2. 傾向を要素分解し、フレーズ一致除外やリストで対策
3. それ以外の出すべきでないものは完全一致除外
4. Google管理画面からの追加推奨（「本日IMPあり」「除外済」フィルタが便利）

### コンフリクト率の定期モニタリング
- 個別除外より**構造的対処**が有効
- クエリベースでユニーク/重複を分割集計し、登録KWのカテゴリベースで傾向集計 → どんな拡張が原因かを特定
- 例：単ワードとエリア掛け合わせのコンフリクトは多業種で発生 → 単ワード/都道府県名を最初から相互除外

## 8. 改善事例（hagakureの弊害を受けた求人サイト）

### 構造刷新フェーズ
- グループ数23 → 600に分割（「不動産 求人」「秘書 転職」など全く違うモチベが同グループだった）
- 適切なユーザーに適切なTD・LPを当てられるように
- ほぼ全KWが絞り込み部分一致購入 → 無意味な絞り込みを止め、部分一致購入KWを大幅拡大
- IMP0完全一致など不要なものは断捨離
- Googleトレンド確認でほぼ平坦 → 施策有効性が実証

### さらなる部分一致追加フェーズ
- 一般単ワード（「転職 スカウト」「就活エージェント」「職務履歴書」）に部分一致追加 → 想定外軸の発掘
- 初動問題（職務履歴書が新卒就活系に拡張）はあったが、メンテで成果拡大
- 職種単ワード（「秘書」「一般事務」）も部分一致追加 → トータルで成果改善

## 太一の示唆
- 「自動入札時代は部分一致が原則」をクライアント説得材料の土台にできる
- 構造ができていない状態で部分一致を入れるとコンフリクトで死ぬ → **まずグループ構造の整備が前提**
- 検証は「厳密にやるならD&E、走りながら評価するなら前後比較＋コントロール」の2段階で提案可
- 求人サイトの事例（23→600グループ）は、構造刷新の必要性をクライアントに見せるベンチマークになる
