## 検索広告の基本構造

### 検索広告のリッチ性 — ページ最上部の支配力

> ユーザーが検索して最初に目にするのは検索広告。検索結果画面の大部分を、ページ最上部に掲載された広告が占めている。

| デバイス | ページ最上部の検索広告占有率 |
|---|---|
| **PC** | **51%** |
| **スマートフォン** | **91%** |

※検索連動型ブランディング広告が非表示かつ広告表示オプションがすべて掲載された場合（PC：拡張クイックリンク掲載）の検索結果ファーストビューでの割合

### 検索広告のクリック分布

ページ上部に表示される検索広告がクリックの大半を占める。**特に注力したいキーワードでは上部掲載を意識した運用が重要**。

| 掲載位置 | PC | スマートフォン |
|---|---|---|
| ページ最上部1本目 | 約55% | 約60% |
| 2本目 | 約22% | 約23% |
| 3本目 | 約13% | 約14% |

```
オークションランクの計算方法
オークションランク = 入札価格 × 広告の品質
```

### 機能併用の重要性

検索広告は各機能を**併用**することでパフォーマンスを最大化できる：

```
広告表示オプション × 自動入札 × 部分一致 × レスポンシブ検索広告
       ↓                                                       
視認領域を広げて   ニーズに対して掲載順位・   変化するマーケットの   ユーザーのニーズに
広告掲載時の効果を   タイミングを入札価格で   検索を部分一致で       最適な広告を配信
最大化する         最適化させる             捉える                  
```

#### 機能の併用による効果向上の事例

- 完全一致以外のマッチタイプ（部分一致・フレーズ一致）・自動入札・広告表示オプション・レスポンシブ検索広告の併用により：
  - **CV数 25%増加**
  - **CV単価 24%低下**
  - **検索クエリー数（CVに至った部分一致・フレーズ一致）40%増加**
- 期間: 2021/5〜6 通信業種の事例

## Step1 基盤構築 (P.9-27)

> 現在の検索マーケットにおいて、最大のパフォーマンスを発揮するためには**アカウントの構造と基礎設定**が非常に重要。インプレッション分散を回避するアカウント構造で、基礎設定を行って視認領域を最大化した配信を行うことが基盤構築のポイント。

### 概要図

```
検索マーケット ◀── アカウントの構造 + 基礎設定
                  ↑                ↓
            インプレッション分散を回避する
                                    視認領域を最大化した配信
```

### 重要指標と確認ポイント

| 指標 | 目的 | アクションイメージ |
|---|---|---|
| **エンティティ数**（CP数・ADG数・広告数） | インプレッション分散を防ぐために、不要なCP/ADG分けをしていないかを確認 | 業界平均より多い場合、不要な分割を行っていないか確認し、統合を検討 |
| **ユニーククエリー率** | 複数のADGで同一の検索クエリーでIMPが分散していないかを確認（コンフリクト把握） | 数値が基準より低い場合、同じ軸のKWを同一ADGにまとめる・対象外KWを活用 |
| **3種広告表示オプションご利用金額率** | 広告配信時の効果を最大化できる状態か確認 | 未導入のCPで広告表示オプションの導入を進める |
| **インプレッションシェア損失率（予算）** | CPの1日予算不足によって広告が表示されなかった割合を可視化 | 数値が発生している場合、CP日額予算を上げる or 自動入札の目標調整など、0%を目指す |

### 理想的なアカウント構造 (P.12-17)

> アカウントの構造をシンプルにすることで、機械学習による最適化がかかりやすい状態を創出。

3つの基本原則：
- **Simplification（アカウントをシンプルに）**: 運用におけるPDCAと機械学習のサイクルが最低限の工数で最適化されている状態
- **Account Structure（アカウントの構築）**: コンフリクトが生じないアカウントの構成、広告レベルで統計的有意性が確保され広告の品質が正しく算出されている
- **Automated bidding（自動入札機能）**: 投資対効果のある広告リクエストに対して入札が自動化されている

#### 階層ごとの設定内容

| 階層 | 設定可能なもの |
|---|---|
| **アカウント** | 広告主情報管理／広告費用入金／請求（月額） |
| **キャンペーン** | 入札戦略（自動or手動）／1日の予算／配信スケジュール／ターゲティング（デバイス・地域・曜日時間・ターゲットリスト・入札調整率）／広告表示する検索画面／対象外KW・対象外KWリスト／CPタイプ |
| **広告グループ** | 入札価格／自動入札の目標値／デバイス入札価格調整率／効果の高い広告の優先表示／対象外KW |

#### なぜシンプルにすべきか

```
オークションランク = 入札価格 × 広告の品質
```

オークションランクを構成する「広告の品質」を**より適切に算出するために、アカウントをシンプルにすることが重要**。

#### 十分な実績の重要性 (P.15)

広告の品質を正しく算出し改善を行いやすくするには、**広告の実績を十分に蓄積して統計的に評価できる状態**にすることが重要。

- 実績不十分: 統計的有意差が出ず、広告の良し悪しがはっきりしない
- 実績十分: 統計的有意差が出るため、広告の良し悪しがはっきりしシステムが機能する

### アカウント内のコンフリクト回避 (P.16-17)

同一の検索クエリーに複数の登録キーワードが反応する状態 → IMP分散・広告品質が正しく算出されない懸念。

**対策**:
1. **同じ訴求軸のキーワードを1つのADGにまとめる**
2. **対象外キーワードを活用する**

例: 「新着 求人 営業」というクエリに、ADG-A（フレーズ一致「新着 求人」）・ADG-B（部分一致「営業 募集」）・ADG-C（部分一致「新着 営業 求人」）が反応してIMP分散 → ADG-Bに統合し、ADG-A側に「営業」を対象外KW登録することで、ひとつのKWに集約。

### ユニーククエリー率 (P.18)

検索クエリーに対して、複数のADGの登録KWが反応してIMP分散が発生しているかの確認指標。**同一KWが登録されていなくても、IMP分散が発生している可能性がある**。

例: ADG-A「営業 人材」/ADG-B「営業職」/ADG-C「求人」/ADG-D「営業 採用」が、すべて「求人 営業」クエリに反応する場合 → ユニーククエリー率0%。

### 広告表示オプションの3種 (P.19-20)

設定可能な広告表示オプションを全て活用することで、広告に加えて詳細情報掲載ができ、広告占有面積が大幅に広がる。

#### 3種類
1. **クイックリンクオプション** — PCでは最大6本表示可能、最もリッチな「拡張クイックリンク」では4本+説明文2本ずつ表示
2. **テキスト補足オプション** — タイトル・説明文に補足テキストを追加
3. **カテゴリ補足オプション** — カテゴリ補足テキストを追加

#### 効果

> 3種網羅的に設定することで、さらなる広告効果アップが見込める

| デバイス | クリック率の改善 |
|---|---|
| PC | **67%UP** |
| スマートフォン | **27%UP** |

期間: 2022/9/5〜10/4、Yahoo!JAPAN自社調査、広告表示オプション3種すべてでIMP発生CP vs 非発生CPの比較

### インプレッションシェア損失率（予算）の運用 (P.21)

CPの1日予算不足で広告表示されなかった割合。発生していたら：
- CP日予算引き上げ
- 自動入札の目標値調整
- 0%を目指す

### コンバージョン測定補完 (P.22-26)

プライバシー保護対応として、以下の補完機能を導入する：
- **コンバージョン詳細マッチング**: ユーザー同意情報を活用
- **コンバージョンAPI**: サーバー側からCVデータ送信
- **推定コンバージョン**: 計測できないユーザーのCVを推定（今後リリース）

これらにより、CVデータ補完による類似拡張範囲拡大、1stPartyデータを用いた高精度の推定が可能。

## Step2 最適入札

> 自動入札の利用によって、Yahoo! JAPANの膨大なデータをもとに様々なシグナルを参照しながら、自動かつリアルタイムで効果の高い入札価格になるよう最適化。

### 重要KPI
- **自動入札ご利用金額率**
- **入札鮮度**

### 自動入札タイプ（YSA）

| タイプ | 目的 | 推奨 |
|---|---|---|
| クリック数最大化 | 流入数増加 | なし |
| CV数最大化 | 予算内でCV数最大化 | なし |
| **コンバージョン単価の目標値（tCPA）** | 目標CPAでCVを最大限獲得 | **30日以内CPN単位20件CV** |
| ページ最上部掲載 | 検索結果ページ最上部に掲載 | なし |
| **広告費用対効果の目標値（t-ROAS）** | 目標CPNでの売上最大化 | **30日以内CPN単位50件CV** |

詳細は事例編（`2111-2302_Yahoo_カンファレンス事例集_YSA編.md`）の Part 2を参照。

## Step3 効果効率

> パフォーマンス向上のために配信する検索クエリーの最適化とターゲティング機能を活用。より効率的な配信のために、リーチ拡大実施後にも配信する検索クエリーの最適化を行う。

### 重要KPI
- **サイトリターゲティングご利用金額率**
- **対象外キーワード登録率**

### 主要な打ち手

1. **サイトリターゲティング（YSA-STG）**: 自社サイト訪問者に対する検索広告配信。指名/競合/一般での効率重視
2. **対象外キーワードの精査**: 形態素解析を活用したノイズ排除（事例編Part 1の③を参照）
3. **サーチターゲティング**: YDA側のKW指定機能と連携

## Step4 拡大成長

> 変化を続けるインターネット上でのユーザー行動を捉えながら、将来の顧客となりうるユーザーへのリーチを拡げることで、継続的な顧客獲得とビジネス発展に寄与。

### 重要KPI
- **マッチタイプ完全一致以外のご利用金額率**
- **アクティブキーワード数**
- **キーワード最終更新日**
- **DASご利用金額率**

### 主要な打ち手

1. **部分一致・フレーズ一致の活用**: 完全一致だけでなくマッチタイプを拡張し、新規クエリ捕捉
2. **ポテンシャルKW追加**: 自社未入稿のクエリを機械学習スコアで抽出（事例編Part 1の①参照）
3. **競合差分クエリ追加**: 競合の収益クエリを取り込む（事例編Part 1の②参照）
4. **DAS（動的検索連動型広告）の活用**: サイトクロールから自動的に広告生成

## Step5 最適表現

> ユーザーが求める情報に合致するクリエイティブを配信し、ユーザーに期待するアクションの確率を高める。広告の品質は配信によるパフォーマンスの良し悪しを分ける重要な要素。

### 重要KPI
- **RASご利用金額率**
- **タイトルのクエリー含有率**
- **拡張クイックリンクご利用金額率**
- **広告の最終更新日**
- **キーワードの自動挿入・アドカスタマイザーご利用金額率**

### 主要な打ち手

1. **RAS（レスポンシブ検索広告）の活用**: タイトル・説明文を複数登録して機械学習で最適組み合わせ配信
2. **タイトルへのクエリー含有**: 検索クエリーをタイトルに含めることでCTR向上
3. **拡張クイックリンク**: PCの最上部限定、最大6本表示の最もリッチな表示
4. **キーワード自動挿入・アドカスタマイザー**: 動的にタイトル/説明文を変更

## So What — 戦略家視点での示唆

### 1. 「上部掲載＝勝ち」の事実をクライアントに伝える

- スマホで91%、PCで51%がページ最上部に集中
- → 「3本目以下に下がるだけで露出が10分の1以下になる」と説明できる
- 注力KWでは入札・品質を引き上げて上部掲載を維持する戦略が、媒体仕様上の絶対解

### 2. アカウント診断の入口は「エンティティ数 × ユニーククエリー率」

- 業種平均との比較でアカウント構造の妥当性が一発で出る
- ユニーククエリー率が低い = コンフリクト多発 = 機械学習が機能しにくい
- → 新規案件の初期診断ルーチンとして、この2KPIから入る

### 3. 「機能の組み合わせ」が定量効果として示せる

- 通信業種事例: CV+25% / CPA-24% / クエリ+40%
- → 単機能改善ではなく、「マッチタイプ×自動入札×表示オプション×RAS」のセット提案として打ち出す
- 67% CTR UP（PC）、27% UP（SP）は広告表示オプション3種網羅の根拠データ

### 4. 「アカウントをシンプルに」と「実績の十分性」は表裏一体

- 細分化すると統計的有意性が出ない → 機能しない → 細分化したまま放置 → 悪循環
- → クライアントが「リストごとにレポート見たい」と言ってきても、構造を分けず**レポート機能で対応**

### 5. プライバシー保護対応の三段構え（CV補完）も検索広告にとって必須

- CV詳細マッチング × CVAPI × 推定CV
- これらは類似拡張範囲の維持に直結する
- → 「プライバシー保護対応していない案件は将来的に拡張余地が縮小する」というロジックで提案
