# 入札調整での注意点 — 目標CPA × デバイス調整比の落とし穴

## 出典

- 記録者: 田村太一（自身の運用気づき）
- 記録日: 2026年9月
- 対象: Google Ads（ポートフォリオ入札戦略のキャプチャで確認したが、**通常の入札戦略でも同様に発生**）
- 参照：https://numerous-violet-s1bbvirc.edgeone.dev/
- 参照：https://smart-violet-dly4gjv4.edgeone.dev/

## 用途

- 目標CPAを設定しているのに実績CPAが目標を大きく超えているとき、原因の切り分けとして最初にチェックする
- 「媒体側は成果OKとして挙動しているのに、なぜ目標に近づかない？」の答え合わせに使う
- 入札戦略の目標CPAを再設定するときのチェック項目として使う
- 新規案件の初期設計時、デバイス調整比を入れる／入れないの判断材料として使う

## 事象（起きていたこと）

- 実績CPA：3.8万円（高い状態）
- 目標CPAの平均：4.0万円（実績よりも高くなっていた）
- 設定していた目標CPA：3万円
- → **設定 3万 なのに、媒体側では「目標CPA 4万で運用中」の認識になっていた**

この状況だったため、媒体側では**「この成果でOKとしている」**という認識で挙動していた。だから3万に近づけようとする学習が働かなかった。

## 原因

**デバイス調整比をかけていた（デバイス +30%）ため。**

イメージ:

```
設定した目標CPA  3万円
       ×
デバイス調整比  +30%
       =
媒体側の実質目標  約4万円で運用
```

つまり、UIで入力した「目標CPA 3万」は媒体内部で調整比によって嵩上げされ、**実質 4万** で最適化が回っていた。実績3.8万は「実質目標4万」から見れば範囲内 → 媒体は「達成できてる」判断で動く。

## 今後の運用ルール

前提として：**目標CPAと実績CPAに差分が生まれすぎないように調整する** は継続する。

その上で、**適切な目標CPA（「このCPAでとって欲しい」の数値）を設定するときは、以下を必ず確認する**：

- [ ] デバイス調整比を設定しているか？
- [ ] 設定しているなら、どれくらいの比率か？（+30%？ -20%？）
- [ ] その調整比を織り込んだ上で、UIに入れる目標CPA数値を逆算する

例：本当に狙いたいCPAが3万で、デバイス +30% がかかっているなら、
→ UI入力する目標CPAは `3万 ÷ 1.3 ≒ 2.3万` に設定する（実質3万に着地させる）

## 学び

- 「目標CPA = UIで入力した数値」ではない。**媒体内部では調整比が掛け算されて実質目標が決まる**
- 実績CPAが目標に寄らない案件を見たら、まず**入札戦略まわりの調整比（デバイス／地域／時間／オーディエンス）**が入っていないか確認する
- 引き継ぎ案件では、前任者がどんな調整比を入れているかを最初にチェックする（引き継ぎ時のチェックリスト項目に追加すべき）
