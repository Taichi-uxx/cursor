## Part 1：iOS14対策とリタゲ補完／代替（2111ベース）

### iOS14リリースの影響範囲

#### ITP/iOSアップデートによるトラッキング規制年表

| 時期 | 規制内容 |
|---|---|
| 2017/9 | **ITP1.0**: Safariの3rd party cookieに制限（24時間以上の情報参照不可） |
| 2018/9 | **ITP2.0**: 3rd party cookieの制限強化、1st party cookieも制限 |
| 2019/9 | **ITP2.3**: 1st party cookieの制限さらに強化、Local Storageにも制限 |
| 2020/9 | **iOS14**: Safari 1st/3rd Cookie完全ブロック、IDFA許諾制、アプリ内WebViewも適用 |

> **2020年9月の規制強化から、配信/計測の影響が大きくなってくると懸念される**

#### iOS14リリース以降のリタゲ可否マトリクス

| ユーザー流入元 | 広告配信面 | IDFA利用 | リタゲ可否 |

### iOS14対策ターゲティングのファネル整理

#### 顕在層：リターゲティング補完

| ターゲ名 | 概要 |
|---|---|
| **自社サイト流出ターゲ** | Yahoo! JAPANから自社サイトに流出（遷移）したユーザーに広告配信。ただしプレミアム広告、YDA、YSAクリックユーザーは含まれない（Yahoo!JAPANページ、Yahoo!検索結果からの流入ユーザーのみ） |

#### 潜在・検討層：リターゲティング代替

| ターゲ名 | 概要 |
|---|---|

### 推奨運用方法

1. **実績が分散しないよう、RTG除外を推奨** → リタゲ除外の組み合わせリストの作成
2. **複数リスト紐付けによりADG単位のCV数を担保** → 1ADGへ複数のリストを紐付け
3. **配信結果に応じて各TGの運用レバーを最適化** → 配信結果比較対象と、期間に注意

#### ※複数リスト紐付けの注意事項

同一ADGに紐付けたリスト種別（リタゲリスト・サーチターゲリスト・プレースメントリストの3種）が異なる場合は **AND配信** になる：
- リスト種別同じ場合（OR）: AもしくはBどちらかの条件を満たしたユーザーへリーチ
- リスト種別異なる場合（AND）: A、Bのどちらの条件も満たしたユーザーへリーチ
- 例: リターゲティングリストとサーチターゲティングリストを紐付けた場合 → AND配信

## Part 2：YDA自動入札（CVMax）の運用ポイントと事例

### CVMax（CV数の最大化）とは

```
指定日予算内でコンバージョンを最大化する入札戦略（自動入札）
```

#### 特徴
1. **指定予算内でCVを最大化**：設定した予算を最大限消化し、CV数最大化を図る
2. **低獲得単価が見込めるものから配信される**：獲得見込みのあるリクエストのうち、より低い獲得単価が見込めるものに配信

#### 適合条件
キャンペーンにおいて、**過去7日間で最低20CV程度、過去7日間で推奨50CV以上**を満たすことが推奨。

### CVMaxのメリット

1. **運用工数削減**：日予算設定するだけ
2. **インプレッション損失率の改善**：IMPシェア損失率（予算）が大きい場合、自動入札○○の最大化導入で獲得単価の改善・獲得数の拡大が期待できる

### 仕様・実装の注意点

#### ① 媒体推奨CV数
過去7日間のキャンペーン単位の媒体推奨CVは50件以上。最低でも20件程度のCVが必要。20件程度確保されていない場合に学習が発生。1キャンペーンあたり**20〜50件/過去7日間**のCV数が確保されていることが推奨。

#### ② 挙動
基本的に**学習期間中はクリック数を最大化する挙動**。CVが20件/過去7日間確保されていない場合にも学習に入り、クリック数を最大化する挙動になる。学習終了後にCV数を最大化する挙動になる。

#### ③ 検証方法
スプリットテスト（GoogleのD&E類似機能）で検証できる。媒体社への依頼必要：
- メールテンプレ件名: 【直販商流】【YDA新自動入札スプリット配信実施依頼】アカウント名/株式会社アイレップ
- 「スプリット」で検索すると当該件名へ遷移可能

### CVMaxフローチャート（仮説段階）

```
予算重視 → 自動入札: CV数最大化を設定
  ↑ MaxCVでは設定日予算守ろうとする挙動が見られるため、
  予算消化重視のKPI案件でMaxCVとの親和性が高いのではないか？

成果重視 → 
  ・トレンド変化が大きくない案件 → tCPAが優勢
  ・IMP損失率が大きい → 自動入札: CV数最大化（IMP損失改善で成果改善見込める）
  ・tCPA推奨CV数を満たしていない → MaxCV導入で成果改善見込める
```

### CVMax事例集

#### 事例①：美容業界（×評価）

**背景**: コスト大きいキャンペーンでIMP損失率高め。予算減額に伴い1日あたり利用金額減少。tCPA入札で配信抑制していたものの、IMP損失が多く発生。

**施策**: YDAキャンペーンの入札戦略をCVs最大化に変更

**結果**:
- テスト・コントロールともに前期間より後期間の成果悪化、コントロールよりテストの方が悪化幅大 → 導入による成果改善は判断できず（×）
- IMP損失率は後期間で高く推移
- 後期間: 媒体CVR 6.66%（前: 13.67%）、CPA ¥1,160（前: ¥405）、IMP損失率 23.70%（前: 4.77%）

**※注**: CVsについて、YDAはマイクロCVsも計測しているため、ボリュームに差はあり。

#### 事例②：人材業界（○評価）

**背景**: 自動入札推奨要件を満たした状態でtCPAを実施したが、うまくワークしなかった

**施策**:
- 自動入札導入推奨要件を満たした状態でtCPAの導入を実施
- tCPA導入がうまくワークしなかったため、MaxCVの導入推奨要件は満たしていなかったが、**MaxCVの導入を実施**

**結果**:
- ①eCPC → tCPA: CTR・CVR低下、獲得効率悪化（導入直前1週間に獲得不良発生していたことが影響）
- ②tCPA → MaxCV: CTRは同程度のまま推移、**CVRが4倍程度まで改善**。獲得件数増・CPA改善
- 3/17にMaxCV切り替え後、CVRが安定して回復、効率改善しながら獲得数を伸ばせている

#### 事例（YDA-コールドスタート検証 2208）

**背景**: 媒体CVが少ない状況でYDA自動入札・CV最大化導入。媒体非推奨だが、成果が安定する場合、運用工数の削減が見込める。

**結果**:
- 前後で獲得効率の変化は見られなかったが、コスト増加に対しCPCは低下、CTRは上昇しており、流入効率の改善
- IMP損失を最低にしながら必要コストを配信する観点で手動入札に課題があったが、その点については改善

**検証事例まとめ**:
- 配信の安定化: MaxCVになってもCV増えないが配信は安定しており、**CV件数が少ない場合でも配信の安定化は見込める**
- 成果改善の寄与: 手動入札で成果不調の場合MaxCVに切り替えで成果関与するかの示唆は得られなかった
- 今後の取り組み: 事例が少ないため検証案件を募集。手動入札で成果不調の人は一応配信は安定するので導入してみた場合は連絡

**※tCPAで実施しなかった背景**: 推奨CV件数に満たない場合の挙動がMaxCVとtCPAで異なる
- MaxCV: CP単位で直近7日間にCV数が20件以下であればクリック数最大化の挙動になる
- tCPA: GRP単位でCV件数が不足している場合、CP・アカウントと上位階層の実績が貸し出されるため**シュリンクする可能性**

### CV数が少ない場合の対策案（共通）

| 対策 | 内容 |
|---|---|
| **キャンペーン/広告グループの統合** | 類似する訴求内容の場合、統合して1キャンペーンあたりのコンバージョン数を増やす（CP-A 30件 + CP-B 20件 = CP-C 50件） |
| **自動入札「CV数最大化」の利用** | CV数増加後、「広告費用対効果の目標値」の利用に切替 |
| **マイクロCVの設置** | 実際のCVに近いポイント（カートページ等）に設定 |
| **オフラインCVのインポート** | サイト外で発生したCVデータを連携 |

## Part 3：レスポンシブ広告（アセット複数素材）（2211〜2302）

### 仕様

レスポンシブ広告（画像）に対して、画像・説明文・タイトルを複数登録することで、各素材を自動選択して広告配信。効果の良い素材を自動選択し、入稿作業・運用工数を削減、効果の良いレスポンシブ広告の配信可能。

### 入稿規定

| 項目 | 入稿可能サイズ | 入稿可能文字数 | 入稿可能上限数 | 備考 |
|---|---|---|---|---|
| 画像 | アスペクト比1.91:1（1200×628）、1:1（300×300、600×600以上） | - | **15件** | |
| タイトル | - | 20文字以内 | **5件** | タイトルと説明文それぞれで、同一の記号を2種類ずつ利用可能 |
| 説明文 | - | 90文字以内 | **5件** | 同上 |
| ロゴ | 180×180pixel | - | **1件** | |

- 1広告グループ配下に作成可能なレスポンシブ広告（アセット複数素材）の上限数は**3件**まで
- レスポンシブ広告（アセット複数素材）では動画未対応
- 広告グループ配下に作成可能な広告の上限数は通常のレスポンシブ広告と合わせて300件まで

### アセット別広告掲載結果の評価

アセット一覧画面の「掲載結果」欄では、直近2週間で広告配信が行われた日の掲載状況をもとに、**「高」「中」「低」「学習中」「-」の5段階**で広告効果が高いかどうかを評価。

#### 「学習中」「-」のステータスとなる条件

**■学習中**
- インプレッション発生日が過去14日間で3日未満のアセット
- ADのimp数が1,000未満

**■「-」**
- 審査で否認された場合
- 画像が削除されている場合
- 画像が配信停止にされている場合

### 審査について

アセット単位で審査。配信に必要な組み合わせが1組でも存在すれば承認され、広告が配信される仕組み。アセットの一部を差し替えた場合、承認済みの素材は再審査されず、**追加入稿した素材だけ審査される**が、すべての素材の審査が完了するまでは、広告のステータスが「編集内容審査中」となり、承認済み（審査前）の状態で広告配信が継続される。

### Yahoo!社推奨の活用ケース（5つのポイント）

1. **アスペクト比別でレスポンシブ広告（アセット複数素材）をわけて入稿**
   - 現時点では仕様上の観点から、RADの入稿可能のアスペクト比1.91:1とアスペクト比1:1は同一アスペクト比でまとめ、広告を分けて作成することが推奨

2. **レスポンシブ広告以外の広告タイプも入稿**
   - 配信機会の最大化のために、レスポンシブ広告以外の広告タイプの入稿が推奨

3. **アセットは3つ以上入稿して配信**
   - 1広告内で、タイトル、説明文、画像は3つ以上入稿し、できるだけ複数の訴求内容を試す

4. **キャンペーン目的に応じて必要な実績担保**
   - 1アセット（特に1画像）あたりの実績が少ない場合、アセットの選択が最適化されない可能性
   - キャンペーン目的に応じて必要な実績が確保できるよう、アセット選択や運用を行うことが推奨

   ▼キャンペーン目的別の過去30日間での確保したい実績について（媒体推奨）
   | キャンペーン目的 | クリック数（過去30日） | コンバージョン数（過去30日） |
   |---|---|---|
   | サイト誘導 | 500件/1アセット | - |
   | コンバージョン、商品リスト訴求、アプリ訴求 | - | 1件/1アセット |

5. **レスポンシブ広告とレスポンシブ広告（アセット複数素材）は異なる訴求で配信が推奨**
   - 同じ画像・タイトル・説明文を配信することは実績が分散するため、異なる訴求で配信することが推奨

### 検証設計

#### 検証概要
新RAD（アセット複数素材）の集約検証。YDAのRADにおいて、Google同様に複数アセットでの入稿が可能となったことにあわせて、成果改善がみられるか検証。レスポンシブディスプレイ広告（アセット複数素材）は最適なアセットを自動選択するため、CTR・CVRが上昇する想定。1ADG内で入稿広告本数が多い場合、新RAD（アセット複数素材）の最適化がうまく働かず、成果悪化の可能性も想定。

#### 検証設計
- ①新RAD（アセット複数素材）+その他FMT（バナー広告等） vs ②現RAD（単一アセット入稿）+その他FMT（バナー広告等）での成果差分を検証
- ①新RAD（アセット複数素材）+その他FMT（バナー広告等）では、配信の最適化観点でクリエイティブサイズ別での入稿
- 前後比の場合は施策外要因などの変動が想定されるため、スプリットテスト（GoogleのD&E類似機能）が推奨
- YDAのスプリットテストは複製したキャンペーンへ学習の引継ぎがされません
- YDA自動入札資料内のP.43以降を参照

#### 検証イメージ
- テスト: CP/ADG
  - 新RAD (1200*628): 1200*628 × 2
  - 新RAD (300*300): 300*300 × 2
  - その他FMTバナー等: 300*250 × 2
- コントロール: CP/ADG'
  - 現RAD①: 1200*628
  - 現RAD②: 1200*628
  - 現RAD③: 300*300
  - 現RAD④: 300*300
  - その他FMTバナー等: 300*250 × 2

## Part 4：クリエイティブ検証（2211〜2302）

### 検証したいこと

#### ① 最大で同じクリエイティブは何日配信し続けていいのか？"枯れ"は存在するのか？

「同じクリエイティブを配信しつづけると、ユーザーが飽きて反応しなくなる」、ないし媒体に品質評価を下げられるが事実だとすれば、クリエイティブは定期更新しなければいけない。一方で、クリエイティブ更新には制作費がかかる。同じクリエイティブで成果が出るならなるべく長く生かしたい。

**検証概要**:
- 差し替えを行わず、長期間同一クリエイティブを配信しているグループを抽出
- 入稿後3日間を除いた初動一週間のCTRが、移動平均CTRで70%になるまで何日かかるか調査
- 必要日数に差分がある場合、「枯れ」発生に関わる要素を考察

#### ② 最短で何日配信し続ければ学習はおわるのか？何本までなら同時配信しても学習に問題ないのか？

「学習が終わっていない」「クリエイティブに有意差がない」は、数値から見分けることが不可能。学習が未完了であることを、「有意差がない」と判断してクリエイティブを変え続けたとしたら、制作や配信にかかる労力が無駄になってしまう。また、同時に配信する本数も実績確保に影響する。例えば週1クリエイティブを差し替えて良いアカウントとは、どのような条件か？

**検証概要**:
- クリエイティブの差し替えを行っているグループを抽出
- 差し替え後、同一グループ同一サイズで、配信量最大の広告と最低の広告の差分が1.5倍開くまでに必要な期間を調査
- 必要日数に差分がある場合、学習完了に影響を与える要因を考察

**目標**: アカウント規模に応じた推奨入稿本数と、差し替え頻度を推奨として展開する

※2211時点では「12月中に勉強会実施予定」

## Part 5：予測ファネルターゲティング（2211〜2302）

### 予測ファネルターゲティングとは

Yahoo!社が保有する購買や来店などのアクションの可能性をスコア化し、ファネルに落とし込んだソリューション。

- 見込み顧客のボリュームを予測スコア別に把握
- アクション（購買・検索・来店など）の確率に応じて付与されたスコア（0.0〜0.9）のオーディエンスボリュームを把握できる
- **予測ファネル（0.6-0.85）**を活用することで配信機会の拡大

### 既存非リタゲ施策実施アカウントでの調査結果

既存で非リタゲ施策を実施しているアカウントでも0.6以上のユーザーへのリーチ割合は20%程度となっており、予測ファネルターゲティング実施による新規リーチ増加が見込める。

#### リーチ率可視化 保険業界
- 期間: 2022/9/1-9/30、YDA/vIMPでの広告接触/非接触ユーザーの割合を可視化
- 0.6-0.8のユーザーには現状80-90%ほどはリーチできていない状況
- 実施済みの非リタゲ: CV行動予測、サーチターゲ、ブロード

#### リーチ率可視化 航空業界
- 期間: 2022/9/1-9/30、YDA/vIMPでの広告接触/非接触ユーザーの割合を可視化
- 0.6-0.8のユーザーには現状80%ほどリーチできていない状況
- 実施済みの非リタゲ: CV行動予測、サーチターゲ、インタレストカテゴリ、インマーケットセグメント

## So What — 戦略家視点での示唆

### 1. iOS14対策は「補完×代替の二段構え」が標準テンプレ

- 顕在層 → 自社流出ターゲ・ADクリッカー（補完）
- 検討〜潜在層 → 類似ユーザー・行動予測・CV予測（代替）
- 他媒体経由ユーザーは原理上補完できないので、代替メニュー拡大が必須。
- **REHATCHでの活用**: 新規YDA案件のキックオフ時、必ずこのフレームで「顕在補完×潜在代替」を提案メニューに入れる。

### 2. CVMax vs tCPA の使い分けは「予算重視か成果重視か」

- 予算消化重視（KPIに予算消化率が含まれる案件）→ CVMax
- 成果重視 → トレンド変化なし or IMP損失率大なら CVMax、それ以外は tCPA
- tCPAでCV要件満たさない場合 → CVMaxへの切替が次の一手
- **数値根拠**: 推奨CV件数を満たさない場合、tCPAは上位階層実績の貸出でシュリンクするが、MaxCVはクリック数最大化挙動になる差分を理解しておく。

### 3. RAD（複数アセット）導入は「1ADG3件まで・既存と訴求を変える」がコア

- 入稿規定（画像15・タイトル5・説明文5）を意識して訴求パターンを設計
- 既存RDA（単一アセット）が残っている場合は**訴求を被らせない**
- アスペクト比別に分けて入稿（1.91:1 と 1:1）
- 検証方法は前後比でなくスプリットテスト（媒体依頼必要）

### 4. 自社流出ターゲ事例は「集計期間1日」が成果改善のキーレバー

- ゼクシィ縁結び事例で、集計期間28日 → 1日変更でリスト精度向上が示唆
- これは導入後の初動だけでなく、**定期的な見直し対象**として運用ルーチン化する価値あり

### 5. 予測ファネルターゲは「既存非リタゲ実施でもリーチ率20%」が活用根拠

- 「うちは既に非リタゲやってるから不要」という反論に対しても、リーチカバー20%程度というデータが反論材料になる
- → **「やり尽くしている案件こそ予測ファネルで上積みが出る」**というロジックで提案できる

### 6. クリエイティブ枯れ・差し替えのルール化はまだ業界全体で未確立

- 2211時点で「12月勉強会実施予定」と書かれているように、明確な基準値がまだ確立されていない領域
- → REHATCHとして案件横断でデータ蓄積し、独自の「枯れタイミング基準」を構築する余地がある領域
