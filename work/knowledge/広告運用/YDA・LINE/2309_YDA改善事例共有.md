# YDA改善事例共有：機械学習時代の運用設計と実案件改善ケース

## 出典

- 資料名: `YDA改善事例共有.docx`（アイレップ社内資料）
- ファイル更新日: 2023年9月21日
- 提供元: 株式会社アイレップ → REHATCHへの引き継ぎ知見

## 用途

- 「統合 vs 分割」のジレンマで迷った時の判断軸を整理したい時
- 自動入札に丸投げになっていないか、運用設計を見直したい時
- 既存YDAアカウントで「もう一段成果を伸ばす」打ち手を考える時
- STG（サーチターゲ）の精査・KW追加・ファネル設計の事例参照
- リーセンシー手動強化、モーメント配信などの**緩急の付け方**を学ぶ時
- AIに任せきりにせず「正しいデータをAIに与える」運用思想を実装したい時

## 前提：機械学習を扱う上で意識すべきこと

### 運用環境の変化

| 以前 | 現状 |
|---|---|
| CP・GRPを細分化、KW-TD-LP-BIDを個別条件で管理して成果改善 | 学習機能発達で**統合管理のメリットが大きく**なった |
| | カスタマイザ機能による統合障壁の緩和 / 学習データ母数の必要性 / カニバリによるオークションデメリット |
| | → 「CP・GRPを当然統合していく」が運用標準化 |

### 不変の原理

> **「正しいターゲットに対して、正しいクリエイティブを、正しい金額で投資し、正しい導線に導くこと」が運用の本質**

— 以前でも現状でも変わらない。

### AIバイアスについて

- AIは外からのデータインプットに基づいて動くが、データを与えるのは人間
- **「どれだけ正しいデータをAIに与えるか」に運用者の手腕がかかっている**

### 運用者が意識すべきデータ設計

#### 1. 機械学習・自動最適に必要なデータ母数を集める

#### 2. データを束ねるルール

##### 類似性のあるデータで束ねる
- どんな性質のユーザーがいるのか、獲得効率の良し悪しに乖離が大きく出ていないか

##### ノイズとなるデータをはじく
例：サーチで言う**指名と非指名を分ける**
- 指名と非指名ではユーザーの検索意図・モチベが違う（ユーザー群・ファネルの違い）
- 指名と非指名では競合性も違う（面の違い）
- 配信の狙いも違う（直接CV狙いか、流入・教育を通じた間接狙いか）

#### 3. 媒体1CVではなく、1CV価値（ビジネスインパクト）を意識して拡大

## ⚠️ Dis（YDA）運用で陥りがちなミス

- 運用設計・配信モニタリング・運用改善の**粒度が粗い**
- **「統合配信 → 機械学習頼み → CVデータ足りなければmCV」**という単純な思考になっていないか
- サーチと同じく、配信意図の違いや傾向差に着眼する必要がある

## 具体的な改善事例

### ケース1：STGを1CP・1ADGで運用

#### 状況
STG内のKWを「指名」「競合」「一般」等にカテゴライズすると：
- 「指名」は成果良い
- 「一般」は成果悪い
- 「競合」はまあまあだが、内訳でCPA差大（「高須クリニック」CPA高騰、「品川クリニック」CVボリューム多くCPAそこそこ）

#### 課題
上記のような傾向差があるのに、自動入札でまるっと最適化 → **緩急がついていない**

#### 示唆
- 指名はもっと出せるのではないか？（IMPシェア確認）
- 「一般」「競合_高須」は抑制すべきでは？

### ケース2 & ケース4：RTGをプレースメントで分けていない

#### ケース2
- YTop面はCVR高くCPAも良いものの、YTop面にしてはIMPボリューム少ない（配信が抑えられている）
- → **YTop面はADG切り出して強化した方が良い**

#### ケース4
- やけに配信が出ている・CTRが高いプレースメントを確認すると、SPでしか見れず**サイトの60%以上が広告枠**になっているサイト
- 誤タップによりCTRが高く最適化されて配信が出てしまっている
- → これは**ノイズ**として除外すべき

### ケース5：手動と自動を組み合わせて操る好例

- リーセンシー × 面（YJ面かどうか）× ブラパネで切っている
- CVR・CPCの傾向差に合わせてADGを分割し、入札差配をかけている

### ケース6：STG改善事例（資格業界？）

#### 実施背景
RTGへの獲得偏重 + 他非リタゲと比較してもSTG成果悪い状況

#### 施策概要

**KW精査**
- STG上で設定しているKWの成果のみでなく、**サーチでのクエリ成果も加味**してターゲットKW精査
- STGで獲得なし＆サーチ上での成果も悪いKWは停止

**KW追加**
- Yahoo!社と連携し、競合のSTG配信実績で成果の良いKW（主に競合名）を追加

**参考**
- サーチ実績や媒体社連携のみならず、PerSONARやDSINSIGHTを活用してCVしやすいユーザーの検索KW傾向を分析することも有効

#### 結果
- 既存KW成果改善＋追加KW純増 → STG全体の成果改善
- コスト化していたKWを停止し、確度の高いKWに絞って配信強化 → 掲載機会を逃さず取り切り、CV増加

#### 今後の展望

**アカウント構造変更**
- 既存KWと競合KWでCVRに開き → 1ADG運用から**ADG分割しそれぞれで入札調整**

**ユーザーの質を高める**
- 「不動産」掛け合わせKWでCVR低い → でもサーチ実績踏まえて停止はもったいない
- → 新たに「不動産掛け合わせ」リスト作成
  - ① 検索期間を短くする
  - ② 検索回数を引き上げる
- 検索意図がより強いユーザーに絞ってターゲティングの質を上げる

### ケース7：リーセンシー1日の切り出し＆手動強化による改善

#### 施策概要
- 「0-1」の短期リーセンシーへの入札調整比率を強化
- 入札調整比率の限度（+100%）まで強化しても足りないので、**別CPで切り出して配信**

#### 考察
- 自動入札はリーセンシーを読み込んで入札をかけてくれるが、**手動でないと到達できない入札額の天井**がある
- そこを手動で無理やり強化したことが功を奏した
- 最上位掲載を狙って入札をドラスティックに行う、**サーチの指名と同じ考え方**

### ケース8：モーメント配信による改善事例（注文住宅）

#### 施策実施前の状態
オーディエンスカテゴリで「注文住宅に興味があるユーザー」に配信していたが、以下のユーザー全てに配信される：
- 検討初期ユーザー（「家建てたいな〜」）
- 検討中期ユーザー（「どこで建てようかな〜」）
- 検討後期ユーザー（「どんな家にしようかな〜」）
- 購入済ユーザー

本来配信を当てたいのは**まだハウスメーカーを決めていない検討初期層**だけ。

#### 施策概要
- **モーメント配信を活用**して、オーディエンスカテゴリに時間軸を掛け合わせ
- まだハウスメーカーを決めていない「検討初期ユーザー」のみをターゲティング

#### 結果
モーメント配信リストの方が**高CVR・低CPAで着地**

## 改善を図る上で注視すべき4つのチェック

1. **すでにリスト区分して成果差分が見えているところに対して、きちんと入札差配が効いているか確認** → IMP伸ばしたいところが伸び切っていない等を発見
   - → 必要であれば切り出し強化
2. **統合配信している内訳に種別の違う塊・実績差分の大きいカットがないか発見・精査** → 切り分けやノイズ排除
3. **成果の振るわない配信に対して、リーセンシー・検索期間・検索回数など特定確度の高そうな条件に絞り込み**、ターゲティングの質・純度を上げる
4. **ターゲティングの追加トライ**（ツール、その他実績、モーメント配信といった追加配信方法）

## So What — 戦略家視点での示唆

1. **「統合 vs 分割」は二項対立ではない**: 「基本は統合・例外は分割」と理解する。分割の根拠は「入札差配が-90%〜+100%の範囲で効かない」「ノイズになっている」「ターゲット質を上げたい」の3つに絞れる。

2. **自動入札への丸投げは「緩急の喪失」を生む**: ケース1の高須/品川クリニックのように、内訳の傾向差が見えているのに統合運用していると、AIは平均値で最適化してしまう。**運用者が「ここを伸ばす・ここを抑える」の意思を明示することが、AIに正しいデータを与える行為**。

3. **手動入札の天井を超える時は「別CP切り出し」を躊躇しない**: ケース7のように、入札調整率+100%でも足りない時は構造を変える判断が必要。AIは入札の天井を破れない。

4. **モーメント配信は「時間軸 × 興味関心」の組み合わせの力**: ケース8のように、興味関心だけだと検討初期から購入済まで全部入る。時間軸を掛けることで、CVR・CPAが劇的に変わる。**「誰に・いつ」の組み合わせ思考を持つ**。

5. **REHATCHでの応用**: クライアントへの改善提案時、これら8ケースをパターンランゲージとして使える。「ケース1型の症状か？」「ケース4型のノイズが混じっていないか？」と診断するフレームになる。
