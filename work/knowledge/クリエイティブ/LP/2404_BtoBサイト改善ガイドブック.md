## 用途（どんな時に活用できるか）

- BtoBクライアントのサイト改善提案を組み立てるとき
- 「どのページを優先して改善すべきか」の根拠・基準が欲しいとき
- CVR 1%を突破できていないサイトの改善余地を洗い出すとき
- 各ページのチェックリストを使って自社・クライアントサイトを棚卸しするとき
- フォームやCTA改善の具体的な施策アイデアを探しているとき
- 効果測定の指標設計・ユーザーテストの実施方法を知りたいとき

## 用語集

| 用語 | 定義 |
|---|---|
| **CV（コンバージョン）** | サイト上でユーザーが行った問い合わせや資料ダウンロードなどの行動のこと |
| **CVR（コンバージョン率）** | コンバージョン数 ÷ サイト全体のセッション数 |
| **フォーム到達率** | フォームに到達したセッション数 ÷ サイト全体のセッション数 |
| **フォーム通過率** | フォーム経由のコンバージョン数 ÷ フォームへの到達セッション数 |
| **CTA** | ユーザーに起こしてほしい行動をボタンやリンクで示したもの。「資料請求する」「お問い合わせ」など |
| **リード** | 商品・サービスに関心を持ち、氏名やメールアドレスなどの情報を提供した見込み顧客 |
| **セッション数** | 一定時間内にユーザーがサイトで行った一連のアクションの単位。PV数とは異なる |
| **PV数** | ページビュー数。特定ページが表示された回数 |
| **ファーストビュー** | Webページを開いてスクロールしなくても見える最初の画面領域 |

## 第一章｜BtoBサイトの基本

### BtoBサイトとは

商品・サービスのマーケティングや営業への貢献を目的として作られたWebサイト。本ガイドブックでは**リード獲得を目的とするBtoBサイト**を改善対象とする。

BtoBサイトは見込み顧客が商品・サービスの情報収集・カタログやパンフレットを入手する場所。

---

### なぜBtoBサイトが重要か（統計データ）

> 以下はすべて引用データ。意思形成の大半がオンライン・サイト経由に移行していることを示す。

- **65.1%** の購買担当者が「企業のWebサイト」を仕事上の情報源として最も多く挙げている（トライベック・ブランド戦略研究所「BtoBサイト調査2023」）
- 購買プロセスの **57%** が、営業担当者と初めて接触する**前に**終わっている（CEB社調査）
- 2025年までにBtoBの購買の **80%** がデジタルチャネル経由になる（Gartner予測）
- BtoBの購買担当者の **61%** はオンラインで自分で情報収集したい
- **67%** の購買担当者が「営業担当者とのやりとりを第一の情報収集源としたくない」

→ サイトが購買プロセスの大半を担う。営業と会う前の意思形成を完結させる設計が必要。

---

### BtoBサイトに訪れる見込み顧客の4層

| 層 | 特徴 | BtoBサイトへの関係 |
|---|---|---|
| **明確層** | 特定のサービスを使いたい | メインターゲット |
| **顕在層** | 悩みを解決したい | メインターゲット |
| **準顕在層** | 悩みはあるが解決策が不明 | ブログ・ノウハウ資料で対応 |
| **潜在層** | これから悩みを持つ可能性がある | ブログ・SNSで認知醸成 |

BtoBサイトでは**明確層・顕在層のニーズに応えるコンテンツを優先**して用意する。

---

### CVRの目標基準：1%以上

バケツの穴をふさぐ比喩：集客（広告費）を増やしても、サイトに穴があればリードは増えない。まず穴（CVR低下要因）をふさぐことが先決。

| CVR | アクション |
|---|---|
| **1%未満** | サイト改善を優先。集客投資はその後 |
| **1%以上** | 集客（広告・SEO）への投資フェーズへ移行 |

**参考ベンチマーク：**
- BtoBサイトのCVR平均は **2%超**（Ruler Analytics調査）
- 検索広告のCVR平均：**2.41%** / ディスプレイ広告：**0.46%**

> 「正しい型を使えば80点まではすぐに到達できる」（才流）

---

### BtoBサイトには正しい型がある

才流×WACUL×ベイジの3社共同で**163項目のチェックリスト + ワイヤーフレーム**を公開。
これをもとに改善すれば、ゼロから考えなくても水準以上のBtoBサイトが作れる。

---

### BtoBサイトに必要な7つのページ

1. ホーム
2. サービス・機能紹介
3. 価格
4. 資料ダウンロード
5. 事例紹介
6. 会社情報
7. フォーム（お問い合わせ、資料請求）

#### ① ホーム

Webサイトの入口。ファーストビューに**キャッチコピー・課題・特徴・CTA**を配置。  
- 商品1つ → ファーストビューにCTAを設置し即コンバージョン誘導  
- 商品複数 → ファーストビューに商材一覧を設置し目的の商材へ即誘導

#### ② サービス・機能紹介

おもに検討フェーズのユーザーが閲覧。最多は「製品/サービス情報」へのニーズ（ITコミュニケーションズ×B2Bマーケティング「BtoB商材購買行動調査2023」）。冒頭で商品・サービスの特長や競合との違いを伝える。

#### ③ 価格

- 競合より高い場合は明記するとCVR下がる傾向
- 一方、価格ページがあればWeb行動履歴から「価格への関心」を把握できる（MA活用時に有利）
- 価格を明記しない場合は「価格お問い合わせフォーム」「価格表ダウンロード」「価格シミュレーション」のいずれかのCTAを設置

#### ④ 資料ダウンロード

ホワイトペーパー・eBookなど。**BtoBサイトで最もリードを獲得できるページ**。  
コンテンツ例：調査データ・導入事例・市場動向の解説・機能紹介・ノウハウ紹介

#### ⑤ 事例紹介

口コミが生まれにくいBtoB商材の信頼構築に有効。購買担当者が決裁者を説得する資料としても使われる。

#### ⑥ 会社情報

「取引しても大丈夫な会社か」を確認するページ。掲載必須：商号・代表者名・事業内容・設立日・所在地・経営者プロフィール。

#### ⑦ フォーム（お問い合わせ、資料請求）

フォーム通過率の目標は**25%**（ページに入ってきたユーザーの1/4以上が送信完了）。コンバージョンに直結する最重要ページ。

### BtoBとBtoCの違い（比較表）

| 観点 | BtoC | BtoB |
|---|---|---|
| 対象 | 生活者 | 法人や団体 |
| 顧客数 | 多い | 少ない |
| 購買関与者 | 一人 | 複数人・多層 |
| 利用者 | 多くの場合、購買者と同じ | 購買者と同じとは限らない |
| 購買目的 | 所有・体験・課題解決 | 課題解決 |
| 検討期間 | 短期間 | 長期間 |
| 購買時の重視点 | ブランドや付加価値も影響 | 機能や実績 |
| 購買単価 | 少額（数百円〜数万円） | 高額（数十万円〜数億円） |
| サービス置き換え | 容易 | 困難 |
| 購入元 | 販売員やECサイト | 営業パーソン |

**BtoBの特殊性（顧客側）**
- 自分の財布から購入するわけではない
- 失敗回避の心理が強く働く
- 予算や決算期という概念がある
- 決裁者と現場担当者でBtoBサイトを訪問する目的が異なる

**BtoBの特殊性（提供側）**
- 広告の出稿先が少なく、BtoBサイトの重要性が高い
- BtoBサイト経由で受注したリードのLTVを計測する難易度が高い

### TIPS｜BtoBサイトのドメイン設計FAQ

**Q. 潜在層は意識しなくてよいか？**  
A. ブログ・コラムで潜在層を集客する場合は意識する。ただしまず明確層・顕在層向けに最適化し、次のフェーズで潜在層向けコンテンツを整えていく順序が推奨。

**Q. コーポレートサイトとサービスサイトのドメインは統一すべきか？**  
- 同ドメインのメリット：被リンク・サイテーションによる評価が集中し、SEOに有利
- 異なるドメインのメリット：指名検索で両サイトを上位表示できる可能性あり、複数事業のターゲットが異なる場合は統率が取りやすい

## 第二章｜BtoBサイトの現状把握（チェックリスト）

### 現状把握の進め方（3ステップ）

```
STEP 1: 足りないページを特定する
  → 7つの必須ページのうち不足しているものを新規作成
  ↓
STEP 2: 大通りを特定する
  → セッション数が多い上位10ページ（過去1年間）
  → コンバージョンしたユーザーが閲覧する上位10ページ（過去1年間）
  ↓
STEP 3: 大通りの改善事項を洗い出す
  → チェックリスト163項目を使って空欄を特定
  → 空欄 = 改善が必要
```

> 改善で大きな成果が得られるのは「大通り」。小道（一部ユーザーしか通らないページ）は大通り改善後に取り組む。

---

### チェックリスト｜ホーム

**概要：** Webサイトの入口。ファーストビューにCTA・よくある課題・商品の特長など必要情報を配置。文字量は3,000文字以上にする。

#### ホームのチェックリスト 1/2

- [ ] 企業や商品・サービスを端的に表現するコピーが真っ先に目に入る
- [ ] メインビジュアルで、ユーザーが求める情報をカルーセルで隠していない（※ユーザーニーズの少ない企業都合の情報は除く）
- [ ] メインビジュアルは競合の商品・サービスと似たものにしていない
- [ ] ファーストビューに英語のメッセージや抽象的なメッセージを置いていない
- [ ] ニュースや更新情報、PRのような、多くのユーザーが必要としない情報をページ上部に設置していない
- [ ] （商材が1つの場合）ファーストビューにCTAを設置し、コンバージョン目的で訪問したユーザーを即座に誘導している
- [ ] （商材が複数ある場合）ファーストビューに商材一覧を設置し、目的の商材をすぐに発見できるようになっている
- [ ] 初めて訪問したユーザーでも迷わない、一般的なサイト構造・UIになっている（※奇をてらったものにしていない）

#### ホームのチェックリスト 2/2

- [ ] 企業や商品・サービスの特長を掲載している（※別途特長を整理したページを設けている場合は不要）
- [ ] ローディングやアニメーションなどでユーザーを待たせていない
- [ ] ホームの文字量が **3,000文字以上** ある

**ワイヤーフレームのポイント：**
1. FV：企業・商品を端的に表現するキャッチコピー＋CTA（英語・抽象語は使わない）
2. こんな課題はありませんか？（営業提案時によく出る顧客課題を掲載）
3. このサービスは○○○○に最適（初めてのユーザー向けにサービス概要を端的に）
4. 特長（機能紹介だけでなく企業・商品の強みを訴求。流し読み対応で図を配置）
5. 事例（タイトルは一目で改善内容や効果がわかる内容に。業種・規模・職種などを提示）
6. ご利用の流れ（商品の導入までに必要な期間・利用開始までにやるべきことを説明）
7. ブログ・お知らせ（**ファーストビューには置かない**。ページ下部に配置）
8. CTA（ページ最下部に設置）

### チェックリスト｜サービス・機能紹介

**概要：** 商品・サービスそのものや機能を紹介するページ。おもに検討フェーズのユーザーが閲覧。冒頭で商品の特長や競合との違いを伝える。

- [ ] リンク元のCTAの文言とページタイトルが一致している
- [ ] （スクロールするのが手間と感じるほどページが長い場合）ページ内の指定した箇所に遷移するアンカーリンクや目次を設置している
- [ ] ページ冒頭でページの主題や言いたいことをおおむね把握できるようになっている
- [ ] 見出しは「なぜ得するのか」「どう得するのか」など、ユーザー視点で端的に書かれている
- [ ] 見出しは本文のフックとして、ユーザーが興味を持ちやすい内容になっている
- [ ] 見出しは **20字程度、最大でも40字以下** にまとまっている
- [ ] 本文は簡潔に書かれている
- [ ] （商品・サービス名や機能名を一覧表示する場合）短い説明文を併記して内容を想像できるようにしている
- [ ] 「ソリューション」「価値提案」などの曖昧で抽象的な言葉を使っていない
- [ ] 「なぜそれが大事なのか」「なぜそれが求められるのか」といった前提を説明している
- [ ] 図を適度に配置し、見出しと一緒に流し読みすれば理解できるようになっている
- [ ] （商品・サービスのイメージや写真がある場合）図やイラストではなく、商品・サービスのイメージや写真を掲載している
- [ ] 意味を持たない飾りだけの写真やアイコンを使っていない
- [ ] アニメーションのような、ユーザーがコンテンツに没入するのに邪魔な演出をしていない
- [ ] ファーストビュー、ページ下部にCTAを置き、ユーザーがすぐにアクションをとれるようになっている

**ワイヤーフレームのポイント：**
- 冒頭：サービス概要がつかめる＋「1分でわかる動画」や「資料をダウンロード」のCTA
- 提供サービス：商品・サービスのメリットを紹介（機能・サービス名だけを羅列しない）
- ご利用の流れ：導入までの期間・スタートまでにする必要があることを説明

---

### チェックリスト｜価格

**概要：** 商品・サービスの価格情報を掲載。よくある質問は必ず掲載。価格を明記しない場合の代替CTAも設計する。

- [ ] （価格を明記する場合）専門用語を使わず、できる限りわかりやすく説明している
- [ ] （複数のプランがある場合）プランによる違いやオプションは、表やグラフを用いてわかりやすく表現している
- [ ] （複数のプランがある場合）最も売りたいプランが一番目立っている
- [ ] （複数のプランやオプションがある場合）組み合わせ例を複数紹介している
- [ ] （オーダーメイド型で価格算出方法が明確な場合）価格シミュレーターを提供している
- [ ] （オーダーメイド型で価格体系が曖昧な場合）価格例で金額の目安を伝えている
- [ ] 価格を確認してから商品・サービスの情報を見にいくユーザーを想定した導線を設置している（※通常のグローバルナビゲーションでも可）
- [ ] ページ下部には価格を見た後に問い合わせをするユーザーを想定したCTA（料金表ダウンロード、見積もり依頼など）を設置している
- [ ] 価格に関するよくある質問と回答を掲載している

**価格を明記しない場合の3パターン：**
1. 価格ページに**価格お問い合わせフォームを設置**（個社ごとに見積もりが必要な商品に最適）
2. **価格表ダウンロードのCTA**を設置（価格表を用意できる場合）
3. **価格シミュレーションのCTA**を設置（人数や数量で価格が変わる商品に有効 → フォーム到達率**2倍**、コンバージョン数**1.5倍**の事例あり）

### チェックリスト｜資料ダウンロード（一覧ページ）

**概要：** ホワイトペーパー・eBookなどのお役立ち資料をダウンロードできるページ。BtoBサイトで最もリードを獲得できるページ。資料が5つ以上の場合は一括ダウンロードを設ける。

- [ ] 「お役立ち資料」のような、ユーザーがメリットを感じられるページ名称にしている
- [ ] 資料一覧には、資料の内容や有益な資料であることがわかる情報を掲載している
- [ ] 資料一覧や詳細では、どんな人の役に立つのか、どんなことがわかるのかを端的に説明している

**ユーザーに喜ばれる資料コンテンツ（才流2021年アンケート調査 n=108）**

| コンテンツ種類 | 回答率 |
|---|---|
| **調査データ** | **55.6%**（最多） |
| 解決できる課題 | 51.9% |
| 導入事例 | 48.1% |
| 市場環境 | 44.4% |
| 機能解説 | 44.4% |
| 成功ポイント | 39.8% |
| 失敗例 | 33.3% |
| 選定ポイント | 29.6% |

> 資料は積極的に「調査データ」を取り入れることでDL率向上につながる。

**お役立ち資料の適切なページ数：**  
10ページ以内・11〜20ページ・21〜30ページがほぼ同程度。合算すると約80%が「30ページ以内」を希望。→ **30ページ以内を目安**に制作する。

---

### チェックリスト｜資料ダウンロード（フォーム）

- [ ] フォームの横には資料内容の一部を掲載している
- [ ] フォームでは、リード獲得に必要な最低限の情報だけを取得している
- [ ] ダウンロード完了画面で、他の資料やコンテンツをリコメンドしている
- [ ] （資料が複数ある場合）複数の資料をセットにしてダウンロードできるようにしている
- [ ] （資料が複数ある場合）一度入力した情報は、他の資料をダウンロードするときには入力不要としている
- [ ] （資料が5つ以上ある場合）一括ダウンロードを設け、フォーム入力の手間を省いている

**改善ポイント：複数資料をセットにしたダウンロードの設計**  
複数資料がある場合「○○がわかる3点セット」のようなCTAを設けると「とりあえずこれ」という心理が働き、迷わずダウンロードできる。無駄に資料数を増やしても意味がなく、**3点セットがちょうどよいバランス**（才流検証結果）。

---

### チェックリスト｜事例紹介（一覧ページ）

**概要：** 事例紹介ページでは一目でわかる一覧ページと各事例の詳細ページを作成。**事例20件以上**になったら絞り込み機能の実装を検討。

- [ ] 10件以上の事例を掲載している
- [ ] 信頼獲得につながる企業の実績と、業界が同じ・業態が似ているなど、とくに狙いたいユーザーが親近感を覚える企業の実績の両方を掲載している
- [ ] 事例一覧は、ユーザーがよく知らない企業ばかりが並んでいる状態ではない
- [ ] 事例一覧では、企業規模・業界・部署・役職・改善内容など、ユーザーが知りたい情報をサマリーで見られる
- [ ] ファーストビューには、事例集ダウンロードのCTAを設置している

### チェックリスト｜CTA

**概要：** CTAはユーザーに起こしてほしい行動をボタンやリンクで表示したもの。フォームページを除くすべてのページのグローバルナビゲーション・ファーストビュー・ページ下部にかならず設置する。

**CTAの設置箇所（5箇所）：**
1. ヘッダのグローバルナビゲーション
2. ファーストビュー（またはフォームを設置）
3. 右下追従バナー・下部追従バナー（遷移率が変わらない場合もあるので必要に応じて設置）
4. フロントページ最下部（コンテンツに合わせてコピーやデザインを変える）
5. フッタのグローバルナビゲーション

- [ ] フォーム以外のすべてのページのファーストビューにCTA、もしくはフォームを設置している
- [ ] グローバルナビゲーションにCTAを設置している
- [ ] コンテンツを読み終わったタイミングでCTAをクリックできるようになっている
- [ ] CTAは、コンテンツ内容にあわせて内容や文言を変えている
- [ ] CTAボタンは、ほかのボタン要素とは明らかに違う色や形をしている
- [ ] CTAボタンは、中央揃えで視線をブロックするように配置している
- [ ] コンテンツを読み終わった後のCTAは、自然と目に入ってくる
- [ ] コンテンツを読み終わった後のCTAには、コンバージョンに誘導するためのテキストを用意している
- [ ] CTAには電話番号のような、オンライン以外の重要なアクションも記載している
- [ ] CTAの数は1つに限らず、ユーザーニーズに沿うように必要な数を用意している

**ユーザー層別のCTA例：**

| ユーザー層 | 適切なCTA例 |
|---|---|
| 明確層（特定サービスを使いたい） | お問い合わせ・見積もり依頼・製品カタログのダウンロード |
| 顕在層（悩みを解決したい） | 資料請求・料金表のダウンロード・事例集のダウンロード |
| 準顕在層（悩みはあるが解決策は不明） | 事例紹介セミナーの申し込み・ノウハウ紹介資料のダウンロード |

## 第三章｜BtoBサイトの改善

### BtoBサイトを改善するときの基本的な考え方

#### ① ユーザー視点に立つ

BtoBサイトではつい自社の言いたいことを前面に打ち出しがち。しかしユーザーが興味を持つには、**何を伝えるか・いつ・どこで伝えるか・どのように伝えるか**を常にユーザー視点で考える必要がある。

「ユーザーが知りたいことを」＋「わかりやすいタイミングで」＋「わかりやすい表現をする」

#### ② ユーザーはしっかりサイトを見てくれない前提に立つ

Webサイトは基本的に「流し見」されるもの。わかりにくい・レイアウトが見づらいだけで「自社の課題は解決してくれない」と思われ候補から外れる可能性がある。

**初期検討時に閲覧されやすいページ：**
- ホーム（とくにファーストビューとセカンドビュー）
- 会社情報
- 価格

---

### ホームの改善ポイント

**よくある失敗例：**
- ✗ ファーストビューで商品・サービスについて触れていない
- ✗ ファーストビューやセカンドビューにお知らせや新着情報を掲載している
- ✗ 誰向けのサイトなのかわからない

**ポイント1：FVにはユーザーが知りたいことを掲載する**  
商品・サービスを検討しているユーザーがまず知りたいのは商品・サービスの情報。ミッション・ビジョンはFVではなく**会社情報ページへ移動**。お知らせ・新着情報は**ページ下部へ移動**。

**ポイント2：ターゲットをわかりやすく伝える**  
「この商品・サービスのターゲットは当社だ」と思えるよう、どんな企業向けの商品・サービスなのかをわかりやすく伝える。導入企業の紹介もターゲット理解に役立つ。

---

### サービス・機能紹介の改善ポイント

**よくある失敗例：**  
商品・サービスの紹介はしているが、何を売っている会社なのか・競合との違いがユーザーに伝わっていない。

**ポイント：商談時に顧客に刺さったスライドを有効活用する**  
商談時のキラースライドをBtoBサイトで活用するのは有効な手段。**商談時のキラースライドを挿入したことでコンバージョン率が2倍になった事例**あり。よいスライドがある場合はBtoBサイトにも掲載する。

### 価格の改善ポイント

競合より高い・見積もりが必要・具体的な価格を出しづらいなどの理由で価格を明記できないケースがある。**しかし価格を明記しない場合でも価格ページは作成するのが望ましい**。

**価格ページの3パターン（価格非掲載の場合）：**

| パターン | 概要 | 効果 |
|---|---|---|
| 価格のお問い合わせフォームを設置 | 個社ごとに見積もりが必要な商品に最適 | — |
| 価格表ダウンロードのCTAを設置 | 価格表を用意できる商品に最適 | — |
| 価格シミュレーションのCTAを設置 | 人数・数量で価格が変わる商品に最適 | フォーム到達率 **2倍**、コンバージョン数 **1.5倍** の事例あり |

### 資料ダウンロードの改善ポイント

**ポイント1：複数の資料をセットにしてダウンロードできるようにする**  
「○○がわかる3点セット」のようなCTAを設けると「とりあえずこれ」心理が働き迷わずDL。**才流の検証では3点セットがちょうどよいバランス**。

**ポイント2：ユーザーにとって「うれしいコンテンツ」を取り入れる**  
才流の2021年アンケート調査で最多は「調査データ」（55.6%）。積極的に調査データを入れることを推奨。お役立ち資料は**30ページ以内**が約80%の支持を得ている。

### 事例紹介の改善ポイント

作成の負担が軽いものから取り組む：①ユースケース・ケーススタディ → ②お客様の声 → ③企業ロゴ。  

企業名を出せない顧客でも**匿名の課題解決事例**として作成可能。業種・社員数などを付与することで十分な品質のコンテンツになる。

### 会社情報の改善ポイント

会社情報ページにCTAを置くことを忘れがち。ユーザーは「どういった会社なのかを知りたい」ため、**会社紹介資料をダウンロードできるCTA**を設置する。

改善前：会社情報ページにCTAなし → 改善後：会社紹介資料をダウンロードできるCTAを設置

---

### フォームの改善ポイント

フォームへの入力を開始するユーザーは見込み度の高いリードである可能性が高い。できる限りのことをして離脱を防ぐ。

**ポイント1：入力項目はできるだけ少なくする**  
- **1項目減らすと通過率が約2%pt向上**（WACUL研究）
- 入力項目が**5を超えると通過率が下がる傾向**（HubSpot Japan調査）
- 削除しやすい項目：郵便番号・住所・ふりがな・任意項目

**ポイント2：フォームはファーストビュー完結型にする**  
ファーストビュー完結型にすることで入力中の離脱を防止。  
改善事例：フォーム送信完了率 **20%→30%** に改善

**ポイント3：入力項目が多い場合はステップ式のフォームを採用する**  
複数ページにまたがるステップ式フォームで心理的ハードルを下げる。  
改善事例：フォーム通過率 **3.6%→8.3%** に改善

**ポイント4：リンク元のCTAの文言とフォームのタイトルを一致させる**  
「料金を見る」CTAボタンから遷移したのに「○○に関するお問い合わせ」というフォームが表示されると、ユーザーは目的が果たされないと感じて離脱する。

**ポイント5：フォームのテキストを読みやすくする**  
背景は白・テキストは濃い文字色を使い、高い視認性を保つ。

**ポイント6：資料の一部や相談・問い合わせ例を見せる**  
ユーザーがフォーム送信後の行動を具体的にイメージできるようにする。

**ポイント7：送信ボタンは行動を表す文言にする**  
「送信」ではなく「**資料をダウンロードする**」「**資料をメールで受け取る**」のような行動を表す文言を使用。

**ポイント8：確認ページは設置しない**  
確認ページがあると「入力が完了した」と勘違いして離脱するリスクがある。省略したほうがコンバージョンに至りやすい。

**ポイント9：フォームページ内のヘッダ・フッタなどの不要なリンクを削除する**  
せっかく入ってきたユーザーを逃さないためにフォームページ内に不要なリンクを置かない。

**ポイント10：すぐに電話したいユーザーのために電話番号を記載する**  
フォーム入力自体がストレスなユーザーへの代替手段としても機能する。

---

### ナビゲーションの改善ポイント

**コンバージョン率が高いページへの導線をつくる**

ナビゲーションの最適化は遷移率に直結する。次の2点を調べてナビゲーションを最適化する：
- どのページをたどるとコンバージョン率が高いのか
- どのページをたどるとコンバージョン率が低いのか

コンバージョン率が高いページへの導線は**グローバルナビゲーションの一番左（先頭）**に配置。コンバージョン率が低いページへの導線は右に配置するか削除する。

---

### CTAの改善ポイント

CTAはコンバージョン率・数の向上に直結する重要な要素。内容や文言、配置箇所を変えるだけで大きな成果につながる可能性がある。

**ポイント1：お問い合わせ以外のCTAも用意する**  
「お問い合わせ」しかCTAがない場合、ニーズが顕在化していないユーザーへのハードルが高い。「とりあえず資料が欲しい」「まずは価格が知りたい」などのニーズに応えるCTAも用意する。CTAを変えるだけで**リード獲得数が2倍になった事例**あり。

**ポイント2：トライアル以外のCTAも用意する（SaaS系）**  
SaaSサービスで「無料トライアル申し込み」しかCTAがないケースが多い。社内調整や稟議が必要な日本企業ではいきなりトライアルは現実的でない。**資料請求や料金表ダウンロードのようなハードルの低いCTA**も用意する。

**ポイント3：ページごとにCTAの内容や文言を変える**  
- 料金ページ：「料金表をダウンロードする」
- 事例紹介ページ：「事例集をダウンロードする」
ページごとにCTAの内容や文言を検討する。

**ポイント4：ページ中盤にポップアップバナーを設置する**  
ページ中盤にポップアップバナー型のCTAを設置。**月に40件のコンバージョンを獲得できた事例**あり。本文の邪魔にならないように設置すること。ファーストビューでいきなりポップアップバナーを表示させない。

---

### ブログ・コラムの改善ポイント

ブログ・コラムで集客できるようになったが、コンバージョンにつながらないという声が多い。CTAの配置が不適切なケースがほとんど。

**ポイント1：CTAをテキストリンクにする**  
ブログ・コラムのような記事コンテンツでは、バナー＝広告と認識されてしまう懸念がある。文脈に沿ったテキストリンクを挿入すると自然に読んでもらえる可能性が高い。才流でも記事ごとに文脈に沿ったテキストリンクを追加したことで**1ヶ月でコンバージョン数が50件以上増加**。

**ポイント2：記事ページには最低限3つのCTAを設置する**  
設置箇所：① タイトル直下 or 目次の前か後 ② 2つ目のH2（見出し）の直前 ③ 記事の末尾

- ① タイトル直下：具体的な情報を探しているDoクエリからの流入ユーザーはすぐCVしたい
- ② H2の直前：H2はデザイン的に「切れ目」になるので離脱が発生しやすく、ここでCTAを置くと効果的。半数近くがここで離脱する場合もある
- ③ 記事末尾：最後まで読んだユーザーは熱量が高く、次に何をしようかと手持ちぶさたになる

---

### セミナー・イベントの改善ポイント

**ポイント：一覧ページにはユーザーが参加を判断するために必要な情報を掲載する**  
最低限さえておきたい6つの情報：①セミナー概要がわかる画像 ②募集状況 ③開催形式 ④開催日時 ⑤タイトルや紹介文 ⑥費用（有料・無料混在の場合）

**ポイント：参加者の声を掲載する**  
同テーマの競合セミナーが多く、どれに参加すべきか迷うユーザーに向けて、参加後に得られるメリットをアンケートから2〜3個の声で掲載。

### TIPS｜BtoBサイトでよくある改善点TOP3

才流コンサルタントが2022年3月〜2023年3月に集計した指摘事項の上位3件（BtoBサイトの業種・業態によらず共通）。

**1位：商品・サービスの説明（指摘数：217件）**
- 他社の類似商品・サービスとの違いがわからない
- 「〜しましょう」という提案があるが、どのようなメリットがあるのかわからない
- 顧客視点ではなく、自社視点のキャッチコピーになっている
- 誰に向けた、何のサービスなのかわからない
- コスト削減や業務効率化を謳っている商品なのに導入前・後の効果を示せていない
- 「膨大な」「次世代の」「お客様の事業を成長させる」などの抽象的な表現をしている

→ **バリュープロポジション**（自社が提供でき、競合他社が提供できない、顧客が求める独自の価値）を使って整理する。参考：https://sairu.co.jp/method/10557/

**2位：デザインの不備・不整合（指摘数：114件）**
- フォントサイズが小さすぎて、または大きすぎて読みづらい
- トンマナがカジュアルで、法人向けWebサイトに見えない
- 画像が見切れている、画像の解像度が低い
- 文章と画像の内容が合致していない
- 色を多用しすぎて目線が定まらない
- 解決できることや特長など立たせるべきテキストが目立っていない
- Webサイト全体のデザインが10年以上前に採用されたもので、現代的でない

→ デザインの良し悪しに自信がなければ**ユーザーテスト**（後述）を実施して評価する。

**3位：CTAボタン（指摘数：99件）**
- CTAボタンの数が多すぎて、どれを押せばいいかわからない
- CTAボタンの数が少なく、押される確率が低くなっている
- CTAボタンがコンテンツの文脈に沿った配置・表記になっていない
- CTAボタンが目立つ色・サイズ・配置になってない
- とくに誘導したいCTAボタンが強調されていない

## 第四章｜効果測定

### 週次・月次で確認する3つの指標

改善や施策実行の有無にかかわらず、週次・月次で継続確認する。

| # | 指標 | 計算式 | 目標値 |
|---|---|---|---|
| ① | **フォーム到達率** | 到達セッション数 ÷ サイト全体のセッション数 | **10%以上** |
| ② | **フォーム通過率** | フォーム経由のCV数 ÷ 到達セッション数 | **25%以上** |
| ③ | **コンバージョン率** | コンバージョン数 ÷ サイト全体のセッション数 | **1%以上** |

> コンバージョン率は計測していても、フォーム到達率・フォーム通過率を計測していないケースが多い。両者はコンバージョンのボトルネック特定に不可欠。

**参考ツール：** BtoBサイトに特化したGA4対応版Looker Studioテンプレート（才流）→ https://sairu.co.jp/method/16327/

### ユーザーテストのやり方

「どう直したらいいのか」「解決策は本当にこれでよいのか」と改善内容について迷う場合にユーザーテストが有効。

**ユーザーテストとは：**  
一般の消費者や見込み顧客、実際のユーザーなどに製品やWebサイトを見てもらったり、操作してもらったりし、その様子を観察するテスト。改善が必要な点を洗い出したり、逆に評価されている点を見つけたりできる。

**5人のテストで重大な欠陥の85%がわかる（Jakob Nielsen「Why You Only Need to Test with 5 Users」より）。** 6人目以降から発見できる問題が急激に減る。

**ユーザーテストの5ステップ：**

1. **STEP 1：仮説立案**  
   現在のBtoBサイトについて、どんな課題があるのか、ユーザーはどのように行動すればよいのかを考え仮説を立てる。  
   仮説の例：「会員登録のステップに欠陥があるのでは」「トップページを見ただけではサービスを理解しにくいのでは」「ユーザーはどこをクリックすればいいか、わからないのでは」

2. **STEP 2：ユーザーに依頼する内容を決定する**  
   検証したい仮説にもとづいてユーザーへの依頼内容を決定。1分で終わる簡単なものから15〜30分かかる複雑なものまで何でも可。  
   依頼内容の例：「ホームを見てもらい、サービスについて説明してもらう」「会員登録のステップを実際にやってもらう」「CTAを探して、クリックしてもらう」

3. **STEP 3：ユーザーに実際に操作してもらう**  
   ユーザーに作業内容や感じていること、思っていることを言葉に出しながら作業してもらう（**発話法**）。作業の内容・いま見ている場所・思ったことなどをなるべく多く言葉にしながら進めてもらう。

4. **STEP 4：操作内容を撮影する**  
   オフライン：スマートフォンやビデオカメラなどで操作する様子を動画撮影。  
   オンライン：ユーザーに画面共有をしてもらい録画。

5. **STEP 5：撮影した動画を共有し課題を抽出する**  
   撮影した映像をチームで共有しディスカッション。テスト現場にいた人は冷静に結果を見られないこともあるため、後で映像を確認することを推奨。

---

### TIPS｜細かなA/Bテストの積み重ねは不要

BtoBサイトにおいては**細かなA/Bテストの積み重ねは不要**（才流の見解）。

理由：BtoBサイトのセッション数は月に数千〜多くても数万程度。月5,000セッションの場合、CVRを0.1ポイント上昇させてもコンバージョンは5件しか増えない。細かなA/Bテストを重ねてCVRを上げるよりも、**新たなチャネルを開拓し、認知拡大や集客強化に注力するほうがインパクト・費用対効果ともに大きい**。

→ まずはCVR1%以上を目指し、達成したらBtoBサイトの改善は一旦ストップ。効果的な施策はほかにもっとたくさんある。

## 示唆・アクションまとめ

- **CVR1%が分岐点**：1%未満はサイト改善を優先、1%以上は集客投資フェーズへ
- **大通り優先**：セッション数の多いページとCVユーザーが通るページの最大20ページを先に改善
- **フォーム改善のROIが最高**：入力項目削減・FV完結型・ステップ式のどれも数値改善が期待できる
- **CTAは複数種類用意**：「お問い合わせだけ」は機会損失。資料DL・料金表・セミナーなどユーザー層に合わせて設計
- **ブログのCTAはテキストリンク化**：バナー型は広告認識されやすく、テキストリンクの方が読んでもらいやすい
- **ユーザーテストは5人で充分**：重大な欠陥の85%を発見できる。改善方向が迷ったら5人に試す
- **BtoBサイトのよくある失敗TOP3**：①商品・サービスの説明不足 ②デザインの不備 ③CTAボタンの問題
- **確認ページは不要**：フォームの確認ページは離脱リスクを高めるだけ。省略する
- **ホームの文字量は3,000文字以上**、**ブログ本文は17px以上**など数値基準を押さえておく
