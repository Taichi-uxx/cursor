# デジマス最適化事例（freee）— LTVベース運用とミドルファネル評価

## 出典
- ファイル: `知見・ナレッジ移管/デジマス最適化事例(freee).docx`
- 作成: 2023年9月頃（推定）
- 内容: IrepによるfreeeのSaaS広告運用事例。LTV予測モデルの構築から、ミドルファネル（TVCM）をLTVで評価するデジマス統合運用までの手法論と成果。

## どんな時に活用できるか
- SaaS／継続課金型クライアントに対し、CPA運用からLTV運用への切り替えを提案する時
- 広告CV発生と売上計上のタイムラグが長く、施策評価ができないクライアントへの対処設計
- TVCM等ミドルファネル施策の効果可視化（Cookie計測ができないメディア）を提案する時
- 「ロワーに追加投資 vs ミドル新規投資」のどちらが効率的かをシミュレーション提案する時
- 確定申告のような**モーメント型商材** vs **検討期間長い商材**でデジマス戦略を分岐させる時
- LTV運用構築の工数・必要スキル感を見積もり、コンサル費請求の論拠にする時

## 1. 一番最初に提案したこと — LTVで評価して、運用する

### freeeのビジネスモデル
```
広告出稿 → 会員登録（媒体CVポイント） → 課金（3か月～1年後） → 数年継続 → 解約
```
売上として回収できるのは**広告出稿からかなり先**。
これがLTV運用を提案した根本理由。

### Irep以前の状態と懸念
- プロダクトごとに予算が決まっている
- プロダクトごとに運用最適化
- → **過剰投資・過少投資のプロダクトが存在している可能性**
- LTV可視化ができておらず、合理的な投資ポートフォリオが組めていなかった

### Irepの提案
**全プロダクト横断のLTV評価に切り替え**、freee社全体としての売上最大化を目指す。

## 2. LTV可視化の方法

### 計算式
```
LTV ＝ 会員登録数 × 課金転換率 × 一人当たりLTV
```
- **課金転換率**：Irepが分析
- **一人当たりLTV**：クライアントが分析

### 課金転換率の分析手法（CustomerIDベース）
GAで取れるCustomerIDをキーにする。
1. CustomerID単位で**会員登録のデータ**を取得
2. 登録から課金したユーザーのデータをCustomerIDで取得
3. この2つのデータを統合する

### なぜCookieではダメだったのか
- 登録から数日～数か月経過した後に課金されるケース
- 登録はスマホ、課金はPCのような**デバイスまたぎ**が発生
- → Cookieベースだとこれらを追跡できない。CustomerIDで突合する必要がある

### 太一の示唆
**「Cookieじゃ追えない」がSaaS LTV運用の出発点**。
GAのCustomerIDを設計段階から仕込めているかが、後の打ち手の幅を決める。新規SaaS案件は最初にここを確認すべき。

## 3. LTV運用最大の課題：CV発生と売上発生のタイムラグ

### 問題
- 媒体の入札最適化は**会員登録地点**で行われる
- 売上発生は**課金〜解約までの期間**（最大1年）
- アクチュアルデータで施策評価すると**1年待ち**になる
- → 運用に使えない

### 解決アプローチ：予測する（pLTV）

### 発見した相関
- 会員登録後**7日間に発生した課金数** と **90日間に発生した課金数**が **R²≒0.97 でほぼ線形**
- つまり7日間のデータで90日後の課金数が高精度で予測可能
- さらに**課金転換率自体は時期変動（確定申告期はお試し増で下がる）するが、7日転換率と90日転換率の比はほぼ一定**

### pLTV計算式
```
pLTV ＝ 会員登録数 × 7日課金率 × 7to90norm値 × 一人当たりLTV
```
- "7to90norm値"というノーム値を発見したことで、**7日間データで精度高くLTV予測ができるようになった**
- 案件KPIも「pLTV（predicted LTV）」を正式指標に設定
- **施策評価期間：1年 → 7日に短縮**

### 太一の示唆
SaaSのLTV運用は「データ取得設計」だけでなく「**ノーム値の発見**」がブレイクスルー。
案件ごとに固有のノーム値（早期データ ⇔ 最終KPIの相関係数）を探索することが、評価サイクル短縮の本質。

## 4. 案件成果

| 項目 | 内容 |
|---|---|
| 前年LTV確認結果 | 投資ポートフォリオが崩壊。**赤字プロダクト／過少投資プロダクトが存在** |
| 投資見直し後 | **全プロダクト黒字／過少投資プロダクトへ適切配分／ポートフォリオ最適化** |
| **数値インパクト** | **広告費 5,000万円減 ／ 粗利 1.8億円増 ／ 計上利益ベース 2.3億円創出** |

### 太一の解釈
「広告費を増やして売上を伸ばす」のではなく、**広告費を減らしながら利益を増やせる**のがLTV運用の核心インパクト。
ポートフォリオ管理の発想は、複数プロダクト／複数媒体を持つクライアントすべてに転用可能。

## 5. LTV運用の実行に必要なスキル

> 基礎的な構築であればLTV運用は**それほど難しくない**。
> IF文・参照系関数（XLOOKUP等）・四則演算程度の関数で自動化できる。
> ただし、**扱う行列数と処理回数が多いため、気合と情熱が必要**。
> 時間がかかるので**コンサル費＋作業費の請求を強く推奨**。

### 構築レベル別のツール

| レベル | ツール |
|---|---|
| **基礎的な構築** | GAレポーティング ／ Excel（毎日メンテ必要） |
| **ちょっと自動化** | スプシ（ファイル間自動連携に強い） ／ GAS ／ Data Portal |
| **ちゃんとした自動化** | BigQuery ／ SQL |

### 共通で必要なスキル
- **基礎的な予測スキル**（単回帰／重回帰）
- **ビジネスモデル ⇔ アウトプット ⇔ インプット の逆算思考**
  「こういうビジネスモデルなら → こういう指標が取りたい → そのためにはこういうデータソースが必要」

### 太一の示唆
SaaS／継続課金型クライアントへの**LTV運用構築は受託料金として明示請求する**ことが正解。
構築物の見た目以上に工数がかかる事実をクライアントと事前合意することが、提案成立の前提。

## 6. ミドルファネル（TVCM）をLTVで評価する手法 — 確定申告freee

### なぜLTVでミドルを評価するのか
- 認知増・セッション増・指名検索増ではなく、**LTV（粗利）でミドルを評価**
- ミドルとロワーを同じ指標で評価できれば、**ミドル×ロワーの予算アロケーションが可能**になる
- これがデジマス統合運用の核心

### 課題：TVCMはCookie・セッションで計測できない
- GAで顧客IDが取れない → 通常手法ではLTV算出不可
- AtmaでのCookie計測も可能だが：
  - 計測対象者が限定的
  - 世帯単位での計測
  - ITP影響を受ける
  - → 正確性・信頼性に欠ける、運用負荷も大
- ※Atmaは「傾向は悪」のために使うのが良い、と整理されている

### 解決：LTV計算式を分解して"観測可能な部分"で勝負する
```
LTV ＝ 登録数 × 7日課金率 × 7to90norm値 × 一人当たりLTV
```
- **「7日課金率 × 7to90norm値」はミドル実施時期の平均値を適用**
- そのため、**会員登録数のリフトさえうまく観測できればミドルもLTV評価可能**

### 会員登録数のリフトをどう測るか — Causal Impact
- **差分の差分法（DiD）の進化版**
- 「広告を打った時の実績値 − 反実仮想値（広告を打たなかった場合の予測値）＝ 広告効果」
- **反実仮想値をベイズ推計で高精度・高詳細に算出**

### 確定申告freeeの結果
| 項目 | 数値 |
|---|---|
| ミドルファネル投資額 | 約2.5億円 |
| 獲得LTV | 想定3.6億円 |
| **ROAS** | **142%** |

### ロワー追加投資との比較シミュレーション
| 投資先 | 純増ROAS |
|---|---|
| ロワーに2億円追加 | **30%未満（純増5,500万）** ※サチュレーション |
| ミドルファネル | **142%** |

→ 明らかにミドル投資の方が効率的だった。

### 補足：ミドル効果は指名検索だけでなくCTR・CVRも改善
一般論では「ミドル＝指名検索を増やす」だが、freee検証では**CTR・CVRの上昇にもつながった**。

## 7. さらに先進的な事例 — 余剰予算1,000万の最適投下

### クライアント依頼
「余剰予算1,000万が発生したので、最も効率の良いものに投下して」

### Irepの答え
「**テレビが最も効率的、急いでSAS（スポットアドサービス）で出稿**」

### 答えの裏側
- リスティングに1,000万追加した場合のシミュレーション
  - 純増ROAS 64%（赤字回収）
  - **サチュレーション**起こしていて、これ以上伸びない
- 同時期のテレビCM純増ROASは113%
- → 質の良い番組枠だけ抽出すれば、明確にテレビCMが効率的

### 「質の高い番組枠」を選ぶ方法 — ダブルスコア
- **テレビCM出稿前後3〜15分のWeb反応（スパイク）を観測し、放送枠の効果を可視化**するIrepオリジナルツール
- 枠単位でアクチュアルGRP・サイト流入数・流入効率が可視化される
- → **枠の買い足し判断に合理性を持たせる**

### 太一の示唆
「予算余ったのでロワーに突っ込んどく」がいかに非合理かを示す事例。
**サチュレーション診断 → ミドルへのスポット振替**という発想は他クライアントでもそのまま使える。
ダブルスコアのような枠評価ツールの有無で、TVCMのPDCA速度が桁違いに変わる。

## 8. うまく評価できなかった事例 — 会社設立freee

### 数値
- ミドルファネル投資の**サイト全体での純増ROAS：9%**
- ただしセッション数など流入指標は大幅リフト
- 興味喚起・サイト引き寄せの効果はあったと考えられる

### 仮説
- 「いつか起業したい人」へのリーチ・興味喚起がされた
- "いつか"なので即効性なく、CVRが低い
- 対照的に確定申告freeeはタイミングが確定申告直前で「**今すぐ確定申告しなきゃ**」層が多くROASが高かった

### 残された課題
- この人たちはいつ会員登録するのか？
- それをどう計測するか？
- freeeへの興味を持ち続けてもらうにはどうするか？

## 9. 2事例の総括 — デジマス統合運用が効く条件／効きにくい条件

鍵は「**検討期間**」にある。

### 効く（Good）：応用可能な案件タイプ
- ターゲットユーザーが多い
- 今やるべき理由がある（モーメント型）
- CVハードルが低い

**例**：ゲームアプリ／中低価格通販／無料サンプリングKPI
→ TVCM未実施なら、**TVCM導入で爆発的な改善余地あり**

### 効きにくい（More）：まだ評価手法が確立していない案件タイプ
- ターゲットが限定的
- 今じゃないけど"いつか"系ユーザーが多い

**例**：社内検討必要なBtoB商材／高価格"いつか"系（家・車・保険）／突発ニーズ商材（水道工事・消費者金融）

### 対策の方向性
**「モーメントが立った瞬間に、一番近くにいるブランドという状況を作り、その状況がどの程度の利益を生み出すかを評価する手法」が必要**

### 太一の示唆
SaaS／BtoBクライアントに認知投資を提案する際、**「今モーメントがあるか」をまず判定**する。
- モーメント型（確定申告／決算／引っ越しシーズン等）→ デジマス統合運用が刺さる
- "いつか"型 → 純増ROASでは評価しきれない。**ブランドリフト・想起率＋"モーメント時の指名検索/CV"の組み合わせ**で評価設計を考える必要がある

## 10. デジマス統合運用とは何か（Irepのポジション）

- ミドル（マス）とロワー（デジ）両方を運用・統合できるプレイヤーは市場に少ない
- Irepの強み：**クライアントの予算と成果を主語とした、デジマス間の自由自在な運用**
- コミュニケーション・クリエイティブ領域までを包括した統合ソリューション集団

### 太一の解釈
"運用代理店"と"クリエイティブ／マスメディア代理店"の境界が崩れている。
**REHATCH側からもLTV運用＋ミドル評価の手法を持てれば、運用の枠を超えた戦略パートナーになれる**領域。

## まとめ

1. **SaaSはLTVで運用設計する**。CPAだけで見るとプロダクト間ポートフォリオの歪みが見えない
2. CV〜売上のタイムラグは**早期データ ⇔ 最終KPIのノーム値**を発見することで予測可能（freee: 7日 vs 90日でR²=0.97）
3. TVCMは**Causal Impact × LTV計算式分解**でLTV評価可能に。ミドル×ロワーの予算アロケーションが現実解になる
4. 「予算余ったらロワー追加」は**サチュレーション診断**して、必要に応じてミドルに振替
5. **検討期間が短い／モーメント型商材**ではこの手法が刺さる。**"いつか"型商材**ではまだ評価手法の確立が課題
6. 構築物は意外と平易な関数でできる。ただし工数大なので**コンサル費＋作業費の明示請求が前提**
