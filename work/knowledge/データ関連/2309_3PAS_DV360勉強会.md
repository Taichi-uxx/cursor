# 3PAS・DV360勉強会 — Google Marketing Platform（SA360/CM360/DV360）と周辺計測ツールの全体像

## 出典
- ファイル: 3PAS・DV360勉強会.docx
- 種別: 社内勉強会資料
- 作成時期: 2023年9月（yymm = 2309）

## 用途（どんな時に活用できるか）
- 認知～獲得まで複数媒体を横断する大型クライアントに対し、媒体個別最適から「全体最適」への移行を提案するとき。SA360/CM360/DV360のどれが効くかをセットで語れる状態にする。
- ディスプレイや動画の認知施策を提案する際、「クロスメディアでの重複排除リーチ／ビュースルー計測／FQコントロール」をどう実現するかを設計するとき。
- 既にYahoo!とGoogleの検索アカウントを別運用しているクライアントに、SA360導入による媒体横断DDA・自動入札統合のメリットを定量的に説明したいとき。
- ブランドセーフティ／アドフラウド／ビューアビリティ（3大デジタル広告課題）の質問が来た際に、3PAS／DV／IAS／MOAT／CHEQの位置づけと使い分けを即答するとき。
- 店舗ビジネス（リテール／自動車／飲食）クライアントに対して、位置情報（Foursquare）×第三者配信での来店計測・ペルソナターゲティングを提案するとき。
- 既存案件でGoogle Adsだけ運用しているクライアントに、PMP／OTT／DOOH／タクシー広告／音声広告などプレミアム枠への拡張余地としてDV360を提案するとき。

## 概要
本資料は、Google Marketing Platform（GMP）を中心とした第三者計測・配信エコシステムを、戦略家視点で網羅的にカバーした社内勉強会資料。扱われるプロダクトは **SA360（検索広告自動最適）／Campaign Manager 360（第三者配信）／DoubleVerify・MOAT・IAS・CHEQ（アドベリ）／DAR（ユニークリーチ計測）／Foursquare（位置情報）／DV360（DSP）** の7プロダクト群。

中心思想は明快で、**「媒体個別運用では取りこぼす"横断"の価値を、3PAS／DSPレイヤで一元的に取りに行く」** という設計。検索（SA360）→ 計測（CM360）→ 品質保証（アドベリ）→ ユニーク計測（DAR）→ オフライン補完（Foursquare）→ ディスプレイ／動画／音声／OTT（DV360）という形で、ファネル全体を同一基盤で扱える状態を目指す。

特にCS／ディレクター視点で押さえるべきは、**「単独媒体の自動入札では到達できない最適化ポイント」が明確にいくつか存在し、それを解消するためにこれらツール群が必要になる**、という構造。たとえばYahoo!とGoogleの予算配分はSA360でないと横断自動化できないし、媒体横断のFQコントロールはCM360／DV360でしか不可能。これらをクライアントの課題に紐付けて語れるかどうかが、提案の幅を大きく分ける。

なお、3rd Party Cookie規制の進行により、DV360で利用できる3rd Partyデータは縮小傾向にあり、YouTube面では既に3rd Partyデータが利用不可。今後は1st Party／オフライン在庫（DOOH／タクシー／音声）への重心シフトが進む見通し。

## 本文構造

### 1. 3PAS（サードパーティ広告サーバ）プロダクト全体像

GMPおよびその周辺で3PASに分類される主要製品は以下の通り。

| 製品名 | 製品区分 | 製品概要 |
|---|---|---|
| Search Ads 360（SA360） | 検索広告自動最適 | YahooとGoogleを横断した全体最適 |
| Campaign Manager 360（CM360） | 第三者配信 | メディア横断ビュースルー計測／アトリビューション評価 |
| DoubleVerify／MOAT／IAS／CHEQ | アドベリフィケーション | ブランドセーフティ／ビューアビリティの保証 |
| DAR（Digital Ad Ratings） | デジタル広告リーチ計測 | 重複を除いたユニークなリーチ算出 |
| Foursquare | 位置情報計測 | 店舗来店計測／オフライン行動軸ターゲティング |

3PAS全体の特長は2軸でまとめられる。

- 運用と成果の **「効率・拡張」**：媒体個別自動入札では到達できない、横断的な予算配分・FQ最適化を実現。
- 媒体を横断した精緻な **「計測」**：ビュースルー計測／重複排除リーチ／アトリビューションが可能。

### 2. Search Ads 360（SA360） — 検索広告自動最適

#### 2.1 SAが解決する6つの課題

1. GACVのデータをYahoo!検索にも反映したい
2. GoogleのDDAモデルの成果が良いからYahoo!検索にも適用したい
3. 検索キャンペーンの予算配分を手動で行うと、成果の良いGoogleに寄らざるを得ない
4. 申込フォーム以外のサイト内情報も変数で取得して、CV重み付けの最適化精度を上げたい
5. Yahoo!とGoogleの検索アカウントを統合管理して、データも横断で使えれば良いのに
6. 在庫切れ商材の広告配信を自動で制御できれば運用も成果も効率化できるけど

#### 2.2 SAの仕組み

> YGを共通のタグ・入札戦略で管理できるため、CV重複を排除しつつデータ蓄積量増加によるパフォーマンス向上がSA360の大きな特徴。様々なデータソースを活用できるため、ゴール（目標）をカスタマイズした最適化配信が可能。

入札頻度の重要な差分：
- Googleの入札頻度は **リアルタイム**
- Yahoo!の入札頻度は **1日4回**（Yahoo!はSibylという予測アルゴリズムが活用される）

**Sibylとは**：YouTubeのレコメンドエンジンに使用されている予測アルゴリズム。KWや商品群のCVR予測のために、全KWと商品グループのエンティティ（LP／キーワードの意味／アカウント構成／ラベル等）から類似性を識別。データがまばらなロングテールKWについては、類似度が高い対象物のパフォーマンスから予測。外部シグナル（セール期間／天気／株価等）やサイクルパターン（週次／月次／休日）も活用。

| Googleアナリティクスデータ | △（YSAはAPI環境開発必須） | ○ |

| 入札可能ネットワーク | サーチ／ディスプレイ | サーチ／P-MAX |

#### 2.4 利用可能なコンバージョンソースとリアルタイム入札可否

| コンバージョンソース | Google Ads | YSA |
|---|---|---|
| Floodlightコンバージョン | ○ | × |
| Google広告コンバージョン | ○ | × |
| Adobeコンバージョン | ○ | × |

リアルタイム入札不可（×）のCVソースには **1日4回の入札調整** が入る。

> Google広告も重み付けして数式列に組み込んだ場合、1日4回の入札調整になるので注意（数式を調整する必要がある）。
> 例：`5×Floodlight_conv1 + 5×GoogleAds_conv1` → 1日4回／`5×Floodlight_conv1 + 1×GoogleAds_conv1` → リアルタイム入札

#### 2.5 Floodlightコンバージョンのカウント方法

Floodlightのアクティビティは2種類あり、それぞれに複数の定義方法を持つ。

**カウンタアクティビティ**（イベントに関連付けられたCV数をカウント）

| 定義方法 | カウント方法 |
|---|---|
| 標準 | すべてのコンバージョンをカウント |
| ユニーク | 24時間ごとに各ユニークユーザーの最初のコンバージョンをカウント |
| セッションごと | セッションごとに各ユーザーのコンバージョンを1回カウント。セッション長は定義可能 |

**セールスアクティビティ**（販売数や購入商品数をトラッキング）

| 定義方法 | カウント方法 |
|---|---|
| トランザクション | すべてのCVに加えて、発生した販売の合計数や関連収益の合計をカウント |
| 販売アイテム | 各CVに加えて、商品アイテムの合計販売数や関連収益の合計をカウント |

#### 2.7 ショッピング広告：商品ID単位の自動入札

「商品グループの自動細分化」機能により、収益力のある商品の露出機会を増やしつつ、**商品ID単位** でピンポイント自動入札最適化が可能。

#### 2.8 CM360／GA4／SA360の連携メリット

**CM360 × SA360**
- YouTubeの動画広告接触後の検索行動を経由したサイト訪問の間接効果を、CM360上で可視化・統合分析。
- SearchAds 360連携で「どのような検索クエリでサイトに流入したか」も可視化。
- 同一モバイル端末のWeb↔Appを跨いだパス分析が可能。

**GA4 × SA360**
- SA360管理画面で、独自CVタグで計測したCVと、GA4のアプリ＆サイトのエンゲージメント指標を **KWレベルで** 確認可能。→ 最もCV／エンゲージメントに寄与しているCP／広告／KWを可視化。
- SA360のトラフィック・メトリクスをGA4管理画面へエクスポート可能。
- GA4 CVをSA360にインポートして最適化可能 → サイト内の複雑なユーザー行動条件をGA4でCVとして計測し、SA360に引き渡せる。

#### 2.9 6つの課題への解決マップ

| 課題 | SA360での解決 |
|---|---|
| ①GACVデータをYahoo!検索にも反映 | SA独自CVタグで計測したCVをYahoo!入札に活用（GA4 CV連携で粒度拡張） |
| ②GoogleのDDAをYahoo!にも適用 | 媒体間で計測が分断されないため、媒体横断DDAが可能 |
| ③YGアカウント統合管理＆データ横断 | SA360上で入札戦略を設計し、YG横断の自動予算配分と全体最適 |
| ④サイト内情報を変数で取得し最適化精度UP | Floodlightで既存／新規・LTV評価・商品カテゴリ・購入金額等を取得し、数式列＋重み付けで入札最適化 |
| ⑤在庫切れ商材の配信を自動制御 | フィード連動でCP／広告グループ／広告／KWを自動生成。在庫切れは自動停止 |
| ⑥オフラインCVも最適化に組込 | オフラインデータをSA360にアップロードしCVソース化。ビジネスインパクトの大きいKPIで最適化 |

### 3. Campaign Manager 360（CM360） — 第三者配信ツール

#### 3.1 CM360が解決する6つの課題

1. 媒体を横断し、重複を排除したビュースルー計測を実施したい
2. 認知施策の効果測定をしたいが、媒体視聴の分散化で効果測定指標が統一できない
3. ユーザーがCVに至った経路と媒体間重複を可視化したい
4. CV経路を可視化し、アトリビューション評価へ繋げたいが知見がない
5. 媒体規格以上のメッセージ色が強いクリエイティブを動的に生成・配信したい
6. 媒体を横断したフリークエンシーコントロールを掛けたい

#### 3.2 第三者配信（3PAS）とは

> 第三者配信（3rd-Party Ad Serving）とは、従来媒体社やDSP等のアドサーバへそれぞれ直接入稿・配信されていた広告を、広告主側アドサーバで一元配信管理する仕組み。

活用観点は2軸。

**配信観点**
- 媒体横断でFQコントロールをかけたい
- 天気に応じてバナー内コンテンツを変化させたい

**効果測定観点**
- 複数媒体を同一基準で計測・貢献分析したい
- 媒体重複分析を行いたい

#### 3.3 配信観点：第三者配信の機能

| 機能 | 内容 |
|---|---|
| オプティマイゼーション | 均等配信、CTR／CVR等の効果によるリアルタイム最適配信 |
| シナリオ配信 | 想定シナリオに沿った優先順位での配信 |
| エリアターゲティング | 国・都市単位でエリア制御 |
| 時間／曜日／OSなど | ターゲットに合わせた配信 |
| FQコントロール | 各ユーザーの広告接触回数に合わせた配信制御 |
| ダイナミッククリエイティブ | クリエイティブ内の一部を可変にし動的に出し分け |

仕組みのポイント：
- アドサーバに代わりクリエイティブを配信する第三者配信サーバー。
- DSPやアドサーバー（媒体）の原稿規定や機能を超える表現をする際、媒体やDSPを横断でクリエイティブを制御する際に活用。
- **枠の買い付けが行えるわけではない**（あくまで配信・計測レイヤ）。

#### 3.4 計測観点：第三者配信の機能

媒体／デバイスを横断した効果測定＆アトリビューション評価が可能。ユーザーファネルに合わせた施策KPIを可視化：

- 認知 → リーチ重複配信
- 興味関心 → FQ別CTR分析
- 比較検討 → CV経路分析

第三者配信を行うと、施策全体の配信結果データがすべて集約されるため、媒体／メニュー個別の評価から、横断的な評価へ移行できる。

#### 3.5 6つの課題への解決マップ

| 課題 | CM360での解決 |
|---|---|
| ①媒体横断・重複排除ビュースルー計測 | CM360で広告（動画／静止バナー／検索）接触経路を可視化／クロスデバイスCV・ユニークリーチ計測（※ATTの影響でiOSは計測不可） |
| ②認知施策の指標統一 | 第三者配信で複数媒体を同一基準で計測 |
| ③CV経路と媒体間重複の可視化 | 媒体間重複リーチレポート／Path to CVレポート |
| ④アトリビューション評価への展開 | Path to CVで間接／直接効果を評価 |
| ⑤動的クリエイティブ | インタラクティブバナー（ユーザーアクションでパーツ切替）／DCO（外部データに応じた出し分け、例：天気） |
| ⑥媒体横断FQコントロール | CM360（およびDV360）で実現 |

### 4. アドベリフィケーションツール（DoubleVerify／MOAT／IAS／CHEQ）

#### 4.1 アドベリツールが解決する3つの課題

- 公序良俗に反するコンテンツや著作権侵害コンテンツに広告を配信したくない
- 人間ではなくボット（機械）が閲覧・クリックしている割合を確認したい
- 広告がちゃんと人間の目に触れているか精緻なデータが欲しい

#### 4.2 デジタル広告の3大課題

| 課題 | 内容 |
|---|---|
| ブランドセーフティ（掲載面の品質） | ポルノ・薬物・ヘイトスピーチなどの公序良俗違反、著作権侵害コンテンツへの配信 |
| アドフラウド（人間に届いてる？） | ボットによる閲覧・クリック。クリック偽装で予算が「盗まれる」 |
| ビューアビリティ（広告見られてる？） | サイトの下方に表示されImpはカウントされても、実際にはユーザーに見られていない |

#### 4.3 アドベリの3つの活用例

**活用例①：計測タグ挿入（除外はしない）**
- 各配信に計測タグを入れ、アドベリ的にどういう実績だったかを計測する。
- イメージ：AdFraudの高いサイトをBlacklistへ／BrandRiskの高い配信を停止／Viewable CPMでの評価開始／実績を基にアロケーション。

**活用例②：第三者配信からの出し分け（※3PAS必須）**
- 入札後にクリエイティブをサーブする際に、適切な面なら配信／不適切なら代替バナーという出し分け。
- AdFraud／Viewabilityは「入札してしまうこと自体が問題」なので、ここでは基本対象外。
- 主に **BrandSafety** に対して使うサービス。CPMで支払い済みでも、マイナスイメージを与える面は出し分けで除外できる。

**活用例③：入札時（Pre-Bid）ターゲティング**
- 入札時に各種アドベリ項目を参照し、入札するかを判定。
- ベリフィケーションベンダーがインテグレーション済の配信プラットフォームに限定。
- 配信除外（Blocking）と違い、**入札（配信）費用の無駄を防げる**。
- **Fraud／ViewabilityはPre-Bidでしか除外・ターゲティングできない**（事後では既に費用発生）。

### 5. DAR（Digital Ad Ratings） — デジタル広告リーチ計測

#### 5.1 DARが解決する課題

- ブランディング広告の効果測定で、Cookieではなく **人ベースのリーチ計測** を実施したい
- ブランディング広告配信先媒体でどの程度リーチ獲得できるか可視化したい
- 接触ユーザー属性やオンターゲット率を可視化したい

#### 5.2 デジタル広告計測の2課題

- **媒体選定**：媒体ごとに指標がバラバラで「誰が広告を見ているのか」がわからない → 【ターゲット層へのリーチ】を同一指標として媒体選定すべき。
- **過剰フリークエンシー**：ITPの影響で過剰FQをかけている可能性が高い → ターゲティング実施時にもリーチを確保できているか検証が必要。

#### 5.3 DARで計測できる指標（人単位）

- リーチ（何人？）
- 平均フリークエンシー（何回？）
- Gross Rating Point（延べ何回？）
- 構成割合（含有率）
- ターゲット（オンターゲット率）
- デバイス

DARの強みは「人数化ができる＝人数構成もわかる」「在庫構成（売り切れなかったIMP）もわかる」「PC・SPの重複を除いたユニークリーチ計測が可能」。Cookieレスを見据えた測定環境構築の中核。

### 6. 位置情報ベンダー（Foursquare）

#### 6.1 位置情報ツールが解決する課題

- 媒体ターゲティングではターゲティングしづらいペルソナがある
- Webサイトから実店舗へ誘導し、購買意欲の高いターゲティングを実施したい
- 広告配信先複数媒体を横断し、実店舗への来店リフト率を測定したい

#### 6.2 サービスラインナップ

**ターゲティング**：既存媒体で「媒体では出来ないターゲティング」を行い、新たな切り口の施策を実現
- 「高級住宅街居住・ゴルフ場に良く行く富裕層」「休日の海・山に行くアクティブ層」
- 「休日のサービスエリアに行くドライブ好き」「ジムやランニングをする健康関心層」
- 「テレワークしてる人」

**来店計測**：GDN／YouTube／サーチ／SNS広告等、各種優良媒体配信の来店CVを横断計測

#### 6.3 Foursquare × 複数媒体接触の来店計測

CM360を経由することで、DSPだけでなく **GDN／YouTube／Twitter** のビュースルー来店計測も可能。
※GDN・YouTubeなどGoogle Ads／DV360配信の計測でも **CM360利用が必須**。

#### 6.4 位置情報データの取得方法

「ユーザー（端末）の位置データ」「POIデータ（地点情報）」「来店判定アルゴリズム」の3要素を組合せて計測。

#### 6.5 課題別の活用パターン

**課題①：媒体ターゲティングではしづらいペルソナへのアプローチ**
- 「オフライン行動」軸で考えれば「媒体では出来ないターゲティング」が可能（例：Toyotaであれば自動車保有者の行動属性で切る）。
- 媒体ターゲと併用でより確度の高いターゲティング（例：「小さい子供の親」をターゲティング）。

**課題②：Webから実店舗誘導／購買意向の高いターゲティング**
- ロイヤリティ別ターゲティング：
  - 自社ロイヤルカスタマー → 限定クーポン等のリテンション策
  - 競合ロイヤルカスタマー → 「乗換割」クーポン等
  - 自社・競合両方に行く人 → ポイントプログラム案内
  - 離脱ユーザー → 「おかえり割」クーポン等
  - 最近初めて来た人 → 「2回目クーポン」等
- 商圏ターゲティング：徒歩圏内（小型スーパー・ドラッグストア）／自転車圏内（大型スーパー・ホームセンター・フードデリバリー）
- OOH補完：OOH周辺エリア（OOH接触者へのリタゲ、未接触者へのリーチ補完）
- ペルソナターゲティング：自動車／美容・ファッション／トラベル／B2B・ビジネスマン／消費財・食品・飲料メーカー の業界別ペルソナ多数

**課題③：複数媒体横断で実店舗の来店リフト率測定**
- CM360管理画面で「毎日」アップデートされる「来店CV」が確認可能。
- 来店率リフト計測：広告を「見た人」と「見ていない人」の来店率比較（「広告を見ずに来店した人」を除外）。
- 来店者の導線・アトリビューション分析：どの経路が一番CVに寄与したかを計測。

### 7. DV360（Display & Video 360） — DSP

#### 7.1 DV360の活用を推奨する理由

> DV360はSSP在庫とYouTubeの両方に配信出来る唯一のDSP。

特長：適切なオーディエンスに、適切なタイミングで、適切なコミュニケーションが取れる **世界最大級のDSP**。

#### 7.2 DV360とGoogle Adsの比較

**(1) 配信在庫**
- DV360の在庫量はGoogle Adsの **2.5倍ほど**。
- Adsだけ／DV360だけが買い付けできる配信面が存在する。

DV360でのみ配信可能な在庫：

| 在庫 | 概要 | 例 |
|---|---|---|
| PMP | 一部のラグジュアリー／テレビ系のプレミアム在庫。純広かPMPでしか購入できない超プレミアム面 | 日経、ダイヤモンドオンライン、グノシー、食べログ、VOGUE、GQ |
| OTT | 一部テレビ局の在庫 | 日テレ、TBS、テレ東、DAZN |
| Audio | Spotifyの一部メニュー／取引形態 | Spotify、YouTubeMusic、ラジコ |
| Rich Media | 主にネットワーク在庫。多彩なクリエイティブFMT活用 | — |
| DOOH | 屋外ビルボード・デジタルサイネージ。デジタル単体より認知・来店効果が向上する傾向 | — |
| タクシー広告 | 動画の視聴完了率が高く、都心の富裕層・ビジネス層にアプローチ可能 | — |

利用シーン例：与件「ブランドセーフティが担保されているサイトにだけ配信したい」→ PMP／OTT配信を実施でき、プレミアムな在庫のみへ配信可能。

**(2) 利用可能データ**
- DV360はGoogleオーディエンスデータに加えて、1st／3rd Party データの活用が可能。
- ただし **YouTubeでは3rd Partyデータは利用不可**。
- 3rd Party Cookie規制により3rd Party データは縮小傾向。

参考：DV360で利用可能なベンダー例
- Foursquare：位置情報を利用したセグメンテーション（来店計測も可能）
- マスターカード：購買データを基に作成されたセグメント
- PIA DMP：国内最大級のライブエンタメユーザーデータ

加えて、Viewability加味のターゲティングやプレースメント指定が可能。Googleデフォルトのアドベリに加え **IAS／DoubleVerify** も利用でき、「見られる」広告枠への配信でImp価値が上がる（※在庫数は制限されるので注意）。

利用シーン例：
- 与件①「ニッチなターゲティングで誘導効率よく配信」、与件②「獲得案件でポテンシャルの高いユーザーへ配信」→ 3rd Partyデータ＋Googleの最適化ロジックで配信安定。

**(3) YouTubeの利用**
- DV360・Google Adsともに、YouTubeへの配信は可能。配信メニューも基本的に共通。
- ただし、Google AdsではYouTubeのFQキャップは可能だが、他で配信しているGDNと **統合FQコントロールは不可**。
- DV360は **メディア横断で統合的にFQコントロール可能**。

利用シーン例：与件「YouTube配信が同じユーザーに偏ってしまうのでリーチ拡大のため他サイトにも配信したい」→ YouTube配信とディスプレイ・動画配信の統合管理、媒体横断FQコントロール。

**(4) 最適化入札テクノロジー**
- KPI／目的に合わせた入札戦略を指定し的確な配信を実施。
- クリック・CVだけでなく **視聴／Viewable指標** も加味した配信が可能。

**(5) 豊富なクリエイティブフォーマット**
- YouTube／Display／Outstream／Audio Ads／OTT／Taxi Ads／DataDrivenCreative／特殊FMT等。
- **Storytelling配信**：DV360はクリエイティブを跨いだStorytelling配信が可能。最大6STEPまでストーリー作成に対応し、ユーザーの態度変容検証が可能。YouTubeインストリームでのVAS配信も実施可。

## 太一視点の示唆 / 次のアクション

### A. 提案・営業文脈で押さえるべきポイント

1. **「媒体個別自動入札では到達できない領域」を5つ言えるようにする** — ①YG横断の予算配分自動化（SA360）、②媒体横断FQコントロール（CM360／DV360）、③媒体横断重複排除ユニークリーチ計測（CM360／DAR）、④商品ID単位のショッピング自動入札（SA360）、⑤PMP／OTT／DOOH／タクシー／音声などのプレミアム在庫（DV360）。これらをスラスラ提示できるかが、Google Ads＋Yahoo!広告だけのCSと、戦略提案できるCSの境目になる。

2. **「3rd Party Cookie規制」を中核に据えた説明軸を持つ** — DV360で3rd Partyデータが縮小／YouTube面では既に3rd Party不可／DARが「人ベース計測」を強みにする背景もここ。クライアントが「Cookieレス時代どうする？」と聞いてきた瞬間に、CM360＋DAR＋Foursquare（オフライン軸）の話に持ち込める準備をしておく。

3. **「iOS（ATT）の計測穴」を明示できる** — CM360のクロスデバイスCV・ユニークリーチ計測は **ATTの影響でiOS端末は計測不可**。提案時にここを隠さず明示することで、信頼を得られる。「iOS割合が高い案件なら別アプローチが必要」というファクトを持っているのは強い。

### B. 既存案件で即活用できる視点

4. **Floodlightで「価値の異なるCVに重み付け」を提案する** — SA360事例⑤（電気・ガス）／事例⑨（教育）／事例⑩（仮想通貨）の汎用パターン。CVが複数存在する案件は基本的にこのフレームで成果改善余地がある。担当案件で「CV種別ごとの売上／LTV差」を即座に確認するクセをつける。

5. **在庫連動キャンペーン自動生成は、EC／リテール／中古車／不動産系で即提案候補** — SA360事例⑥⑦は再現性が高い。在庫切れの広告配信で費用対効果が悪化している案件が既存にないか、棚卸しする価値がある。

6. **位置情報×3PAS連携で「店舗ビジネスのCS」になる** — Foursquareの来店計測はCM360必須。店舗ビジネスのクライアントを抱えているなら、CM360導入の提案セットで「Webから店舗までの一気通貫計測」を提案できる状態を作っておく。

### C. 戦略家として深掘りすべき問い

7. **「自動入札は本当に媒体内最適で十分か？」を常に問う** — Google AdsのtCPA／tROASは強力だが、Yahoo!や他媒体との予算配分・CV重複・媒体横断DDAは管理画面の自動入札では絶対に解けない。CPA改善で頭打ち感のある案件は、SA360／DV360導入が次の打ち手になり得る。

8. **「DDAをYahoo!にも適用できる」のインパクトを定量試算する** — SA360事例④（大手通信キャリア）の通り、YG横断DDAでYahoo中心の獲得伸長が出る。自社担当案件でも、Yahoo!の獲得構成比が低い案件は試算する価値あり。

9. **「アドベリのPre-Bid型」を必ず提案セットに入れる** — Fraud／Viewabilityは事後除外では費用が無駄になるため、Pre-Bid（入札時判定）でしか防げない。DV360＋IAS／DVのPre-Bid連携は、ブランド型クライアントに刺さる構造的優位。

10. **次のステップ**：①担当4〜10社のうち、SA360／CM360／DV360のいずれかが効きそうな案件をリストアップ（基準：媒体横断3つ以上／月予算500万以上／認知～獲得まで設計が必要）。②そのうち最も効きそうな1社にミニ提案を作る。③社内で3PAS導入の意思決定者にレビューを受けてから、クライアント提案へ。
