# GA4レポート活用ガイド：標準レポート・探索・広告・設定の全体像と使い分け

## 出典
- ファイル: GA4勉強会~レポート活用編~.docx
- 種別: 社内勉強会資料
- 作成時期: 2023年9月（yymm = 2309）

## 用途（どんな時に活用できるか）
- 新規クライアントのGA4管理画面に初めて入ったとき、どのメニューから何が読み取れるかを最短で棚卸ししたい
- UA時代の感覚で「カスタムレポート的な深掘りをしたい」と言われたとき、探索（自由形式・目標到達プロセス・経路データ等）のどれを使うべきか判断したい
- 「SNS投稿直後の反応を即時で見たい」「TVCMの効果を確認したい」など、即時性が求められるシーンでリアルタイムレポートを案内したい
- ECクライアントでCV経路・LTV・コホートを分析したい時、標準レポートでは足りない領域を探索でどう補うかの設計をしたい
- アトリビューション変更によるチャネル評価の見直し提案を、広告メニュー（モデル比較・コンバージョン経路）を起点に組み立てたい
- カスタムディメンション・カスタムイベント・オーディエンス設計を依頼された時、設定メニューでの操作手順と思想を即座に思い出したい

## 概要
GA4は「ヒット単位」のUAから「イベント単位」の計測モデルに移行し、アプリとウェブを横断したユーザーベース分析を可能にしたツール。BigQuery無償連携・予測指標・柔軟なCV設定・デフォルト取得イベントの拡充など、UA比で「分析の即時性／柔軟性」と「データ基盤連携」が大きく強化されている一方、ナレッジの蓄積が乏しく現場では「どの画面で何ができるか」がボトルネックになりやすい。

本資料はGA4の主要メニューを「レポート（標準）」「探索」「広告」「設定」の4ブロックに整理し、それぞれの役割・代表的な指標・使い分けの起点を示すリファレンス。

特に重要なのが「標準レポート＝定型観測」「探索＝自由仮説検証」という二段構えの理解。標準レポートはユーザー属性・テクノロジー・ライフサイクル（集客／エンゲージメント／収益化／維持率）を定常モニタリングする箱で、ディメンションは最大2軸まで。これに対し探索は3軸以上のディメンション組み合わせや、目標到達プロセス・セグメント重複・ユーザーエクスプローラー・コホート等、UAのカスタムレポート＋αに相当する深掘り機能群を提供する。

設定メニューはイベント／コンバージョン／オーディエンス／カスタムディメンションを司り、ここを整えなければレポートも探索も意味のあるアウトプットを返さない。「設定→計測→レポート観測→探索で深掘り→広告メニューで貢献度評価」というデータ活用の一連の流れを、本資料は俯瞰できる構成になっている。

## UA → GA4 の本質的な違い

| 観点 | UA（既存GA） | GA4 |
|---|---|---|
| データ計測の単位 | ヒット単位 | **イベント単位** |
| ナレッジの入手 | 〇（情報豊富） | △（情報が少ない） |
| 分析の即時性・柔軟性 | △ | 〇（予測指標／探索レポート等） |
| イベント収集の柔軟性 | △（追加実装が必要） | 〇（デフォルト取得イベント拡充） |
| BigQuery連携 | 有償版のみ | **無償版でも可**（※エクスポート上限あり） |

> GA4は、アプリとウェブの統合して解析を行える他、クロスプラットフォームでのカスタマージャーニー可視化、BigQueryへのデータエクスポート、予測データのマーケティング利用、コンバージョンの柔軟な設定が可能。

**示唆**：「UAの代替」ではなく「データ基盤（BigQuery）への入口」「機械学習活用（予測指標）」を前提にした設計思想。クライアントへの提案も「GA4で何が見えるか」より「GA4を起点に何ができるか」を軸に組み立てるべき。

## 標準レポート：定型観測の箱

### 全体感
- メニューはリニューアルでシンプル化。サブメニューは各サマリー画面から遷移
- 各レポートはカスタマイズ・ディメンション変更・セカンダリディメンション設定が可能（ただし**プライマリ＋セカンダリの2軸まで**）

### レポートのスナップショット
- ダッシュボード的な役割。主要指標を一覧把握、独自カスタマイズも可能
- 案件キックオフ時の「最初に見るべき画面」として使える

### リアルタイム
- **標準レポートでは前日までのデータしか見えない**。リアルタイムだけが今この瞬間の挙動を見せる
- 代表的な使用例：
  - SNS投稿後のサイト内行動の把握
  - TVCM影響の把握
  - 設定したタグが正常に機能しているかどうかの確認
- 取得できる主な情報：
  - 過去30分間における1分間ごとのユーザー数・デバイス別割合
  - リアルタイム流入中ユーザーの参照元
  - 表示中のページ・スクリーン（タイトル別／スクリーン別）

### ユーザー
- **ユーザー属性**：国・市区町村・性別等での比較
- **テクノロジー**：デバイス・ブラウザ・アプリバージョン別の確認
- それぞれ「概要（サマリー）」と「詳細」の2階層構成

### ライフサイクル（実務で最も使う）
ユーザーの一連の行動を「流入前 → 流入中 → 購買 → 流入後」の時間軸で追える構造。

1. **集客（流入前）**：アクセス情報・新規ユーザー獲得数・流入経路
2. **エンゲージメント（流入中）**：サイト／アプリにとって有益な行動を読み取る
3. **収益化（購買）**：オンライン購買行動の詳細（合計収益・購入数）
4. **維持率（流入後）**：維持率・継続ユーザー行動

#### 集客の使い分け：ユーザー獲得 vs トラフィック獲得
- **ユーザー獲得**＝ユーザー軸（そのユーザーが「最初に」どこから来たか）
- **トラフィック獲得**＝トラフィック軸（各セッションがどこから来たか）
- ディメンション例：「最初のユーザーのデフォルトチャネル」＝ユーザーの初回セッションのチャネル

#### エンゲージメントの定義
「エンゲージメントがあったセッション」に集計されるのは以下のいずれかを満たす場合：
- a. 10秒以上継続したセッション
- b. コンバージョンイベントが発生したセッション
- c. 2回以上のスクリーンビューやページビューが発生したセッション

> これらは「サイト、アプリにとって有益な行動（エンゲージメント）」と判断される

エンゲージメント配下のレポート：
- 概要：主要指標
- イベント：イベントベースでの詳細指標
- コンバージョン：CV設定したイベントの指標
- ページとスクリーン：ページ表示回数・スクリーン数

## 探索：GA4の目玉（仮説検証の場）

### 全体感
**UAでいう「カスタムレポート」に近い機能**だが、それを超える深掘り能力を持つ。

### メリット
1. **簡単な操作性**：ドラッグ＆ドロップで構築
2. **細やかな仮説検証**：標準レポートは「プライマリ＋セカンダリ」の2軸までだが、**探索は3軸以上のディメンションを指定可能**
3. **分析情報の共有**が可能
4. **探索でしか見られない指標**が存在する

### レポート種別と使いどころ

| 種別 | 用途 | こんな時に使う |
|---|---|---|
| 自由形式 | 任意の指標×ディメンションで自由集計、ビジュアル変更可 | 標準レポートで足りない切り口での集計全般 |
| **目標到達プロセス** | CVに至るステップを可視化、各ステップのユーザー動向確認 | フォーム離脱・カート離脱の特定／LP→申込のステップ最適化 |
| **セグメントの重複** | 最大3つのセグメント間の重複確認 | 「広告流入×購入者」と「リピーター」の重なり等、施策ターゲット精緻化 |
| **ユーザーエクスプローラー** | 個別（N1）ユーザーの行動分析 | 高単価ユーザーの行動再現／トラブル発生ポイント特定 |
| **ユーザーライフタイム** | LTVベースの分析 | LTV最大化施策の優先順位付け |
| **経路データ探索** | ツリーグラフでユーザー移動経路を表示（UAの「行動フロー」相当） | サイト内回遊設計の現状把握 |
| **コホートデータ探索** | 獲得新規ユーザーの再訪問・定着率を確認 | リテンション施策の効果検証 |

> ユーザーエクスプローラー：ユーザーごとに異なるユーザーエクスペリエンスを提供したり、特定のユーザーエクスペリエンスについての分析やトラブルシューティングを行ったりする場合に使用。
> 例：平均注文値が顕著に大きいユーザーの行動を分析したり、注文時に問題が発生するポイントを確認するなど

**示唆**：N1分析（ユーザーエクスプローラー）が標準機能で組み込まれているのはGA4ならでは。広告運用の「平均」では見えない優良ユーザー像を解像度高く描けるため、ペルソナ設計・クリエイティブ訴求の見直しに直結する。

## 広告：アトリビューションの再評価ツール

- **広告スナップショット**：概要画面
- **モデル比較**：各アトリビューションモデル（ラストクリック／データドリブン等）ごとの比較が可能
- **コンバージョン経路**：ユーザーのCVまでの経路を把握しつつ、アトリビューションモデルを切り替えることで**各タッチポイントの貢献度を臨機応変に把握できる**

**示唆**：ラストクリック評価だと過小評価されていた認知系チャネル（ディスプレイ／動画／SNS）の真の貢献を、モデル比較で定量的に再評価できる。クライアントへの予算配分提案の根拠として強力。

## 設定：計測基盤の心臓部

### 4つの設定対象
1. **イベント**：設定・変更、件数や上下動の確認、設定済みイベントのCV化が可能
2. **コンバージョン**：設定済みCVの件数・推移を確認
3. **オーディエンス**：オーディエンス設定／トリガー作成／ユーザー数・推移確認
4. **カスタムディメンション**（カスタム定義）：デフォルト以外の任意ディメンションを使用可能にする

### キーポイント
- **イベントのコンバージョン化**：GA4ではCVもイベントの一種。設定した任意イベントをトグル一つでCV化できる柔軟性がUAとの大きな違い
- **カスタムディメンション**：これを設定しないと、独自パラメータ（例：会員ランク・流入キャンペーン詳細など）はレポートで切り口として使えない。**計測設計の最後の仕上げ**として必須

## 太一視点の示唆 / 次のアクション

### 戦略上の気づき
- **GA4は「観測（標準レポート）」と「仮説検証（探索）」の二層構造**として捉えるのが本質。クライアントには「定常モニタリングはレポート、深掘りは探索」と説明し、両者を行き来する分析プロセスを設計する
- **設定 → レポート → 探索 → 広告（貢献度評価）** の流れが回って初めてGA4のROIが出る。設定（イベント・CV・カスタムディメンション）が雑なまま後工程に進むと、全てが砂上の楼閣
- **「ユーザー軸」と「トラフィック軸」を区別する文化**を組織に根付かせる必要がある。新規獲得効率を語るときは前者、CV直前のチャネル評価は後者、と使い分けを明示

### 次の一手（具体アクション）
1. **担当案件のGA4設定棚卸し**：イベント／CV／カスタムディメンションの設定状況を全件チェック。特に「カスタムディメンション未設定」「CVがGA4の自動設定のまま」のクライアントは即座に再設計提案
2. **クライアント向け定常レポート雛形を「標準＋探索」のハイブリッドで再構築**：スナップショット＋集客（ユーザー獲得）＋エンゲージメントを標準、目標到達プロセス＋コホート＋経路データ探索を探索で組む
3. **モデル比較を使った「アトリビューション見直し提案」を月次ミーティングの定番議題化**：ラストクリック偏重の予算配分を見直すきっかけにする
4. **N1分析（ユーザーエクスプローラー）を高LTVユーザー特定に活用**：上位購入者の行動経路から共通パターンを抽出し、新規獲得ターゲティングへフィードバック
5. **BigQuery連携を「未実装クライアント」全件で検討**：無償版でも可になったメリットを活かし、GA4の標準UIでは触れない深い分析を可能にする基盤を先回りで整備
6. **「リアルタイムレポートの活用シーン3点」をクライアントへ周知**：SNS投稿後／TVCM後／タグ実装直後の3つを定型化し、運用フローに組み込む
