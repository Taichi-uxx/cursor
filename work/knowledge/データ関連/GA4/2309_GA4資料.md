## 用途（どんな時に活用できるか）
広告運用と分析を回す戦略家として、以下のシーンで即座に開きたい資料。

1. **新規クライアントのGA4監査・初期設定**：プロパティ立ち上げ・データ保持14ヶ月化・参照元除外・クロスドメイン・IP除外などを抜け漏れなく入れる時のチェックリストとして
2. **GAからGA4へ移ったクライアントの数値説明**：「直帰率が消えた」「CV数が増えた」「滞在時間が短くなった」などのズレを根拠付きで説明する時
3. **CV・カスタムイベント設計**：GTM×DataLayer×カスタム定義の3点セットを忘れずに設計するためのレシピ集として
4. **探索レポートでの深掘り分析**：「成果に効いている流入元は？」「CV直前の経路は？」「離脱が多いLPは？」を出す時の12テンプレ集として
5. **BigQuery連携を提案・実装するとき**：無料版でも連携できる強みを生かしてLooker Studioや独自分析の幅を広げる際のセットアップ手順として
6. **GTM/GA4実装トラブルシューティング**：DebugView・gtm_debugパラメータ混入問題・サンプリング発生時の対処を即引きする時

## 概要
本資料はGA4（Google Analytics 4）の概論を、思想・計測仕組み・指標定義変更・プロパティ作成・初期設定・レポート・探索・セグメント・オーディエンス・AI機能・データインポート/削除・カスタム実装・eコマース・コンテンツグループ・デバッグ・BigQueryまで縦串で網羅した370ページの教科書。**「概論」と銘打つが、実務で必要な設定UIキャプチャと手順がほぼ全て含まれている**ため、リファレンスとして手元に置くべき水準。

GA4の本質は **「ページ×訪問」から「ユーザー×イベント」への思想転換**。これに伴い、セッション・直帰率・CV・滞在時間といった主要指標の定義が全て変わり、UAとの数値が原則ズレる。±5%が許容範囲、CVとセッション滞在時間はそれ以上ズレるケースもある、と小川氏は経験則を提示している。

GA4で初めて **無料版でもBigQuery連携が可能**になった点は分析の自由度を大きく広げる戦略的インパクトであり、本資料も後半1/3をBigQueryに割いている。一方で、データ保持期間は初期設定2ヶ月（探索機能のみ影響、要14ヶ月変更）、レポート用識別子（ブレンド/モニタリング対象/デバイスベース）の選択がしきい値発生に直結するなど、**設定ミスが分析の限界を決める**ポイントが多い。

なお、本資料のベース時点（2023年1月）以降、UAは2023年7月で計測停止済・画面閲覧も2023年末まで。GA4移行は既に完了フェーズだが、**「なぜそう設計されたか」を理解するために本資料の価値は不変**。

## 1. GA4の思想転換：なぜUAと数値が合わないのか

### 1.1 計測思想の根本的変化

| 観点 | GA（UA）まで | GA4 |
| --- | --- | --- |
| 基本単位 | ページ・訪問（セッション） | アクション（イベント）・ユーザー |
| 計測対象 | ページ表示中心 | ユーザー行動・態度変容 |
| データ種別 | pageview / event / Eコマース / カスタムDim を別々に送信 | **全てイベントとして送信**（PVもイベントの1種） |
| イベントの粒度 | カテゴリ・アクション・ラベル・値の4種固定 | イベント名+複数パラメータ（自由設計） |

> ページの表示を軸にした考え方は2005年当時は良かったが、現在はユーザーの行動の実態を表していない（P.23）

GA4が弱点とする「動画20分視聴後の離脱 vs 3秒で離脱」「アプリ計測」「最後までスクロール vs ただスクロール」「アプリ×ウェブ横断」を捉えるための変更。

### 1.2 GA4の4つの大きな変化（+1）
1. 全ての計測が「イベント」単位に変更
2. Google Signalとの連携強化（クロスデバイス・属性データ取得）
3. Googleタグ形式への移行（動的JSタグ）
4. **BigQueryの利用が無料版でも可能に**
5. （+）レポーティング画面の大幅変更（集計用「レポート」と分析用「探索」に分離）

## 2. イベント計測の仕組み

### 2.1 イベントの3種類
1. **自動取得イベント**：全プロパティで自動計測（first_visit / page_view / session_start / user_engagement）
2. **特定のイベント名の利用を推奨しているイベント**：オンライン販売の `purchase` `add_to_cart` `begin_checkout` 等、ゲームの `level_up` 等、専用レポートが用意される
3. **カスタムイベント**：独自のイベント名・パラメータで自由に計測

### 2.2 拡張計測機能で取れる主なイベント（管理画面ON）

| イベント名 | タイミング | 主なパラメータ |
| --- | --- | --- |
| scroll | 各ページの90%スクロール時 | page_locationなど |
| click | 外部ドメインリンククリック | link_url, link_domain, outbound |
| view_search_results | URLにq/s/search/query/keywordパラメータ含む時 | search_term |
| video_start / progress / complete | YouTube埋め込みで再生・10/25/50/75%進行・完了 | video_title, video_url, video_percent |
| file_download | pdf/xlsx/docx/txt/rtf/csv/exe/key/pp(t/tx)/7z/pkg/rar/gz/zip/avi/mov/mp4/mpe?g/wmv/midi?/mp3/wav/wma | file_extension, file_name, link_url |
| form_start / form_submit | 最初の項目から次の項目へ移動時 / 送信時 | form_id, form_name, form_destination |

### 2.3 計測の上限（無料版）

| アイテム | 上限 | 補足 |
| --- | --- | --- |
| イベント名で区別されるイベント | **ウェブは上限なし** / アプリは500個 | 自動収集・拡張計測は対象外 |
| イベント名の長さ | 40文字 | 超えると `_c` 付かずCV登録不可 |
| イベントあたりのイベントパラメータ | 25個 | 自動取得は含まない・BQでは集計可 |
| イベントパラメータ名の長さ | 40文字 | |
| イベントパラメータ値の長さ | 100文字 | |
| ユーザープロパティ | プロパティごとに25件 | |
| コンバージョン | 30個（旧GAは20個） | |
| 登録済みテキスト/数値パラメータ | 50個 | 利用推奨イベントは含まない |
| データ保持 | 最長14ヶ月 | **初期設定は2ヶ月→要変更** |
| 分析サンプリング上限 | クエリごと1,000万件のイベント | |

### 2.4 ユーザー識別のキー（IDの優先順位）

GA4は4種類のIDを以下の順で利用してユーザーを特定する。

| ID | 意味 |
| --- | --- |
| User-ID | 実装で設定（通常は会員ID等） |
| Google Signal | Googleログイン+広告最適化ONユーザーに自動発行。デバイス横断対応。**BQへエクスポート不可** |
| デバイスID（cid） | ファーストパーティーCookieの自動発行ID。〜2013年まではこれのみ |
| モデル化データ | Cookie/User-ID取得不可ユーザーの行動を機械学習で推定 |

レポート用識別子は管理画面で3種類から選択：
- **ブレンド**：1=UserID → 2=Signal → 3=デバイスID → 4=モデル化（推奨）
- **モニタリング対象**：モデル化を使わない
- **デバイスベース**：デバイスIDのみ評価

> Google Signalを識別子として利用すると「しきい値」が発生しやすくなり、少数データはレポートに表示されなくなる。**GA4導入時やテスト時は「デバイスベース」の利用を強く推奨**（P.107）

## 3. 指標の主な計測定義変更（実務でズレに困った時の根拠）

### 3.1 ユーザー
- レポート上の「アクティブユーザー」は**実ユーザー数ではなくエンゲージメントのあったユーザー**（user_engagementイベントで計測）
- 条件：前面（画面に映った状態）で**1秒以上のページ表示**
- 実ユーザー数を見るには「探索」機能の「ユーザーの合計数」を利用

### 3.2 セッション

| 項目 | UA | GA4 |
| --- | --- | --- |
| 滞在時間 | 最後のPV - 最初のPV | 最後のイベント発生時間 - session_start発生時間。前面表示時のみ計測 |
| 最長の長さ | 24時間 | 制限なし |
| 別セッションになるヒット間隔 | デフォルト30分（1分〜4時間で変更） | デフォルト30分（5分〜7時間55分・5分刻みで変更） |
| 流入元が変わった時 | 新しいセッション | **新しいセッションにならない** |
| 日をまたいだ時 | セッションが切れて別セッション | **別セッションにならない**（訪問回数は日ごとに1ずつカウント） |
| 日またぎデータ送付 | 4時間以内のデータを処理 | 72時間以内のデータを処理 |

### 3.3 コンバージョン
- UA：1回の訪問で複数回CV達成しても「1」しかカウントされない
- **GA4：1回の訪問で複数回CVするとその回数分カウントされる**
- そのため設定している目標によってはGA4のほうが件数が高く出る傾向
- CV率は別計算：
  - セッションCVR = CVが発生したセッション数 ÷ セッション数（**重複は1としてカウント**）
  - ユーザーCVR = CVが発生したユーザー数 ÷ ユーザー数

### 3.4 直帰率
- 定義が変わった：**「100% - エンゲージメント率」**
- 探索機能で利用可能。**今までのGAと直接比較できない指標**

### 3.5 エンゲージメント（新概念）
以下のいずれかを満たしたらカウント：
1. **10秒以上の滞在**（管理画面で10秒〜60秒の間で10秒刻みで変更可）
2. **2ページ以上の閲覧**
3. **CVイベント発生**

### 3.6 滞在時間が短くなる理由
- 該当ページ（ブラウザ）やアプリ画面が**ユーザーの視界に入る前面にあるときのみ**カウント
- 直帰や離脱ページの滞在時間はGAでは計算除外されていたが、**GA4では含むので短くなる要因**

### 3.7 流入元の分類が細かくなった
| 流入チャネル | 主な定義（一部抜粋） |
| --- | --- |
| Organic Search | Googleの指定検索サイト or Medium=organic完全一致 |
| Paid Search | Google Ads(Search/Partners) or 指定検索サイト×Medium=`^(.*cp.*\|ppc\|paid.*)$` |
| Paid Video / Display / Organic Social / Paid Social | （詳細はP.67参照） |
| Email | Source/Mediumがemail等 |
| Affiliate | Medium=affiliate |
| Direct | Source=直接 かつ Medium=(not set) または (none) |
| Mobile Push Notifications | Medium=push or Mediumにmobile/notification含む |
| unassigned | どの定義にも一致しない流入元 |

「Googleが指定している」リストがGAとGA4で違うため数値にズレが発生。

### 3.8 数値のズレ実例（小川氏の検証）

| サイト1（BtoCメディア） | GA | GA4 | ズレ率 |
| --- | --- | --- | --- |
| PV数 | 80,078 | 79,056 | 99% |
| セッション数 | 54,521 | 54,061 | 99% |
| ユーザー数 | 47,706 | 48,108 | 101% |
| 平均セッション時間 | 53秒 | 9秒 | **17%** |
| 自然検索流入 | 582 | 991 | **170%** |
| 離脱指標 | 直帰率83.8% | エンゲージメント率17.2% | — |

> **主要な指標は全てズレます。許容範囲は±5%。ただしCVとセッション滞在時間はそれ以上ズレるケースがある**（P.69）

**So What**：クライアント報告で「先月比較できない」とハマる前に、UA期間とGA4期間の境目で「定義変更による不連続」を必ず断り書きにする。

## 4. プロパティの作成と構造

### 4.1 GA4プロパティの作成パターン

```
GA導入済み？
├ Yes → GTM導入済み？
│   ├ Yes → GTMでGA4の記述を追加
│   └ No → gtag.js形式でGA計測中？
│       ├ Yes → gtag.jsをそのまま利用してGA4を導入
│       └ No → GTM導入後にGA4を設定
└ No → GTM導入後にGA4を設定
```

### 4.2 サブプロパティ・統合プロパティ（有償版のみ）
- **GA4には「ビュー」がない**。代わりにサブプロパティと統合プロパティで擬似的に再現
- **サブプロパティ**：1つのプロパティをフィルタ条件で絞り込んだ新プロパティ。参照元プロパティのイベント費用の50%が追加発生
- **統合プロパティ**：複数のプロパティをまとめた新プロパティ。同じく追加費用50%
- 注意：サブプロパティだけの新しいイベント追加は不可。データストリーム追加/削除、オフラインイベントインポート、イベント修正/削除も不可

### 4.3 デモアカウント
2種類が利用可能（Googleアカウントにつき100個まで）：
- **Google Merchandise Store**（ウェブデータ、UA/GA4両方）：https://shop.googlemerchandisestore.com/
- **Flood-It!**（アプリとウェブ、GA4のみ）：https://flood-it.app/

## 5. 初期設定チェックリスト（必須項目を太字）

| 名称 | 設定内容 | 必要性 |
| --- | --- | --- |
| プロパティのアクセス管理 | GA4の閲覧・編集権限の付与 | 必要に応じて |
| **Google シグナル** | サイト来訪者の属性情報取得（年代・性別・興味関心）+広告配信 | 要確認 |
| **レポート用識別子** | ユーザー識別子（ブレンド/モニタリング対象/デバイスベース） | 要確認 |
| **データ保持期間** | 探索機能で使えるデータ期間。**初期2ヶ月→14ヶ月推奨** | **必須** |
| **拡張計測機能** | ファイルDL・外部リンククリック等の機能拡張 | 要確認 |
| **アトリビューション設定** | デフォルトは「データドリブン」（機械学習形式）。要確認 | 要確認 |
| クロスドメイン設定 | 複数ドメイン利用時のみ。単一ドメイン+サブドメインは不要 | 必要に応じて |
| IPアドレス除外 | 社内アクセスの除外。CIDR方式・最大20個 | 必要に応じて |
| 除外する参照のリスト | EC決済等の外部経由を流入元として無視 | 必要に応じて |
| Google広告/AdManager/BigQuery/Search Consoleリンク | 該当サービス利用時に設定 | 必要に応じて |
| **コンバージョンの設定** | サイトで実現してほしい行動を登録 | **必須** |
| eコマーストラッキング | EC売上情報取得 | 必要に応じて |

### 5.1 IPアドレス除外の手順
1. 管理>データストリーム>Googleタグの「タグ設定を行う」
2. 「内部トラフィックの定義」→ ルール名+`traffic_type=internal`+IPアドレス指定
3. データ設定>データフィルタ>「Internal Traffic」を選択
4. パラメータ`traffic_type=internal`で除外設定
5. **テスト**で確認後、**有効**モードに変更（テスト/有効/無効の3モードあり）

注意：**正規表現は使えない**。CIDR方式で記述。

### 5.2 参照元除外の挙動
- 設定**してから条件が反映**される（過去に遡らない）
- **自ドメインは設定不要**（サブドメインも同様）
- 参照元のドメインが「クロスドメイントラッキング設定をしているドメイン」と同じ場合は参照元として計測されない

### 5.3 アトリビューションのモデル比較

| モデル名 | 意味 |
| --- | --- |
| **データドリブン（デフォルト）** | 機械学習。CVからの経過時間・デバイス・広告インタラクション数・表示順序など加味 |
| ラストクリック | 最後の流入元に全て割当（ノーリファラーの場合は次の流入元） |
| ファーストクリック | 最初の流入元に全て割当 |
| 線形 | 全チャネルに均等割当（ノーリファラーは無視） |
| 接点ベース | 最初と最後に40%ずつ、残り20%を均等 |
| 減衰 | CV発生から時間が近いほど貢献度大（半減期7日間） |
| 広告優先のラストクリック | 最後のGoogle広告チャネルに全割当。発生しない場合はラストクリック |

## 6. ユーザー権限管理

| 権限 | できること |
| --- | --- |
| 管理者 | ユーザー追加・権限変更・削除など全権限+編集権限 |
| 編集者 | プロパティ内の設定・編集権限+アナリスト権限 |
| マーケター | オーディエンス・CV・アトリビューション・イベント・ルックバックウィンドウの編集権限+アナリスト |
| アナリスト | アトリビューションモデル・カスタムレポートなどのアセット作成・編集・削除・共有+閲覧者 |
| 閲覧者 | レポートデータと構成設定の閲覧 |
| なし | 該当アカウント/プロパティの閲覧権限なし |
| コスト指標なし | コスト関連指標のみ閲覧不可 |
| 収益指標なし | 収益関連指標のみ閲覧不可 |

**注意**：アカウントで付与した権限は全プロパティに適用。プロパティ単独でより上位の権限を付与すると上書き。コスト/収益指標は例外で、アカウント禁止+プロパティ許可も可能。

## 7. レポート画面の構造

### 7.1 集計用「レポート」と分析用「探索」に分かれた最大の変更点
- **集計レポート**：「比較」はできるが「セグメント」は作成できない。全体状況の把握用
- **探索レポート**：データの深堀や気づき発見。Firebaseや有償版にあった機能をGA4に無料提供

### 7.2 5つのメニュー
| メニュー | 内容 |
| --- | --- |
| ホーム | 主要レポート案内・直近/閲覧頻度高いレポート案内・自動Insights |
| レポート | スナップショット・リアルタイム・ユーザー属性・テクノロジー・ライフサイクル（集客・エンゲージメント・収益化・維持率）・ライブラリ |
| 探索 | 自由形式・コホート・目標到達プロセス・セグメント重複・経路データ・ユーザーエクスプローラ・ユーザーのライフタイム |
| 広告 | スナップショット・パフォーマンス・アトリビューション（モデル比較・経路） |
| 設定 | 近々削除予定（管理画面に移動済） |

### 7.3 集計レポートの主要メニュー（2023年1月時点）
- **ユーザー属性**：国・市区町村・言語・インタレストカテゴリ・年齢・性別（後半3つはGoogle Signal有効時）
- **テクノロジー**：プラットフォーム・OS・デバイス・ブラウザ・画面サイズ・アプリバージョン・クラッシュ率
- **集客**：集客サマリー / ユーザー獲得（新規のみ）/ トラフィック獲得（全流入）
- **エンゲージメント**：概要 / イベント / コンバージョン / ページとスクリーン / ランディングページ
- **収益化**：概要 / eコマース購入数 / アプリ内購入 / パブリッシャー広告
- **維持率**：新規ユーザーとリピーター・LTV
- **ライブラリ**：レポートカスタマイズ機能

### 7.4 レポート機能のポイント
- データ期間：押下で設定画面。比較含め自由設定可
- セカンダリディメンション追加で内訳閲覧可
- ディメンションのフィルター：**部分一致のみ、正規表現不可**
- 比較機能：最大4個まで同時比較。AND最大5つまで、ORは使えない。比較の名称変更・保存不可（レポート間引継ぎあり）
- **比較の設定は「探索」に引き継げる**（探索ボタン）

### 7.5 ライブラリ機能（コレクション作成）
- 既存/新規レポートをまとめた「コレクション」を作成
- 「公開」することで同プロパティ閲覧権限者に共有可能
- サマリーレポート：最大16カードまで追加（ドーナツ/棒/データ表/マップ等）
- 詳細レポート：1から or テンプレートから。グラフ・指標・ディメンション選択可

## 8. 探索機能（最重要）

### 8.1 仕様
- **自分で項目を選ばないと何も出ない**
- **セグメント機能は探索内のみで作成可能**
- **前日のデータまでが対象**（当日データは見られない）
- データ期間とデータ量によってはサンプリングが発生
- セグメント・ディメンション・指標は**最大20個まで**選択可能
- 探索1つあたりセグメントは**最大10個まで**作成可能（違う探索を作成する場合は引き継がれない）

### 8.2 7つの手法（テンプレート）

| 手法 | 用途 |
| --- | --- |
| 自由形式 | ディメンション・指標を組み合わせた表/円/折線/棒/散布図/地図（最大500行） |
| コホートデータ探索 | 継続率分析（初回接触日/特定イベント等の登録条件→リピート条件→粒度） |
| 目標到達プロセスデータ探索 | 自由ステップ設定で遷移率を閲覧（ページである必要なし）。間接的ステップで他イベント有無・時間条件指定可 |
| セグメントの重複 | 最大3つのセグメントの重複人数・率をベン図で確認 |
| 経路データ探索 | ツリーグラフで遷移内訳。視点/終点指定可 |
| ユーザーエクスプローラ | ユーザーのログを個別閲覧。カスタムディメンション登録パラメータも表示 |
| ユーザーのライフタイム | ユーザー軸で見た滞在/セッション回数/収益などの分析 |

### 8.3 カスタムディメンションの登録（重要）

> **カスタム定義の登録を行わないと「探索」レポートで作成してイベントパラメータを利用することができません**（イベント名は自動で登録）（P.298）

**カスタムディメンション登録手順**：
1. 設定>カスタム定義
2. 「カスタムディメンションを作成」
3. ディメンション名・スコープ（**ユーザー or イベント**）・イベントパラメータ名を設定
4. スコープ選び：会員IDや累計購入回数→**ユーザースコープ**、お気に入り追加件数等→**イベント**

### 8.4 探索レポートの機能
- やり直す（Ctrl+Y）/元に戻す（Ctrl+Z）
- データ取得：Googleスプレッドシート/TSV/CSV/PDF/PDF(全タブ)
- 他ユーザーと読み取り専用で共有可能
- サンプリング情報表示

### 8.5 おすすめ探索レポート12選（小川氏選定）

| # | レポート名 | 主な設定 | 活用方法 |
| --- | --- | --- | --- |
| 1 | 時系列 | Dim=日付、指標=任意 | 数値変化発見→全指標 or 特定指標か→Dim追加で原因特定 |
| 2 | 集客 | Dim=デフォルトチャネルグループ+参照元/メディア、ネスト=Yes | 流入元の回遊・成果特徴を発見 |

| 4 | 訪問回数 | Dim=ga_session_number（カスタム登録）、指標=ユーザー/エンゲージ率/CV率 | 訪問回数ごとの分布・行動変化・CV率で再訪促進判断 |
| 5 | ランディングページ | Dim=LP | 第一印象を決めるページ、改善優先順位、離脱なし→滞在/CVに繋がっているか |
| 6 | 入口・出口ページ | Dim=ページ階層、指標=表示回数/閲覧開始数/離脱数 | 閲覧開始率・離脱率を算出して問題点を発見 |
| 7 | コンバージョン | Dim=イベント名、指標=CV/ユーザーあたりイベント数、Filter=CVイベント=true | CVR・各CV発生回数を流入元と掛け合わせて内訳発見 |
| 8 | 外部リンククリック | Dim=ページパス+リンク先URL、Filter=イベント名=click | 外部遷移元ページ・飛び先・クリック率（÷PV）を算出 |
| 9 | ファイルダウンロード | Dim=ページパス+リンク先URL、Filter=イベント名=file_download | DL元ページ・人気ファイル・DL率算出 |

| 12 | CV直前ページ逆引き | 経路データ探索、CV入口（フォーム等）を終点設定 | CV手前の動きを発見、上位順位確認、強める導線を決めて施策評価 |

## 9. セグメント機能

### 9.1 3種類のセグメントスコープ

| セグメント | 活用例 |
| --- | --- |
| ユーザー | 特定ユーザー群の母数・行動量、行動前後の動き、シーケンスセグメントで順番計測 |
| セッション | CVR算出のためのセッション数把握、特定アクション訪問時の動き把握 |
| イベント | 特定アクション・行動の発生回数把握 |

### 9.2 条件内のスコープ
| スコープ | 意味 |
| --- | --- |
| 全セッション | どのタイミングでも条件を満たせばOK |
| 同じセッション内 | 同セッション内である必要あり |
| 同じイベント内 | 同イベント内である必要あり |

**例**：流入元=Organic Search かつ purchase の場合
- 全セッション：該当ユーザーが検索流入かつ購入（時間問わず）
- 同じセッション内：検索から流入し購入したセッション
- 同じイベント内：検索流入直後が購入（基本発生しない）

### 9.3 セグメントの計算例（同じデータでも数値が変わる）
1ユーザー・3セッション・9PVで、ページBを見た条件を設定した場合：

| セグメント種別 | 結果 |
| --- | --- |
| ユーザーセグメント | 3セッション・9PV（条件満たすユーザーの全データ） |
| セッションセグメント | 2セッション・6PV（B見たセッションのみ） |
| イベントセグメント | 1セッション・3PV（B見たヒットのみ）（※実際は条件次第） |

「シーケンス」条件は**ユーザーセグメントのみ**利用可能。

## 10. オーディエンス

### 10.1 仕様
- 特定条件に合致するユーザー群を作成
- Google広告連携でリターゲティング配信に活用可
- 条件を満たした際に「イベント」として計測でき、CV登録も可能
- **過去にさかのぼっての再集計は行われません**（作成日から条件を満たしたユーザーが分類）
- 作成後の名称変更可、**条件は変更不可**
- 1プロパティ内100個まで

### 10.2 予測オーディエンス（利用条件あり）
**満たすべき条件**：
- 購入あるいは離脱が7日間で1000以上
- 上記状態を継続して満たしている
- ウェブ/アプリでの購入イベント実装

**利用できる指標**：
- 購入の可能性（過去28日来訪者が7日以内に購入する可能性）
- 離脱の可能性（過去7日来訪者が7日以内に来訪しない可能性）
- 収益予測（過去28日来訪者が今後28日に購入を通じて生む総収益）

## 11. AI的な機能

### 11.1 はずれ値の検出
予想値と実際値が外れた時にグラフ上で案内。トレーニング期間（最大日数）と感度を調整可能。

### 11.2 カスタムインサイト
推奨5種（1日のイベント数/ユーザー数/視聴回数/CV数/収益の異常値）+ゼロから作成可能。

**設定項目**：評価頻度・セグメント・指標・条件・値・比較期間・通知メールアドレス。

### 11.3 コンバージョンモデリング
- **流入元に紐付いていないCVに、機械学習で流入元を紐付ける**
- 背景：Cookie/App Tracking Transparency対応、広告クリックデバイスとCVデバイスが違う場合
- 効果：流入元不明（Direct）や未分類（UnAssigned）を減らす
- 2021年7月末から反映、過去データは対象外
- 影響レポート：イベント・コンバージョン・アトリビューション・探索の行イベント追加時など広い
- **「実データ」と「モデリングデータ」両方が合わさった数値で表示され、内訳は確認できない**

## 15. コンテンツグループの作成方法
- ウェブページやアプリ画面を自由なルールでグルーピングする機能

- **現状作成できるのは1種類のみ**（複数種類不可）

**実装**：
```javascript
// gtagの場合

```

## 16. デバッグ機能（DebugView）

### 16.1 表示される3条件のいずれか
1. **Google Analytics Debuggerの拡張機能をオンにしている時**（Chrome拡張）
2. **GTMやgtag.jsのイベント設定で`debug_mode=true`パラメータを設定している場合**
3. **GTMのプレビューモードでページを開いた時**

### 16.2 イベント色分け
- 青=通常イベント
- 緑=コンバージョンイベント
- オレンジ=エラーイベント

### 16.3 デバッグ運用順序
1. まずGTM側が正しく設定されているかGTMプレビューモードで確認
2. 問題なければGA4デバッグ機能でGA側にデータが正しく飛んでいるか確認
3. 問題無くGTMを本番公開したら、リアルタイムや通常レポートで確認

### 16.4 注意：gtm_debugパラメータ混入問題
GTMプレビュー時、URLに`?gtm_debug=x`が含まれるため、**パラメータ付きでGA4または旧GAにて計測される**（ページURLが汚れる）。

**除外方法**：
- **旧GA**：ビュー設定>除外するURLクエリパラメータに`gtm_debug`を追加
- **GA4**：パラメータ除外設定不可なので**IPアドレスで除外**を行う（GTMプレビューチェックを外す手もあるがサイト表示影響可能性あり）

## 17. BigQuery活用

### 17.1 セットアップ手順
1. **GCP側**：Google Cloud Platform→BigQuery→新しいプロジェクト作成（プロジェクト名・場所）
2. **GA4側**：管理>BigQueryのリンク設定>リンク>プロジェクト選択>データロケーション=東京(asia-northeast1)>データストリーム選択>頻度（毎日 or ストリーミング）

### 17.2 BigQuery無料枠
- データ保存：毎月10GBまで無料（以降$0.020/GB）
- データ取得：毎月1TBまで無料（以降$5/TB）
- 無料版GA4はBQに**100万ヒット/日**の制限あり

### 17.3 BQでのデータ構造
- 1つのプロジェクトに1つのデータセット

- テーブル名：`events_YYYYMMDD`

### 17.4 主要フィールド

| user_ltv | LTV情報 |

### 17.5 BQクエリ例

**ネスト解消**：
```sql
SELECT
  event_name,
  params.key AS event_param_key,
  params.value AS event_param_value
FROM `analytics_249579457.events_*`,
UNNEST(event_params) AS params
WHERE _table_suffix = '20201105'
  AND event_name = 'page_view'
```

**ディメンション+ユニークカウント（user_pseudo_id×event_timestampでユニーク特定）**：
```sql
SELECT
  PARSE_DATE('%Y%m%d', event_date) AS date,
  device.mobile_brand_name AS brand,
  device.operating_system AS OS,
  COUNT(DISTINCT CASE WHEN event_name='first_visit' 
    THEN CONCAT(user_pseudo_id, CAST(event_timestamp AS STRING)) END) AS first_open,
  COUNT(DISTINCT CASE WHEN event_name='page_view' 
    THEN CONCAT(user_pseudo_id, CAST(event_timestamp AS STRING)) END) AS pageview,
  COUNT(DISTINCT CASE WHEN event_name='file_download' 
    THEN CONCAT(user_pseudo_id, CAST(event_timestamp AS STRING)) END) AS file_download
FROM `analytics_249579457.events_*`
WHERE _table_suffix BETWEEN '20201101' AND '20201105'
GROUP BY 1,2,3
```

## 18. 太一視点の示唆 / 次のアクション

### 18.1 クライアント案件で即使う示唆

1. **GA4監査時の最優先4点**（数分で判定可能）
   - データ保持期間が14ヶ月になっているか（初期2ヶ月のまま放置されてる案件が多い）
   - レポート用識別子が用途に合っているか（テスト初期はデバイスベース推奨）
   - 参照元除外と内部IP除外が入っているか
   - CV設定30個の枠を使い切れているか・条件が正規表現/AND不要な形か

2. **GA4 vs UAの数値ズレ説明テンプレート**
   - 「主要指標は全て定義変更により±5%、CVとセッション滞在時間はそれ以上ズレることがあります（出典：HAPPY ANALYTICS 小川卓氏 ベンチマーク）」
   - 「直帰率は100%-エンゲージメント率なので、UAと比較ではなく『エンゲージメントセッション率』をモニタリングする運用に切り替えましょう」

3. **CV計測「水増し」リスク**：GA4は1セッション複数回CVを全カウントする。フォームのエラー再送信や複数ページ閲覧がCV条件だと、UAより件数が高く出る→**CVR算出時はセッションCVR/ユーザーCVRを併用**

4. **アトリビューションのデフォルトはデータドリブン**：機械学習で配分されており、ラストクリックと数値が違う。**Google広告のCV単価議論で「GA4のCV」を持ち出すときはアトリビューションモデルを揃える**ことを前提化

### 18.2 提案ネタになる活用ノウハウ

1. **無料版でBigQuery連携を案件に提案する切り口**
   - 14ヶ月の壁を越えてデータを長期保存
   - Looker Studioで複雑な集計（GA4画面では出せない）
   - CV直前経路の深掘り（経路データ探索の上限超）

2. **小川氏おすすめ探索12テンプレを案件用ダッシュボードに移植**
   - 「初回獲得エンゲージメント」「訪問回数別CV率」「主要導線の遷移」は広告運用に直結。月次レポートに固定枠で入れる

3. **オーディエンスを使った広告施策**
   - 予測オーディエンス（7日以内購入可能性高）をGoogle広告にエクスポートして高入札→CPA改善余地
   - CV未達成セグメントへのリターゲ配信

### 18.3 自分の知識ストックとしての発見

1. **「ユーザー軸」への移行は単なる集計変更ではなく、態度変容を捉える分析思想の変化**。GA4でPVのみ追っている運用は本質を取りこぼしている。**LTV/維持率/予測オーディエンスまで含めて初めてGA4の価値**

2. **カスタム定義の登録忘れが「分析が出せない」最頻ハマりポイント**：イベント名は自動登録されるがパラメータは手動。実装直後にカスタム定義のチェックを習慣化

3. **gtm_debugパラメータ混入問題**：自分が新規実装をする時にも発生する。本番反映前に必ず内部IP除外が効いていることを確認

4. **GA4のデータドリブンアトリビューション+コンバージョンモデリングはブラックボックス**。**「実データ」と「機械学習補完データ」の混在を意識しないと、「数字を信じすぎる」リスクがある**。レポート報告時には「機械学習による補完を含む」と注意書きする運用を検討
