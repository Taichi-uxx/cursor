# CDP導入とデータ利活用の3ステップ（社内勉強会まとめ）

## 出典
- ファイル: CDP勉強会.docx
- 種別: 社内勉強会資料
- 作成時期: 2023年9月（yymm = 2309）

## 用途（どんな時に活用できるか）
- クライアントに「CDP導入を起点としたデータ統合・利活用」を提案するときの全体ロードマップとして提示する
- 「とりあえずCDPを入れたい」という要望が出た際、Step①→②→③の順で着実に進める必要があることを説明し、いきなりツール選定から入ろうとする顧客の手戻りを防ぐ
- データ統合プロジェクトのキックオフで、要件定義に必要なステークホルダー（情シス／事業部／マーケ／GCPスペシャリスト等）を網羅的に洗い出すチェックリストとして使う
- GA計測環境の整備・計測パラメータガイドライン作成が「CDPに乗せるデータの源流」であることをクライアントに納得してもらう資料として援用する
- 自社（REHATCH）が広告運用だけでなく「データ取得〜統合〜利活用」まで伴走できることを示す提案書のベース素材とする

## 概要
本資料は、CDP（カスタマーデータプラットフォーム）を含むデータ利活用プロジェクトを「3つのステップ」で整理した社内勉強会の抜粋である。論点は**ツールではなくプロセス**にあり、「①データ取得 → ②データ統合 → ③データ利活用」という順序で、各ステップで何を決め、誰を巻き込むかを定義している。

CDPはこの流れの中で「②データ統合」の中核を担う基盤として位置付けられる。CDP単体を導入しても、Step①での計測設計が曖昧であれば乗せるデータが信用できず、Step③の活用ゴールが描けていなければ統合キーの選定もできない。つまりCDPは「前後の工程が整って初めて機能する基盤」であり、ツール先行ではなくゴール逆算で進める必要がある。

特に強調されているのが、**Step②の「ゴールから逆算」「ER図レベルでの整理」「優先順位付け」「全方位ステークホルダーの巻き込み」**の4点。データ統合は技術論ではなくプロジェクトマネジメントの仕事である、というのが本資料の通奏低音である。

## 本文構造

### Step① データ取得

データ利活用の起点。「何のデータを、どこから、どう取り続けるか」を決める工程。

1. **データの用途や場所、構造をヒアリング**
   - 接続環境、データ定義、更新スケジュールを確認する
2. **取得すべきデータの定義**
   - 用途から逆算して、本当に必要なデータだけを定義する
3. **実装・取得**
   - 必要なデータを**確実に計測し続けられる仕組み**の整備が必須
   - GAの計測環境の整備
   - 計測パラメータ・ガイドライン作成

> 必要なデータを確実に計測し続けられる仕組みの整備も必要

— ここが疎かだと、CDPに乗せるデータの品質が崩れ、後工程すべてが破綻する。「取得」は単発作業ではなく**継続運用のガイドライン作成**まで含むのがポイント。

### Step② データ統合

CDPの中核工程。複数ソースのデータを共通キーで紐付け、活用可能な状態に整える。

1. **IDの紐づけ・データの加工**
   - 紐づけキーの選定（顧客IDなのか、決算IDなのか等）
2. **紐づけキーをもとに自社データと外部データを統合**

#### データ統合の際のポイント（4点）

1. **ゴール（マーケティング上でどう活用するか）から逆算して考える**
   - ツール先行ではなく、活用シーンから必要な統合を定義する
2. **各データの連携状況を整理する**
   > ER図に落とし込めるレベルで

   — 「なんとなく繋がっている」では設計できない。テーブル単位・キー単位で図示できるレベルまで因数分解する必要がある。
3. **優先順位案の整理**
   - 実現可能性や施策インパクト等を考慮しながら、データ統合の条件や優先順位を整理する
   - 「全部やる」は失敗する。インパクト×実現可能性のマトリクスで取捨選択する
4. **ユーザー企業・ベンダー双方の様々な立場を必ず巻き込む**
   - 巻き込むべきロール例:
     - 全社DX推進部
     - 各事業情シス部
     - 新規リード獲得部
     - ナーチャリング部
     - プロマネ担当
     - GCPスペシャリスト
     - 広告運用担当
     - データ分析担当
   - これらを横断して要件定義＆ツール選定を行う

統合されたデータを実際の打ち手に変換する工程。想定される論点:

## 太一視点の示唆 / 次のアクション

### 示唆
- **CDP提案は「ツール選定の話」にしない**。Step①の計測設計が崩れていればCDPは無価値。提案の入口は必ず「現状の計測環境ヒアリング」から始めるべき
- **Step②の「ゴール逆算」は広告運用屋の強み領域**。「どんな配信・打ち手をしたいから、このデータを紐付けたい」という言語化は、データエンジニアではなくマーケ側（＝自分）にしかできない。ここで主導権を握れば、CDPプロジェクト全体のディレクションを取れる
- **ステークホルダー巻き込みリストはそのまま提案資料に転用可能**。クライアントの担当者は「情シスとマーケで握れていない」ケースが多く、このリストを見せるだけで「CDPは全社案件である」という認識を共有できる
- **Step③の余白が大きい**＝ここに自社の独自ノウハウ（広告運用×データ統合）を差し込む余地がある

### 次のアクション
1. このフレームを「データ統合提案テンプレート」として、現行担当クライアントで該当しそうな案件（特にGA計測が雑な顧客）に対し、診断シートを作成して提示
2. Step②の「巻き込むべきロールリスト」をチェックリスト化し、CDP・データ統合の話題が出た案件のキックオフで必ず使う
3. Step③（データ利活用）の「広告運用文脈での活用パターン集」を自前で整備し、本資料の欠損部分を埋める形で社内ナレッジ化する（LTV最適化／類似拡張／MA連携／LookerStudio可視化の4本柱）
4. BigQuery勉強会・TreasureData勉強会資料と接続し、「CDP（概念）→ BigQuery（基盤）→ TreasureData（製品例）」の階層で社内ナレッジを統合管理する
