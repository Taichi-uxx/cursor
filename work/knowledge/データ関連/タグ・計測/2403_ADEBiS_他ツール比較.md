# 計測ツール比較 ADEBiS vs 他社（GA4 / CATS / WebAntenna）

## 出典
- ファイル: ADEBiS×他ツール比較.pdf
- 種別: ベンダー（アドエビス／YRGLM Inc.）比較資料
- 作成時期: 2024年3月（yymm = 2403）
- 注意: アドエビス側が自社優位を打ち出す立場の資料。機能差・数値は事実として参考にしつつ、「○△×」の評価軸はベンダーバイアスを差し引いて読む。

## 用途（どんな時に活用できるか）
- クライアントへ計測ツール選定（新規導入）を提案するとき、ADEBiS／GA4／CATS／WebAntennaの違いを1枚で説明する
- 「GA4だけで十分では？」と問われたときに、GA4の弱点（ITP対策、CV行動可視化、サポート無し、データ反映の遅さ）を具体的に切り返す
- 既存ツール（CATS／WebAntenna）から乗り換え検討時の論点整理 — 特に「ユーザートラッキング期間」「クロスデバイス対応」「サポート体制」が判断の決め手
- ITP起因のCV乖離（媒体レポート vs GA計測）が発生しているクライアントに、原因と打ち手の選択肢を提示するとき
- 自社（運用代行）が広告効果測定の前提として、どのツールを推奨デフォルトに据えるかの判断材料

## 概要
本資料は、広告効果測定ツール「アドエビス（ADEBiS）」を、GA4・CATS・WebAntennaという3つの代表的なツールと、機能・計測精度・運用負荷の観点で比較したベンダー資料である。

比較の軸は大きく4つに整理されている。①設計思想（誰のための何のツールか）、②適切な施策評価・一元管理（CPA可視化、CV行動把握、計測環境）、③データ活用（Cookie規制への対策）、④活用難易度（メンテナンス工数・パラメータ設計・サポート体制）。

結論として資料は「ADEBiSが総合的に優位」と主張する。とりわけ差が出るのは、(a) ITP対策下でのユーザートラッキング期間（ADEBiS=最大366日 vs 他社=即時〜7日）、(b) クロスデバイス／クロスブラウザでの同一ユーザー類推（ADEBiSはAIで90%以上の精度、他社はほぼ不可）、(c) パラメータ自動入稿による設定漏れ防止（他社は手動運用で平均35%の媒体で計測漏れ発生）の3点。

後半では「データの正確性」を切り口に、ITP・クロスデバイス・パラメータ設定漏れの3トピックを深掘りし、池部楽器店（広告予算3倍・売上3倍）、ストリートアカデミー（予算2倍）の事例で訴求を補強している。

#### 3-1. 一元管理の表示形式の差（資料P.5）
- **ADEBiS**: 画面上で合計値が自動集計される。媒体種別／キャンペーン／広告グループなど、確認したい粒度をワンクリックで切り替え可能。
  - 例: キャンペーンA → クリック35,000／CV650 が1行で表示される。
- **CATS**: 画面上で合計値が自動集計されず、常時1行＝1パラメータ分のデータ。Excel等で再集計が必要なため、一元管理には不向き。
  - 例: キャンペーンA → A-1（クリック20,000／CV350）とA-2（15,000／300）が別行で表示され、合計はExcelで作る必要がある。

> 「同じ一元管理」と謳っていても、合計値の自動集計UIの有無で日常工数は大きく変わる、という訴求。

### 5. データの正確性（横断テーマ）

資料後半では「データの正確性」を3つの観点で深掘り。

```
データの正確性
├── 01. Cookie規制（ITP）対策
├── 02. クロスデバイス＆クロスブラウザへの対応
└── 03. パラメータの設定漏れ防止対策
```

#### 5-1. Cookie規制（ITP）対策

| ツール | 対応 | 内容 |
|---|---|---|
| ADEBiS | ○ | 最新のITP対策の設定で、最大366日間のユーザートラッキングが可能 |
| WebAntenna／CATS／GA4 | × | 通常「即時〜7日間」でCookie情報が削除される |

**仕組みの差**:
- 一般的な計測方式: タグ設置のみで計測可能だが、JavaScriptで付与された1st Party Cookieが即時〜最大約7日でITPにより削除される。
- 1st Party Cookieプログラム方式（ADEBiS推奨）: プログラムをお客様のWebサーバー上に設置し、サーバー側で発行される1st Party Cookieを用いて計測。ITP規制対象外となり延命できる。

> ITPでは「3rd Party Cookie」だけでなく「1st Party Cookie」も規制対象。規制対象外の（サーバー発行の）「1st Party Cookie」を使用することで、Cookieの延命を可能にしている。

**ITP分断のメカニズム（資料P.10の流れ）**: iOS/Safariユーザーが広告媒体A → 広告媒体B → 広告媒体C → 購入と遷移する間、A→B、B→Cの間が7日以上空くと、通常計測では各接点のCookieが切れて「最後の1〜7日以内」しか紐づかない。ADEBiSは366日トラッキングなのでファネル全体を捉える。

**事例 — 株式会社池部楽器店 × イレストプラス**（ITP / EC）
- 課題: GAではWeb広告経由売上が全体の約10%だったが、媒体レポートでは約20%と大きな差異
- 結果: ITP対応により「GAではDirect扱いだった広告流入」を広告として復元。アドエビスでの広告紐づけCV数はGAの2倍。
- インパクト: 正確な投資判断により広告予算3倍・売上3倍

| - | click | 直接CV | 初回接触 |
|---|---|---|---|
| Direct（ITP分断後の見え方） | 1 | 0 | 0 |
| 自然検索 | 1 | 1 | 0 |
| ↓ ITP対策後 | | | |
| 広告 | 1 | 0 | 1 |
| 自然検索 | 1 | 1 | 0 |

#### 5-2. クロスデバイス・クロスブラウザ

| ツール | 対応 | 内容 |
|---|---|---|
| ADEBiS | ○ | 機械学習により一部ユーザーの紐づけが可能 |
| GA4 | △ | Googleアカウントデータを基に一部ユーザーの紐づけが可能 |
| WebAntenna／CATS | × | クロスデバイス・クロスブラウザの発生で別ユーザーだと認識される |

**クロスブラウザ発生の典型例**: Instagram広告 → アプリ内ブラウザ内LP → 離脱 → デフォルトブラウザでGoogleリスティング広告 → LP → CV。アプリ内ブラウザとデフォルトブラウザは別ブラウザ扱いになるため、通常は同一ユーザーと認識されない。

**ADEBiSのAI類推の仕組み**:
1. 各種アクセスログ（PV／Click／View／CV／Search）をADEBiSに蓄積
2. ユーザーIDなどの確実なデータから同一ユーザーを収集（教師データ化）
3. 独自開発のAI（特願2018-115031）＝機械学習で類推
4. 不明ユーザーを既知の同一ユーザー群に紐づけ
5. 90%以上の精度でユーザー特定（実クライアントデータでの検証結果）

**事例 — ストリートアカデミー（クロスデバイス分析）**
- 課題: Facebookの評価が急激に下がり予算を50%削減 → CV数も悪化。仮説：ブラウザ／デバイス跨ぎでCookie分断
- 結果: クロスデバイス分析でFacebookの成果は約2倍に修正。Facebook管理画面でも「スマホ接触→PCでCV」のケースを確認
- インパクト: 予算2倍

#### 5-3. パラメータ設定漏れ防止

**実態（n=156）**:
- 完璧: 101件
- 〜10%漏れ: 23件
- 〜30%漏れ: 16件
- 30%〜漏れ: 16件
- → **約35%の媒体で計測漏れが発生**

**計測不備の典型ミス**:
- フラグメント「#」と「dmai=」を並べて記述: `{purl}#argument=●●●●●&dmai=■■■■`
- 「?」と「ai=」を並べて記述: `{purl}?utm_source=yahoo&utm_medium=display&utm_campaign=~~~&ai=■■■`
- Facebook広告のURLパラメータにフラグメント「#」を利用
- パラメータの記載ミス（？抜けや、スペルミス等）

> 当社調査によると、アドエビスと接続されている媒体の約35%で計測漏れが発生。サポートに寄せられたお問い合わせから1万Click強の計測漏れが判明するケースもあり、設定ミスが機会損失につながっています。

**ADEBiSの解（AD EBiS シンク）**:
- 通常フロー: 媒体登録 → ツール側で広告登録（入稿用パラメータ発行） → 媒体側で入稿用パラメータ登録・出稿開始 → 計測開始
- AD EBiSシンク: 媒体登録 → （中間ステップ省略） → 計測開始
- 対応媒体: Google, Yahoo!, Facebook（Instagram）

### 6. まとめ — ベンダー資料の主張ポイント

- **トラッキング期間**: ADEBiS 366日 vs 他社 7日（GA4は90日だが反映遅・サポート無）
- **クロスデバイス**: ADEBiSのみ実用水準（90%以上の精度）、GA4は限定的、CATS/WebAntennaは未対応
- **入稿パラメータ**: ADEBiSは主要媒体で自動化、他社は手動 → 35%が計測漏れリスク
- **サポート**: ADEBiS専任 vs GA4無し／WebAntennaメールのみ／CATSはChatwork等

## 太一視点の示唆 / 次のアクション

### バイアスを差し引いた読み方
- この資料は「ADEBiSが○、他社が×／△」という構図で書かれており、評価記号そのものはベンダー視点。鵜呑みにせず、**(a) 数値（366日／90日／7日、35%、90%、月額3万円など）と (b) 仕組みの差（1st Party Cookieプログラム、AI類推、自動入稿）** を事実として抜き出す。
- GA4の弱点として挙げられている「CPA一覧不可」「CV行動可視化困難」は、Looker Studio／BigQueryで補完すれば実用上は問題ない領域もある。ADEBiSの優位は「すぐ使える状態で揃っている」点であり、「絶対にGA4ではできない」わけではない。

### 提案・選定時の判断軸
1. **ITP影響の大きさで分岐**
   - iOS／Safari比率が高い案件（BtoC EC、女性向け、若年層）→ ADEBiSの366日トラッキングの恩恵が大きい。媒体レポートとGA計測の乖離20%以上が出ているなら、まず疑う。
   - BtoB SaaS（PC Chrome中心）→ ITP影響は相対的に小さい。GA4＋媒体管理画面で十分なケースも多い。
2. **クロスデバイス／クロスブラウザの重要度**
   - Instagram／TikTokなどアプリ内ブラウザ起点の流入が多い案件は、ADEBiSのAI類推が刺さる。
   - 検索広告中心・PC完結ジャーニーなら優先度は下がる。
3. **運用体制の成熟度**
   - パラメータ設計を運用者が手動で管理している現場 → 35%計測漏れリスクは現実的。AD EBiSシンクの自動入稿で人的ミスを潰すROIは大きい。
   - すでに入稿フローが自動化されている／ガバナンスが効いているなら、ADEBiSである必然性は薄れる。
4. **コスト感**
   - GA4「無料」の裏には、GTM Server-Side（月額3万円〜）／BigQuery／構築工数が乗る。ADEBiSの月額と総コストで比較する視点を持つ。

### クライアントへの切り返しテンプレート
