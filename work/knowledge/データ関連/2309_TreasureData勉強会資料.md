## 用途（どんな時に活用できるか）
戦略家視点で「いつ取り出すか」を明確化したシーン集。

1. **クライアントへのCDP提案／比較検討の論点整理**  
   既存のCDP・DMP・DWHを比較する場面で、Treasure Data側の強み（国内シェア41.7%／500超のコネクタ／FISC・GDPR等のコンプラ対応／日本リージョン選択可）を即座に提示できる。Salesforce CDP・Adobe・Tealium・mParticleなど競合15社との位置関係も把握しておく。
2. **「データがサイロ化しています」というクライアントの悩みに対する解像度上げ**  
   EC／マーケ／店舗／営業／製造のデータ統合という典型構図を、CDPで解く絵で説明できる。導入事例（アパレル／流通小売／健康食品）の課題→施策→成果の型をそのまま提案書テンプレに転用可能。
3. **広告運用ディレクターとして「CDPを噛ませる広告施策」を設計するとき**  
   Cookieレス時代の1st Party Dataとして、ハッシュ化メールやIDFAをキーに各広告媒体（Google／Facebook／LINE／TheTradeDesk／Criteo／DSP各社）へどう連携できるか、Profile APIで3rd Party Cookieに依存しないターゲティングを実現する流れを説明できる。
4. **広告以外の出口（Web接客・MA・コールセンター）まで含めたCRM横断提案**  
   KARTE・VWO・Google Optimize・Salesforce Marketing Cloud等との連携パターンを示し、広告だけでなく「データを溜める→分類する→全チャネルに出す」の絵で提案を厚くする。
5. **機械学習を絡めた「次のひと押し」提案**  
   Predictive Scoring（教師データと予測対象を2セグメント指定するだけで100点満点／ABCDランクが自動付与）の活用で、解約予測・LTV向上・成約率3.3倍など、CPA改善の先にある売上・利益直結の打ち手を提示できる。

## 概要

Treasure Data CDPは、米国Mountain Viewに本社を置くTreasure Data inc.（2011年12月設立）と、日本法人トレジャーデータ株式会社（2012年11月設立、千代田区）が提供するCustomer Data Platform。創業期は「Hadoop as a Service（ビッグデータ基盤）」として始まり、2016年からCDP提供を開始、2020年以降は「DXを支えるプラットフォーム（Digital Transformation Platform）」として位置付けを進化させている。国内CDPシェア41.7%（2020年度予測、ITR調査）でトップ。Forbes Global 2000の国内218社のうち60社以上が導入済み。

製品の本質は「散在しているデータの統合基盤」。EC・マーケ・店舗・営業・製造といった事業部／チャネルごとにサイロ化したデータを、"個客"（個別の顧客IDを軸に解像度を上げた顧客）単位で名寄せ・統合・分析し、500を超えるコネクタで広告・MA・LINE・コールセンター等の施策ツールに連携する。Hive / Presto / Hivemall / SQLによる分析エンジンとWorkflowによるジョブ管理、Audience Studio（セグメント管理GUI）、Predictive Scoring（機械学習）、Profile API（Webサイト／広告へのリアルタイムセグメント返却）を内包する。

2021年9月以降は"Beyond Marketing"をテーマに、マーケティング領域を超えて「Treasure Data CDP for Service（カスタマーサポート向け）」「Treasure Data CDP for Sales（営業向け）」もリリース。次世代CRMのデータ基盤として、顧客とのリレーション全般に活用領域を拡張している。

国内対応の手厚さも特徴で、2000ページ超の製品ドキュメント日本語化、CCO設置、日本リージョンのデータセンター選択可、FISC安全対策基準対応、改正個人情報保護法に対する知見提供などエンタープライズ要件を満たす体制を整える。Advertiser Perceptionsの調査ではArchitecture（87%）／Compliance/Privacy（89%）／Scalability（85%）／Data Security（85%）の全カテゴリで主要CDP15社中1位を獲得。

#### 2-2. 事例1: アパレル企業（39ブランド・1300店舗のグループ）
- **背景**: ECサイト運営・デジタル戦略を管轄
- **課題**: DWHと一部ツール連携で成果は出ていたが、配信先拡張時の開発スピード・工数が多大／1st Party Dataだけではチャネルアクセス時のデータに留まり、顧客解像度が上がらない
- **選定理由**: 外部連携の豊富なコネクタ／外部データを含む統合管理が可能
- **実現内容**: 複数サイト行動データと既存DWH／購買・会員DBを統合、Treasure Data CDPで広告配信先拡張。3rd Party Data（デモグラ、職業、世帯年収、興味関心：旅行/料理/美容）を活用し顧客データをリッチ化。連携先はCriteo、MicroAd BLADE、AudienceOne等
- **成果**: 広告配信先拡張を初期開発コスト・工数をかけず約2ヶ月で実現／行動データ取得元サイトの拡大とMA連携によるCRM活用も予定／ブランド横断の買いまわり・解像度の高い分析が可能に

#### 2-3. 事例2: 流通／小売業
- **課題**: アプリ導入を進めていたが、活用するためのデータ統合基盤がなかった／DX推進が決まったが社内データが散在
- **施策**: 自社サイト・ECサイトログ、複数ドメインのオウンドメディアログ、会員ID、購買データを統合
- **構成**: WEBデータ（アクセスログ／オウンドメディア／アプリログ）と基幹システムデータ（顧客／購買）をTreasure Dataに集約し、MA（メール・アプリプッシュ・コンテンツ出し分け）と広告配信に展開
- **成果**: アプリ導入後のデータ収集／施策実施をスムーズに実現／会員行動分析でメッセージ精度・コンテンツ出し分けを実現／新規購入促進・新規会員獲得プラットフォームとして活用

#### 2-4. 事例3: 健康食品メーカー
- **Before**: RFM分析で「N+◯日」の画一ルール×紙カタログによるコミュニケーション／基幹システムからのデータ出力をSQLで生成し直接施策ツール連携で運用負荷大
- **After**: 購買データに加えリアルタイム行動ログを追加し顧客セグメント細分化／固定の「N+◯日」シナリオから脱却／施策ごとに様々な切り口の分析が可能に／CDPコネクタ活用でMAツールやLINEなど新チャネルとの柔軟な連携を実現
- **構成**: Web（ECサイト・広告LP）／オフライン（電話・紙カタログ）／基幹システム（顧客・商品・注文履歴・売上）→ Treasure Data → 4つのデータマート（分析用→Tableau／レコメンド用→Rtoaster／外部連携用→ADNW・DSP・SSP／MA用→WEBCAS・Salesforce Marketing Cloud・TONARIWA）
- **KPI**: 主力製品のライン使い／1年以上継続で離脱率低減

### 3. Treasure Data サービス概要

#### 3-1. CDPによる顧客理解の高解像度化
- **静的データ**（顧客属性・購買データ等、一時点の事実）と**動的データ**（Web/Appの行動データ）を統合
- 既存顧客の鮮明化、潜在顧客の捕捉、施策実行精度の向上
- 購買結果だけでなく**プロセスを含めて顧客行動を一元把握**

#### 3-2. CDPの役割と必要要素
| # | 重要なこと | 必要な要素 | 仕組み／インフラ |
|---|---|---|---|
| 1 | 個客理解の深化 | 事業で発生するデータを保有する | 基幹DB／DWH |
| 2 | 個客理解の深化 | "個客"単位でデータを統合／管理 | **CDP（Treasure Data）** |
| 3 | 個客理解の深化 | 最適コミュニケーションのため"個客"を分析・分類 | **CDP** |
| 4 | 個客コミュニケーション | "個客"データを各プロセスに連携 | **CDP** |
| 5 | 個客コミュニケーション | "個客"に応じて最適コミュニケーションを実行 | 施策ツール |

#### 3-3. CDP活用の有無による顧客理解の差（例: 桃スイーツ購入のBさん）
- **CDP無**: サイト/アプリ・オンラインショップ・店舗の3チャネルそれぞれで「桃に興味がある人」「閲覧後離脱した人」「複数日にわたって桃関連商品を購入した人」と**分断**された理解
- **CDP有**: 7/23にSNSで桃フェアを認知→サイトで商品・関連ページ閲覧→A店で白桃ショートケーキ購入→7/30に白桃プレミアムパフェ購入、という**統合された一人のジャーニー**として把握可能

#### 3-4. Treasure Data CDPの5つの特長（Digital/Physicalのデータを人を起点に繋ぐ）
- **Point 1**: 多種多様なデータ蓄積基盤（フルマネージドのデータマネジメントサービス、超大規模・多様なデータを柔軟に集計／分析）
- **Point 2**: 外部ツールとの連携処理（500を超えるマーケティングツールへのデータ連携／広告施策含む）
- **Point 3**: データ分析処理の基盤実装済み（機械学習による類似ユーザー抽出、自然言語処理など多様なソリューションを実装済み）
- **Point 4**: 外部企業とのデータ連携（Treasure Dataユーザー企業同士でのデータ連携／広告施策含む）
- **Point 5**: セキュリティ・安全・防護・保障（迅速丁寧なサポート含む）

#### 3-5. Treasure Data CDPの全体像
- **データ収集・連携**: 顧客/会員・購買・CRM・広告ログ・ソーシャル・App・Web・外部 → Connector/Embulk/SDKによるデータ収集・連携機能
- **データ統合・管理・分析**: 分析エンジン（Hive/Presto/Hivemall/SQL）／ジョブ・フロー管理（Workflow）／可視化／統計解析／BI／スコアリング（Predictive Scoring）／セグメント管理（Audience Studio）
- **データ活用**: 広告配信・コンテンツレコメンド・メール・LINE・ソーシャル・アプリメッセージ・コールセンター・接客

#### 3-6. データフロー: Raw → Element → Master Segment → Segment → Activation
```
Owned System → ①データ収集処理（JSタグ／Mobile SDK／Data Connector）
            → Raw Data
            → ②加工/集計処理（SQL）
            → Element Data（マスタ・属性・行動）
            → ③Master Segment生成（GUI）：会員オーディエンス／アノニマスオーディエンス
            → ④Segment生成（GUI）：購入金額・入会年月・家族構成・居住地・WEB訪問・趣味嗜好など
            → ⑤Activation設定（GUI）
            → Campaign：通知（メール/LINE/PUSH）・システム連携（MA/リアル接点）・画面出し分け・広告出稿・可視化
```
**役割分担**: ①〜③（Raw→Master Segmentまで）は**IT・情シス**領域、④〜⑤（Segment生成・Activation）は**マーケター**領域として明確に分かれているのが運用設計上のポイント。

### 6. Profile API（広告／Web接客／コンテンツ出し分けの起点）

#### 6-1. Profile APIとは
Treasure Data CDPのAudience Studioで作成したセグメントの「**セグメントID**」「**アトリビュート**」情報をAPIでWebやアプリに送信できる機能。

**動作フロー**:
1. ユーザーがWebサイト訪問
2. TD_JS_SDKがUser ID（Cookie or ADID/ADFA）をTREASURE CDP（Web Personalization API / Customer Profiles / Segmentation）に送信
3. Segment IDsを受領
4. カスタムパラメータとしてセグメントIDsをA/Bテスト・レコメンド・出し分けツール（Adobe Target / Optimizely / Custom）に送信
5. Webサイトに対してパーソナルコンテンツを配信

#### 6-2. 主な使い所
1. Facebookにアノニマスユーザーのセグメント情報を送信し、カスタムオーディエンスで広告配信
2. Google Adsにセグメント連携してターゲティング広告配信
3. KARTE連携などWeb接客ツールと連携
4. コンテンツ出し分けなど、Optimizeツールとのシームレス連携

#### 6-3. Profile APIを使った広告セグメント連携の3rd Party Cookie非依存性
- TD CDP内で作成したセグメントに対して、Webサイト/アプリから任意のID（cookie/uuid/user_id等）をKeyにしてセグメント情報を問い合わせ
- セグメント問い合わせ時のKey IDと、Webブラウザに返した後のセグメントIDを引き渡すID（cookie）を**別にすることができる**ため、**3rd Party Cookieに依存しないセグメント連携が可能**
- 2回目以降のサイトアクセスでProfile APIが`td_ssc_id`（任意のID）でセグメント問い合わせ→td_segment_idを返却→facebook PixelやGAのDatalayer経由でFacebook/Google Adsへ`td_segment_id: 11111,22222,33333`を送信

#### 6-4. Facebook連携
- 3rd Party Cookie・Emailアドレスを使わずにセグメント連携可能
- アノニマスユーザーに対して機械学習をかけ購買予測したセグメントを作成し、配信セグメントとして抽出することも可能
- フロー: ①サイトアクセス → ②1st Party Cookieでセグメント問い合わせ → ③セグメントIDを返す → ④セグメントIDをFacebook Pixel経由で引き渡し → ⑤カスタムオーディエンスでの配信設定

#### 6-5. Google Ads連携
- 3rd Party Cookie・Emailアドレスを使わずにセグメント連携可能
- アノニマスユーザーへの機械学習による購買予測も可能
- フロー: ①サイトアクセス → ②1st Party Cookieでセグメント問い合わせ → ③セグメントIDを返す → ④セグメントIDをGAのcookie情報と合わせて引き渡し → ⑤Google Adsへセグメント連携

#### 6-6. KARTE / VWO連携（Web接客）
A/Bテスト・Web接客ツールともProfile APIで連携可能。

- **リアルタイム連携 TD→KARTE**: CDPに格納のユーザー紐づきセグメント情報を連携。CDPのProfile API機能を利用し、ユーザーに紐づくセグメント情報をKARTEにリアルタイム連携、セグメント情報に基づいた施策をKARTEにて実施（webサイト上へTD_JSタグ実装が必要）
- **リアルタイム連携 KARTE→TD**: KARTEで発生したイベントデータを連携。KARTE接客イベントのカスタムJS組込機能でTD JS SDK発火しKARTEマクロ値（接客アクションID）を取得／Webhookを介してKARTEのイベントデータを都度、CDPのPostback API経由でTDに送信

#### 6-7. Google Optimize連携（コンテンツ出し分け）
無料で使えるGoogle Optimizeと連携してWebサイトのコンテンツ出し分けを実装。見込みが高い顧客の再来訪時だけにSale案内を入れるなど販促費の効率運用が可能。

### 8. Appendix: 予測リードスコアリング・機械学習

#### 8-1. Predictive Scoring（GUI操作で自動実行）
- 「教師データ」と「予測したい対象データ」の2つをセグメント抽出し、予測モデルに投入するのみ
- 予測モデルからは対象毎に100点満点で「予測スコア」が自動抽出、ABCDランクの4段階で分類
- 対象ごとのランク/スコア軸で抽出したセグメントは、コネクタを介してマーケティングツールに連携可能
- 生成した予測モデルは、根拠となる「特徴量」がCDP上に開示され、変数のチューニングも簡単な操作で可能

**仕組み**: Positiveに設定したセグメント（例: 既に資料請求したユーザー）と、Scoringに設定したセグメント（例: 未だ資料請求していないユーザー）の類似度を機械学習でスコアリング。CV予測や解約予測など様々な予測に活用可能。

**結果の見え方**: Unlikely／Marginally／Possibly／Likely の4分類でスコアと類似度合いを表示。

**特徴量の可視化**: 各特徴量がスコアに与えた影響度を「スコアを下げている特徴」「スコアを上げている特徴」として確認可能（例: 解約予測でinternational_plan#no、customer_service_calls、day_mins、day_charge等が影響）。

#### 8-2. 機械学習を活用した需要予測
予測を行うための"豊富なデータ"と"開発・運用を行う機械学習に長けた人材"が必要。予測期間が長くなるほど精度を上げる難易度は加速度的に上昇。**初期モデル構築に3ヶ月〜半年、その後の精度改良・運用にも人的リソース確保が必要**。

**精度を上げるためのデータ例**: 過去の売上・販売履歴／Web・アプリのアクセス履歴／商品マスタ（売価・商品カテゴリ等）／祝日・休業日カレンダー／マーケティング施策履歴（広告出稿の種類・費用・期間）／SNSの情報（フォロワー数・投稿掲載日・いいね数）

**方法論**:
1. 販売履歴がユーザIDで管理されていない場合 → 時系列の分析により過去のトレンドから予測。テレビCMの出稿などマーケティング施策の履歴がトレンドを捉える要素として重要
2. ID-POS等により販売履歴がユーザIDで管理されている場合 → 個々のユーザに対して購入確率を予測し、その確率を足し上げて需要とする。個々のユーザ行動履歴から予測するため、1)より予測精度は上がりやすい（例: ユーザID別にN日以内の購入確率と売上期待値を算出→合算で予測客数584／予測売上¥150,243）

#### 8-3. 予測リードスコアリング機能の5つのメリット
1. **簡単で直感的な操作**: 予測したい命題（例: 3ヶ月後に成約する見込客は？）があれば、「予測用セグメント（教師データ）」「オーディエンス（予測したい対象）」の2つをセグメント抽出し予測モデルに投入するだけ。機械学習に詳しくなくても実行可能
2. **予測スコアの自動抽出/セグメント項目反映**: 100点満点で予測スコア自動抽出。ABCDランクで分類、これらは「セグメント項目」として反映
3. **アクションへのスムーズな連携**: 抽出したセグメントをCDPコネクタ経由であらゆるアクションチャネル（営業・コールセンター・Web・広告・メール等）に連携可能。例: 大手自動車会社はABCDランク毎の見込客セグメントデータをディーラーに渡し接客に活用
4. **全量データに基づく精度**: 投入データの上限がなく、CDPに蓄積されている多種大量データを使った予測が可能。例: 大手自動車会社で膨大なWebアクセスログ／ディーラーCRMデータ／外部データ等をすべて投入し、成約率予測の精度向上（**従来比3.3倍**）を実現
5. **現場の知恵に基づくチューニング**: 一度生成した予測モデルは根拠となる「特徴量」（例: 自動車でいえばWebサイトの閲覧カテゴリ／資料請求の有無／来店時の滞在時間等）がCDP上に開示され、簡単な操作でチューニング可能。「機械学習＋現場の知恵」で持続的に精度向上

#### 8-4. 活用事例（Appendix）

**大手自動車会社「3ヶ月後の成約客を自動予測」**
- オンライン・オフラインの複数データソース蓄積により、様々な説明変数を用いた需要予測モデルを実装

## 太一視点の示唆 / 次のアクション

### CDP比較における立ち位置の理解
- **国内シェア41.7%（ITR 2020年度予測）でTreasure Dataがトップ**。提案時の「実績」訴求として有力だが、**逆に既に飽和した大企業群が顧客の中心**である点も認識すべき。中堅以下クライアントには初期コスト・運用人員の壁があるため、案件規模で適合性を判断する。
- Advertiser Perceptions調査の4カテゴリ（Architecture／Compliance/Privacy／Scalability／Data Security）で1位は強みだが、これは**エンタープライズ向け評価軸**であり、スピード重視のクライアントには別軸（Segment、mParticle等）が刺さる可能性もある。
- 競合との大きな違いは「**日本リージョン選択可・FISC対応・改正個人情報保護法の知見**」。金融・公共・保守的な大企業のCDP提案では決定打になる。

### 広告運用ディレクター視点で「美味しい」機能
- **Profile APIによる3rd Party Cookie非依存のセグメント連携**は、ITP/Cookieレス時代において即戦力。Google Ads・Facebook・KARTE・Google Optimize全てに同じ仕組みで適用可能なため、**1つの基盤で複数チャネルのターゲティング高度化**が成立する。
- **CDPなしでも、ハッシュ化メールでの広告連携は可能**だと自社で明言しているスライドは重要。「CDPでないとできないこと＝複数データソースのセグメンテーション×機械学習」を提案フックにすべき。単純なメアド連携だけならCDPは過剰投資。
- **国内DSP・アドネットワーク（FreakOut、AudienceOne、MicroAd BLADE、Logicad、ScaleOut）はCookie Syncなしで連携可能**。海外プレイヤー（Google、Facebook）と比べてセットアップが軽い。国内案件で広告連携を急ぐ場合の打ち手として記憶しておく。

### 「2倍にする」視点での次の打ち手
- 現在の広告運用（CPA改善）の次のステップは、**Predictive Scoringで解約予測リストへの先回り施策**。OISIX事例の「解約率半減」はサブスクモデルクライアント（コンサル契約、SaaS、定期通販）に直接転用できる。**現状のクライアントポートフォリオでサブスク／継続課金型がある場合は、解約防止スコアを噛ませる広告除外リスト・別予算CRMキャンペーンを設計する**。
- 大手自動車会社「成約率3.3倍」事例の構造は **アクセスログ無しモデル（属性のみ）22% → アクセスログ有り 73%**。広告配信先に「自社サイトアクセスログを溜める仕掛け」を入れるかどうかで成約率が3倍以上変わる。**広告のCV改善とは別軸で「アクセスログ収集導線設計」が成果に直結する**ことを提案で強調できる。
- 機械学習の「特徴量可視化」が運用にとって最も重要。**「なぜそのスコアが付いたか」が広告運用者（人間）にとってわかるのは、施策設計の根拠になる**。ブラックボックスでないAI活用として、クライアント説明にも説得力が出る。

### 提案テンプレ用に残すフレーズ
- 「データ統合は売上増加とコスト削減の両面で評価する」というCDP導入評価軸（4-1）
- 「データを溜める／統合する／分析・分類する／連携する／実行する」の5段階（3-2）—— これはCDP一般論として汎用的
- 「IT・情シス領域（Raw→Master Segment）／マーケター領域（Segment生成→Activation）」の役割分担（3-6）—— **クライアント社内体制を提案する時のスタートライン**
- 「CDP無時の分断された顧客理解（桃スイーツBさん事例）」（3-3）—— **クライアント教育の鉄板スライド**として再利用可能

### 次に深掘りすべき領域
- Treasure Data以外の主要CDP（**Salesforce CDP（旧Marketing Cloud Customer Data Platform）／Tealium AudienceStream／mParticle／Segment（Twilio）／BlueConic**）の比較表を別ナレッジとして作成すべき。本資料はTreasure Data側からの一方的な強み訴求のため、客観比較が手薄。
