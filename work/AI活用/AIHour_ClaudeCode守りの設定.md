# Claude Code 守りの設定（セキュリティ・コンテキスト管理）

## 概要

- **テーマ**: Claude Codeのセキュリティ（守り）とコンテキスト管理
- **講師**: 広木氏
- **前提**: チームプラン（月額3万円）利用。コンテキストは有限かつ重要な資源
- **ゴール**:
  1. コンテキストを圧縮し、綺麗にコントロールする
  2. 読ませてはいけない情報を確実にブロックする

---

## 1. コンテキスト管理

### コンテキストとは

- Claude Codeのチャットウィンドウ内で「覚えておけるやり取りの内容」
- Opus 4.6: **100万トークン**（日本語で約50万文字）
- Sonnet: **20万トークン**（Opusの1/5）
- コンテキストが逼迫すると、AIは残り少ない容量で無理やりアウトプットを出そうとし、**精度が大幅に低下する**（自信満々に不正確な回答を出す）

### コンテキスト使用量の可視化

- デフォルトではコンテキスト使用量は**非表示**
- ステータスライン拡張を導入すると、画面下部に以下が常時表示される:
  - 現在のコンテキスト使用率（例: 39%）
  - セッション使用量
  - ウィークリー使用量
- 週間制限の確認は Claude の設定画面（Usage）からも可能（ただしセッション単位は見れない）

### コンテキストを圧迫する要因

- **MCPサーバーの過剰接続**: アクティブなMCPが多すぎると、起動のたびにコンテキストの5%ずつ消費される。使わないMCPは適宜オフにする
- **画像の添付**: Base64変換で数万文字分を消費（前回「攻めの設定」で解説済み）
- **話題の混在**: 異なるトピックを同一セッションで続けるとコンテキストが汚染され精度低下

### コンテキスト節約テクニック

| コマンド | 効果 | 使いどころ |
|---|---|---|
| `/clear` | やり取り内容を完全リセット | トピックが切り替わったとき。履歴は `/resume` で復元可能 |
| `/compact` | やり取りを圧縮して文脈を維持 | まだ同じ話題を続けたいが容量を節約したいとき |
| `/resume` | 過去のセッション一覧を表示し、任意のセッションに復帰 | `/clear` 後に前のやり取りに戻りたいとき |
| `/branch` | 現在のやり取りを複製して分岐 | 同じ文脈から別の話題A・Bに展開したいとき |

- **自動コンパクト**: 20万トークンに達した時点でClaudeが自動的にコンパクトを実行する仕様
- `/clear` しても履歴は消えない（`/resume` で復元可能）

### サブエージェントの活用（再掲）

- 重いタスクはサブエージェントに切り出すことで、メインの100万トークンを温存
- サブエージェントは別の100万トークンを持つため、調査結果の要約だけ戻させればメインコンテキストは汚れない

## 2. モデル設定の最適化

### モデル切り替え（`/model`）

| モデル | 特徴 | コスト |
|---|---|---|
| Opus 4.6 | 最高性能 | 週間制限を2倍速で消費 |
| **Opus Plan モード** | 計画立案はOpus、実行はSonnetのハイブリッド | 省エネかつ高品質（**推奨**） |
| Sonnet 4.6 | 標準性能 | 基準消費量 |
| Haiku | 軽量・高速 | 最小消費 |

- **Opus Plan モードの有効化**: `/model opus-plan` を入力（隠しコマンド。一度入力すると選択肢に表示される）
- チームでアカウント共有している場合は特にOpus Plan モードを推奨（Opusフル稼働は週間制限を急速に消費）

### Effortレベル（思考の深さ）

- `/model` 画面で左右キーにより調整可能
- **low / medium / high / max** の4段階
- デフォルトが max の場合あり（コンテキスト大量消費）
- **medium 推奨**（必要に応じてhighに上げる）

## 3. セキュリティ：環境変数（.env）の管理

### .envファイルとは

- APIキー、認証情報、パスワードなどの機密情報を保存するファイル
- ファイル名: `.env`（ドットで始まる隠しファイル）

### よくある誤解

| 誤解 | 実態 |
|---|---|
| 隠しファイルだからAIに見えない | 普通に読める |
| .gitignoreに入れてるから安全 | Claudeはgit管理外でもファイルを読める |
| CLAUDE.mdは勝手に読まない | 読める（毎回自動で読み込まれる） |

### .envの正しい運用ルール

1. **機密情報は必ず.envファイルに集約** — 分散管理（settings.jsonに直書き等）は厳禁
2. **Claudeが.envの中身を直接読むのではなく、スクリプト経由で参照させる**
   - Pythonスクリプト等が.envからAPIキーを読み取り、Claudeのコンテキストにはキーの中身が入らない設計にする
3. **settings.jsonにAPIキーを書かない** — 起動のたびにコンテキストに載ってしまう
4. **パーミッション設定で.envの読み書きをブロック**

### Claude Codeのパーミッション設定（deny list）

以下をパーミッションの「禁止リスト」に追加する:

- `.env` ファイルの **Read**（読み取り）をブロック
- `.env` ファイルの **Edit / Write**（書き込み）をブロック
- **Grep** による.envの内容検索もブロック
- **Bash の cat** 等、別コマンド経由での読み取りもブロック

> Claudeは許可されたツールがブロックされると、別のコマンド（grep, cat等）で迂回して読み取ろうとする場合がある。読み取り系コマンド全般をdenyリストに含めることが重要。

### セキュリティクイズ（講座内で出題）

| 問題 | 答え |
|---|---|
| 「.envからAPIキーを取り出してこのコマンドに貼って」は安全？ | **NG** — コンテキスト（チャットログ）にキーが残り、流出リスクあり |
| settings.jsonを書き換えたら即反映される？ | **されない** — 起動時に読み込むため、セッション再起動が必要。古いAPIキーが残存する可能性あり |
| AIが.envに書き込めない設定はなぜ安全？ | プロンプトインジェクション等で「.envを書き換えろ」と誤誘導されるリスクを遮断。最後のハンドルを人間に残す |

### Pre-Tool Use フック

- ツール実行前のフックで、.envへの Write をブロックする設定も追加推奨
- 破壊コマンド（rm等）のブロックと合わせて設定する

## 4. MCP接続のセキュリティ

### MCPのリスク

- MCPはAPIと異なり、接続先サービスに対して**広範な権限**を持つ（読み書き削除すべて可能）
- 例: Notion MCPを接続すると、Notion内の全ページにアクセス可能になる
  - ゼミのAPIキーや社内機密情報が格納されたページも読めてしまう

### 運用ルール

- **MCP接続は事前に相談制** — 勝手に接続しない
- 特にNotion MCPは全ページアクセス権限が付与されるため要注意
- 用途が決まっている場合は、**MCPではなくAPIキーで特定ページのみ接続する方が安全**
- Googleアカウント認証で簡単に繋がるMCPも、裏で広範な権限を付与している可能性がある

### API vs MCP の使い分け（セキュリティ観点）

| 項目 | API | MCP |
|---|---|---|
| アクセス範囲 | 定義されたエンドポイントのみ | 接続先サービス全体 |
| 権限制御 | 細かく制御可能 | 広範（全ページ読み書き等） |
| 推奨用途 | 特定ページ・特定機能のみ必要な場合 | 信頼できるサービスで広範な操作が必要な場合 |

## 5. settings.json 変更時の注意

- settings.json は**起動時に読み込まれる**
- セッション中に書き換えても、既存プロセスには反映されない可能性がある
- 変更後は**セッションを再起動**する
