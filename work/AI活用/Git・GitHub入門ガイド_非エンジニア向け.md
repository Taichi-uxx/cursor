# AI駆動開発のための"非エンジニア"向けGit/GitHub使い方ガイド

## 概要

CursorやClaude Code、Gemini CLIなどのAIツールを使った開発が当たり前になってきた今、非エンジニアの方々もコード管理の必要性が高まっています。本ガイドでは、GitHubを使ったコード管理の基本を解説します。

**参考記事**: [AGIラボ - AI駆動開発のための"非エンジニア"向けGit/GitHub使い方ガイド](https://chatgpt-lab.com/n/n51a6200501ac)

## なぜ今、非エンジニアもGitHubを学ぶべきなのか

### コード管理をしないと起きる問題

1. **昨日動いていたコードが今日は動かない**
2. **どの変更が原因でエラーが出たのか分からない**
3. **チームで作業する時に、誰が何を変更したか把握できない**
4. **AIが生成したコードのバージョン管理ができない**

### GitHubを使うメリット

- これらの問題を解決できる
- 最新のAIツールと組み合わせることで、コマンドを覚える必要もない
- コードの変更履歴を記録・管理できる
- チームでの共同作業が可能

## GitとGitHubの違いを理解しよう

### Git（ギット）とは？

**定義**: コードの変更履歴を記録する「バージョン管理システム」

**特徴**:
- パソコンの中で、ファイルの変更を追跡
- Wordの「変更履歴の記録」機能のようなもの
- いつ、どこを、どのように変更したかを記録

**役割**: あなたのパソコンで変更履歴を管理

### GitHub（ギットハブ）とは？

**定義**: Gitで管理しているコードをインターネット上で共有・保存できるサービス

**特徴**:
- Google DriveやDropboxのコード専用版のようなもの
- 単なる保存場所ではなく、チームでの共同作業やコードの公開・共有に特化
- クラウド上でコードを保存・共有

**役割**: その履歴をクラウドに保存し、他の人と共有

### なぜ両方必要なの？

- **Git**: あなたのパソコンで変更履歴を管理
- **GitHub**: その履歴をクラウドに保存し、他の人と共有

この組み合わせにより、安全にコードを管理し、必要に応じて共有できるようになります。

## GitHubの基本用語と概念

### リポジトリ（Repository）

**定義**: プロジェクトのフォルダのようなもの

**役割**: コードやファイルを保存する場所

### コミット（Commit）

**定義**: 変更を記録する操作

**例**: 「この機能を追加しました」というメッセージと一緒に変更を保存

### プッシュ（Push）

**定義**: ローカルの変更をGitHubにアップロードする操作

**役割**: パソコンで行った変更をクラウドに保存

### プル（Pull）

**定義**: GitHubから最新の変更をダウンロードする操作

**役割**: 他の人が行った変更を自分のパソコンに取り込む

### ブランチ（Branch）

**定義**: メインのコードから分岐した作業用のコピー

**役割**: 安全に実験や開発を行うための機能

**メリット**: メインのコードを壊さずに作業できる

## 非エンジニアが陥りやすいGitHubのトラブルと解決法

### 「Permission denied」エラーの対処法

**原因**: GitHubリポジトリへのアクセス権限がない時に発生

**解決方法**:
1. GitHubの認証情報を再設定する
2. SSHキーではなくHTTPSを使用する
3. そもそもそのリポジトリへの権限があるか確認する

## AIエージェント開発で使える実践的なGitHub活用術

### Issues機能でタスク管理する方法

**機能**: GitHubのIssues機能は、タスク管理に最適

**活用方法**:
- タスクをIssueとして作成
- 進捗を管理
- 完了したらクローズ

### Pull Request（プルリクエスト）

**定義**: 安全に変更を反映するための機能

**役割**:
- 変更内容をレビューしてから反映
- チームでの共同作業に最適

### GitHub Actionsを使った自動化

**機能**: 面倒な作業を自動化

**活用例**:
- コードの自動テスト
- 自動デプロイ
- 定期的なバックアップ

## CursorでのGitHub連携設定方法

### 基本的な設定手順

1. **GitHubアカウントを作成**（既に作成済みの場合はスキップ）
2. **CursorでGitHubアカウントと連携**
3. **リポジトリを作成または既存のリポジトリを開く**

### 設定の詳細

- Cursorの設定画面からGitHubアカウントを連携
- 認証情報を入力
- リポジトリへのアクセス権限を付与

## 実践的なワークフロー

### 基本的な流れ

1. **コードを編集**: Cursorでコードを書く
2. **変更を確認**: 変更内容を確認
3. **コミット**: 変更を記録（メッセージ付き）
4. **プッシュ**: GitHubにアップロード
5. **共有**: チームメンバーと共有

### AIツールとの組み合わせ

- **Cursor**: コードを書く際にAIに指示
- **Claude Code**: 長めのタスクを自動でコミット
- **Background Agent**: バックグラウンドで自動的にコミット

## ベストプラクティス

### コミットメッセージの書き方

- **明確に**: 何を変更したか分かるように
- **簡潔に**: 長すぎないように
- **一貫性**: チームで統一した形式を使う

### ブランチの使い方

- **機能ごとにブランチを作成**: メインのコードを保護
- **作業が終わったらマージ**: 変更を反映
- **不要なブランチは削除**: 整理を保つ

### 定期的なバックアップ

- **定期的にプッシュ**: ローカルの変更をクラウドに保存
- **複数の場所に保存**: リスクを分散
- **自動バックアップ**: GitHub Actions等を活用

## セキュリティの注意点

### 重要な情報の管理

- **APIキーやパスワード**: リポジトリに含めない
- **.gitignoreファイル**: 機密情報を除外
- **プライベートリポジトリ**: 個人情報は非公開に

### アクセス権限の管理

- **必要最小限の権限**: 必要な人だけにアクセス権を付与
- **定期的な見直し**: 権限を定期的に確認
- **二要素認証**: セキュリティを強化

## まとめ

### GitHubを使うメリット

1. **コードの変更履歴を記録**: いつ、何を変更したか分かる
2. **安全にコードを管理**: バックアップと復元が可能
3. **チームでの共同作業**: 複数人で安全に作業できる
4. **AIツールとの連携**: 自動化が可能

### 非エンジニアでも使える理由

- **AIツールとの組み合わせ**: コマンドを覚える必要がない
- **視覚的なインターフェース**: Cursor等で簡単に操作できる
- **段階的な学習**: 基本的な機能から始められる
