## 用途（どんな時に活用できるか）

- Claude Code の使い方を見直したい／自分の作業効率にモヤっとしているとき
- 「AIを使いこなせている感」が薄く、改善の切り口を探しているとき
- チームメンバーにClaude Codeの使い方指導をしたいが、属人的な観察に頼らず客観データで示したいとき
- AIツールの「使わせっぱなし」を防ぎ、継続的にワークフローをチューニングする運用を作りたいとき

## `/insights` コマンドとは

Claude Code に新しく追加されたスラッシュコマンド。**過去1ヶ月分の使用履歴を分析し、ユーザー自身のワークフローに対して改善提案をしてくれる**機能。

> これ地味にヤバい。ClaudeCodeに「/insights」コマンドが追加された。1ヶ月分の使用履歴を分析して、ワークフローの改善提案をしてくれる。

## 従来の「ルール設定」との決定的な違い

| 従来 | `/insights` |
|---|---|
| ユーザー → Claude に「こういう時はこうして」とルールを覚えさせる（能動） | Claude → ユーザーに「あなたのこの使い方、改善余地ありますよ」と指摘してくる（受動→気づき） |
| 想定できる範囲内でしかチューニングできない | 自分が気づいていない癖・非効率を客観データから抽出してくれる |

> 今までも「ルールを覚えさせる」ことはできた。でも今回は逆で、Claudeが勝手に指摘してくる。

## Claudeからの指摘例（投稿より）

- 「あなた**計画モード**まったく使ってないですね？」
- 「このプロジェクト**並列作業**にした方が早いっすよ！」

→ ツールが提供する機能のうち、**ユーザーが気づかず使っていない機能や、非効率なワークフローパターンを名指しで指摘**してくる。

## 太一の示唆（So What）

- **AIが「使い方を教える側」に回った**のが本質。今までは人間がAIを使いこなす前提だったが、AI側が人間の使い方を評価しコーチングする関係に反転した
- パーソナルトレーナー的なメタファーが効いている：単なる自動化ツールではなく、**自分の癖を客観視するミラー**として機能する
- クライアントワークで自分がCS的に「使い方指導」しているのと同じ構造を、AIが自分に対してやってくれる → **AIツール自体がCSを内包**し始めている
- 応用: この発想を横展開すると、「ユーザー行動ログを1ヶ月単位で分析して個別最適な改善提案をLLMで返す」という機構は、あらゆるSaaSに実装可能。**プロダクト内CS機能としてのLLM活用**は次の激戦区になる可能性
- 自分の運用アクション: 定期的に `/insights` を回して、自分の使い方のクセを棚卸しする運用ルーチンに組み込む価値あり
