## 1. OpenClawとは何か（30秒サマリ）

**「質問に答えるAI」ではなく「PC上で作業を実行するAI」**。
オーストリアの開発者 Peter Steinberger氏が2025年11月に公開したオープンソースの自律型AIエージェント。SlackやDiscord・Telegramなどのチャットから指示するだけで、ブラウザ操作・ファイル操作・シェル実行・メール送信・レポート作成などをローカルPC上で自律実行する。

- ライセンス: **MIT（無料）**
- GitHub★: **14万〜37万（2026年6月時点）**
- モデル: **マルチプロバイダー対応**（Claude／GPT／Gemini／DeepSeek／Ollama）
- 対応チャネル: **26以上**（Slack, Discord, Telegram, WhatsApp, Teams, Signal, iMessage, LINE 等）
- 名称変遷: Warelay(2025/11) → Clawdbot(12月) → Moltbot(2026/1/27) → **OpenClaw(1/29〜)**
  ※ Anthropicの商標クレームで改名

## 2. 主要機能

| 機能 | 内容 |
|---|---|
| **Computer Use** | 画面を認識してブラウザ・アプリを自律操作（RPAより柔軟。UI変更に強い） |
| **チャット指示** | 26以上のメッセージングアプリから自然言語で命令 |
| **Heartbeat** | 定期チェック＋スリープ防止で24時間自律稼働 |
| **スキルシステム** | ClawHub経由で機能拡張（公式50以上＋コミュニティ製） |
| **長期メモリ** | Markdownで会話履歴・文脈を永続化（ユーザーが確認・編集可） |
| **MCP連携** | 500以上の外部ツールと接続可能 |
| **マルチモデル** | タスクごとにモデル使い分け可能（コスト最適化） |

## 3. 他ツールとの違い（比較表）

### 3-1. AIツール系との比較

| 観点 | OpenClaw | ChatGPT/Claude(通常) | Claude Code |
|---|---|---|---|
| **役割** | PC作業を実行する自律エージェント | 会話・生成 | ターミナル特化コーディング |
| **稼働形態** | ローカル常駐・24H稼働可 | クラウド対話 | ターミナル対話 |
| **操作対象** | ブラウザ・ファイル・シェル・メール等PC全体 | チャット内で完結 | コードベース深掘り |
| **チャネル** | Slack/Discord/Telegram等26＋ | Web/アプリ | ターミナル |
| **料金** | 本体無料＋API従量 | 定額 or API従量 | API従量 |
| **強み** | 業務全般の常駐自動化 | 対話・思考 | 開発深掘り・repo理解 |

### 3-2. 自動化ツール系との比較

| 観点 | OpenClaw | RPA（UiPath等） | Zapier / n8n |
|---|---|---|---|
| **判断力** | AIが画面を理解して判断 | ルール固定・座標依存 | トリガー→アクションのフロー |
| **UI変更耐性** | 高い（画面認識で対応） | 低い（都度メンテ必要） | API依存で無関係 |
| **セットアップ** | チャットで指示するだけ | フロー設計必要 | ノードを組む |
| **無料範囲** | 本体無料（API別） | 有料が中心 | 一部無料枠あり |
| **得意領域** | 非定型・判断を要する自動化 | 大量同一処理 | SaaS連携 |

**要点**: OpenClawはRPAとチャットAIの中間。RPAでは崩れるUI変更やLLM判断が必要な作業を、Zapierより柔軟にこなせるのが差別化ポイント。

### 3-3. 使い分けの判断軸

- **開発深掘り** → Claude Code
- **SaaS連携でトリガー→処理を組みたい** → Zapier / n8n
- **大量の同一定型作業** → RPA
- **チャットから指示できる自分専用の実行エージェントが欲しい／複数ツール横断／常駐したい** → **OpenClaw**

## 5. セキュリティリスク（超重要）

「あらゆるサービスに接続して代わりに行動する」利便性が、**最小権限の原則と根本的に相反する** 構造。導入前に必読。

### 既知の重大脆弱性

| CVE | CVSS | 内容 |
|---|---|---|
| **CVE-2026-25253** | 8.8 | リモートコード実行（WebSocket未検証）ワンクリックRCE |
| **CVE-2026-24763** | 8.8 | Dockerサンドボックス脱出 |
| **CVE-2026-28391** | - | Windowsコマンドインジェクション |

### 実際に起きたインシデント

- **ClawHavoc攻撃キャンペーン（2026年2月）**: 悪意アカウント「hightower6eu」が670件のスキルを公開、うち314件以上でブラウザパスワード・SSH鍵・APIキー・仮想通貨ウォレット秘密鍵を窃取
- **インターネット公開インスタンス問題**: 13万5,000件のOpenClawインスタンスが露出、うち約63%が認証なし状態
- **ClawHubのスキル**: 約7%にセキュリティ欠陥（Cisco調査）

### 主要リスク5点

1. **プロンプトインジェクション** — メッセージ送信者＝エージェントと同じ権限を得られる
2. **過剰権限** — メール/カレンダー/ファイル全体への広範アクセスを要求
3. **悪意あるスキル** — サードパーティスキル経由の情報漏洩
4. **MEMORY.mdへの機密混入** — 会話履歴が平文で永続化される
5. **IT部門承認なしの野良導入** — シェル・データ移動が監査外で行われる

### 最低限の防御策

- ✅ **専用マシン or サンドボックス（VM/Docker/VPS）** で運用
- ✅ **APIキーは環境変数化**、`.env` を必ずgitignore
- ✅ **権限最小化**（読み取り専用→段階的に拡張）
- ✅ `openclaw doctor` `openclaw security audit --deep` で定期診断
- ✅ **本番の機密データは扱わない**（試験は捨てアカウント／サンドボックス）
- ✅ サードパーティスキルはソースコード確認してから導入
- ✅ 実行前承認フローを構築（重要操作は人間チェック）

Northeastern大学のサイバーセキュリティ教授は「**プライバシーの悪夢**」と評価。企業導入は慎重判断が必須。

## 6. 活用事例（マーケ・広告・CS領域）

### 6-1. マーケティング／広告運用
- **競合モニタリング**: 毎週月曜に競合5社サイトの更新をチェック→Slackに自動投稿（週60〜90分削減）
- **KPI日次配信**: GA4データ集計＋メール送信を朝8時に自律実行→営業チームに配信
- **リード調査**: ブラウザ自動操作で見込み客情報を取得
- **月次レポート生成**: Googleスプレッドシート集計→PDF出力（2〜4時間削減）
- **在庫・価格アラート**: 1時間ごと自律監視

### 6-2. カスタマーサクセス
- **メール分類・返信案生成**: 受信メール要約＋一次回答ドラフト
- **チャットボット的初期対応**: 定型問い合わせを即応
- **クライアントレポートの下書き**: 定型フォーマット出力

### 6-3. その他業務全般
- Webリサーチ横断（数時間→数分）
- スケジュール調整
- ファイル整理・データ移動
- 定期通知の自動化

**重要な運用原則**: AI生成物は「下書き・補助」として扱い、**最終確認は必ず人間**が実施。

## 7. 太一の業務との相性・示唆

### 相性が良い場面
- **クライアント横断のルーチン監視**（複数媒体の管理画面チェック、競合広告のスクレイピング、ステータスまとめ）
- **朝の状況把握タスクの自動化**（前日CVレポート→Slackポスト）
- **green社パイロットのようなCS効率化検証**でRPAより柔軟な選択肢として提示可能
- 個人環境での**壁打ち・下書き生成型タスク**の常駐化

### 相性が悪い／注意すべき場面
- **クライアントの本番データを扱う業務** → セキュリティ責任が重い。当面は自分の環境／自分のデータのみ
- **監査ログが求められる作業** → 現状のOpenClawは運用ログの管理が甘い
- **管理画面のパスワード操作を伴う自動化** → 認証情報流出リスクが高すぎる
- **チーム展開・ナレッジ共有前提の業務** → 属人化が加速

### 太一が取るなら現実的な導入ステップ
1. **自分専用のサンドボックスVPS**（月1,000円クラス）に隔離導入
2. **軽量モデル（Gemini Flash）＋Slack連携**でランニング $10〜20/月
3. スコープを **「競合ウォッチ」or「AI Hourネタ収集の定期リサーチ」** に絞って試験
4. 効果測定（削減時間・品質・修正コスト）→ ROIが立てば範囲拡大
5. 本番クライアント業務投入は **監査ログ・権限管理の成熟を待つ**

## 8. 導入手順（3ステップ）

### Step 1: インストール（約2分）
```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

### Step 2: ウィザード設定
- AIプロバイダー選択（Anthropic APIキー推奨、コスト重視ならGemini）
- メッセージングチャネル接続（初回はTelegram推奨。Slackは本番運用向け）
- 基本設定完了

### Step 3: 初回テスト
Telegramから「今日の天気を調べて」など軽い指示で応答確認。

### 必須スペック
- Node.js v22以上
- メモリ推奨16GB（最低4GB）
- ストレージ10GB以上
- macOS / Windows(v2026.6.1以降ネイティブ) / Linux

## まとめ（示唆）

- OpenClawは **「PC操作型AIエージェント」の代表格**。RPAとチャットAIの中間に位置し、UI変更や判断を要する作業に強い

- 太一の使い所は **「自分のサンドボックス環境で、自分専用の情報収集・下書き常駐エージェント」** として仕込むのが現実解。クライアント業務への展開は監査・権限管理が成熟してから
