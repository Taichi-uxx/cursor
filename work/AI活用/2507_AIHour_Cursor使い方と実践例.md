# Cursor研修：使い方と実践例

## 概要

Cursorを使用したAI活用の研修内容。Obsidian + Claudeとの違い、主な機能、セットアップ方法、実践的な使い方について学習。

**開催日**: 2025年7月11日

## 前回の内容（Obsidian + Claude）

### 基本的な構成

- **Obsidian**: ローカルストレージのノートアプリ
- **Claude Desktop**: ローカルで動くClaude
- **連携**: ObsidianのフォルダをClaudeに読み込ませる

### 主な機能

- プロジェクトごとにコンテキストを設定
- 過去の商談情報等を読み込んで相談
- 議事録の作成や事業の相談が可能
- ローカルで動くため処理が高速
- 可視化がしやすい

## Cursorとは

### 基本特徴

- **オールインワン**: エディタとAIチャットが統合
- **複数プロジェクトの同時並行**: 複数のタスクを同時に実行可能
- **ファイル参照のしやすさ**: @メンションで簡単にコンテキストを付与
- **Obsidianとの連携**: Obsidianのフォルダをそのまま開ける

### Obsidian + Claudeとの違い

**Obsidian + Claudeの課題**:
1. **1つのタスクに集中**: 1つのタスクを投げている間、他の作業ができない
2. **画面が2画面**: エディタとAIチャットが別画面

**Cursorの解決策**:
1. **複数プロジェクトの同時並行**: 3-4個同時にClaudeに指示を投げられる
2. **オールインワン**: エディタとAIチャットが1画面に統合
3. **ファイル参照のしやすさ**: @で簡単にコンテキストを付与

## Cursorの主な機能

### 1. 複数プロジェクトの同時並行

**機能**:
- 右側に複数のプロジェクトタブを開ける
- それぞれ独立してAIと対話可能
- 同時に複数のタスクを実行

**使用例**:
- プロジェクト1: 「CursorとObsidianの比較記事を作成」
- プロジェクト2: 「AIOツールを調査」
- プロジェクト3: 「AIネーブルメントのOTRを作成」

### 2. ファイル参照のしやすさ

**@メンション機能**:
- `@`を入力すると、フォルダやファイルを選択可能
- フォルダを指定すると、そのフォルダ内のファイルを自動参照
- いちいちファイルを指定する必要がない

**使用例**:
- `@日報フォルダ`で過去の日報を全て参照
- 「今週の週報を作成して」と指示すると、自動的にフォルダ内のファイルを参照

### 3. ターミナル統合（Claude Code）

**機能**:
- ターミナルからClaude Codeを起動可能
- 長めのタスク（記事執筆等）を実行
- 生成した内容をファイルに自動保存

**使い分け**:
- **軽めのタスク**: 右側のAIチャット
- **重めのタスク**: ターミナルのClaude Code

**使用例**:
- 「生成AIに全力を振ってる企業に就職するべきなのか」という6000文字の記事作成
- 長めのタスクはターミナルで実行
- 生成した内容をファイルに自動保存

## セットアップ方法

### 基本的なセットアップ

1. **Cursorをインストール**
2. **Obsidianのフォルダを開く**
   - Obsidianで既にフォルダを作成している場合、そのフォルダをCursorで開く
   - フォルダを開くだけで、Obsidianと同じファイル構造が表示される

**注意点**:
- Obsidianとの連携機能は不要
- 単に同じフォルダを開いているだけ
- ローカルのフォルダを開いているだけ

### モデルの選択

**利用可能なモデル**:
- Claude（推奨）
- GPT-4
- その他複数のモデル

**Claudeを推奨する理由**:
- 文脈の汲み取り力が高い
- 複数のタスクを同時に回す場合に相性が良い
- アップロードしたファイルを良い感じに拾ってくれる

## Obsidianとの連携

### 連携方法

- **特別な設定は不要**: ObsidianのフォルダをCursorで開くだけ
- **同じファイル構造**: Obsidianで見えるファイルとCursorで見えるファイルは同じ
- **相互編集可能**: どちらで編集しても反映される

### Obsidianを使うメリット

1. **読みやすさ**: 可視化がしやすい
2. **PDFエクスポート**: お客さん向けに共有する際に便利
3. **プラグイン**: マインドマップ等の出力に対応
4. **GitHub連携**: 無料で自動バックアップ可能

### Cursorを使うメリット

1. **AIとの対話**: 複数プロジェクトの同時並行
2. **ファイル参照**: @メンションで簡単にコンテキスト付与
3. **開発環境**: エンジニア向けの機能が充実

## Claude Codeとの違い

### Claude Codeとは

- ターミナルからインストールできるClaude評価バージョン
- より自由度が高い
- 全フォルダを参照してくれる

### 使い分け

**Claude Code**:
- より自由度が高い
- 全フォルダを参照
- ラフに投げても良い

**CursorのAIチャット**:
- @でフォルダを指定する必要がある
- より制御しやすい

**実践的な使い分け**:
- 日報フォルダを指定して週報を作成: AIチャット
- 長めの記事執筆: Claude Code

## 画像処理について

### CursorのAIチャット

**対応状況**:
- 画像のドラッグ&ドロップ対応
- 複数画像のアップロード可能
- マルチモーダル対応

**制限**:
- 画像の出力は難しい
- テキストに特化したツール

### Claude Code

**対応状況**:
- 画像の参照は可能（パスを指定）
- ドラッグ&ドロップは不可
- ファイルパスを指定する必要がある

**使用方法**:
1. 画像をフォルダに配置
2. ファイルパスを指定
3. 「この画像のような見た目を作って」と指示

**注意点**:
- パスをコピーする必要がある
- ドラッグ&ドロップはできない
- 右側のAIチャットの方が使いやすい

### 推奨事項

**テキスト処理**: Cursor、Claude Codeが優位
**画像出力**: PowerPoint、Genesys等の他のツールを使用
**マルチモーダル**: 右側のAIチャットを使用

## GitHub連携

### 機能

- **自動バックアップ**: プラグインで自動連携
- **無料**: 有料プランは不要
- **データ復元**: データが消えた場合も復元可能

### セットアップ

1. GitHubアカウントを作成
2. CursorのプラグインでGitHub連携を設定
3. 自動的にバックアップが開始

### 注意点

- **同時編集は不可**: 個人個人で管理
- **成果物の共有**: 成果物をみんなで共有することは可能
- **会話履歴の共有**: やり取りの履歴を他者が使うことはできない

## 実践的な使い方

### 1. 日報・議事録の管理

**方法**:
- 議論用のチャットと最新情報を保存するファイルの2つを作成
- 議論はチャットで行う
- 反映された後、上のファイルを見る

**実践例**:
- 今日まで喋った内容をサマリーして新しいファイルを作成
- 会話内容が全部入っている
- 参照する時は最新情報のファイルを見る

### 2. インタビュー記事の作成

**実践例**:
- 自分のプロフィールや人生哲学をテキストファイルとして作成
- 「これを前提に会話したい」と指定
- 「インタビュー記事を作成して」と指示
- 実際にインタビューをしなくても記事が完成

**成果**:
- Wantedlyで出したタイガン記事: インタビューも執筆もしていない
- 執筆時間5分程度

### 3. 個人情報の活用

**実践例**:
- 自分の人生哲学を言語化したファイル
- 自分のプロフィール
- これらを前提に会話することで、より精度の高い出力が可能

**使用方法**:
- 「長坂基本情報」フォルダを参照して
- 「このテーマで記事のたたき案を3000字で作って」と指示
- 自動的に参照して作成

### 4. データの蓄積

**実践例**:
- AIネーブルメントのフォルダを1週間で作成
- 事業の話をしながらコンテキストを蓄積
- 今から蓄積し始めても相当な量が入る

**メリット**:
- 過去の情報を参照しながら作業
- 中長期的に考え続けるものに最適
- ChatGPT等では1つ1つが流れて過去参照が難しい

## セキュリティリスクと注意喚起

### 重要な注意点

1. **Claude Codeの導入は待つ**
   - 削除系のリスクが高まる
   - 導入は慎重に検討

2. **GitHub連携は安全に**
   - 全員が安全にGitHub連携できる仕組みを構築中
   - 実現してから全員でGitHub連携
   - カーソルを入れるだけは大丈夫

3. **Google Drive連携のリスク**
   - 技術的には可能だが、リスクが高い
   - 書き込み・削除のリスク
   - 専用ドライブを用意する等の対策が必要

### 推奨事項

- **個人のローカルフォルダで作業**: 基本的に安全
- **共有ドライブの参照**: 慎重に検討
- **重要なアクション**: 一声かけてから実行

## チームでの活用

### 現状の課題

- **Notionとの比較**: Notionは人間に最適化されたUI
- **同時編集**: Notionは同時編集が可能、Cursorは不可
- **クラウド vs ローカル**: クラウドかローカルかの違い

### 解決策の検討

1. **個人用リポジトリと共有用リポジトリ**
   - GitHubで個人用と共有用のリポジトリを作成
   - Markdownファイルをプッシュ
   - 参照することが多いものは全員アクセス可能に

2. **カテゴリー別の管理**
   - 参照することが多いもの: 全員アクセス可能
   - 編集する系のもの: 慎重に

3. **Google Driveとの連携**
   - 技術的には可能
   - セキュリティリスクを考慮
   - 専用ドライブを用意する等の対策

### 実践的なアプローチ

- **個人作業**: ローカルのフォルダで作業
- **共有**: GitHubで成果物を共有
- **参照**: 全員が参照できる場所を作成
- **編集**: 慎重に管理
