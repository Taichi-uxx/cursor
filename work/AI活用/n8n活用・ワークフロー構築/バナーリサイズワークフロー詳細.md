# Stability AI × n8n バナーリサイズワークフロー詳細

## 概要

このワークフローは、Stability AIとn8nを組み合わせて、既存のバナー画像を目的のサイズにリサイズするための2つのアプローチを実装したものです。

## 参照
https://rehatchhq.slack.com/archives/C05LGGA3MG9/p1756644490546749

### 基本コンセプト

従来の単純なリサイズ（拡大・縮小）ではなく、**既存画像を保持しながら、不足する部分をAIで生成・補完する**ことで、画質の劣化を最小限に抑えながら目的のサイズにリサイズすることを目指しています。

---

## ワークフロー構成

### アプローチ1: 余白補完によるリサイズ（上のワークフロー）

このアプローチは、既存画像をリサイズし、不足する部分を余白として追加する方法です。

#### ノード構成と処理フロー

1. **画像ダウンロード1**
   - **ノードタイプ**: HTTP Request (GET)
   - **処理内容**: 元画像をURLからダウンロード
   - **URL**: `https://re-hatch.jp/wp-...`
   - **出力**: ダウンロードした画像データ

2. **元画像情報取得1**
   - **ノードタイプ**: Edit Image (Get Information)
   - **処理内容**: ダウンロードした画像の情報（幅、高さ、フォーマットなど）を取得
   - **出力**: 画像のメタ情報

3. **サイズ分割1**
   - **ノードタイプ**: Code/Function
   - **処理内容**: 目的のサイズに合わせて、どの部分をリサイズし、どの部分を余白として追加するかを計算
   - **出力**: リサイズパラメータと余白情報

4. **Merge2**
   - **ノードタイプ**: Merge
   - **処理内容**: 元画像データとサイズ分割情報を統合
   - **モード**: Combine
   - **出力**: 統合されたデータ

5. **ステップ1: リサイズ1**
   - **ノードタイプ**: Edit Image (Resize)
   - **処理内容**: 元画像を目的サイズに合わせてリサイズ
   - **出力**: リサイズされた画像

6. **リサイズ後情報取得1**
   - **ノードタイプ**: Edit Image (Get Information)
   - **処理内容**: リサイズ後の画像情報を取得
   - **出力**: リサイズ後の画像メタ情報

7. **Merge3**
   - **ノードタイプ**: Merge
   - **処理内容**: リサイズ後の画像と情報を統合
   - **モード**: Combine
   - **出力**: 統合されたデータ

8. **ステップ2: キャンバス生成1**
   - **ノードタイプ**: Edit Image (Create)
   - **処理内容**: 目的サイズの空のキャンバスを生成
   - **出力**: 空のキャンバス画像

9. **ステップ3: 画像合成**
   - **ノードタイプ**: Edit Image (Composite)
   - **処理内容**: リサイズした画像をキャンバス上に配置し、余白部分を補完
   - **出力**: 合成された画像

10. **Google Drive保存**
    - **ノードタイプ**: Google Drive (Upload)
    - **処理内容**: 完成した画像をGoogle Driveに保存
    - **出力**: 保存されたファイル情報

#### このアプローチの特徴

- **メリット**
  - 元画像の画質を保持
  - 処理が比較的シンプル
  - AI生成を必要としないため、コストが低い

- **デメリット**
  - 余白部分が単調になりがち
  - デザインの一貫性が保ちにくい場合がある

### アプローチ2: 拡張生成によるリサイズ（下のワークフロー）

このアプローチは、Stability AIのOutpaint機能を使用して、既存画像の周辺部分をAIで生成・拡張する方法です。**実行済みのワークフロー**として表示されています。

#### ノード構成と処理フロー

1. **When clicking 'Execute workflow'**
   - **ノードタイプ**: Manual Trigger
   - **処理内容**: ワークフローの実行開始
   - **出力**: 1 item（トリガーイベント）

2. **元画像ダウンロード1**
   - **ノードタイプ**: HTTP Request (GET)
   - **処理内容**: 元画像をURLからダウンロード
   - **URL**: `https://re-hatch.jp/wp-...`
   - **ステータス**: ✅ 実行成功
   - **出力**: 1 item（ダウンロードした画像データ）

3. **元画像情報取得2**
   - **ノードタイプ**: Edit Image (Get Information)
   - **処理内容**: ダウンロードした画像の情報を取得
   - **ステータス**: ✅ 実行成功
   - **出力**: 1 item（画像のメタ情報）

4. **スマートサイズ計算1**
   - **ノードタイプ**: Code/Function
   - **処理内容**: 目的サイズと元画像サイズを比較し、どの方向にどれだけ拡張する必要があるかを計算
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（複数の拡張パターンまたはバッチ処理結果）

5. **データ統合**
   - **ノードタイプ**: Merge
   - **処理内容**: 元画像データとサイズ計算結果を統合
   - **モード**: Combine
   - **入力1**: 5 items（元画像データ）
   - **入力2**: 5 items（サイズ計算結果）
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（統合されたデータ）

6. **スマートリサイズ1**
   - **ノードタイプ**: Edit Image (Resize)
   - **処理内容**: 元画像を拡張生成に適したサイズに調整（必要に応じて）
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（リサイズされた画像）

7. **Merge**
   - **ノードタイプ**: Merge
   - **処理内容**: リサイズ後の画像と拡張パラメータを統合
   - **モード**: Combine
   - **入力1**: 5 items
   - **入力2**: 5 items（リサイズ後の画像）
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（統合されたデータ）

8. **Stability AI Outpaint**
   - **ノードタイプ**: HTTP Request (POST)
   - **処理内容**: Stability AIのOutpaint APIを使用して、画像の周辺部分をAI生成で拡張
   - **エンドポイント**: `https://api.stability.ai/...`
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（拡張生成された画像）

9. **元画像情報取得**
   - **ノードタイプ**: Edit Image (Get Information)
   - **処理内容**: 拡張生成後の画像情報を取得
   - **ステータス**: ✅ 実行成功
   - **出力**: 5 items（拡張後の画像メタ情報）

10. **Merge1**
    - **ノードタイプ**: Merge
    - **処理内容**: 拡張後の画像と情報を統合
    - **モード**: Combine
    - **入力1**: 5 items
    - **入力2**: 5 items（拡張後の画像情報）
    - **ステータス**: ✅ 実行成功
    - **出力**: 5 items（統合されたデータ）

11. **PNG保存1**
    - **ノードタイプ**: Google Drive (Upload) または File System
    - **処理内容**: 完成した画像をPNG形式で保存
    - **ステータス**: ✅ 実行成功
    - **出力**: 5 items（保存されたファイル情報）

#### このアプローチの特徴

- **メリット**
  - AI生成により、拡張部分が自然で一貫性のあるデザインになる
  - 元画像のスタイルを維持しながら拡張可能
  - 複数のバリエーションを同時に生成可能（5 itemsの出力）

- **デメリット**
  - Stability AI APIの利用コストが発生
  - 処理時間が長くなる可能性
  - AI生成の品質に依存する

## 技術的な詳細

### データフローの特徴

#### アプローチ1（余白補完）
- シンプルな1対1のデータフロー
- 各ステップで1つの画像を処理

#### アプローチ2（拡張生成）
- **バッチ処理**: 5 itemsのデータが流れる
- 複数の拡張パターンやバリエーションを同時に処理
- Mergeノードでデータを統合しながら処理を進める

### Mergeノードの役割

両方のワークフローでMergeノードが重要な役割を果たしています：

1. **データ統合**: 異なるソースからのデータを1つにまとめる
2. **パラメータの結合**: 画像データと処理パラメータを組み合わせる
3. **バッチ処理の維持**: 複数のアイテムを統合しながら次のステップに渡す

**モード設定**: `Combine`モードを使用し、`position`または`All possible combination`でデータの対応関係を制御

### Stability AI Outpaint API

- **機能**: 既存画像の周辺部分をAIで生成・拡張
- **用途**: 画像のサイズ拡張、アスペクト比調整、余白の自然な補完
- **APIエンドポイント**: `https://api.stability.ai/...`
- **認証**: APIキーによる認証が必要

## 使用シーン

### アプローチ1（余白補完）が適している場合

- コストを抑えたい場合
- シンプルな余白追加で十分な場合
- 処理速度を重視する場合
- デザインの一貫性よりも画質保持を優先する場合

### アプローチ2（拡張生成）が適している場合

- 高品質な拡張が必要な場合
- デザインの一貫性を重視する場合
- 複数のバリエーションを生成したい場合
- プロフェッショナルな仕上がりを求める場合

## 実装時の注意点

### 1. API制限とコスト

- Stability AI APIの利用制限とコストを確認
- バッチ処理（5 items）の場合、APIコール数が増える可能性

### 2. 画像サイズと処理時間

- 大きな画像の処理には時間がかかる
- メモリ使用量に注意

### 3. エラーハンドリング

- API接続エラーの処理
- 画像フォーマットの検証
- タイムアウト処理

### 4. データの整合性

- Mergeノードでのデータ統合時の整合性確保
- バッチ処理時のデータ順序の維持

## 今後の拡張案

1. **両アプローチのハイブリッド**: 余白補完と拡張生成を組み合わせる
2. **品質評価機能**: 生成された画像の品質を自動評価
3. **自動サイズ最適化**: 目的サイズに最適なアプローチを自動選択
4. **バリエーション生成**: 複数の拡張パターンを生成して最適なものを選択
5. **プレビュー機能**: 処理前のプレビュー表示

## まとめ

このワークフローは、従来の単純なリサイズとは異なる、**AIを活用した高度なリサイズ手法**を実現しています。

- **アプローチ1**: シンプルでコスト効率の良い余白補完
- **アプローチ2**: 高品質なAI拡張生成

どちらのアプローチも、目的と要件に応じて選択することで、効率的なバナーリサイズワークフローを構築できます。
