# 競合Webサイト監視ワークフロー詳細

## 概要

このワークフローは、n8nを使用して競合Webサイトを定期的に監視し、変更点を検出してAIで分析し、重要変更があればSlackに通知する自動化システムです。

**主な特徴**:
- フォームトリガーで監視対象URLと指示を簡単に入力
- OpenAIで自然言語の指示をURLとプロンプトに解析
- FirecrawlでWebページをスクレイピング
- 1日間隔で2回スクレイピングして差分を検出
- AIエージェントで変更内容を分析
- 重要変更があればSlackに自動通知

## ワークフロー全体の流れ

1. **フォームトリガー**: 監視対象URLと指示を入力
2. **OpenAIで解析**: URLとプロンプトを解析
3. **Firecrawlでスクレイピング**: 初回スクレイピング
4. **1日待機**: 時間差を設けて再度スクレイピング
5. **AIエージェントで差分分析**: 変更内容を分析
6. **Slack通知**: 重要変更があれば通知

## 各ノードの詳細

### カテゴリー1：リクエスト処理と解析

#### 1. Enter the Request（リクエスト入力）

- **ノードタイプ**: Form Trigger / Manual Trigger
- **役割**: ユーザーからの監視指示を受け取る
- **入力内容**:
  - 監視対象URL
  - 監視指示（例：「価格変更を監視して」「新機能の追加を監視して」）
- **出力**: 1 item（リクエストデータ）

#### 2. Convert Message to Website URL & Instruction（メッセージをURLと指示に変換）

- **ノードタイプ**: HTTP Request (POST)
- **API**: OpenAI API
- **エンドポイント**: `https://api.openai.com/...`
- **役割**: 自然言語の指示を解析し、WebサイトURLと具体的な監視指示（プロンプト）に変換
- **処理内容**:
  - ユーザーが入力した自然言語の指示を解析
  - 監視対象のURLを抽出
  - 監視すべき内容を具体的なプロンプトに変換
- **出力**: 1 item（URLとプロンプトを含むデータ）

#### 3. Parse Results（結果を解析）

- **ノードタイプ**: Code / Function
- **役割**: OpenAIからのレスポンスを解析し、URLとプロンプトを抽出
- **処理内容**:
  - JSONレスポンスをパース
  - URLとプロンプトを分離
  - 次のステップで使用できる形式に整形
- **出力**: 1 item（解析されたデータ）
- **フィードバックループ**: 解析結果が不十分な場合、`convert message to website url & instruction`ノードに戻って再処理（-1 itemのループ）

### カテゴリー2：Webスクレイピング

#### 4. Scrape Page - 1（初回スクレイピング）

- **ノードタイプ**: HTTP Request (POST)
- **API**: Firecrawl API
- **エンドポイント**: `https://api.firecrawl.d...`
- **役割**: 監視対象Webサイトの初回スクレイピングを実行
- **処理内容**:
  - Firecrawl APIを使用してWebページをスクレイピング
  - ページのHTMLコンテンツを取得
  - テキストデータを抽出
- **出力**: 1 item（スクレイピングされたデータ）

#### 5. Wait 1 Day（1日待機）

- **ノードタイプ**: Wait / Delay
- **役割**: 1日間の時間差を設ける
- **処理内容**:
  - 初回スクレイピングから1日後に2回目のスクレイピングを実行
  - 定期的な監視のための時間間隔を確保
- **出力**: 1 item（待機後のデータ）

#### 6. Scrape Page - 2（2回目のスクレイピング）

- **ノードタイプ**: HTTP Request (POST)
- **API**: Firecrawl API
- **エンドポイント**: `https://api.firecrawl.d...`
- **役割**: 1日後のWebサイトを再度スクレイピング
- **処理内容**:
  - 初回スクレイピングと同じページを再度スクレイピング
  - 変更点を検出するための比較データを取得
- **出力**: 1 item（2回目のスクレイピングデータ）

### カテゴリー3：AIエージェントによる分析

#### 7. 競合Webサイト監視_AIエージェント（中央のAIエージェント）

- **ノードタイプ**: AI Agent
- **役割**: スクレイピングされた2つのデータを比較し、変更点を分析
- **構成要素**:
  - **Chat Model**: OpenAI Chat Model
  - **Memory**: 過去の分析結果を記憶
  - **Tool Output Parser**: ツールの出力を解析
  - **複数の入力ポート**: 3つの"+"サインで示される拡張可能な入力

**入力ソース**:
1. **Scrape Page - 2**: 2回目のスクレイピングデータ（実線の矢印）
2. **OpenAI Chat Model**: LLMモデルからの分析支援（破線の矢印）
3. **Send a message in Slack**: Slackからのフィードバックや追加指示（破線の矢印）

**処理内容**:
- 初回と2回目のスクレイピングデータを比較
- ユーザーが指定した監視指示に基づいて変更点を分析
- 重要度を判定
- 変更内容を要約

**出力**: 分析結果（重要変更の有無、変更内容の要約）

### カテゴリー4：外部サービス連携

#### 8. LLMモデル（OpenAI Chat Model）

- **ノードタイプ**: OpenAI Chat Model
- **役割**: AIエージェントの分析を支援
- **機能**:
  - スクレイピングデータの解釈を支援
  - 変更点の重要度判定を支援
  - 分析結果の要約を生成
- **接続**: 破線の矢印でAIエージェントに接続

#### 9. Slack（Send a message in Slack）

- **ノードタイプ**: Slack - Send Message
- **役割**: 重要変更があればSlackに通知
- **機能**:
  - AIエージェントの分析結果を受け取る
  - 重要変更が検出された場合のみ通知
  - 変更内容の要約をSlackチャンネルに投稿
- **接続**: 破線の矢印でAIエージェントに接続
- **通知内容**:
  - 監視対象URL
  - 検出された変更内容
  - 変更の重要度
  - 変更の詳細説明

## データフローの詳細

### フロー1：リクエスト処理と解析

```
フォームトリガー
  ↓ (1 item)
OpenAI API（メッセージ→URL&指示変換）
  ↓ (1 item)
結果解析
  ↓ (1 item)
  ├→ フィードバックループ（-1 item）→ OpenAI API
  └→ 次のフローへ
```

### フロー2：スクレイピングと分析

```
解析結果
  ↓ (1 item)
初回スクレイピング（Firecrawl）
  ↓ (1 item)
1日待機
  ↓ (1 item)
2回目のスクレイピング（Firecrawl）
  ↓ (1 item)
AIエージェント
  ├← OpenAI Chat Model（破線）
  ├← Slack（破線）
  └→ 分析結果
      ↓
Slack通知（重要変更がある場合）
```

## 技術的な詳細

### Firecrawl API

**役割**: Webページのスクレイピング

**特徴**:
- JavaScriptでレンダリングされたページも取得可能
- テキストデータをクリーンに抽出
- API経由で簡単に利用可能

**使用例**:
- 初回スクレイピング: ベースラインとなるデータを取得
- 2回目のスクレイピング: 変更点を検出するための比較データを取得

### OpenAI API

**用途1: メッセージ解析**
- 自然言語の指示をURLとプロンプトに変換
- ユーザーの意図を正確に理解

**用途2: AIエージェントの分析支援**
- スクレイピングデータの解釈
- 変更点の重要度判定
- 分析結果の要約生成

### AIエージェントの構成

**主要コンポーネント**:
1. **Chat Model**: OpenAI Chat Modelを使用
2. **Memory**: 過去の分析結果を記憶し、一貫性のある分析を実現
3. **Tool Output Parser**: ツールの出力を適切に解析
4. **複数入力ポート**: 複数のデータソースから情報を受け取る

**処理の流れ**:
1. 2回目のスクレイピングデータを受け取る
2. 初回のスクレイピングデータと比較（メモリから取得）
3. OpenAI Chat Modelの支援を受けながら分析
4. 変更点を検出し、重要度を判定
5. 重要変更があればSlackに通知

### フィードバックループ

**仕組み**:
- `parse results`ノードから`convert message to website url & instruction`ノードに戻るループ
- 解析結果が不十分な場合、再処理を実行

**用途**:
- 解析精度の向上
- エラーハンドリング
- より正確なURLとプロンプトの抽出

## 実践的な使用例

### 使用例1：価格変更の監視

**入力**:
- URL: `https://competitor.com/pricing`
- 指示: 「価格変更を監視して、変更があれば通知して」

**処理**:
1. OpenAIが指示を解析し、価格セクションを監視するプロンプトを生成
2. Firecrawlで初回スクレイピング
3. 1日待機
4. 2回目のスクレイピング
5. AIエージェントが価格の変更を検出
6. 重要変更があればSlackに通知

### 使用例2：新機能の追加監視

**入力**:
- URL: `https://competitor.com/features`
- 指示: 「新機能の追加を監視して、重要な機能追加があれば通知して」

**処理**:
1. OpenAIが指示を解析し、機能セクションを監視するプロンプトを生成
2. 同様のフローで監視
3. 新機能の追加を検出
4. 重要度を判定して通知

### 使用例3：デザイン変更の監視

**入力**:
- URL: `https://competitor.com`
- 指示: 「トップページのデザイン変更を監視して、大幅な変更があれば通知して」

**処理**:
1. OpenAIが指示を解析し、デザイン要素を監視するプロンプトを生成
2. スクレイピングでHTMLとCSSを取得
3. デザインの変更を検出
4. 大幅な変更があれば通知

## ワークフローの特徴

### 1. 自然言語での指示

**メリット**:
- 技術的な知識がなくても使用可能
- 柔軟な監視指示が可能
- ユーザーフレンドリー

**実現方法**: OpenAI APIで自然言語を解析し、具体的なプロンプトに変換

### 2. 時間差スクレイピング

**メリット**:
- 定期的な監視が可能
- 変更点を正確に検出
- 1日間隔で自動実行

**実現方法**: Waitノードで1日待機してから2回目のスクレイピングを実行

### 3. AIによる差分分析

**メリット**:
- 単純な差分だけでなく、意味のある変更を検出
- 重要度を自動判定
- 変更内容を要約

**実現方法**: AIエージェントが2つのスクレイピングデータを比較し、ユーザーの指示に基づいて分析

### 4. 重要変更のみ通知

**メリット**:
- ノイズを削減
- 重要な情報だけを受け取れる
- Slackチャンネルが煩雑にならない

**実現方法**: AIエージェントが重要度を判定し、重要変更がある場合のみSlackに通知

## 実装時の注意点

### 1. Firecrawl APIの制限

- **レート制限**: APIの利用制限を確認
- **コスト**: スクレイピング回数に応じたコストが発生
- **エラーハンドリング**: スクレイピング失敗時の処理

### 2. OpenAI APIのコスト

- **トークン消費**: メッセージ解析とAIエージェントの分析でトークンを消費
- **コスト管理**: 使用量を監視
- **最適化**: 不要なAPIコールを削減

### 3. 待機時間の設定

- **1日間隔**: デフォルトは1日だが、要件に応じて調整可能
- **スケジュール実行**: 定期的な監視の場合はスケジュールトリガーも検討

### 4. データの保存

- **初回スクレイピングデータ**: メモリまたはデータベースに保存して比較に使用
- **分析結果**: 履歴として保存することで、トレンド分析が可能

### 5. エラーハンドリング

- **スクレイピング失敗**: リトライ機能の実装
- **APIエラー**: 適切なエラーメッセージと通知
- **フィードバックループ**: 解析が失敗した場合の再処理

## 拡張可能性

### 1. 複数URLの監視

- 複数の競合サイトを同時に監視
- 各URLに対して同じワークフローを実行
- 結果を統合してレポート生成

### 2. カスタム分析ルール

- 特定の業界やサービスに特化した分析ルール
- より詳細な変更検出
- 業界特有の重要度判定

### 3. ダッシュボード連携

- 分析結果をダッシュボードに表示
- 変更のトレンドを可視化
- 過去のデータとの比較

### 4. 自動レポート生成

- 定期的なレポートを自動生成
- PDFやスプレッドシートに出力
- メールやSlackで配信

### 5. アラート設定

- 重要度に応じたアラートレベル
- 緊急度の高い変更は即座に通知
- 定期的なサマリーレポート

4. **自動通知**: 重要変更があればSlackに自動通知
