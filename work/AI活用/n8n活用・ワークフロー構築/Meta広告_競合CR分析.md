# 競合他社の広告戦略を自動分析するn8nワークフロー

## 概要

n8nとApifyを使用して、競合他社の広告を自動的にスクレイピング・分析し、Slackに主要なトレンド、新しい広告、インサイトを送信するワークフロー。毎週月曜日7時に自動実行され、手動作業を削減。

**動画URL**: https://www.youtube.com/watch?v=71kwdlJL-34

## 使用ツール

- **n8n**: ワークフロー自動化プラットフォーム
- **Apify**: 広告スクレイピング（Meta、LinkedIn、TikTok対応）
- **AI Agent**: 競合分析（Competitive Intelligence Center）
- **Slack**: 分析結果の通知先

## ワークフロー全体の流れ

1. スケジュールトリガー（毎週月曜7時）
2. Setノードでライブラリフィールドを設定
3. Apifyで競合他社の広告をスクレイピング（過去30日間、アクティブな広告50件）
4. データセットから広告データを取得
5. JavaScriptコードでデータを構造化
6. Edit Fieldsで必要なフィールドのみ抽出
7. Filterで過去7日間の広告のみ抽出
8. Aggregateで全アイテムを1つに集約
9. AI Agentで競合分析を実行
10. Slackに分析結果を送信

## 各ステップの詳細

### 1. スケジュールトリガー

- **ノード**: Schedule Trigger
- **設定**: 
  - 実行時間: 毎週月曜日 7:00 AM
  - カスタマイズ可能: 曜日・時間を変更可能

### 2. Setノード（手動マッピング）

- **ノード**: Set
- **役割**: ライブラリフィールドを手動でマッピング
- **理由**: 広告スクレイピング時に実際のライブラリフィールドを送信するため

### 3. Apify - Run Actor

- **ノード**: Apify - Run Actor
- **設定**:
  - **スクレイピング対象**: Meta広告ライブラリ
  - **取得件数**: 過去30日間の広告50件
  - **フィルター**: アクティブな広告のみ
- **対応プラットフォーム**: 
  - Meta（Facebook/Instagram）
  - LinkedIn
  - TikTok
  - その他数千の統合が可能

### 4. Get Dataset Items

- **ノード**: Apify - Get Dataset Items
- **設定**: 
  - Default Dataset ID: Run Actorの出力から取得
- **取得データ**: 
  - 広告ID
  - Act ID
  - User ID
  - JSON（デフォルトデータセット）

### 5. JavaScriptコード（データ構造化）

- **ノード**: Code (JavaScript)
- **役割**: Metaから出力される不整合なデータを構造化
- **理由**: 
  - Metaの出力データは一貫性がない
  - AIが分析しやすい形式に整形
  - 同じ出力形式を保証

### 6. Edit Fields（フィールド抽出）

- **ノード**: Edit Fields
- **抽出フィールド**:
  - `adId`: 広告ID
  - `startDate`: 開始日（重要）
  - `daysRunning`: 実行日数（重要）
  - `platforms`: 実行プラットフォーム
  - `variations`: バリエーション（カルーセル等）
  - `titles`: タイトル
  - `body`: 本文
  - `CTA`: コールトゥアクション
  - `landingPageUrl`: ランディングページURL
  - `imageUrl`: 画像URL

### 7. Filter（過去7日間のフィルタリング）

- **ノード**: Filter
- **条件**: `daysRunning < 7`（実行日数が7日未満）
- **理由**: 
  - スクレイピングは過去30日間を取得
  - ワークフローは7日ごとに実行されるため、過去7日間のみが必要
  - データ量を削減（例: 116件 → 22件）

### 8. Aggregate（データ集約）

- **ノード**: Aggregate
- **役割**: 全アイテムを1つのアイテムに集約
- **理由**: 
  - AIが1回のインスタンスで分析可能
  - 22個のアイテムを個別に処理すると22回実行され、トークンコストが増加
  - 1つのアイテムにまとめることで効率化

### 9. AI Agent（競合分析）

- **ノード**: AI Agent - Competitive Intelligence Center
- **入力**: Aggregateで集約された競合データ
- **出力形式**: Slack Markdown形式のJSON
- **分析内容**:
  - 主要な発見（Key Findings）
  - 今週の新規広告（New This Week）
  - 参考になる戦術（Steal Worthy Tactics）
    - 競合が実施していること
    - なぜ機能しているか
    - 対抗策としてのアクション
  - フォーマットとルール
  - Metaライブラリへのリンク

### 10. Slack通知

- **ノード**: Slack - Send Message
- **送信内容**:
  - メトリクス（広告数、パーセンテージ）
  - 主要なトレンド
  - 競合の成功要因
  - 今週の新規キャンペーン
  - 対抗戦術

## 出力される分析内容

### 1. 広告フォーマット（Ad Formats）

- カルーセル、動画、画像などの形式
- 例: 過去7日間で8つのカルーセル、うち4つが動画

### 2. CTA戦略（CTA Strategy）

- 使用されているコールトゥアクション
- 例: "Shop now"が主要なCTA

### 3. パフォーマンスシグナル（Performance Signals）

- 広告の実行期間
- 例: 平均2日以上実行されている広告

### 4. 主要な発見（Key Findings）

**例**:
1. **パートナーシップ・コラボ重視**: インフルエンサーとのコラボレーション
2. **季節性の推進**: Q4、クリスマス時期の特別キャンペーン（例: "25 days of gains"）
3. **価値提案**: 週次でのオファー（例: "29ドル以上の商品購入でMy Proteinアイテム無料"）

### 5. 今週の新規広告（New This Week）

- 新しく作成されたキャンペーン
- 前週との比較で新規要素を特定

### 6. 参考になる戦術（Steal Worthy Tactics）

- 競合が実施している具体的な戦術
- なぜ機能しているかの分析
- 自社ブランドへの応用方法

### 7. Metaライブラリへのリンク

- スクレイピングした広告を直接確認可能

## カスタマイズ可能な設定

### 実行頻度

- **デフォルト**: 毎週月曜日7時
- **変更可能**: 
  - 隔週実行
  - 30日ごと
  - 任意の曜日・時間

### スクレイピング期間

- **デフォルト**: 過去30日間をスクレイピング、過去7日間を分析
- **変更可能**: 要件に応じて期間を調整

### 取得件数

- **デフォルト**: 50件
- **変更可能**: 必要に応じて増減

### 競合他社の設定

- MetaライブラリのURLを変更することで、異なる競合他社を追跡可能
- 複数の競合他社を並行して追跡することも可能

## ワークフローのメリット

1. **時間の節約**: 手動での競合分析作業を自動化
2. **定期的な監視**: 毎週自動的に最新情報を取得
3. **包括的な分析**: 複数のチャネル・競合他社を同時に追跡
4. **アクション可能なインサイト**: 具体的な戦術と対抗策を提示
5. **コスト効率**: Aggregateノードにより、AIの実行回数を削減

## データ処理のポイント

### データの構造化

- Metaの出力データは不整合なため、JavaScriptコードで構造化が必須
- AIが分析しやすい形式に整形

### フィルタリングの重要性

- 過去30日間をスクレイピングするが、分析は過去7日間のみ
- 不要なデータを除外し、処理効率を向上

### 集約による最適化

- 複数のアイテムを1つに集約することで、AIの実行回数を削減
- トークンコストの削減

## 拡張可能性

1. **複数の競合他社**: 同じワークフローで複数の競合他社を追跡
2. **複数のプラットフォーム**: Meta、LinkedIn、TikTokを同時に分析
3. **データベースへの保存**: 分析結果をデータベースに保存し、トレンドを追跡
4. **ダッシュボード連携**: 分析結果を可視化ダッシュボードに送信
5. **アラート設定**: 特定の条件（例: 新規広告が10件以上）でアラートを送信

## 注意点

1. **Apifyの設定**: スクレイパーの設定を適切に構成する必要がある
2. **AIプロンプト**: 分析の質はAIプロンプトに依存するため、プロンプトの最適化が重要
3. **データの精度**: Metaライブラリのデータが正確であることを前提とする
4. **実行頻度**: 過度なスクレイピングはレート制限に引っかかる可能性がある
