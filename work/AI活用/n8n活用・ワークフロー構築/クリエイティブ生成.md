# クリエイティブ自動制作システム ワークフロー解説

## 概要

Slackから企業URLを受け取り、ブランド分析と画像生成を自動化するn8nワークフロー。企業のサービスページを分析し、トンマナ（トーン&マナー）情報を抽出して、AI画像生成用のプロンプトを作成し、クリエイティブ画像を自動生成する。

## 参考
https://rehatchhq.slack.com/archives/C05LGGA3MG9/p1755222347146469

## ワークフロー構成

### 処理フロー

```
Slackトリガー（企業URL受信）
    ↓
URL抽出
    ↓
URL存在チェック
    ├→ [true] → Firecrawl取得（スクレイピング）
    │              ↓
    │          ブランド分析（AI）
    │              ↓
    │          ブランドデータ検証
    │              ↓
    │          広告プロンプト生成（AI）
    │              ↓
    │          Dumpling AI画像生成
    │              ↓
    │          最終データ整理
    │              ↓
    │          Slack成功応答
    │
    └→ [false] → Slackエラー応答
```

## 各フェーズの詳細

### 1. Slackトリガー

- **トリガータイプ**: Slack Webhook
- **入力**: Slackメッセージ（企業URLを含む）
- **起動方法**: Slackで企業URLを添付してメンション

### 2. URL抽出フェーズ

- **ノード名**: URL抽出
- **処理内容**: Slackメッセージから企業URLを抽出
- **出力**: 抽出されたURL

### 3. URL存在チェックフェーズ

- **ノード名**: URL存在チェック
- **処理内容**: 抽出されたURLの有効性を検証
- **分岐**:
  - **true**: 次の処理（Firecrawl取得）に進む
  - **false**: エラー応答をSlackに送信

### 4. ブランド分析フェーズ

#### 4-1. Firecrawl取得

- **ノード名**: Firecrawl取得
- **処理内容**: 企業のサービスページをスクレイピング
- **取得データ**:
  - スクリーンショット
  - テキスト情報
- **用途**: ブランド分析のためのデータ収集

#### 4-2. ブランド分析（AI）

- **ノード名**: Chat Model（ブランド分析）
- **使用モデル**: Anthropic Chat Model（Claude）
- **処理内容**: スクレイピングしたデータからトンマナ情報を分析
- **分析項目**:
  - トーン&マナー
  - ブランドカラー
  - デザインスタイル
  - ビジュアル要素

#### 4-3. ブランドデータ検証

- **ノード名**: ブランドデータ検証
- **処理内容**: AI分析結果の妥当性を検証
- **出力**: 検証済みブランドデータ

### 5. 画像生成フェーズ

#### 5-1. 広告プロンプト生成（AI）

- **ノード名**: 広告プロンプト生成
- **使用モデル**: Anthropic Chat Model（Claude）
- **処理内容**: ブランド分析結果を基に画像生成用プロンプトを作成
- **入力**: ブランドデータ検証の結果
- **出力**: 画像生成プロンプト

#### 5-2. Dumpling AI画像生成

- **ノード名**: Dumpling AI画像生成
- **API**: Dumpling AI（POSTリクエスト）
- **処理内容**: 生成されたプロンプトを使用して画像を生成
- **現状の課題**: 文字の生成が弱い

#### 5-3. 最終データ整理

- **ノード名**: 最終データ整理
- **処理内容**: 生成された画像と関連データを整理

### 6. 通知フェーズ

#### 6-1. Slack成功応答

- **ノード名**: Slack成功応答
- **送信内容**:
  - ブランド分析結果
  - 生成された画像のURL
  - テキスト情報のURL

#### 6-2. Slackエラー応答

- **ノード名**: Slackエラー応答
- **送信条件**: URL存在チェックがfalseの場合
- **送信内容**: エラーメッセージ

## 技術仕様

### 使用ノードタイプ

- `n8n-nodes-base.slack`: Slack連携（トリガー・通知）
- `n8n-nodes-base.code`: URL抽出処理
- `n8n-nodes-base.if`: 条件分岐（URL存在チェック）
- Firecrawl連携ノード: ウェブスクレイピング
- `@n8n/n8n-nodes-langchain.agent`: AIエージェント（ブランド分析・プロンプト生成）
- `@n8n/n8n-nodes-langchain.lmChatAnthropic`: Anthropic Claude API連携
- HTTP Requestノード: Dumpling AI画像生成API呼び出し

### 使用AIモデル

- **ブランド分析**: Anthropic Claude
- **プロンプト生成**: Anthropic Claude
- **画像生成**: Dumpling AI（現状）/ FLUXモデル（予定）

### 外部サービス連携

- **Firecrawl**: ウェブページスクレイピング
- **Dumpling AI**: 画像生成API
- **Slack**: トリガー・通知

## 現状の課題と対応

### 画像生成の課題

- **問題**: 文字の生成が弱い
- **現状**: n8nのGPTノード（DALL-E 3）では文字生成が不十分
- **検証予定**: 
  - MidjourneyをHTTPリクエストで使用
  - GPTの画像生成をHTTPリクエストで使用

## ワークフローの特徴

### 強み

1. **完全自動化**: Slackからのトリガーで全プロセスが自動実行
2. **エラーハンドリング**: URL検証による安全な処理
3. **AI活用**: ブランド分析からプロンプト生成までAIで自動化
4. **統合性**: Slack、Firecrawl、AI画像生成を統合

### 改善の余地

1. **画像生成品質**: 文字生成の精度向上が必要
2. **バリエーション**: 複数パターン生成機能の実装
3. **ストレージ**: Googleドライブ連携による画像管理

## データフロー

1. **入力**: Slackメッセージ（企業URL）
2. **処理**: 
   - URL抽出・検証
   - ウェブスクレイピング
   - ブランド分析（AI）
   - プロンプト生成（AI）
   - 画像生成
3. **出力**: 
   - Slack通知（分析結果・画像URL）
   - 生成された画像データ

## 使用例

1. Slackで企業URLを添付
2. ワークフローをメンション
3. 自動でブランド分析と画像生成が実行される
4. Slackに結果が通知される
