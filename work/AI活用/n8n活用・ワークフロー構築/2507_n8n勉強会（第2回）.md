## n8nの概要

### ディファイとの違い

**n8nの特徴**:
- **トリガーの自由度**: 外部のアクションからワークフローを起動可能
- **自動実行**: チャットだけでなく、定期実行や外部イベント検知が可能
- **連携の強さ**: Salesforce、HubSpot、カレンダー等の変更を検知して自動実行

**ディファイの特徴**:
- **チャット中心**: チャットで問い合わせたらワークフローがスタート
- **設定の複雑さ**: 自動実行や条件設定はAPIで呼び出す必要があり、非エンジニアには難しい

**使い分け**:
- **ディファイ**: 簡単なアプリ開発、RAGを使ったアプリケーション
- **n8n**: 外部ツールとの連携、自動実行、一歩踏み込んだ実装

### 主な機能

1. **トリガーの多様性**
   - スケジュール実行（毎週月曜日7時等）
   - 外部サービスの変更検知（Salesforce、HubSpot等）
   - Slackメッセージ、ファイルシェア
   - Webhook

2. **AIエージェントの統合**
   - AIエージェントノードを使用
   - チャットモデル（Claude、OpenAI等）を選択可能
   - ツール連携（カレンダー、Gmail、Slack検索等）

3. **セキュリティ制限**
   - 最初は読み取り権限のみ許可
   - 書き込み・更新・削除は慎重に設定
   - 実行前に確認を推奨

## Claudeを使ったワークフロー生成

### 基本的なアプローチ

**問題点**:
- n8nの設定が細かく、1つ1つ設定するのが大変
- 非エンジニアには敷居が高い

**解決策**:
- Claudeにn8nのワークフローJSONファイルを作成させる
- 生成したJSONをn8nにインポート
- エラー部分を修正しながら完成させる

### 実装手順

1. **Claudeへの指示**
   ```
   n8nのワークフローJSONファイルで作りたいです。
   n8nのワークフローをJSONファイル見せたあるあるですね。
   変化押したら、n8nのワークロージェイソンファイルで作りたいです。
   質問あったら聞いてください。
   ```

2. **やりたいことを明確に記述**
   - Google Calendarで予定が終わったら
   - その予定の概要等の情報を送ってきて
   - AIで要約を作って
   - その内容プラス「お疲れ様でした」というメッセージをSlackに送る

3. **JSONファイルの生成**
   - ClaudeがJSONファイルを生成
   - 右側でJSONファイルをダウンロード

4. **n8nへのインポート**
   - n8nで「Create Workflow」を開く
   - 右上の3点マークから「Import from File」を選択
   - 生成したJSONファイルをアップロード

5. **エラー修正**
   - 最初の1発では上手くいかないことが多い
   - エラー内容をClaudeに伝えて修正
   - 複数回のやり取りで完成

### Claudeプロジェクトの活用

**n8n作成アシスタント**:
- Claudeのプロジェクト機能で「n8n作成アシスタント」を作成
- 指示を設定しておくと、より綺麗にJSONを生成してくれる
- ヒアリングしてからJSONを作成してくれる

**使用例**:
- 「Salesforceでリードが作成された時に、Slack通知して」と指示
- 詳細をヒアリング
- 確認後にJSONを生成

## 実践例：Google Calendar連携とSlack通知

### ワークフローの構成

1. **Google Calendarトリガー**
   - イベントが終わったら（Event Ended）
   - カレンダーを選択

2. **AIエージェントノード**
   - チャットモデル: Claude
   - 予定の情報を要約

3. **Slackノード**
   - メッセージを投稿
   - チャンネルを選択

### 認証設定

#### Google Calendar認証

1. **Google Calendarノードをダブルクリック**
2. **「Select Credential」→「Create New」**
3. **OAuth認証画面が表示**
4. **Googleアカウントで認証**
5. **カレンダーを選択**（複数選択可能）

**注意点**:
- 複数人のカレンダーを取得する場合は、ノードを複製するか、Expressionで調整
- フィルターを設定して、必要な予定のみ取得

#### Claude API認証

1. **AIエージェントノードを開く**
2. **「Chat Model」の「+」をクリック**
3. **「Anthropic Chat Model」を選択**
4. **「Select Credential」→「Create New」**
5. **API Keyを入力**
6. **Save**

**API Keyの取得**:
- Notion等で共有されたAPI Keyを使用
- またはAnthropicのサイトから取得

#### Slack認証

1. **Slackノードを追加**
2. **「Message」→「Post Message」を選択**
3. **認証が必要な場合はOAuth認証**
4. **チャンネルを選択**

**注意点**:
- チャンネル選択が表示されない場合は、認証を再設定
- 権限が強めなので、送信先チャンネルに注意
- テスト時は専用チャンネルを使用

### よくあるエラーと対処法

#### 1. カレンダーデータの大量取得

**問題**:
- 全期間の予定を取得してしまう（例: 1900年からの誕生日メッセージ等）

**対処法**:
- フィルターを設定
- Start Time、End Timeで期間を指定
- Order By Start Timeで並び替え

#### 2. 日本語のDescriptionが取得できない

**問題**:
- カレンダーのタイトルは取れるが、Description（説明）が日本語で取得できない

**対処法**:
- 仕様としてまだ対応していない可能性
- タイトルのみで対応するか、今後のアップデートを待つ

#### 3. AIエージェントのエラー

**問題**:
- 「Text parameter is input」等のエラー

**対処法**:
- 左側のカレンダーノードからデータをドラッグ&ドロップ
- テキストフィールドを一度削除してから再設定
- マニュアルマッピングで設定

#### 4. Slackチャンネルが表示されない

**問題**:
- チャンネル選択画面が表示されない

**対処法**:
- 認証を再設定
- チャンネルIDを直接入力（チャンネル詳細からIDを取得）
- ノードのバージョンが古い場合は更新

#### 5. 大量のメッセージが送信される

**問題**:
- 500件の予定が全てSlackに送信される

**対処法**:
- フィルターを設定して必要な予定のみ取得
- 実行前にデータ件数を確認
- テスト時は専用チャンネルを使用

## 実践例：空き時間検索ワークフロー

### 要件

- 複数人（3人）のカレンダーから空き時間を検索
- 2週間後の期間で検索
- 1.5時間以上空いている時間を候補として表示
- Slackに通知

### 実装アプローチ

**0から作るより改良する方が効率的**:
- 既存の動くワークフローをベースにする
- Claudeに改良を依頼
- 段階的に機能を追加

### ワークフローの構成

1. **マニュアルトリガー**（テスト用）
2. **Google Calendarノード**（3人分、それぞれ別ノード）
   - 2週間後の期間を指定
   - 各人の予定を取得
3. **変数設定ノード**
   - 取得した予定を変数にまとめる
4. **Codeノード**
   - 複数の予定データを1つにまとめる
5. **AIエージェントノード**
   - 空き時間を計算
   - 3人全員が空いている時間を抽出
   - 1.5時間以上の空き時間を候補として表示
6. **Slackノード**
   - 結果を通知

### 実装のポイント

1. **複数人のカレンダー取得**
   - 各人のカレンダーノードを個別に作成
   - 認証情報を各人に変更
   - 3つのノードからデータを取得

2. **データの統合**
   - 変数設定ノードで各人の予定を変数に格納
   - Codeノードで1つにまとめる
   - AIエージェントに渡す

3. **空き時間の計算**
   - AIエージェントに指示を明確に記述
   - 「3人全員が空いている時間」
   - 「1.5時間以上空いている時間」
   - 「候補日として表示」

4. **エラー対応**
   - Combineノードのバージョンが古い場合は削除
   - アイテム数が多すぎる場合は制限を設定
   - 実行前にデータ件数を確認

### 改良のプロセス

1. **ベースワークフローの共有**
   - 動くワークフローをJSONでエクスポート
   - 共有またはダウンロード

2. **Claudeへの依頼**
   - ファイルをアップロード
   - 「これを3人分に拡張して」と指示
   - 「1.5時間以上の条件を追加して」と指示

3. **段階的な改良**
   - まず1人で動作確認
   - 3人に拡張
   - 条件を追加
   - エラーを修正

## ベストプラクティス

### ワークフロー作成のアプローチ

1. **0から作るより改良する**
   - 既存の動くワークフローをベースにする
   - X（Twitter）等で公開されているワークフローを活用
   - 実績のあるワークフローを改良

2. **段階的な実装**
   - まず最小限の機能で動作確認
   - 機能を段階的に追加
   - エラーが出たら修正してから次へ

3. **Claudeとの協働**
   - 最初の生成はClaudeに任せる
   - エラー部分は人間が修正
   - 改良はClaudeに依頼

### セキュリティの注意点

1. **権限の制限**
   - 最初は読み取り権限のみ
   - 書き込み・更新・削除は慎重に
   - 実行前に確認

2. **チャンネル選択**
   - テスト用チャンネルを使用
   - 本番チャンネルに送信する前に確認
   - 大量送信に注意

3. **認証情報の管理**
   - API Keyは適切に管理
   - 共有する場合は安全な方法で
   - 定期的に更新

### トラブルシューティング

1. **エラーが出た場合**
   - エラーメッセージを確認
   - Claudeにエラー内容を伝えて修正依頼
   - 段階的に修正

2. **データが取得できない場合**
   - 認証を再設定
   - フィルター条件を確認
   - 期間指定を確認

3. **ワークフローが動かない場合**
   - 各ノードを個別にテスト
   - データの流れを確認
   - エラーログを確認
