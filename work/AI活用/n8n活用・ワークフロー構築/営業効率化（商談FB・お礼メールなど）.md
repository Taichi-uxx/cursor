# 営業効率化ワークフロー：Notta商談文字起こし活用

## 実際のワークフロー
https://kota-rehatch.app.n8n.cloud/workflow/SAAnu7hT24HvTwGX

## 概要

このワークフローは、**Notta**から商談の文字起こしを取得し、AIを活用して以下の3つのタスクを自動化するn8nワークフローです：

1. **商談のフィードバック**: 商談内容を分析してフィードバックを生成
2. **お礼メール作成**: 商談内容をもとにしたお礼メールを自動生成
3. **ヒアリング情報のまとめ**: 商談でのヒアリング情報を整理

**主な特徴**:
- Google DriveとNottaを連携して自動トリガー
- Anthropic Chat Model（Claude）を使用した高品質なAI処理
- 社外企業のみをフィルタリングして処理
- 手動実行も可能でテストが容易
- Slack通知とGoogle Driveへの保存で結果を共有

## ワークフロー全体の流れ

### 処理フロー図

```
[Google Drive自動連携]
Google Drive（Nottaフォルダ）でファイル作成
    ↓
最新ファイルをダウンロード
    ↓
JSONに変換・社外以外をフィルター
    ├→ [true] → 商談内容FB（AI処理）
    │              ↓
    │          ヒアリング情報（AI処理）
    │              ↓
    │          Merge（統合）
    │              ↓
    │          お礼メール作成くん（AI処理）
    │              ├→ Google Driveに保存
    │              └→ Slack通知
    │
    └→ [false] → No Operation（何もしない）

[手動実行]
手動トリガー
    ↓
テストデータ
    ↓
商談内容FB（AI処理）
    （以下、自動連携と同じ流れ）
```

## セクション別の詳細解説

### セクション1：使い方（左側の黄色パネル）

#### ①認証が必要なものは自分で設定する

**必要な認証**:
- **Google Drive**: Nottaフォルダへのアクセス権限
- **Slack**: 通知先チャンネルへの投稿権限
- **Gmail**: メール送信権限（必要に応じて）

#### ②カスタマイズ箇所

**Slack設定**:
- 通知したいチャンネルを自分で設定
- ワークフロー内のSlackノードでチャンネルを指定

#### ③必要セットアップ

**NottaとGoogle Driveの連携**:
1. NottaとGoogle Driveを連携する
2. 自分のフォルダを作成して設定する
3. **推奨**: documentのみ、またはtxtのみにしておいた方が安定する可能性がある（フィードバック歓迎）

### セクション2：Google Drive自動連携（上部ピンクセクション）

#### ノード1：Google Drive - ファイル作成トリガー

**ノードタイプ**: Google Drive Trigger

**設定**:
- **トリガー**: fileCreated（ファイル作成時）
- **フォルダー**: 自分のNottaフォルダを選択
- **役割**: NottaからGoogle Driveに文字起こしファイルが作成されたときに自動的にワークフローを起動

**処理内容**:
- Nottaフォルダで新しいファイルが作成されると自動的にトリガー
- ファイル作成イベントを検知して次のノードに渡す

#### ノード2：Google Drive - 最新ファイルをダウンロード

**ノードタイプ**: Google Drive - Download

**設定**:
- **オペレーション**: download: file
- **役割**: 作成された最新のファイルをダウンロード

**処理内容**:
- トリガーで検知されたファイルをダウンロード
- ファイルの内容を取得して次のノードに渡す

#### ノード3：テキストファイルから抽出・JSON変換・フィルター

**ノードタイプ**: Extract From Text File

**設定**:
- **処理内容**: 
  1. ダウンロードしたファイルからテキストを抽出
  2. JSON形式に変換
  3. 社外企業以外をフィルターする

**フィルター条件**:
- **社外企業のみ処理**: 社内の商談は除外
- **判定ロジック**: JSONデータ内の企業情報を確認し、社外かどうかを判定

**出力**:
- JSON形式の商談データ
- フィルター結果（true/false）

#### ノード4：フィルター分岐

**ノードタイプ**: IF / Filter

**設定**:
- **条件**: 社外企業かどうか
- **分岐**:
  - **true**: 社外企業の場合、次の処理に進む
  - **false**: 社内企業の場合、No Operationに進む

**処理内容**:
- フィルター結果に応じて処理を分岐
- 社外企業のみを処理対象とする

#### ノード5：Set（trueパス）

**ノードタイプ**: Set

**設定**:
- **モード**: manual
- **役割**: フィルターでtrueになった場合のデータを設定

**処理内容**:
- 社外企業の商談データを整形
- 次のAI処理ノードに渡すためのデータを準備

#### ノード6：No Operation（falseパス）

**ノードタイプ**: No Operation

**設定**:
- **役割**: 何もしない

**処理内容**:
- 社内企業の場合は処理を終了
- ワークフローを終了する

### セクション3：手動実行（下部紫セクション）

#### ノード1：手動トリガー

**ノードタイプ**: Manual Trigger

**設定**:
- **トリガー**: "When clicking 'Execute workflow'"
- **役割**: 手動でワークフローを実行する

**使用シーン**:
- テスト実行
- 既存のファイルを処理したい場合
- デバッグ時

#### ノード2：テストデータ

**ノードタイプ**: Set / Manual

**設定**:
- **モード**: manual
- **役割**: テスト用のデータを設定

**処理内容**:
- 手動実行時に使用するテストデータを準備
- 実際のNottaファイルの代わりに使用

### セクション4：メイン処理（中央緑セクション）

#### ノード1：商談内容FB

**ノードタイプ**: AI Agent / Chat Model

**設定**:
- **入力**:
  - **Chat Model**: Anthropic Chat Model（Claude）
  - **Memory**: 過去の商談履歴やコンテキストを保持
  - **Tool**: 必要に応じて外部ツールを利用
- **役割**: 商談内容を分析してフィードバックを生成

**処理内容**:
1. Nottaから取得した商談の文字起こしを読み込む
2. Anthropic Chat Modelを使用して商談内容を分析
3. 以下の観点でフィードバックを生成：
   - 商談の進行状況
   - 顧客の反応や関心度
   - 改善点や次回への提案
   - 商談の評価

**出力**: 商談フィードバック（テキスト形式）

#### ノード2：Merge（統合）

**ノードタイプ**: Merge

**設定**:
- **モード**: combine
- **入力1**: 商談内容FBの出力
- **入力2**: ヒアリング情報の出力
- **役割**: 2つのAI処理結果を統合

**処理内容**:
- 商談フィードバックとヒアリング情報を1つのデータに統合
- お礼メール作成に必要な情報をまとめる

#### ノード3：お礼メール作成くん

**ノードタイプ**: AI Agent / Chat Model

**設定**:
- **入力**:
  - **Chat Model**: Anthropic Chat Model（Claude）
  - **Memory**: 過去のメール履歴やテンプレートを保持
  - **Tool**: 必要に応じて外部ツールを利用
  - **Output Parser**: Structured Output Parser
- **役割**: 商談内容をもとにお礼メールを自動生成

**処理内容**:
1. Mergeノードから統合されたデータを受け取る
2. 商談内容とヒアリング情報を基に、適切なお礼メールを作成
3. Structured Output Parserで構造化された形式で出力
4. メールのテイストはカスタマイズ可能

**出力**: 構造化されたお礼メール（件名、本文、宛先など）

#### ノード4：Anthropic Chat Model

**ノードタイプ**: Anthropic Chat Model（Claude）

**設定**:
- **役割**: AI処理の基盤となるモデル
- **接続**: 
  - 商談内容FB（破線で接続）
  - お礼メール作成くん（破線で接続）

**処理内容**:
- 複数のAIノードで共有されるAIモデル
- 高品質な自然言語処理を提供
- 商談分析とメール生成の両方で使用

#### ノード5：ヒアリング情報

**ノードタイプ**: AI Agent / Chat Model

**設定**:
- **入力**:
  - **Chat Model**: Anthropic Chat Model（Claude）
  - **Memory**: 過去のヒアリング情報を保持
  - **Tool**: 必要に応じて外部ツールを利用
- **役割**: 商談でのヒアリング情報を整理・まとめる

**処理内容**:
1. Nottaから取得した商談の文字起こしを読み込む
2. 以下の情報を抽出・整理：
   - 顧客の課題・ニーズ
   - 予算・スケジュール
   - 意思決定者情報
   - 競合情報
   - その他の重要情報
3. 構造化されたヒアリング情報として出力

**出力**: ヒアリング情報（構造化されたデータ）

#### ノード6：Structured Output Parser

**ノードタイプ**: Structured Output Parser

**設定**:
- **役割**: AI出力を構造化された形式にパース
- **接続**: お礼メール作成くん（破線で接続）

**処理内容**:
- お礼メール作成くんの出力を構造化
- JSON形式など、機械可読な形式に変換
- メールの件名、本文、宛先などを分離

### セクション5：設定必要（右側ピンクセクション）

#### ノード1：Slack - メッセージ送信

**ノードタイプ**: Slack - Send Message

**設定**:
- **警告**: 設定が必要（赤い警告マーク）
- **役割**: 商談処理の結果をSlackに通知

**処理内容**:
- 商談フィードバックやお礼メール作成完了を通知
- カスタマイズ: 通知したいチャンネルを自分で設定

**注意点**: チャンネルを設定しないとエラーになる

#### ノード2：Google Drive - テキストからファイル作成

**ノードタイプ**: Google Drive - Create File from Text

**設定**:
- **警告**: 設定が必要（赤い警告マーク）
- **オペレーション**: createFromText: file
- **役割**: 生成されたお礼メールをGoogle Driveに保存

**処理内容**:
- お礼メール作成くんの出力をテキストファイルとして保存
- Google Driveの指定フォルダーに保存

**注意点**: 保存先フォルダーを設定する必要がある

#### ノード3：Google Drive - ファイルダウンロード

**ノードタイプ**: Google Drive - Download File

**設定**:
- **警告**: 設定が必要（赤い警告マーク）
- **オペレーション**: download: file
- **役割**: 保存されたファイルをダウンロード

**処理内容**:
- Google Driveに保存されたファイルをダウンロード
- 次のノード（ディスクへの書き込み）に渡す

#### ノード4：ディスクへの書き込み

**ノードタイプ**: Read/Write Files from Disk

**設定**:
- **オペレーション**: Write File to Disk
- **役割**: ダウンロードしたファイルをローカルディスクに保存

**処理内容**:
- Google Driveからダウンロードしたファイルをローカルに保存
- バックアップやローカル処理のために使用

#### ノード5：Slack - メッセージ送信1

**ノードタイプ**: Slack - Send Message

**設定**:
- **警告**: 設定が必要（赤い警告マーク）
- **オペレーション**: post: message
- **役割**: お礼メール作成完了をSlackに通知

**処理内容**:
- お礼メール作成くんの出力を受け取り、Slackに通知
- メール内容のサマリーやリンクを送信

**注意点**: チャンネルを設定する必要がある

## データフローの詳細

### 自動実行フロー

1. **トリガー**: Nottaフォルダでファイル作成
2. **ダウンロード**: 最新ファイルをダウンロード
3. **抽出・変換**: テキストを抽出してJSONに変換
4. **フィルター**: 社外企業かどうかを判定
   - **true**: 次の処理に進む
   - **false**: 処理を終了
5. **AI処理1**: 商談内容FBでフィードバック生成
6. **AI処理2**: ヒアリング情報を整理
7. **統合**: Mergeノードで2つの結果を統合
8. **AI処理3**: お礼メール作成くんでメール生成
9. **出力1**: Google Driveに保存
10. **出力2**: Slackに通知

### 手動実行フロー

1. **トリガー**: 手動でワークフローを実行
2. **テストデータ**: テスト用データを設定
3. **AI処理1**: 商談内容FBでフィードバック生成
4. **以下、自動実行フローと同じ**

## トラブルシューティング

### よくある問題

#### 1. フィルターが正しく動作しない

**原因**:
- JSON変換が正しく行われていない
- フィルター条件が適切でない

**解決方法**:
- Extract From Text Fileノードの設定を確認
- フィルター条件を見直す
- テストデータで動作確認

#### 2. AI処理がエラーになる

**原因**:
- Anthropic Chat Modelの認証が正しくない
- プロンプトが長すぎる
- Memoryの設定が不適切

**解決方法**:
- APIキーの設定を確認
- プロンプトを短くする
- Memoryの設定を見直す

#### 3. Slack通知が届かない

**原因**:
- チャンネルが設定されていない
- Slackの認証が正しくない

**解決方法**:
- チャンネルを設定する
- Slackの認証を確認

#### 4. Google Driveに保存されない

**原因**:
- 保存先フォルダーが設定されていない
- Google Driveの認証が正しくない

**解決方法**:
- 保存先フォルダーを設定する
- Google Driveの認証を確認
