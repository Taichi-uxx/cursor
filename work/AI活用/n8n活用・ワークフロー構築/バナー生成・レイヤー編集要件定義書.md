## 1. プロジェクト概要
### 1.1 目的
n8nワークフローとnanobanaのHTTPリクエストノードを活用し、広告バナー画像の生成からレイヤー分割、編集、再統合まで一連のフローを自動化するシステムを構築する。
### 1.2 背景
- 広告制作においてデザイナーが手動で行っているレイヤー分割・編集作業の自動化が必要
- AI画像生成技術とnanobana APIを組み合わせることで、プロフェッショナルな広告バナー制作プロセスを実現
- n8nによるノーコード/ローコード環境での実装により、開発・保守コストを削減
### 1.3 スコープ
- **対象範囲**
  - Gemini APIを使用した広告バナー画像の初期生成
  - nanobana APIを使用したレイヤー分割処理
  - レイヤー別編集機能（テキスト、背景、オブジェクトなど）
  - 編集後のレイヤー統合による最終バナー生成
  - n8nワークフローによる一連の処理の自動化
- **対象外**
  - 高度な画像解析（AIによる被写体認識など）
  - リアルタイムプレビュー機能
  - バッチ処理による大量バナー生成
## 2. システム要件
### 2.1 機能要件
#### FR-001: 広告バナー初期生成機能
- テキストプロンプトを入力として広告バナーを生成
- Gemini 2.5 Flash Image Previewモデルを使用
- 広告バナーサイズに対応（1200×628, 728×90, 300×250等）
#### FR-002: レイヤー分割機能
- 生成されたバナー画像をnanobana APIでレイヤーに分割
- 背景レイヤー、テキストレイヤー、オブジェクトレイヤーの識別
- レイヤー情報（位置、サイズ、透明度）の取得
#### FR-003: レイヤー編集機能
- 各レイヤーの個別編集（色調、明度、コントラスト調整）
- テキストレイヤーの内容変更・フォント調整
- オブジェクトの位置・サイズ調整
- 新規レイヤーの追加機能
#### FR-004: レイヤー統合機能
- 編集されたレイヤーを統合して最終バナーを生成
- 出力形式の選択（PNG, JPEG, WebP）
- 圧縮率・品質の調整機能
#### FR-005: プロンプト管理
- 広告ジャンル別のテンプレートプロンプト
- 動的なプロンプト生成（商品名、キャッチコピー等の変数対応）
- 多言語プロンプトに対応
#### FR-006: エラーハンドリング・リトライ機能
- API接続エラーの検知と通知
- レイヤー分割失敗時の代替処理
- 編集処理のロールバック機能
### 2.2 非機能要件
#### NFR-001: パフォーマンス
- 初期画像生成: 30秒以内
- レイヤー分割処理: 15秒以内
- レイヤー編集処理: 10秒以内
- 統合処理: 10秒以内
- 全体処理時間: 60秒以内
#### NFR-002: セキュリティ
- APIキーの安全な管理（n8n認証情報として保存）
- HTTPSによる通信の暗号化
- 処理中画像データの一時保存時の暗号化
#### NFR-003: 可用性
- n8nサーバーの稼働時間に依存
- 手動実行およびスケジュール実行に対応
- 処理失敗時の自動リトライ機能
#### NFR-004: 保守性
- ワークフローのエクスポート/インポート機能
- モジュール化されたノード構成
- 詳細ログ出力による処理追跡
## 3. システム構成
### 3.1 アーキテクチャ
```
[ユーザー] → [n8n UI] → [ワークフロー実行エンジン]
                              ↓
                    [初期画像生成]
                    [Gemini APIノード]
                              ↓
                    [レイヤー分割処理]
                    [nanobana HTTPノード]
                              ↓
                    [レイヤー編集処理]
                    [画像編集APIノード群]
                              ↓
                    [レイヤー統合処理]
                    [統合APIノード]
                              ↓
                    [最終バナー保存] → [ローカルストレージ]
```
### 3.2 利用技術・API
- **プラットフォーム**: n8n (v1.0以上)
- **画像生成API**: Google Gemini API v1beta
- **レイヤー処理API**: nanobana HTTP Request API
- **プロトコル**: HTTPS/REST
- **データ形式**: JSON, Base64エンコード画像, PNG/JPEG
### 3.3 必要リソース
- n8nインスタンス（セルフホスト or クラウド）
- Gemini API Key（Google AI Studio経由で取得）
- nanobana API アクセス権限
- ストレージ容量: 1バナーあたり約5-10MB（レイヤー含む）
## 4. ワークフロー設計
### 4.1 メインフロー
| ステップ | ノード名 | 処理内容 |
|---------|---------|---------|
| 1 | 手動実行トリガー | ワークフロー開始、パラメータ入力 |
| 2 | プロンプト生成 | 広告内容に基づくプロンプト生成 |
| 3 | Gemini画像生成 | 初期バナー画像の生成 |
| 4 | 画像前処理 | Base64デコード、フォーマット変換 |
| 5 | nanobanaレイヤー分割 | 画像をレイヤーに分割 |
| 6 | レイヤー情報解析 | 各レイヤーの属性情報取得 |
| 7 | レイヤー編集処理 | 各レイヤーの個別編集 |
| 8 | レイヤー統合 | 編集済みレイヤーの統合 |
| 9 | 最終バナー保存 | 完成バナーのローカル保存 |
| 10 | 処理結果通知 | 完了通知とファイル情報出力 |
### 4.2 編集フロー詳細
#### 4.2.1 背景レイヤー編集
- 色調補正（彩度、明度、コントラスト）
- グラデーション効果の追加
- パターンオーバーレイの適用
#### 4.2.2 テキストレイヤー編集
- フォント変更（ファミリー、サイズ、太さ）
- 色変更とアウトライン効果
- シャドウ・グロー効果の追加
- テキスト内容の動的変更
#### 4.2.3 オブジェクトレイヤー編集
- 位置・サイズの調整
- 回転・変形処理
- フィルター効果の適用
## 5. API仕様
### 5.1 Gemini API（初期生成）
```json
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-image-preview:generateContent
Request:
{
  "contents": [{
    "parts": [{
      "text": "Create a professional advertising banner for [PRODUCT] with [STYLE] design, size 1200x628px"
    }]
  }]
}
```
### 5.2 nanobana レイヤー分割API
```json
POST [nanobana_endpoint]/separate-layers
Request:
{
  "image": "base64_encoded_image",
  "options": {
    "layer_types": ["background", "text", "objects"],
    "output_format": "png",
    "preserve_transparency": true
  }
}
Response:
{
  "layers": [
    {
      "type": "background",
      "data": "base64_encoded_layer",
      "position": {"x": 0, "y": 0},
      "size": {"width": 1200, "height": 628}
    },
    {
      "type": "text",
      "data": "base64_encoded_layer",
      "position": {"x": 100, "y": 200},
      "size": {"width": 400, "height": 100},
      "text_content": "Sample Text"
    }
  ]
}
```
### 5.3 レイヤー編集API
```json
POST [nanobana_endpoint]/edit-layer
Request:
{
  "layer_data": "base64_encoded_layer",
  "edits": {
    "color_adjustment": {
      "brightness": 1.1,
      "contrast": 1.2,
      "saturation": 1.05
    },
    "text_changes": {
      "content": "New Text",
      "font": "Arial Bold",
      "color": "#FF0000"
    }
  }
}
```
### 5.4 レイヤー統合API
```json
POST [nanobana_endpoint]/merge-layers
Request:
{
  "layers": [
    {
      "data": "base64_encoded_layer",
      "position": {"x": 0, "y": 0},
      "opacity": 1.0
    }
  ],
  "canvas_size": {"width": 1200, "height": 628},
  "output_format": "png"
}
```
## 6. データ仕様
### 6.1 入力データ
- **商品名**: 文字列（最大50文字）
- **キャッチコピー**: 文字列（最大100文字）
- **バナーサイズ**: 選択式（1200×628, 728×90, 300×250, カスタム）
- **デザインスタイル**: 選択式（モダン, クラシック, ミニマル, ポップ等）
- **色調指定**: カラーパレット指定（メイン色、サブ色）
### 6.2 中間データ
- **レイヤー情報**: JSON形式でのレイヤー構成データ
- **編集パラメータ**: 各レイヤーの編集設定値
- **処理ログ**: 各ステップの実行結果
### 6.3 出力データ
- **最終バナー画像**: PNG/JPEG形式
- **ファイル名形式**: `ad_banner_[PRODUCT]_[TIMESTAMP].png`
- **メタデータ**: 制作情報、使用素材情報
## 7. 制約事項
### 7.1 API制限
- **Gemini API**: 分あたり60リクエスト、月間$30予算
- **nanobana API**: 利用規約に準拠、レート制限要確認
- **処理時間**: 複雑なレイヤー編集は時間がかかる場合がある
### 7.2 技術的制約
- レイヤー分割精度はnanobana APIの性能に依存
- 複雑なデザインの分割は完璧でない場合がある
- フォント指定は利用可能フォントに制限される
### 7.3 品質制約
- 生成画像の品質は元画像とプロンプトに依存
- レイヤー編集後の品質劣化の可能性
- 統合処理での色味変化の可能性
