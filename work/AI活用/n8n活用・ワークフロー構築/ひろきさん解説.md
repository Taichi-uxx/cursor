# 毎日ギャグ投稿ワークフロー 解説

## 概要

CSチームとGMセールスチームへの毎日のギャグ投稿を自動化するn8nワークフロー。朝の挨拶とギャグを自動生成し、Slackに投稿する。また、CS案件管理シートから期限切れのアクションを特定して通知する機能も含む。

## ワークフロー構成

### 処理フロー

```
Slackトリガー（定時実行）
    ↓
AIエージェント（ギャグ生成）
    ├→ Googleシート参照（過去のギャグ）
    └→ ギャグ生成
    ↓
Googleシート保存（生成したギャグ）
    ↓
メッセージ組み立て
    ↓
Slack投稿
    ↓
[並列処理]
    ├→ Googleシート取得（CS案件管理）
    ├→ フィルター（失注除外）
    ├→ Aggregate（データ集約）
    └→ AIエージェント（期限切れアクション特定）
        ↓
    Slack通知（期限切れ案件）
```

## 各フェーズの詳細

### 1. ギャグ生成フェーズ

#### 1-1. AIエージェント（ギャグ生成）

- **ノードタイプ**: AIエージェント
- **使用モデル**: Anthropic Claude
- **処理内容**: 朝の挨拶とギャグを生成

##### プロンプト設計

**システムプロンプト**:
```
あなたは日本のビジネスパーソンです。
朝の挨拶と短いダジャレギャグを1つ作ってください。
文字数は30から50文字程度が良いでしょう。
毎回アウトプットするギャグは、100人がいたら全員が笑えるレベルの内容にしてください。
```

**ユーザープロンプト（テンプレート）**:
```
おはようございます。今日も1日AIをお届けします。
[ここに面白いギャグを挿入]
最新資料はこちら: [資料URL]
```

**制約条件**:
- 過去に使ったギャグは同じものは使わない
- Googleシート「朝のギャグ」を参照し、過去のギャグを確認する

##### 重要な設計ポイント

1. **システムプロンプトとユーザープロンプトの使い分け**
   - システムプロンプト: 基本的な役割や制約条件を定義
   - ユーザープロンプト: 毎回の具体的な指示やテンプレート

2. **出力形式**
   - JSON形式ではなく、自然言語のみで出力
   - メッセージ組み立てで後から整形するため

#### 1-2. Googleシート連携（過去ギャグ参照）

- **ノードタイプ**: Google Sheets
- **操作**: Get All Rows
- **シート名**: 朝のギャグ
- **用途**: 過去に生成したギャグを参照し、重複を避ける

#### 1-3. Googleシート保存（生成ギャグ保存）

- **ノードタイプ**: Google Sheets
- **操作**: Append or Update Row
- **シート名**: 朝のギャグ
- **保存項目**:
  - 日時（ワークフロー実行日時）
  - アウトプット内容（生成されたギャグ）

### 2. メッセージ組み立てフェーズ

- **処理内容**: 生成されたギャグをSlack投稿用のフォーマットに整形
- **出力**: メンション付きメッセージ

### 3. Slack投稿フェーズ

- **ノードタイプ**: Slack
- **操作**: Post Message to Channel
- **チャンネル**: 通知テスト（テスト用）
- **メンション**: 指定ユーザーIDにメンション付きで投稿

### 4. CS案件管理連携フェーズ

#### 4-1. Googleシート取得

- **ノードタイプ**: Google Sheets
- **操作**: Get All Rows
- **シート名**: CS案件管理シート > AI打診
- **フィルター条件**:
  - ステータス: 打診中のみ
  - 打診日: 空欄でないもの

#### 4-2. フィルター処理

- **ノードタイプ**: Filter
- **条件**: ステータスが「失注」でないもの
- **目的**: 失注案件を除外

#### 4-3. Aggregate（データ集約）

- **ノードタイプ**: Aggregate
- **目的**: 複数行に分割されたデータを1つのアイテムに集約
- **重要性**: このノードがないと、各行ごとにAIエージェントが実行され、処理時間が大幅に増加する

#### 4-4. AIエージェント（期限切れアクション特定）

- **ノードタイプ**: AIエージェント
- **使用モデル**: Anthropic Claude（高速モデル推奨）
- **処理内容**: 打診日が過去になっている案件を特定

##### プロンプト設計

```
以下のシートを参照して、期限切れのアクションを特定したいです。
打診日が以前になっているものを抽出し、企業名、担当者名、アクション内容をセットにして出力してください。
本日の日付を基準にして、期限切れの内容のみまとめて出力する。
```

**入力データ**:
- Googleシートから取得した全データ（JSON形式）

**出力形式**:
- 期限切れの案件情報をまとめて出力

### 5. Slack通知フェーズ（期限切れ案件）

- **ノードタイプ**: Slack
- **処理内容**: 期限切れのアクション情報をSlackに通知

## 開発プロセスで学んだ重要なポイント

### 初期の問題点（3点評価）

1. **ノードが繋がっていない**
   - データが流れないため、Slack投稿が実行されない

2. **エラーチェックの分岐が不適切**
   - エラー判定ノードで、true/falseどちらに分岐しても同じエラーになる
   - エラーハンドリングが機能していない

3. **HTTPリクエストの使用**
   - AIエージェント専用ノードがあるのに、HTTPリクエストで実装
   - 専用ノードの方が設定が簡単で、認証も自動化される

### 修正内容

#### 1. AIエージェントノードの使用

- **変更前**: HTTPリクエストでOpenAI APIを直接呼び出し
- **変更後**: AIエージェントノードを使用
- **メリット**:
  - 認証設定が簡単（Bearerトークン不要）
  - プロンプト管理が容易
  - エラーハンドリングが自動化

#### 2. プロンプト設計の改善

- **システムプロンプトとユーザープロンプトの明確な分離**
- **出力形式の指定**: JSONではなく自然言語のみ
- **制約条件の明確化**: 文字数、品質基準、重複回避

#### 3. Googleシート連携の最適化

- **過去ギャグの参照**: 重複を避けるため
- **生成ギャグの保存**: 履歴管理のため
- **フィルター条件の追加**: 必要なデータのみ取得

#### 4. データ集約の実装

- **問題**: Googleシートから取得したデータが複数行に分割され、各行ごとにAIエージェントが実行される
- **解決**: Aggregateノードでデータを1つに集約
- **効果**: 処理時間の大幅短縮（63回実行 → 1回実行）

#### 5. フィルター条件の最適化

- **ステータス**: 打診中のみ取得
- **打診日**: 空欄でないもののみ
- **失注案件**: 除外
- **効果**: 63アイテム → 11アイテムに削減

## 技術仕様

### 使用ノードタイプ

- `n8n-nodes-base.slack`: Slack連携（投稿・通知）
- `@n8n/n8n-nodes-langchain.agent`: AIエージェント
- `@n8n/n8n-nodes-langchain.lmChatAnthropic`: Anthropic Claude API連携
- `n8n-nodes-base.googleSheets`: Googleシート連携
- `n8n-nodes-base.aggregate`: データ集約
- `n8n-nodes-base.filter`: データフィルタリング

### 使用AIモデル

- **ギャグ生成**: Anthropic Claude
- **期限切れアクション特定**: Anthropic Claude（高速モデル推奨）

### 外部サービス連携

- **Google Sheets**: データ保存・参照
- **Slack**: 通知・投稿

## パフォーマンス最適化

### 処理時間の改善

1. **Aggregateノードの追加**
   - 63回実行 → 1回実行
   - 処理時間: 数分 → 数秒

2. **フィルター条件の最適化**
   - 63アイテム → 11アイテム
   - 不要なデータの取得を削減

3. **高速モデルの使用**
   - 期限切れアクション特定には高速モデルを推奨
   - 処理速度の向上

## ベストプラクティス

### ワークフロー設計

1. **要件定義の重要性**
   - 最初からJSONコードで全体を作成する方が効率的
   - 要件を明確に定義してから実装

2. **専用ノードの活用**
   - HTTPリクエストではなく、専用ノードを使用
   - 認証やエラーハンドリングが自動化される

3. **データ集約の考慮**
   - 複数行のデータを処理する場合は、Aggregateノードで集約
   - 各行ごとに処理が実行されることを防ぐ

### プロンプト設計

1. **システムプロンプトとユーザープロンプトの分離**
   - システムプロンプト: 基本的な役割や制約
   - ユーザープロンプト: 具体的な指示やテンプレート

2. **出力形式の明確化**
   - JSONが必要な場合のみ指定
   - 自然言語のみで十分な場合は指定しない

3. **制約条件の明確化**
   - 文字数、品質基準、重複回避などを明記

### エラーハンドリング

1. **分岐の適切な設計**
   - true/falseで異なる処理を実行
   - 両方で同じエラーにならないようにする

2. **ノードの接続確認**
   - データフローが正しく接続されているか確認
   - 未接続のノードがないか確認

## 今後の改善案

1. **メモリー機能の活用**
   - 過去のギャグをメモリーに保存し、重複を避ける
   - Googleシート参照よりも高速

2. **複数パターンの生成**
   - 条件分岐を追加し、複数のギャグパターンを生成
   - A/Bテスト用のバリエーション作成

3. **処理時間の最適化**
   - 高速モデルの使用
   - 並列処理の実装

4. **エラーハンドリングの強化**
   - より詳細なエラーメッセージ
   - 自動リトライ機能
