## ハーネスエンジニアリングとは

- **語源**: 馬具（ハーネス）＝AIを安全かつ自分好みにコントロールするための仕組み
- **背景**: プロンプトエンジニアリング → コンテキストエンジニアリング → ハーネスエンジニアリングと進化
- **効果**: Anthropicの2025年3月ブログによると、ハーネスの有無でOpusのベンチマークが **78% vs 42%**（約2倍の差）
- **本質**: モデルとの1対1のラリーではなく、モデルの性能を最大化する「環境設計」

## カスタマイズ一覧（重要度付き）

### S: 最優先で導入すべき

#### 1. CLAUDE.md（AIの取扱説明書）
- 各フォルダ（プロジェクト）ごとに配置できる設定ファイル
- Claude Codeが毎セッション自動で読み込む
- **書き方のコツ**:
  - 細かいNG表現の羅列ではなく、**思想・ゴール**を書く
  - 制約をガチガチにすると、アウトプットの天井も下がるリスクがある
  - AIは自分よりIQが高い存在として扱い、目的を与える
- **例**:
  - 「私はディレクターでありデータドリブンな実行者ではない。実行するのはAI」
  - 「文章は読者の人生を動かすつもりで書く。読んだ人に感動を与えたい」
- **行数目安**: 200行まで読み込まれるが、**50行前後**がベスト（長すぎるとコンテキストを圧迫）
- **作り方**: `claude md 作って` でAIに生成させるか、手動でファイルを配置

#### 2. メモリ（MEMORY.md）
- セッションをまたいでClaudeが記憶を保持する仕組み
- 会話中に学んだことをMarkdownに自動保存（200行まで）
- 「これ覚えておいて」「メモリに入れておいて」で明示的に記憶させることも可能
- **Dream機能（新機能）**: メモリの整理・統合を自動で行う（人間の睡眠中のメモリ整合に近い概念）
- **活用例**: 「10時半以降は作業を止めて進捗更新を提案してくる」などパーソナライズが効く

#### 3. サブエージェント（エージェントチーム）
- メインの100万トークンを温存するため、調査等をサブエージェントに委譲
- サブエージェントは**同時実行可能** → 直列タスクを並列化し作業効率を大幅向上
- CLAUDE.mdに「隙あらばサブエージェントを起動しろ」と記載しておくと自動的に活用される
- **例**: 調査タスク / 実行タスク / 追加調査 を3並列で同時進行

#### 4. スキル・コマンドの作成
- **コマンド**: ユーザーが明示的に `/` で呼び出すもの
- **スキル**: AIが自律的に判断して呼び出すもの（エージェンティックスキル）
- 「同じことやってるな」「面倒だな」と思ったらスキル化を検討
- スキルの精度が低い場合 → ハーネス（CLAUDE.mdやエラーレポート項目の追加）で補強
- **スキルが基本**: あらゆることに横展開できるため、まずスキルを作ることが最重要

#### 5. 破壊コマンドブロック
- `rm` や `delete` など危険なコマンドの実行前に必ずブロック（確認）を入れる設定
- AIの暴走によるデータ全消失を防ぐための安全装置
- **必須設定**

#### 6. 進捗MD（プロジェクト管理）
- プロジェクトごとに進捗ファイルを作成し、以下を管理:
  - 現在のステータス
  - プロジェクトの背景・目的
  - タスク一覧
  - 現セッションの停止地点
  - 作業履歴
- 複数ターミナルの各エージェントから参照可能
- 3ステップ以上のタスクは進捗MDで管理するルールを推奨
- 自分の頭でアクション管理する必要がなくなる

---

### A: 強く推奨

#### 7. Ghostty（ターミナルエミュレータ）
- 複数ターミナルを高速に分割・タブ管理できるデスクトップアプリ
- **主な操作**:
  - `Cmd + D`: 横に分割
  - `Cmd + Shift + D`（推定）: 下に分割
  - `Cmd + W`: ペイン閉じる
  - `Ctrl + U`: 入力行を一括削除
- クライアントごと・プロジェクトごとにタブを開き、複数Claude Codeを同時稼働
- Cursor内蔵ターミナルより軽量で、文字数制限の問題もない
- **代替**: Warp MAXも選択肢（GUIボタン操作が可能でとっつきやすい）

#### 8. オートモード
- Claude Code v2.1.84以降で利用可能
- 安全なコマンドは承認なしで自動実行される設定
- ポチポチ承認の手間を大幅削減
- デフォルトでオンにしておくことを推奨

#### 9. Playwright（ブラウザ操作プラグイン）
- AIがブラウザ操作・スクリーンショット取得を自動で行える
- **活用例**: スキルの自動検証（起動 → 入出力確認 → スクショ → レポート作成）
- Claude Codeのプラグインとしてインストール可能

---

### B: 推奨（環境に応じて）

#### 10. Obsidian（エディタ / ビューア）
- ターミナルをGhosttyに切り出した場合、ファイルプレビュー用のエディタが必要
- 画像挿入やプレゼン資料作成にはObsidianが適する
- テキスト/コードのみなら **Zed** がおすすめ（変更箇所の色分け表示あり）

#### 11. Source Han Code JP（フォント）
- 空白文字や特殊文字の視認性が向上
- ターミナルやエディタのフォント設定で導入

#### 12. 時刻の自動注入
- Claude Codeに現在時刻を認識させる設定
- ライフスタイルに合わせた提案が可能に
- **例**: 「10時半なので今日はここまでにしましょう」「ジム前にこれやりませんか」

---

### C-D: あると便利

#### 13. 画像の自動圧縮（Pre-Tool Use）
- 画像をBase64変換で読み込む際、数万文字分のコンテキストを消費する問題への対策
- ファイルパスで画像を指定し、読み込み前に自動圧縮するフックを設定
- 長時間セッションで画像を多用する人向け

#### 14. 音声通知（Ping）
- セッション完了時に音声で通知
- ElevenLabsで日本語音声を生成し、カスタム通知音として設定可能
- GhosttyやWarp MAXの標準通知でも代用可

#### 15. スキル内のエラーレポート項目
- スキル定義内にエラー発生時の記録項目を追加
- スキルの精度改善サイクルを回すための仕組み

## 重要な考え方・Tips

### ハーネス設計の段階的アプローチ
1. **まずスキルを作る**（大体これで十分）
2. スキルの精度が低い → CLAUDE.mdにルール追加やエラーハンドリングを記載
3. 複雑なケース（全体の2-3割）→ 本格的なハーネス化（チェックプログラムの作成等）

### チェックプログラムの先行作成
- 成果物を直接作らせる前に、品質チェック用のプログラムを先に作らせる
- 例: CLAUDE.mdが200行以内かチェックするスクリプト
- 人間のチェック工数を削減し、品質を担保

### 情報収集
- XでAI系インフルエンサーをフォロー
- AIニュースの自動収集・投稿の仕組みを構築（Gemini + 自動投稿）

### 「使いながら学ぶ」姿勢
- 完全に理解してから始めるのではなく、まず導入して使いながら理解を深める
- 「自転車をこぐ」ように、スキルを作るという反復が最も効果的な学習法
