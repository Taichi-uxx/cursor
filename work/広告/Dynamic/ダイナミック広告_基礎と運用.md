# ダイナミック広告 基礎と運用

## ダイナミック広告とは

ダイナミック広告とは、ユーザーのサイト閲覧状況や行動履歴に基づいて、最適な広告クリエイティブを自動的に生成して配信する広告手法です。

### 主な特徴

#### 1. パーソナライズされた広告配信

ユーザー一人ひとりに合わせた広告を配信できることが最大の特徴です。ユーザーが過去に閲覧した商品やサービスの情報を基に、関連性の高い広告を自動的に生成します。ユーザーの行動に合わせて動的に広告内容が変化します。

#### 2. 自動クリエイティブ生成

タグを通じて収集したユーザーの行動データとデータフィード（商品カタログ）を組み合わせることで、広告クリエイティブを自動的に生成します。これにより、多数の商品やサービスがあっても、一つひとつ手作業でバナーを作る必要がなくなります。

#### 3. 複数商品の同時表示

一つの広告枠に複数の商品を表示できます。ユーザーが興味を示した商品に加え、関連商品や他のユーザーが一緒に購入した商品なども併せて紹介することが可能です。

#### 4. CVRが高い

ユーザーの関心に合致した広告を表示するため、通常の広告に比べてCTR/CVRが高くなる傾向があります。LPが商品詳細ページになるケースが多く、スタティック広告よりもCVまでの導線が短くなることも要因の一つです。

## スタティック広告とダイナミック広告の違い

### スタティック広告（静的バナー）

**特徴**
- 全てのユーザーに対して同じ内容の広告を表示
- あらかじめ決められた形式で配信される固定的なクリエイティブ

**メリット**
- 初期設定が比較的容易
- 統一されたブランドメッセージの伝達が可能
- クリエイティブの質をコントロールしやすい
- 配信準備の工数が少ない

**デメリット**
- ユーザーの興味関心に合わせた配信ができない
- 商品数が多い場合、全ての商品に対応するバナーを個別に作成する必要がある
- コンバージョン率がダイナミックバナーと比較して低くなる傾向がある

### ダイナミック広告（動的バナー）

**特徴**
- ユーザーごとに異なる最適化された広告を配信
- ユーザーの行動履歴に基づいて広告コンテンツを自動生成
- Criteoでは複数要素の掛け合わせで最大17兆通り以上のバナーパターンが存在

**メリット**
- ユーザーごとにパーソナライズされた広告配信が可能
- 一つの広告に複数の商品を表示できる
- 広告クリエイティブが自動で生成される
- コンバージョン率の向上に直結する
- 費用対効果が高い

**デメリット**
- 初期設定に手間がかかる（タグの設置、データフィードの準備など）
- 適切なタグ設定やデータフィードの構築・管理が必要
- 運用データを分析して継続的な改善が必要

### ダイナミック広告活用により効果が期待できる商材

**データベース系**
- 総合EC、ファッションEC、不動産、人材、旅行など

**効果が期待できる条件**
- サイト流入時点で明確に特定商品/サービスに興味関心があると判断できない場合

## ダイナミック広告が配信可能な媒体

### ディスプレイ/ネットワーク型

#### Google広告
- 200万以上のwebサイトに配信可能
- Googleアドセンス広告枠、ライブドアブログ、教えてgoo、食べログ、ピクシブなど

#### Yahoo!広告
- Yahoo!サービスサイト（Yahoo!ニュース、知恵袋など）
- Yahoo!ディスプレイアドネットワークのWebサイトやアプリ

#### Criteo
- 1日の広告配信数は40億と言われる大規模な配信ネットワーク
- Yahoo!サイトにも第三者媒体として広告配信が可能
- Meta、Smartnews、Bingなどにも配信が出る
- TikTok面も接続を試みている

#### RTBHOUSE
- ディープラーニングアルゴリズムを搭載
- Google、国内外のSSPに配信

#### Logicad
- ソニーの技術力を活かしたDSP
- SSP経由で配信

### ソーシャル/インフィード型

- **Meta**（Meta Advantage+ カタログ広告）
- **LINE**（LINEダイナミック広告）
- **SmartNews**（SmartNews Dynamic Ads）
- **TikTok**（TikTok ダイナミック広告）

## Criteoにおけるタグ/フィード設計

### タグ設計のポイント

どのユーザー(Cookie)が優良なのかの判断は、**「どの個別タグが何回発火したか」**でなされます。

#### ①ドメイン配下全ページへ網羅的に設定すること（学習データ量最大化）

- 1ユーザーがどの程度ページ回遊したのかが明確にわかるようになる為、重要となる
- タグ発火⇒次のタグ発火までの時間から、ページ滞在時間なども学習データとして読み込んでいる

#### ②個別タグを適切に使い分けること（学習データの質判断）

Criteoでは下記7つのタグが存在。下にいくほど重要なデータとして学習に活用される。

1. **訪問タグ**（RTG対象にならない）
2. **ホームページタグ**
3. **一覧ページタグ**
4. **商品タグ**
5. **カート追加タグ**
6. **カートタグ**
7. **CVタグ**

#### ③各地点で適切な商品ID/価格/個数の情報を返すこと（学習データの精度）

一覧ページ以降で、タグ発火時に特定の情報を通信する設定を行う必要あり。

| タグ種類 | 通信する値 |
| --- | --- |
| 訪問タグ | 通信する値なし |
| ホームページタグ | 通信する値なし |
| 一覧ページタグ | 商品ID 最大3つ通信可能 |
| 商品タグ | 商品ID 1つのみ通信可能 |
| カート追加タグ | 商品ID/価格/個数 それぞれ1つのみ通信可能 |
| カートタグ | 商品ID/価格/個数 それぞれ複数情報通信可能 |
| CVタグ | 商品ID/価格/個数 それぞれ複数情報通信可能（別途トランザクションIDの設定は必須） |

### フィード設計のポイント

#### ①商品IDをタグと合わせる

- タグとフィードが一致しない場合、どの商品に興味関心があるのかの学習ができない
- レコメンド、入札時の予測CTR算出等の精度低下により、パフォーマンス低下する
- 最小単位のSKUをIDとするか、一段上の粒度をIDとするかを決定する必要あり
- 基本一段上の粒度をIDとする形が推奨だが、タグ側で特定ページ以降SKUしか取れない場合があれば、SKUをIDとする

#### ②常に最新情報になっているか

- サイトに合わせフィードを最新情報にできていない場合、バナーの該当商品クリック⇒デッドリンクという最悪のケースが起こる可能性あり
- ユーザー体験として最悪なので、避ける必要あり
- 新商品発売日当日からバナー表示できないことでの機会損失も発生するため、重要な要素となる
- 1日4回まで自動取り込み設定が可能なため、基本最大数取り込み設定を行いたい

#### ③既存カラムを網羅的に活用する

それぞれの情報がバナー上のどこに出るのかが明確に決まっている為、活用できていないと、バナー内に意図せず空白ができてしまい、CTR低下に繋がる可能性あり。

**既存カラム一覧（Criteo Performance Product Feed（CPPF））**

| 項目 | 概要 | 例 |
| --- | --- | --- |
| **id（必須）** | 単一の商品を表す一意の識別子。商品のレコメンドがこのidを元にして行われるので、タグで送信される商品IDとフィードのidは必ず一致するようにしてください。 | abc123-hogehoge-45 |
| **title（必須）** | バナーに表示される商品名。最小6文字、最大26文字程度が表示されます。（バナーサイズによって表示される文字数に変動があります）改行は削除してください。 | プルオーバー（ブラック） |
| **link（必須）** | バナーをクリックしたときに遷移する商品のリンク先URL | https://example.com/item/knit/12345678 |
| **image_link（必須）** | 特定の商品の画像へのファイルパスを指定するURL | https://example.com/item/image/12345678.png |
| **additional_image_link(任意)** | 特定の商品の画像へのファイルパスを指定するURL | https://example.com/item/image/12345678_2.png |
| **price（必須）** | priceはバナーに表示される商品の価格 | 1234.56 |
| **sale_price(任意)** | sale_priceはセール中の商品の価格 | 99.99 |
| **availability(任意)** | 商品がサイトで購入できるかどうかを次の3つの値で指定<br>・「preorder」（仮注文: 商品は現在出荷できないが注文は可能である場合）<br>・「out of stock」（在庫切れ: 商品は出荷しておらず、注文も受け付けていない場合）→バナーの表示対象から除外<br>・「in stock」（在庫あり: 商品は出荷中で注文を受付可能である場合） | in stock |
| **description（任意: 但しFacebookに広告を出稿する場合、description は必須）** | バナーに表示される商品説明文 | 女の子らしく可愛く仕上げたキャミソール。伸縮性にも優れ着心地バツグンです。 |
| **google_product_category(任意)** | Googleの商品分類に基づいて商品アイテムのカテゴリーを指定 | 2271またはアパレル＆アクセサリー > トップス > キャミソール |
| **product_type（任意）** | 「>」の区切り文字で、3つまでの商品属性を指定。ユーザーが興味のある他の商品を予測するために利用 | FFブランド > Tシャツ > 女性向け |
| **star(任意)** | アイテムの評価（小数点を区切り記号として使用） | 4.5 |
| **item_group_id** | 商品カタログ内でバリエーション商品をグループ化する一意の商品識別子。商品の詳細（size [サイズ]、color [色]、material [素材]、pattern [柄]など）のみが異なる類似したバリエーション商品をグループ化できる。 | abc123 |
| **adult(任意)** | すべてのユーザーやオーディエンスに商品を提示しても安全かどうかを示す属性。「yes」または「no」のいずれかで指定。 | no |
| **extra_atp（任意）** | クリエイティブのpriceエリアに「price」項目より優先して表示される内容（文言可）。価格以外の情報を訴求したい場合に活用できるカラム。 | サマーセール開催中！ |

## 改善施策について

### 構造（※1CPN1ADGで設定）

#### RTG配信（リーセンシー0~400日 最大日数設定）

- セグメントを切る、フリークエンシー制限をかける等は行わず、全ユーザーを配信対象に含み、AIにターゲティングを任せる形が推奨

#### CCA配信（ターゲティング：Similar or LAL リーセンシー0~400日 最大日数設定）

- サイト未訪問ユーザーも配信対象に含むメニュー。ターゲティングは複数あるが、この2つが効果観点で推奨
- サイト訪問者も配信対象とし、RTGと重複させて配信することで、優良IMPの取りこぼしが少なくなる為、推奨

**その他ターゲティング**
- **人軸**：興味関心、ペルソナ、ジオ、アフィニティ、楽天データ連携
- **面軸**：コンテクスチュアル

#### 自動入札の活用

- 手動入札の場合、設定CPCに応じて媒体側で上限CPMが決まる仕組みとなるため、優良IMP獲得機会損失が起きやすい
- 自動入札は2種類存在
  - **ACO**：目標優先×CV最適×自動入札 予算傾斜を大きくかけて配信しない場合に使用
  - **BCO**：予算優先×CV最適×自動入札 予算傾斜を大きくかけて配信する場合に使用

#### 最適化地点変更（他媒体でのMCV施策）

- CVデータが少ない場合、効果が非常に悪くなる傾向あり
- CV最適⇒3件/日、売上最適⇒4件/日が最低でも必要とされている為、これを担保できる箇所にCVタグを動かす
- アカウント単位で1つのCV地点しか設定できない為、全CPNに影響が出る

#### 最適化指標変更（GA4連携）

- 今後GAのイベントを最適化指標に設定できるようになる想定

### クリエイティブ

#### タイトル/画像の変更

- 要素として大きい為、変更した際の改善インパクト大

#### カテゴリー情報の変更

- レコメンドする商品を決定する際の補完情報となるため、ユーザーが商品を探す軸としているカテゴリーを設定することが推奨
- CPPFでは最大6つ設定可能
- 該当カラム：google_product_category/product_type

#### クーポン設定の活用

- 静止画をローテーション表示させる設定
- ロゴ部分のみ反映と全体反映の2パターン存在。全体反映が推奨
- ローテーション表示する静止画を複数枚設定できるため、カルーセル的な見せ方も可能。多くても3枚程が推奨

#### 他CRフォーマット導入

**Showcase（ダイナミック系）**
- 静止画＋ダイナミックのフォーマット
- 特にアッパーファネル向け配信では活用したい

**アダプティブ広告（スタティックのレスポンシブ広告）**
- アッパーファネル向け配信での活用推奨

### その他

#### IMタグ実装（インティメートマージャータグ）

- IM社のタグと連携し類推IDを活用することで、Cookie欠損が起きているユーザーの補完が可能となる
- サイト内にIMタグを設定する必要あり

#### HashedPII連携

- IMタグ実装と目的は同じだが、類推IDではなく確定IDを活用するため、精度が高い
- 各媒体タグ内のスクリプトを書き換え、サイト内のハッシュ化メールアドレスを取得する設定を行う
- サイト内にハッシュ化メールアドレスを置いていない場合、サイト改修が必要となる
